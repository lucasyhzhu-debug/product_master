Information model (v2 — engagement feed). Events are a unioned feed grouped by day (Today / Yesterday / This week / Earlier — the HubSpot/Intercom pattern), each carrying a direction axis (← inbound · → outbound · • system) and a type (order / finance / message / document / schedule / milestone). A separate "next step" concept is pinned above the feed (CRMs treat upcoming tasks distinctly from past activity). Filters act on type; the day-bucket headers are sticky. Implies: `getCustomerTimeline` returns events tagged `{ type, direction, occurredAt }`; "next step" is a separate query (due invoices / open tasks), not part of the past feed. Comment on the taxonomy: are direction + day-buckets the right primary axes, or is type/object the better primary grouping (see v3)?
