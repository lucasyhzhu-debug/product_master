Invoice Lifecycle

Status transitions and what triggers them

No Invoice

Default state for all orders

Most orders never need an invoice. The sidebar shows a "Generate Invoice" button for orders in Confirmed status or later.

📄 Generate Invoice → creates draft
Draft

Work in progress — editable, auto-saves

Created when user clicks "Generate Invoice" or loaded from a previous session.
All fields editable. Auto-saves on field changes (debounced 2s).
No invoice number assigned yet. Can be discarded (deletes the draft record).
One draft per order at a time.

✅ Generate → finalizes to Final
👁 Preview → read-only view (still draft)
🗑 Discard → deletes draft, back to No Invoice
Final

Immutable — invoice number assigned

All data snapshotted at generation time (seller, buyer, items, amounts).
Sequential invoice number assigned: INV-YYMM-NNN.
Customer record updated with company/NPWP/billing address.
Cannot be edited or deleted — this is the permanent record.

Need a correction? Generate a new invoice for the same order. The new one gets the next number. Both are preserved in history.

🖨 Print / Save as PDF
👁 View anytime from Order Detail
📄 + New Invoice → creates fresh draft
Key rule: One draft, many finals An order can have at most ONE draft invoice at a time (work in progress). But it can have MULTIPLE finalized invoices (revisions/corrections). The Order Detail sidebar always shows the latest final invoice prominently, with a link to view older ones if they exist.
