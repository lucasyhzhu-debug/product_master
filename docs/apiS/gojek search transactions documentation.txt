=====================================
SECTION 1: AUTHENTICATION
=====================================

The GoBiz authentication uses a 2-step browser login flow, then refresh tokens for ongoing access.
All auth endpoints use: POST https://api.gobiz.co.id/goid/...


--- 1A: Login Request (Step 1 of 2) ---
Purpose: Tell the API we're starting an email/password login.
This MUST be called before the token request (Step 2).

POST /goid/login/request

Required Headers:
  Content-Type: application/json
  Authentication-Type: go-id
  Authorization: Bearer
  Gojek-Country-Code: ID
  Gojek-Timezone: Asia/Jakarta
  Origin: https://portal.gofoodmerchant.co.id
  Referer: https://portal.gofoodmerchant.co.id/
  X-AppVersion: platform-v3.98.1-bf97ae9c

Notable response headers:
  x-verification-method: password
  transaction-id: <uuid>  (may be needed for audit trail)

Automation note: This endpoint WORKS from curl/Node.js (no TLS fingerprint check).


--- 1B: Token Request - Password Login (Step 2 of 2) ---
Purpose: Submit password to get access_token + refresh_token.
Must be called AFTER login/request (Step 1).

POST /goid/token

Same headers as Step 1.

Payload:
{
  "client_id": "go-biz-web-new",
  "grant_type": "password",
  "data": {
    "email": "<EMAIL_FROM_ENV>",
    "password": "<PASSWORD_FROM_ENV>"
  }
}

Response (201 Created):
{
  "access_token": "<JWE token, ~1500 chars>",
  "refresh_token": "<JWE token, ~500 chars>",
  "dbl_enabled": true
}

AUTOMATION NOTE - BLOCKED FROM CURL/NODE.JS:
  This endpoint uses TLS fingerprinting (JA3) to detect non-browser clients.
  curl and Node.js fetch both get rejected with:
    401 {"errors":[{"code":"goid:error:unauthorized","message":"Please update to the latest official app version"}]}

  This means password login can ONLY be done from a real browser.
  Workaround: Use the refresh token flow below (1C) for automated access.


--- 1C: Token Refresh (AUTOMATABLE) ---
Purpose: Get a new access_token using a refresh_token. No TLS fingerprint check.
This is the KEY endpoint for automation.

POST /goid/token

Same headers as above.

Payload:
{
  "client_id": "go-biz-web-new",
  "grant_type": "refresh_token",
  "data": {
    "refresh_token": "<REFRESH_TOKEN>"
  }
}

Response (201 Created):
{
  "access_token": "<NEW access token>",
  "refresh_token": "<NEW refresh token>",
  "dbl_enabled": true
}

IMPORTANT: Each refresh returns BOTH a new access_token AND a new refresh_token.
You must store the new refresh_token for the next refresh cycle.
The old refresh_token becomes invalid after use.

AUTOMATION NOTE - WORKS FROM CURL/NODE.JS:
  Tested 2026-02-15: curl and Node.js fetch both successfully refresh tokens.
  This is the recommended path for server-side automation.

Automation Strategy:
  1. ONE-TIME (manual): Login via browser, copy access_token + refresh_token
  2. Store refresh_token in Convex platformCredentials table (platformId: "gobiz")
  3. Before any GoBiz API call:
     a. Try the API with stored access_token
     b. If 401, call /goid/token with grant_type=refresh_token
     c. Store the NEW access_token + refresh_token back to DB
     d. Retry the original API call
  4. If refresh also fails (token expired), alert user to re-login via browser

Token Lifetime (observed):
  - access_token: ~24 hours (needs confirmation)
  - refresh_token: ~2-3 days (needs confirmation, expired tokens seen after 3 days of no use)
  - Recommendation: Refresh proactively every 12 hours to keep the chain alive
