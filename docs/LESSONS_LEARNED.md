## 2026-02-23 — Production Outage: Vite Vendor Bundle TDZ Crash

**Severity:** P0 — site completely blank for all users
**Duration:** ~1 session (debug + fix + deploy)
**Root cause:** Circular cross-chunk dependency in `vite.config.ts` `manualChunks`

### What Happened

After a recent code change, production threw:
```
Uncaught ReferenceError: Cannot access 'E' before initialization
    at vendor-BoGX653r.js:1:23918
```

The `'E'` is a minified variable name. The site was a complete blank.

### Root Cause

Two bugs in `vite.config.ts` `manualChunks` created a circular dependency between the `vendor` and `vendor-react` chunks:

**Bug 1 — `scheduler` in wrong chunk:**
`scheduler` (react-dom's runtime scheduler) didn't match the `vendor-react` condition because the path is `node_modules/scheduler/...` — no `/react/` substring. It fell to the generic `vendor` chunk. But `react-dom` (in `vendor-react`) imports `scheduler`, so `vendor-react → vendor`.

**Bug 2 — `@floating-ui/react` in wrong chunk:**
The broad check `id.includes('/react/')` matched `@floating-ui/react` because its dist path contains `/react/dist/`. This pulled it into `vendor-react`, but its own deps (`@floating-ui/core`, `@floating-ui/dom`) fell to `vendor`. So `vendor → vendor-react` (via sonner importing React).

Result: `vendor-react → vendor` AND `vendor → vendor-react` — a cycle. Vite can't guarantee initialization order, so minified output accesses `E` before it's initialized → TDZ crash.

### Fix

In `vite.config.ts`:
1. Replaced `id.includes('/react/')` with exact package checks: `/node_modules/react/`, `/node_modules/react-dom/`, `/node_modules/react-router/`, `/node_modules/react-router-dom/`, `/node_modules/scheduler/`
2. Moved `@floating-ui` packages into `vendor-ui` (alongside `@radix-ui` which depends on them)

### Learnings

| # | Learning |
|---|---------|
| 1 | **TDZ in vendor bundle = circular chunk.** `Cannot access 'X' before initialization` in a minified vendor file always means two chunks depend on each other. Start by auditing `manualChunks`. |
| 2 | **Use exact paths in manualChunks.** `id.includes('/react/')` matches `@floating-ui/react`. Always use `/node_modules/package-name/` with a leading slash to prevent false positives. |
| 3 | **`scheduler` belongs with `react-dom`.** It's react-dom's runtime dep. If react-dom is in `vendor-react`, scheduler must be there too — match on `/node_modules/scheduler/`. |
| 4 | **The zustand deprecation warning was a red herring.** It came from Vercel's instrumentation bundle, not the app. Don't chase warnings that come from `instrument.*.js`. |
| 5 | **`gsd-debugger` commits directly to main.** The `/gsd:debug` agent applies fixes without respecting the branch workflow. After a debugger session, always check `git log` and `git branch --show-current` before deploying. |

### How to Diagnose Future Vite TDZ Errors

1. Run `npm run build` locally — it often surfaces warnings about circular chunks
2. Check `bundlemeta.json` (generated by vite-plugin-bundlesize) for chunk-to-chunk import graph
3. Look for any `manualChunks` pattern using substring matching (`id.includes`) — replace with exact `/node_modules/pkg-name/` prefix matches
4. Verify the chunk dependency graph is a DAG: `vendor-react` should import from zero other custom chunks
