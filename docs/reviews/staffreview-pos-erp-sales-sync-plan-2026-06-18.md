### Issue 1 — action auth
Verified: `requireRole(ctx: QueryCtx \| MutationCtx, token, roles): Promise<Doc<"users">>`
(`convex/lib/auth.ts:128-132`). Verified pattern: **there is no `protectedAction` in this project**;
public actions gate by calling an internal query that runs `requireRole` inside
(`convex/qrisPayments/actions.ts:7,29-31`). **Fix:** add an internal query `assertAdmin({token})`
(in `checkpoint.ts` — a non-node file; queries cannot live in the `"use node"` `sync.ts`) that runs
`requireRole(ctx, token, ["admin"])`; `triggerPosSync` calls it via `ctx.runQuery` before `runAction`.

### Issue 2 — orchestration belongs in the action
Verified: K3Mart does the parent→child orchestration inside its `"use node"` **action**, looping
`ctx.runMutation(saveRevenue)` → `ctx.runQuery(hasExternalRevenueItemsQuery)` →
`ctx.runMutation(saveRevenueItemsWithCounts)` (`convex/integrations/k3mart/adapter.ts:617-688`). A
mutation cannot call `runMutation`/`runQuery`. **Fix:** delete the two `applyPos*Page` mutations; the
action drains and orchestrates per page (mirroring K3Mart). Tests drive the **action** with a stubbed
`fetch` (covers dedup, refund-sign, parent-only, cursor-resume end-to-end). This also removes the
`v.any()` page validator smell.
