### TL;DR

The product has matured fast and the planning/migration discipline (GSD phases, runbooks, code reviews) is genuinely strong. The codebase pays for that velocity in three places that now cost you money on every change:

1. **Two parallel auth systems coexist (`requireRole` vs `protectedMutation`/`protectedQuery`).** Migration is half-done — 32 files use the new wrapper, 58 use the old, 7 mix both — and at least 64 mutations across `orders/`, `inventory/`, `feedback/`, `componentTypes`, etc. enforce **no auth at all**.
2. **Two parallel order-status models coexist (`Draft/AwaitingPayment/PaymentReceived/BeingPrepared/AwaitingDelivery/Complete` vs `Draft/AwaitingPayment/Confirmed/InProduction/Boxed/Labeled/WaitingShipment/CompleteShipped/PickedUp`).** 38 files reference the legacy names; CLAUDE.md documents only the new model. This is the single largest semantic landmine in the codebase.
3. **Schema and core mutation files have grown to "god module" size.** `schema.ts` 2,356 lines / 87 tables; `convex/externalData/queries.ts` 1,744; `orders/mutations/orderCrud.ts` 958; 89 files exceed 500 lines and are concentrated in the same 5 domains (orders, externalData, integrations, reports, expenses). Cyclomatic risk is now where bugs land.

P0 items below are blast-radius issues (security/data-correctness). P1 are accumulating drag (the kind that turns a 2-day feature into a 2-week one). P2 are hygiene.

## P0 — Blast-radius issues (fix before next phase)

### P0-1 — Order CRUD has no authentication on 10 of 12 mutations

**Where:** `convex/orders/mutations/orderCrud.ts`

| Mutation | Auth check | Lines |
|---|---|---|
| `create`, `cancel`, `remove`, `completeOrder`, `revertToConfirmed`, `updateOrderDiscount`, `completeBalls`, `createDraft`, `updateDraft`, `updateDeliveryFee` | **none** | 47, 296, 389, 432, 461, 491, 534, 568, 628, 932 |
| `submitOrder`, `copyFromCancelled` | uses `getSessionUser` (returns null silently — does **not** throw) | 765, 820 |

`getSessionUser` returns `null` rather than throwing — so even the two mutations that do "auth-look" fall through silently if the token is absent. None of the twelve calls `requireRole`. Combined with the fact that Convex client functions are world-callable by default, this means anonymous callers can create, cancel, or delete orders against production via the Convex client SDK or direct WebSocket protocol.

Same gap exists in:

- `convex/inventory/mutations.ts` — 6 mutations, 0 auth (`receiveStock`, `transferStock`, `adjustStock`, `deleteBatch`, `expireBatch`, `createComponentAndReceiveStock`)
- `convex/feedback/mutations.ts` — 7 mutations, 0 auth
- `convex/orders/mutations/statusUpdates.ts` — 7 mutations, 0 auth
- `convex/orders/mutations/packaging.ts` — 7 mutations, 0 auth
- `convex/orders/mutations/itemCrud.ts` — 4 mutations, 0 auth
- `convex/orders/mutations/inventoryIntegration.ts` — 4 mutations, 0 auth
- `convex/menuProductComponents/mutations.ts` — 5 mutations, 0 auth
- `convex/productionUnitTypes/mutations.ts` — 5 mutations, 0 auth
- `convex/whatsappTemplates/mutations.ts`, `shipping/mutations.ts`, `channels/mutations.ts` — 3 mutations each, 0 auth

**Why this is P0:** the auth model in `lib/functions.ts` exists and is well-designed. The risk isn't architectural — it's that the migration to it stalled mid-way. An external caller doesn't need to find a bug; the door is open.

**Fix:** every mutation either (a) uses `protectedMutation`, or (b) accepts `token: v.string()` and calls `requireRole(ctx, args.token, [...])` — non-optional. Add a CI grep that fails the build if a `mutation({` declaration in `convex/` (excluding `migrations/`, `auth/seed.ts`, `_generated/`, and an explicit allow-list) does not contain either `protectedMutation` or `requireRole(`.

**Effort:** 2–3 days. Mostly mechanical.

### P0-2 — Public unauthenticated sales endpoints

**Where:** `convex/http.ts:15` and `convex/http.ts:29`

```ts
http.route({ path: "/api/daily-sales", method: "GET", handler: httpAction(...) });
http.route({ path: "/api/daily-sales-csv", method: "GET", handler: httpAction(...) });
```

Both endpoints return CORS `*` and have no shared-secret, basic-auth, or token check. Anyone who learns the deployment URL (`*.convex.site`) can scrape daily revenue per product.

**Fix:** require an `x-api-key` header (validated against `platformCredentials` or an env var) on both routes. Same pattern your GrabFood webhooks already use via HMAC. Tighten `Access-Control-Allow-Origin` to your Vercel domain only.

**Effort:** 1–2 hours.

### P0-3 — Two order-status taxonomies in production simultaneously

**Where:** 38 files reference `BeingPrepared / AwaitingDelivery / PaymentReceived` (319 occurrences); 74 references to the new `InProduction / WaitingShipment / Boxed / Labeled` (CLAUDE.md §9).

Files with old statuses include core paths:
- `convex/orders/helpers/statusTransitions.ts`
- `convex/orders/helpers/kanbanBuilders.ts`
- `convex/orders/helpers/kitchenEnrichment.ts`
- `convex/orders/mutations/inventoryIntegration.ts`
- `convex/orders/queries.ts` (the `list` query's status validator hard-codes the legacy 7)
- `convex/integrations/internal/config.ts`
- `convex/invoices/mutations.ts`
- `convex/kitchenShiftRecords/mutations.ts`

This is not a cosmetic diff — `statusTransitions.ts` literally encodes the state machine, and integrations branch on these strings. A new dev today reading CLAUDE.md will write code against the new model and silently mismatch helpers using the old.

**Why P0:** every order-touching change has to cross-check both lookup tables. Bugs of the form "kitchen shift row never closes because we're checking `BeingPrepared` but production wrote `InProduction`" are exactly what this codebase will keep producing until you unify.

**Fix:** pick the canonical model (CLAUDE.md says it's the 9-state version), add a single typed union exported from `convex/orders/types.ts`, and run a migration that rewrites every legacy string in the database. Use `tsc` + a custom `eslint-no-restricted-syntax` rule to ban string literals matching the legacy names outside the migration file. Do this as one phase — partial cutover is what got you here.

**Effort:** 1 phase (3–5 days) including data migration + tests.

### P0-4 — Deprecated BOM fields still readable on hot paths

**Where:** `convex/schema.ts:115-117, 1041-1042` (and 65 other `@deprecated` markers across the code).

```ts
// DEPRECATED: Legacy fields kept for schema compat with existing docs. Use BOM instead.
productionType: v.optional(v.string()),
productionUnits: v.optional(v.number()),
```

Same fields exist on `orderItems`. CLAUDE.md §10 and pitfall #11 explicitly call this out — `productionType="original"` maps to `BIG_BALL`/`MID_BALL` in misleading ways. The fields are still in the schema, still optional, and code that reads them silently produces wrong ball counts.

**Why P0:** "units sold" / production-volume metrics depend on getting this right. Pitfall #13 is in CLAUDE.md because someone has already burned hours on it.

**Fix:** (1) make these fields `v.literal("__DEPRECATED__")` or remove them via migration — the schema validator will then reject any write; (2) grep for the field names and delete every read path; (3) keep the migration file as the only writer and have it write `null`. Delete in two phases if you're nervous, but get them out of the schema by end of next milestone.

**Effort:** 2 days.

**Pattern:** these aren't accidentally large — they're the seams the team keeps adding to. Split rules:

- **Schema:** split into `convex/schema/` per domain (orders, inventory, integrations, reports, etc.) and import them into `convex/schema.ts`. `defineSchema()` accepts a flat object — composing is one-liner. This alone makes schema PRs reviewable.
- **`externalData/queries.ts`:** carve into `kpi.ts`, `channel.ts`, `lifetime.ts`, `revenuePerBall.ts`. Hot file = hot blame.
- **`OrderForm` vs `OrderFormPOS`:** these share customer/voucher/discount logic; extract into hooks (`useOrderDraft`, `useVoucherApplication`, `useOrderItems`) and let each form be a thin shell. Right-now both are 800–1000 lines and changes have to land twice.
- **Orders package:** has `convex/orders/helpers.ts` (242 lines) AND `convex/orders/helpers/` (12 files). Same for `dispatchPlanner`. Pick one. The dual structure is a paper cut every time someone adds a helper and guesses wrong.

**Effort:** 1 dedicated phase per domain; do schema first (highest ROI per minute).

## P2 — Hygiene

- **`tsconfig.app.json`:** `baseUrl` deprecation warning will break in TypeScript 7.0. Remove `baseUrl` (the `paths` map already works without it via `vite/tsconfig-paths`) or add `"ignoreDeprecations": "6.0"` for now.
- **17 migration scripts in `convex/migrations/`** — once they've all run in production they should be archived. Convex will happily ship dead code and the dashboard `Functions` tab gets cluttered. Move to `convex/migrations/_archive/` or delete.
- **`convex/__tests__/hmac.test.ts`** is the only file in the top-level `convex/__tests__` dir. Move it under `convex/integrations/grabfood/__tests__/` for consistency with the per-domain pattern used everywhere else.
- **Two adjacent organizational patterns:** `convex/orders/helpers.ts` + `convex/orders/helpers/` (with index.ts). Same for `dispatchPlanner`. Pick "directory of helpers" (better) or "single helpers file" (worse at this size) and apply uniformly.
- **`src/lib/types.ts`** is 847 lines and contains both UI types and shared business types. Split into `src/lib/types/` per domain.
- **`xlsx` from CDN** — pinned correctly per CLAUDE.md pitfall #15, but the install fails when the CDN is unreachable (e.g., this sandbox). Consider vendoring the tarball under `vendor/` and updating the install URL — CDN outages have happened to SheetJS before.
- **`src/App.tsx` is 711 lines** and ~62 routes. The lazy-load wrapper boilerplate is 80% of the file. Extract a `routes.tsx` that exports an array `[{ path, element, roles }]` and let `App.tsx` map over it.
- **2 cron jobs only** — fine for now, but `convex/crons.ts` will accumulate. Add a comment block grouping by domain when you add the third.
- **`docs/reports/` already has 3 prior tech-debt reports** from Feb 2026. Check what was promised in `techdebt-2026-02-02.md` vs what's still open here — there may be partial overlap.

## What is genuinely good (don't lose it)

These are non-trivial wins that the next refactor must preserve:

- **GSD phase discipline + branch-per-phase + audit/verify gates.** This is the reason the codebase is 200k LoC and not a smoking ruin. The verification artifacts in `.planning/` are working as advertised.
- **Schema annotations.** `// CACHE:` markers documenting which fields are derived and where they're recomputed are excellent — keep doing this.
- **`lib/functions.ts` design.** The `protectedMutation`/`protectedQuery` API is well-designed. Finishing the migration to it (P1-1) is the highest-leverage hygiene work in this report.
- **`convex/lib/`** generally — `auth.ts`, `costCalculator.ts`, `journalEngine.ts`, `periodRange.ts` are each small, single-responsibility, and well-named. This is what the rest of the codebase should look like.
- **Test infra:** `convex-test` integration coverage of 86 backend specs is rare in real-world Convex apps.
- **CLAUDE.md** is opinionated and operationally useful (pitfalls #1–15). Keep adding to it as you find new sharp edges.
