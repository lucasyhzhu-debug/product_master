**Test name:** `"multi-channel revenue aggregation: gobiz + consignment + internal"`

**Test design (per CONTEXT.md locked decisions):**

1. Seed 3 BOM-linked menu products (one per channel) with simple round-number costs:
   - Product A ("Gobiz Product"): BOM = 1x BIG_BALL (10000) + 1x SMALL_BOX (2000) = 12000 COGS/unit
   - Product B ("Consignment Product"): BOM = 1x MID_BALL (5000) + 1x SMALL_BOX (2000) + 1x STICKER (500) = 7500 COGS/unit
   - Product C ("Internal Product"): BOM = 2x MID_BALL (5000) + 1x LARGE_BOX (3000) = 13000 COGS/unit

2. Seed gobiz channel: gross 100000, commission 10000, 2 units of Product A
   - `seedExternalRevenue(t, { source: "gobiz", periodStart: TEST_WEEK_START, revenueGross: 100000, commission: 10000 })`
   - `seedRevenueItem(t, revenueId, { source: "gobiz", productName: "Gobiz Product", unitPrice: 50000, quantity: 2, totalPrice: 100000, linkedMenuProductId: productAId })`

3. Seed consignment channel: gross 50000, revShare 10000 (20%)
   - `seedExternalRevenue(t, { source: "consignment", periodStart: TEST_WEEK_START, revenueGross: 99999 })`
     **NOTE:** The `externalRevenue.revenueGross` is intentionally set to 99999 (a sentinel value), NOT 50000. The query skips `source === "consignment"` in the platform loop (line 233 of incomeStatement.ts) and only reads gross from `consignmentSettlements.totalRevenue`. If a double-counting bug existed, the test would fail because totalGross would include 99999 instead of 50000.
   - `seedRevenueItem(t, linkedRevenueId, { source: "consignment", productName: "Consignment Product", unitPrice: 25000, quantity: 2, totalPrice: 50000, linkedMenuProductId: productBId })`
   - Create `consignmentOutlets` record with revSharePercent: 20
   - Create `consignmentSettlements` record with totalRevenue: 50000, revSharePercent: 20, revShareAmount: 10000, frolliePayment: 40000, linkedRevenueId

4. Seed internal channel: gross 80000, discount 15000 (via order data)
   - Create customer record (follow existing pattern at `incomeStatement.test.ts:477-479`: `{ name: "Test Customer", createdBy: "test" }`)
   - Create order following existing pattern at `incomeStatement.test.ts:482-498` (includes all required schema fields: customerId, customerName, status, paymentStatus, orderDate, totalCost, totalMargin, deliveryType, itemCount, createdBy). Key fields: orderNumber: "0105-002", totalAmount: 80000, finalTotal: 75000, deliveryFee: 10000
   - Discount = totalAmount - (finalTotal - deliveryFee) = 80000 - (75000 - 10000) = 15000
   - `seedExternalRevenue(t, { source: "internal", periodStart: TEST_WEEK_START, revenueGross: 80000, externalTransactionId: "0105-002" })`
   - `seedRevenueItem(t, revenueId, { source: "internal", productName: "Internal Product", unitPrice: 40000, quantity: 2, totalPrice: 80000, linkedMenuProductId: productCId })`

5. Call query and assert:

   **Per-channel assertions:**
   - gobiz: gross=100000, commission=10000, netRevenue=90000, cogs.production=20000 (2*10000), cogs.packaging=4000 (2*2000), cogs.total=24000
   - consignment: gross=50000, revShare=10000, netRevenue=40000, cogs.production=10000 (2*5000), cogs.packaging=5000 (2*(2000+500)), cogs.total=15000
   - internal: gross=80000, discount=15000, netRevenue=65000, cogs.production=20000 (2*2*5000), cogs.packaging=6000 (2*3000), cogs.total=26000

   **Cross-channel total assertions:**
   - totalGross = 100000 + 50000 + 80000 = 230000
   - totalCommission = 10000
   - totalRevShare = 10000
   - totalDiscounts = 15000
   - totalDeductions = 10000 + 10000 + 15000 = 35000
   - netRevenue = 230000 - 35000 = 195000
   - totalProductionCogs = 20000 + 10000 + 20000 = 50000
   - totalPackagingCogs = 4000 + 5000 + 6000 = 15000
   - totalCogs = 50000 + 15000 = 65000
   - grossProfit = 195000 - 65000 = 130000
   - grossMarginPercent: use `toBeCloseTo(66.67, 2)` — actual is 66.6666... repeating
   - totalAdBurn = 0
   - totalPromoBurn = 0

   **Structural assertions:**
   - `channels.length === 3` (guards against double-counting of consignment channel)

   **Channel ordering:** channels sorted by gross descending: gobiz (100000) > internal (80000) > consignment (50000)

   **Channel-level confidence:** All 3 channels should have `confidence === "exact"` (exact revenue sources, all products have BOM COGS). This validates the `worstConfidence` composition logic.

   **Product confidence:** All 3 channels should have products with confidence = "calculated" (all BOM-linked)

   **Gap analysis (happy path):**
   - `gapAnalysis.unmappedProducts` should be empty array (all products are BOM-linked)
   - `gapAnalysis.totalMappedProducts === 6` (2 items per channel × 3 channels)
   - `gapAnalysis.totalProducts === 6`
   - `gapAnalysis.zeroCostComponents` should be empty array (all component costs > 0)

Note: Use standard component type codes matching existing test conventions (e.g., "BIG_BALL", "SMALL_BOX", "MID_BALL", "STICKER", "LARGE_BOX"). The `buildProductCOGSMap` resolves by `componentTypeId` (Convex `_id`), not by `code`, so collisions don't affect COGS computation. Each `convexTest(schema)` instance has an isolated fresh database.
