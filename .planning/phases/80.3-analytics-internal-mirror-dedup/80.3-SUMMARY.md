## What shipped

A one-line R5 dedup rule inside `loadExternalStream` at `convex/reports/unitEconomics.ts:163` that skips `externalRevenue` rows where `source === "internal"`. These rows are projections of native `orders` rows (created by `syncInternalOrders` for the Sales Aggregation pipeline), so their inclusion in the analytics loader was double-counting every Direct/WhatsApp/Instagram order.

Plus 13 new regression tests in `convex/reports/__tests__/unitEconomics.test.ts` covering all 11 analytics reducers via the 3 snapshot queries that consume `loadFilteredData` after Phase 80.1's consolidation.

## Deviations from PLAN

Three deviations from the PLAN as written, all flagged per the Frustrations directive (precise instruction adherence):

### 1. RESEARCH Section 2 was outdated — Phase 80.1 has shipped

The PLAN's RESEARCH Section 2 said Phase 80.1 was "NOT YET SHIPPED" and instructed Test 17 to iterate the 11 standalone queries (`kpiSummary`, `byWeekday`, `dayHourHeatmap`, `channelEconomics`, `volumeByType`, `unitsPerTxnByChannel`, `aovByChannel`, `skuPareto`, `skuChannelMatrix`, `channelMomentum`, `rollingTrend`).

In reality, Phase 80.1 shipped on 2026-04-18 (commit `daf2997a`) and consolidated all 11 reducers into 3 grouped snapshot queries (`kpiAndChannelSnapshot`, `timeSeriesSnapshot`, `skuSnapshot`). The 11 standalone queries no longer exist as separate exports. Verified via `grep '^export const \w+ = query' convex/reports/unitEconomics.ts` returning only the 3 snapshot wrappers.

**Adaptation:** Test 17 still covers all 11 reducers, but each test invokes the appropriate snapshot query and asserts on its inner result field (e.g. `kpiAndChannelSnapshot.kpi`, `timeSeriesSnapshot.byWeekday`, `skuSnapshot.skuTop`, etc.). All 11 reducers retain symmetric coverage — the only change is the call path. This deviation aligns with PLAN Risk #2 ("if Phase 80.1 ships first, R5 is unchanged") and is consistent with `convex/reports/__tests__/unitEconomics-unlinked.test.ts` (Phase 80.2) which already follows this pattern.

### 2. PLAN Wave 1 acceptance gate `git grep ... | 1 hit` required rewording the inline comment

The PLAN's acceptance gate said: `git grep 'source === "internal"' convex/reports/unitEconomics.ts` returns exactly 1 hit. My initial inline comment included the literal string `source === "internal"`, producing 2 hits. Per the precise-instruction-adherence directive, I rephrased the comment to use `Rows with the \`internal\` source are` and `Authoritative spec: ...` instead, leaving the literal `source === "internal"` only on the executable code line. Acceptance gate now passes (1 hit, line 163).

### 3. Pre-existing test `unitEconomics-unlinked.test.ts` had to be updated

The PLAN did not anticipate that the existing Phase 80.2 test "does not regress already-linked parent with children (internal source)" was asserting the OLD (buggy) behavior — that an internal-mirror parent with children would contribute revenue to a menu product. Post-R5 that revenue must come from the native `orders` row, not the mirror. I updated the test to seed a native `orders` + `orderItems` twin alongside the internal mirror (matching the real production write pattern of `syncInternalOrders`) and kept the same `expect(ours?.revenue).toBe(46000)` assertion — the value now comes from the native order, the mirror contributes 0. This is documented inline in the test with a comment explaining the post-R5 invariant.
