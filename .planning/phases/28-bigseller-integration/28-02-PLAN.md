**Create `src/hooks/convex/useBigSeller.ts`**:

Follow the existing hook pattern in the project (see other hooks in `src/hooks/convex/`).

1. `useBigSellerSyncState()`: Wraps `useQuery(api.integrations.bigseller.queries.getSyncState, { token })`. Uses auth token from `useAuth()`. Returns `{ data: BigSellerSyncState | undefined, isLoading: boolean }`. Note: query now requires auth token (added in Plan 01 Task 3).

2. `useBigSellerOrders(filters?)`: Wraps `useQuery(api.bigsellerOrders.queries.listOrders, { token, ...filters })`. Accepts optional `startDate`, `endDate`, `platform` filters. Returns `{ data, isLoading }`.

3. `useBigSellerUnmappedSkus()`: Wraps `useQuery(api.bigsellerOrders.queries.getUnmappedSkus, { token })`. Returns `{ data: UnmappedSku[], isLoading }`.

4. `useBigSellerOrderStats()`: Wraps `useQuery(api.bigsellerOrders.queries.getOrderStats, { token })`. Returns stats including `allCostFeeZero` for COGS caveat.

5. `useStartBigSellerSync()`: Wraps `useAction(api.integrations.bigseller.sync.startSync)`. Returns the action function.

**Add exports to `src/hooks/convex/index.ts`**: Export all 5 hooks from useBigSeller.

**Create `src/components/salesAnalytics/BigSellerSyncPanel.tsx`**:

This is an expandable panel that renders WITHIN the BigSeller IntegrationHealthCard expansion area in SettingsTab. It is NOT a separate page.

**Layout (per locked decision — step-by-step progress card):**

1. **Sync Controls Row**:
   - Date range inputs (startDate, endDate) — default to incremental (last sync to today). Validate max 31 days.
   - "Sync Now" button (primary). Disabled when: sync already running, or token expired.
   - If token expired: inline warning "Token expired — paste new token" with button to open BigSellerTokenDialog. Per locked decision, no page-level banner.

2. **Progress Card** (visible when sync stage is not idle):
   Step-by-step progress with checkmarks per locked decision. Use `stage` (from `syncState.stage`) not `phase`:
   - Step 1: "Triggering sync..." (spinner when active, checkmark when done)
   - Step 2: "Syncing data (attempt N/8)..." (shows poll count, spinner/checkmark)
   - Step 3: "Fetching orders..." (spinner/checkmark)
   - Step 4: "Storing data..." (spinner/checkmark)
   - Step 5: "Complete" (green checkmark) or "Failed" (red X with error message + Retry button)

   If `stage === "retrying"`: show "Retrying (attempt 2/2)..." between failed first attempt and new poll.

   Use `Loader2` spinner (lucide) for active steps, `CheckCircle2` for completed, `XCircle` for failed.

3. **Summary Card** (visible when stage === "complete"):
   Compact summary per locked decision: "Synced 47 orders (12 new, 35 updated). Revenue: Rp 2.4M. 3 unmapped SKUs."
   Handle empty sync: "No orders found for this date range." (do not show as error).
   Use `formatCurrency` from `src/lib/utils.ts` for revenue display.
   If unmappedSkus > 0: amber "N unmapped SKUs" badge linking to Product Mapping tab.
   Expandable to show more detail (Claude's discretion on exact layout).

4. **COGS Caveat Banner**:
   If `orderStats?.allCostFeeZero === true`, show amber banner: "Profit = Revenue (COGS not configured in BigSeller)". Per locked decision.

**State management**: Subscribe to `getSyncState` via `useBigSellerSyncState()`. The sync state updates reactively as the server-side scheduler-chain progresses — no client-side polling needed. Admin can leave and return to see current state.

**Toast on completion**: When sync transitions to "complete" or "failed":
- If triggered by the "Sync Now" button click in the current session: use `actionToast("Sync complete!", event)` where `event` is the button click event. Pass the event to the submit handler and down to the toast call.
- If admin returned to the page and found sync already completed (background completion): use `toast.info("BigSeller sync completed")` — no click event available.
- For errors: use `toast.error("BigSeller sync failed: " + errorMessage)`.
- NEVER use `toast.success()` — this is a project convention. Use `actionToast()` or `toast.info()` for success states.

**Dark mode**: Follow existing component patterns — reference IntegrationHealthCard.tsx for the established pattern.
