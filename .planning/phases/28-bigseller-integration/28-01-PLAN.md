**Create `convex/integrations/bigseller/helpers.ts`** (pure functions, no "use node"):

1. `buildBigSellerHeaders(mucToken: string)`: Returns headers object with `cookie: muc_token=${mucToken}`, `content-type: application/json`, `origin`, `referer`, `user-agent` per BIGSELLER_PROFIT_API.md.

2. `buildPageListBody(startDate, endDate, pageNo, shopIds)`: Returns the full 25+ field request body per the "Shared Request Schema (Profit)" in BIGSELLER_PROFIT_API.md. MUST include ALL fields — `searchType: "order"`, `platformTemplate: "common"`, `currency: "IDR"`, `orderState` array with all 5 states, `queryType: "sku"`, etc. Missing fields cause silent `code: -1` failures.

3. `detectHtmlResponse(responseText: string): boolean`: Returns true if response starts with `<!DOCTYPE` or `<html` — indicates auth failure per Pitfall 4.

4. `mapOrderToRevenue(order, syncLogId)`: Maps a BigSeller pageList row to `saveRevenue` args format. Source = `order.platform` (lowercase: "shopee"/"tiktok"), NOT "bigseller". Use `externalTransactionId: "bigseller:{platformOrderId}"` for dedup. Fee fields: `commission: Math.abs(order.commissionFee)`. Revenue fields: `revenueGross: order.saleAmount`, `revenueNet: order.platformIncome`.

5. `mapOrderToStorage(order, syncLogId)`: Maps a BigSeller pageList row to `bigsellerOrders` insert format. Keep all raw fee values (negative for costs). Include `skuVoList` array.

6. `buildSyncTaskCreateBody(startDate, endDate)`: Returns body for `sync/task/create.json` — `{ startTime, endTime, timeType: "orderCreatedTime" }`.

**Create `convex/integrations/bigseller/sync.ts`** ("use node"):

This is the core scheduler-chain. Import from `../../_generated/server` (internalAction, internalMutation), `../../_generated/api` (internal), and local helpers/config.

1. **`updateSyncState`** (internalMutation): Upserts the singleton `bigsellerSyncState` document. Args: phase, pollAttempt, maxPolls, attempt, startDate, endDate, optional errorMessage, optional summary, optional completedAt. Query for existing doc — if exists, patch it; if not, insert new.

2. **`startSync`** (action — public, admin-only): Entry point called by frontend. Args: `token: v.string(), startDate: v.optional(v.string()), endDate: v.optional(v.string())`. Validates admin role via `ctx.runQuery(internal.platformCredentials.queries.validateAdminToken)`. If no dates provided, use incremental sync: query last successful sync log for "bigseller" source to get last sync date, default startDate = lastSync or 30 days ago, endDate = today. Validate date range <= 31 days (BIGSELLER_MAX_SYNC_DAYS). Check current sync state — if already `"triggering"` or `"polling"`, return `{ success: false, error: "Sync already in progress" }`. Set sync state to `"triggering"`. Create sync log via `createSyncLog`. Schedule `triggerSync` via `ctx.scheduler.runAfter(0, ...)`. Return `{ success: true }`.

3. **`triggerSync`** (internalAction): Args: startDate, endDate, attempt, syncLogId. Resolve token from platformCredentials (query for bigseller credential, extract currentToken). Call `POST ${BIGSELLER_API_BASE}/sync/task/create.json`. Log raw response via a helper that calls `createSyncLog` or stores in metadata. If `code === -1` and msg contains "sync task is in progress" — this is "join existing sync" per locked decision. Update state to "polling". If `code === 0` — success, update state to "polling". If HTML response detected — auth failure, update state to "failed" with "Token expired — paste new token" error, update platformCredentials lastRefreshStatus to "error". Schedule `pollSyncTask` with 60s delay.

4. **`pollSyncTask`** (internalAction): Args: startDate, endDate, pollAttempt, maxPolls, attempt, syncLogId. Resolve token. Call `GET ${BIGSELLER_API_BASE}/sync/task/detail/new/get.json`. Parse `data.progressInfo.taskStatus`.
   - If `"complete"`: update state to "fetching", schedule `fetchOrders` immediately (runAfter 0).
   - If pollAttempt >= maxPolls: if attempt === 1, update state to "retrying", schedule `triggerSync` with attempt=2 after 5s (auto-retry once per locked decision). If attempt >= 2, update state to "failed" with error "Sync timed out after 2 attempts".
   - Otherwise: update state with incremented pollAttempt, schedule next `pollSyncTask` after 60s.
   - HTML response detection: same auth failure handling as triggerSync.

5. **`fetchOrders`** (internalAction): Args: startDate, endDate, attempt, syncLogId. Resolve token. Call `POST ${BIGSELLER_API_BASE}/pageList.json` using `buildPageListBody`. Paginate: start at pageNo=1, fetch pages while `pageNo <= totalPage` (from response `data.totalPage`). For each page:
   - Parse `data.rows` array (each row = one order).
   - Call `mapOrderToStorage` for each row, batch-insert via `ctx.runMutation(internal.bigsellerOrders.mutations.upsertOrders)`.
   - Call `mapOrderToRevenue` for each row, batch-insert via `ctx.runMutation(internal.externalData.mutations.saveRevenue)`.
   - Collect SKU codes from all orders for product mapping registration.
   - After all pages fetched: call `saveProductMappings` with all unique SKU codes (source = "shopee" or "tiktok" based on order platform).
   - Calculate summary: totalOrders, newOrders (inserted), updatedOrders (patched), totalRevenue (sum of platformIncome), unmappedSkus (count of SKU codes without linkedMenuProductId in externalProductMappings).
   - Update sync state to "complete" with summary.
   - Update sync log to "success" with duration.
   - Handle partial failures: if a page fetch fails, log the error, continue with next page if possible, mark sync as "complete" with partial data rather than failing entirely.
   - HTML response detection: auth failure handling.

**Important implementation notes:**
- All actions use `"use node"` directive at top of sync.ts
- Token resolution: query `platformCredentials` for bigseller credential, extract `currentToken` field
- Use `BIGSELLER_FROLLIE_SHOP_IDS` from config in ALL pageList requests to avoid multi-brand data leakage (Pitfall 3)
- Product mappings: register with source matching the actual platform (e.g., "shopee" not "bigseller") so they appear correctly in ProductMappingTab filtering
