# Phase 70.1: Admin All-Expenses Visibility - Context

**Gathered:** 2026-04-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Admin users can see ALL company expenses (from all users) in the MyExpenses page, with their own expenses pinned to top and highlighted with a blue ring. Void and approval actions available from the timeline panel. Non-admin users see no change.

**Trigger:** Co-founder accidentally approved an employee-paid expense that was company-paid. No way to void it from the UI because MyExpenses only shows own expenses.

</domain>

<decisions>
## Implementation Decisions

### Admin Scope
- **D-01:** Admin-only visibility. Managers do NOT see all expenses (they already have the approval queue). Query restricted to `["admin"]` role.
- **D-02:** Same page, conditional upgrade — no separate admin page. MyExpenses page upgrades in-place when user is admin.

### Data Fetching
- **D-03:** Mutually exclusive hooks — `useMyExpenses` skips for admins, `useAllExpenses` skips for non-admins. Only one real-time subscription active per user.
- **D-04:** New `listAllExpenses` admin-only query uses existing `by_status` index when filtered, full table `collect()` when unfiltered.
- **D-05:** Join submitter names via `nameMap` pattern (same as `listPendingForApproval`). No receipt URL resolution in listing.

### Highlight & Sorting
- **D-06:** Blue ring highlight (`ring-2 ring-blue-400`) for admin's own expenses — matches order kanban pattern exactly.
- **D-07:** Toggle checkbox with ring swatch label ("My expenses") — same as order kanban legend.
- **D-08:** Admin view sorted: own expenses first (pinned to top), then others. Both groups by `createdAt` descending.

### Actions
- **D-09:** Void via timeline panel — clicking expense card opens timeline; admin sees `ApprovalActions` (already has Void button) in panel header. No inline void on cards.
- **D-10:** All existing `ApprovalActions` (approve, reject, acknowledge, flag, mark-as-paid, void, convert-to-capex) available in timeline panel for admin.

### Card Display
- **D-11:** Submitter name shown in metadata row (before vendor) when admin views all expenses. Optional prop, backward compatible.
- **D-12:** Page title changes to "All Expenses" for admin, "My Expenses" for non-admin.

### Claude's Discretion
- Loading state handling during admin query fetch
- Empty state text for admin ("No expenses found" vs "No expenses in this status")
- Ring priority when card is both "mine" and "selected" (selection should take precedence)

</decisions>
