  <action>
Create `convex/migrations/schemaCleanup.ts` with dashboard-callable mutations. Use the same pattern as `bomBackfill.ts` -- each mutation uses `mutation()` (not `internalMutation`), accepts `token: v.string()` for admin auth via `requireRole(ctx, args.token, ["admin"])`, and returns a report object.

**Mutation 1: `backfillIngredientsCostFields`**
For every ingredient where `costPerBaseUnit` is undefined OR `baseUnit` is undefined:
- Calculate `costPerBaseUnit` from `(priceExclShipping + shippingCost) / volumePurchased` then convert to base unit (if unitType is "kg" multiply by 0.001 for per-gram, if "l" multiply by 0.001 for per-ml, otherwise use as-is)
- Set `baseUnit` based on `unitType`: "kg" -> "g", "l" -> "ml", "m" -> "cm", otherwise same as unitType
- Patch the document
Return: `{ total, patched, skipped }`

**Mutation 2: `backfillPackagingMaterialsCostFields`**
Same logic as above but for `packagingMaterials` table.
Return: `{ total, patched, skipped }`

**Mutation 3: `backfillMenuProductsRequiredFields`**
For every menuProduct:
- If `unitCost` is undefined -> set to `0`
- If `cachedProductionSummary` is undefined -> set to `""`
- If `productType` is undefined -> set to `"food"` (the default; all current products are food products)
Return: `{ total, patched, skipped }`

**Mutation 4: `backfillOrdersRequiredFields`**
For every order:
- If `isKitchenVisible` is undefined -> compute from status using the same logic as `statusTransitions.ts`:
  ```typescript
  const kitchenVisibleStatuses = ["Draft", "Confirmed", "InProduction", "Packaging", "Boxed", "Labeled", "WaitingShipment", "WaitingPickup"];
  const isVisible = kitchenVisibleStatuses.includes(order.status);
  ```
- If `completedAt` is undefined AND status is terminal ("CompleteShipped", "PickedUp", "Cancelled") -> set to `order._creationTime` (best-guess for historical orders)
- If `finalTotal` is undefined -> compute: `order.totalAmount - (order.orderLevelDiscount ?? 0)` (if no discount, finalTotal equals totalAmount)
Patch only if any field needed updating.
Return: `{ total, patched, skipped }`

**IMPORTANT: Orders table may have many documents.** Check if the table has > 5,000 documents. If the mutation might timeout, implement cursor-based batching: process N documents (e.g., 500) at a time, return a cursor, and require re-calling the mutation. For simplicity and given this is a small FMCG business, assume < 5,000 orders and process all in one mutation. Add a comment noting to batch if timeout occurs.

**Mutation 5: `backfillKitchenInventoryFields`**
For every kitchenInventory document:
- If `totalProducedOriginal` is undefined -> set to `0`
- If `totalProducedBiteSized` is undefined -> set to `0`
- If `updatedBy` is undefined -> set to `"system"`
Return: `{ total, patched, skipped }`

**Mutation 6: `backfillProductionUnitTypesColor`**
For every productionUnitType:
- If `color` is undefined -> set to `"#93C572"` (default green)
Return: `{ total, patched, skipped }`

**Mutation 7: `clearMenuProductsDeprecatedFields`**

**Mutation 8: `clearOrderItemsDeprecatedFields`**
For every orderItem where `productionType !== undefined` OR `productionUnits !== undefined`:
- Patch with `{ productionType: undefined, productionUnits: undefined }`

**IMPORTANT: orderItems may be the largest table.** This is likely the highest-volume table. Implement cursor-based batching if needed:
```typescript
// Process in batches of 500
const BATCH_SIZE = 500;
const items = await ctx.db.query("orderItems").collect();
let cleared = 0;
for (const item of items) {
  if (item.productionType !== undefined || item.productionUnits !== undefined) {
    await ctx.db.patch(item._id, { productionType: undefined, productionUnits: undefined });
    cleared++;
  }
}
return { total: items.length, cleared };
```

If the table is too large for a single mutation, add a note in the function doc comment: "If this times out, split into multiple calls using cursor-based pagination."

Return: `{ total, cleared, skipped }`
