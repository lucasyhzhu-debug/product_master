# Phase 74.5: Unified Channel Integration Architecture - Context

**Gathered:** 2026-04-19
**Status:** Ready for planning (sub-phases 74.5.1 + 74.5.2 per split below)

<domain>
## Phase Boundary

All six channels (GoFood, Shopee, TikTok, BigSeller, K3Mart sync, K3Mart consignment settlement, internal direct) flow through one atomic `saveRevenueItems` entry that writes revenue AND deducts inventory, driven by an admin-configurable `channelRouting` table, with full historical deduction backfill preserving original sale timestamps.

Discussion clarified HOW to ship this (sub-phase split, K3Mart scope, rollout, backfill UX). New capabilities (pricing consolidation 999.6, SKU resolver service 999.7, channel onboarding doc 999.8) remain out of scope.

</domain>

<decisions>
## Implementation Decisions

### Phase decomposition (user: Two phases; split line: Claude's discretion "best risk/effort balance")

- **D-01:** Ship as two sub-phases — `74.5.1` (additive, non-behavior-changing, all code lands behind OFF flags) and `74.5.2` (behavioral cutover + cleanup + reporting extension).
- **D-02:** `74.5.1` scope — schema (`channelRouting`, `channelAuditReports`, `channelAuditIssues`, `inventoryDeductedAt`, `channel_sale` literal, `source`+`externalRef` on `productInventoryTransactions`, `channelDeductionEnabled` flag map on `productInventorySettings`); types (`ChannelSaleEvent`, `ChannelAdapter`); helpers (`resolveChannelRoute`, `processChannelSaleInternal`, `detectAuditIssues`, `runFullAudit`); `saveRevenueItems` dispatch hook (gated per-channel, all OFF by default); all 5 adapter refactors + K3Mart consignment settlement refactor (all gated); admin UIs (`ChannelRoutingManager`, `ChannelAuditWorkbench`); routing seed migration; unit + integration tests.
- **D-03:** `74.5.2` scope — per-source backfill buttons extending `/admin/unlinked-products-backfill`; per-channel flag-flip sequence (Shopee → TikTok → BigSeller → K3Mart → GoFood); `gofood_sale → channel_sale + source` transaction migration; `processGofoodSales` retirement; schema cleanup (drop `gofood_sale` literal, `channelDeductionEnabled` flags, `gofoodOrderRef` deprecated field); consignment reporting extension (stretch); E2E tests; `docs/CHANNEL_INTEGRATION.md` onboarding recipe; CHANGELOG / SCHEMA / API_REFERENCE updates.
- **D-04:** Split rationale — 74.5.1 is code-heavy but 100% additive and reviewable as one artifact (nothing in prod changes until flags flip). 74.5.2 is ops-heavy, reversible per-channel, and where regression risk is actually taken.
- **D-05:** Each sub-phase runs its own `/triple-review` before execution, mirroring Phase 80 → 80.1/80.2/80.3 discipline.

### K3Mart coexistence (user: Full K3Mart refactor — sync + consignment both)

- **D-06:** Both K3Mart write paths route through `saveRevenueItems` + `processChannelSaleInternal` — the sync adapter (`convex/integrations/k3mart/adapter.ts`) AND the manual consignment settlement mutation path (`convex/consignment/mutations.ts`). Unifies all K3Mart revenue writes on the new spine.
- **D-07:** K3Mart consignment collapsed-period semantics preserved — reuse `collapseRevenuePeriod` helper (per prior-phase lesson); settlement mutation continues to write `periodStart = periodEnd = transactionDate = recognitionDate` on a single `externalRevenue` row, but item rows now flow through `saveRevenueItems` and trigger deduction.
- **D-08:** Regression snapshot tests required for K3Mart — snapshot 5-10 recent K3Mart sync payloads + 5-10 recent consignment settlements pre-refactor; post-refactor outputs must be byte-identical on happy path (per Spec §14 risk mitigation).
- **D-09:** Consignment reporting extension (stretch, lands in 74.5.2) — once settlements write item-level rows, extend existing consignment reporting UI with "products sold" breakdown + "# transactions" per settlement. Marked stretch because report UI is not on the critical path for inventory accuracy.

### Rollout & cutover sequencing (user: Per-channel feature flag)

- **D-10:** Per-channel feature flag stored on `productInventorySettings` table — new field `channelDeductionEnabled: v.optional(v.object({ shopee, tiktok, bigseller, k3mart, grabfood, gofood, internal: v.boolean() }))`. All default false on first write.
- **D-11:** Admin toggles live in a settings-page subsection (part of Channel Routing Manager or inventory settings — planner decides exact placement).
- **D-12:** Cutover order — Shopee → TikTok → BigSeller → K3Mart (sync + consignment together) → GoFood last. GoFood is the only channel with a working legacy deduction path so it carries the highest regression risk — flip it after the new spine has proved itself on the other four.
- **D-13:** Between flips: minimum 24-48h soak + manual stock-outcome verification per channel before the next flip. Documented in 74.5.2 runbook.
- **D-14:** `processGofoodSales` retirement timing — retires atomically when the GoFood flag flips to ON. After GoFood stabilizes for 72h, 74.5.2 final-cleanup task removes `processGofoodSales`, drops `gofood_sale` literal from schema (strip data → drop schema order per existing Convex rule), and removes all `channelDeductionEnabled` flag checks and the flag field itself.

### Backfill execution control (user: Per-source buttons, inside existing `/admin/unlinked-products-backfill`)

- **D-15:** Extend the Phase 80.2 admin page `/admin/unlinked-products-backfill` with a new section "Channel deduction backfill (Phase 74.5)". Reuses the same page-level patterns (admin-only, confirm-to-run, progress display).
- **D-16:** Six per-source buttons: `Backfill shopee`, `Backfill tiktok`, `Backfill bigseller`, `Backfill k3mart`, `Backfill grabfood`, `Backfill gofood`. Each button queries `externalRevenueItems` WHERE `inventoryDeductedAt IS NULL AND linkedMenuProductId IS NOT NULL AND source = <source>`, chunks 200 items per mutation (per Spec §9), calls `processChannelSaleInternal` with `occurredAt = revenue.transactionDate`.
- **D-17:** Each button is disabled while any `channelAuditReports.status === "pending"` has unresolved issues for that source. Audit-gate is enforced per-source (not globally) — Shopee backfill can run even if K3Mart has pending audit issues, as long as Shopee has none.
- **D-18:** Progress visibility — per-source progress card shows items-processed / items-remaining / last-run-at / last-run-by, matching the existing pattern on the Phase 80.2 page.
- **D-19:** Idempotency — re-clicking `Backfill shopee` after completion is a no-op (every item already has `inventoryDeductedAt` set, query returns zero). Matches Spec Req 8 acceptance criterion.

## Existing Code Insights

### Reusable Assets

- **`resolveSubstitutionPlan` + `stockTracker`** (Phase 78) — `processChannelSaleInternal` uses these directly; no new stock-deduction logic to invent.
- **`externalSourceToDisplayChannel` + `channelTaxonomy.ts`** (Phase 80) — Audit UI + routing UI consume the existing taxonomy for consistent source labels, colors, and grouping.
- **`collapseRevenuePeriod` helper** — K3Mart consignment path uses this to write collapsed-period `externalRevenue` rows; refactored path must continue calling it.
- **`/admin/unlinked-products-backfill` page** (Phase 80.2) — Proven admin-page pattern (confirmation, progress, chunked action). Extend with new section rather than new page.
- **`isExternalSource` type guard** (Phase 31) — Use for narrowing runtime strings to `ExternalSource` union inside Convex index queries.
- **`externalProductMappings` table** — Backs the Layer-2 `resolveSkuToMenuProduct` contract this phase formalizes.
- **`productInventorySettings` table** — Existing settings table where feature-flag map lands.

### Established Patterns

- **Internal mutations for adapter side effects** — `saveRevenueItems` is already `internalMutation`; deduction dispatch continues inside the same internal boundary.
- **Additive return types** — Phase 80.2 established "add new return fields, leave existing ones intact" for mutations shared across call sites. `saveRevenueItems` follows this: existing `ids: Id[]` preserved, new fields (e.g., `deductedCount`, `skippedCount`) added.
- **Paginated chunked actions** — Convex mutation time limit forces 200-item chunks for backfill + 500-row chunks for type migration; actions loop until done.
- **`requireRole(ctx, token, ["admin"])`** — Standard enforcement for all admin mutations. New routing + audit + backfill mutations all gate on admin role.
- **`<ProtectedRoute>` with explicit role filter** — Standard for admin routes in `src/App.tsx`.
- **Source-gated cascades need per-source branches** (Phase 80.2 lesson) — Every `if (args.source === X)` branch in the new code must handle all 7 sources explicitly, or refactor to source-neutral design.
- **Existence-based guards, not freshness-based** (Phase 80.2 lesson) — When new additive write blocks are inserted into sync loops, skip-guards must check existence of child rows, not `isNew` flag.

### Integration Points

- `saveRevenueItems` is called by 3/5 adapters today (gobiz, bigseller, internal) — K3Mart + GrabFood + consignment settlement become new callers in 74.5.1.
- `processGofoodSales` is called from the GoFood sync path — retires atomically with GoFood flag flip in 74.5.2.
- `externalOutlets.linkedStorageLocationId` field — seeds the initial `channelRouting` rows via one-shot migration; field is deprecated (stop writing) in 74.5.1 and dropped in future 999.6 cleanup.
- `productInventoryTransactions.transactionType` — `"gofood_sale"` literal stays during 74.5.1, migrates to `"channel_sale" + source: "gofood"` in 74.5.2 pre-retirement.
- Admin navigation — new routes `/admin/channel-routing` and `/admin/channel-audit` register alongside existing `/admin/unlinked-products-backfill` and `/admin/product-mappings`.

<specifics>
## Specific Ideas

- **"Ship dark, flip gradually"** — user preference is per-channel feature flag on `productInventorySettings` (reactive, UI-togglable, reversible), not env var or hardcoded const. All code lands in 74.5.1 behind OFF flags; 74.5.2 is the flip + cleanup phase.
- **GoFood flips last** — it's the only channel with a working legacy deduction path, so changing it carries the highest regression risk. Flip it after the new spine has been proven by 4 other channels (Shopee → TikTok → BigSeller → K3Mart).
- **K3Mart = both write paths refactored** — user explicitly opted for maximum unification: the nightly K3Mart sync AND the manual consignment settlement form both route through `saveRevenueItems` + `processChannelSaleInternal`. Consignment-specific collapsed-period semantics preserved via existing `collapseRevenuePeriod` helper.
- **Consignment reporting extension (stretch)** — because consignment settlements now write item-level rows through `saveRevenueItems`, the existing consignment reporting UI can surface "products sold" breakdown and "# transactions" per settlement. Marked stretch, optional, lands in 74.5.2.
- **Regression snapshot tests are mandatory for K3Mart and GoFood** — per Spec §14. Pre-refactor sample payloads snapshotted; post-refactor outputs must be byte-identical on happy path.
- **Per-source audit gate, not global** — Shopee backfill can run while K3Mart has pending audit issues, as long as Shopee has none. More operationally flexible than spec's global gate; matches per-channel rollout philosophy.
- **Backfill UI reuses Phase 80.2 admin page** — extends `/admin/unlinked-products-backfill` with a new section rather than creating a new admin page. Matches the "prefer admin UI for DB ops" memory note; one page for all backfill operations.

</specifics>
