## Spacing Scale

Declared values (Tailwind default, multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-text gap inside buttons/badges (`gap-1`) |
| sm | 8px | Compact row padding, inline control gap (`gap-2`, `p-2`) |
| md | 16px | Default element spacing, card internal padding (`p-4`, `gap-4`) |
| lg | 24px | Card-to-card vertical spacing on admin pages (`space-y-6`) |
| xl | 32px | Section breaks between major page regions (`mb-8`) |
| 2xl | 48px | Reserved — not used in admin pages (dashboard hero only) |
| 3xl | 64px | Reserved — not used in admin pages |

**Exceptions:**
- Log row internal padding: 8px (`p-2`) for dense monospace execution log (matches `UnlinkedProductsBackfill.tsx:614`).
- Bottom of progress stat grid: 4px vertical gap between stat rows (`gap-y-1`) to keep 7-stat dense cards scannable.
- Page container: `space-y-6` (24px) between top-level cards. Do not override to tighter.

## Typography

All sizes use Tailwind utility classes bound to the `--font-sans` Inter stack. Exactly 4 sizes, 2 weights.

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|
| Body | 14px | 400 regular | 1.5 | `text-sm` |
| Label | 14px | 600 semibold | 1.5 | `text-sm font-semibold` |
| Heading (card title, section heading) | 16px | 600 semibold | 1.4 | `text-base font-semibold` (CardTitle default) |
| Display (page title in PageHeader) | 24px | 700 bold | 1.25 | `text-2xl font-bold tracking-tight` (PageHeader default) |

**Monospace exception:** Execution log entries use `font-mono text-xs` (12px) — log only. Never for UI copy.

**Tabular numerals mandatory** on every numeric counter (items-processed, items-remaining, durations): `tabular-nums` class. Matches `StatRow` on line 86 of `UnlinkedProductsBackfill.tsx`.

**Forbidden:**
- More than 2 weights in any new component.
- Font sizes outside the 4 above (no 13px, no 18px, no 20px).
- `text-xs` outside the execution log, tooltips, and badge text.
- **`font-bold` (700) in any new component authored for this phase.** The 700 weight is reserved to the existing `PageHeader` component only (applied via its default `text-2xl font-bold tracking-tight` class). New components authored in 74.5.1 / 74.5.2 MUST limit themselves to `font-normal` (400) and `font-semibold` (600). If a new surface needs a larger title, use `<PageHeader>` — do not reimplement its styling.

## Color

All colors reference Tailwind v4 `@theme` tokens from `src/index.css` — never hardcode hex.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` / `--color-background` (light: `hsl(0 0% 100%)`; dark: `hsl(224 10% 10%)`) | Page background, form controls, table body rows |
| Secondary (30%) | `bg-card` / `--color-card` + `bg-muted/30` for info panels | Card surfaces (ChannelRoutingManager rows, ChannelAuditWorkbench tabs, preflight stat panels), info banners |
| Accent (10%) | `bg-primary` / `--color-primary` teal (`hsl(172 90% 30%)` light / `hsl(172 60% 45%)` dark) | **Reserved for:** (1) primary action buttons only — "Run Full Audit", "Save Routing Rule", "Backfill {source}", "Flip {source} Flag", (2) active tab underline, (3) focus ring on form inputs |
| Destructive | `bg-destructive text-destructive-foreground` | "Delete Routing Rule" confirmation, "Reverse Channel Sale" admin action, error log entries, flag-flip confirmation when regression risk banner present |

**Channel/source colors — reuse only:**
- ALL per-channel tints (backfill buttons, audit source column, flag toggle rows, status banners) MUST read from `src/lib/platformColors.ts` via `getPlatformPalette(source)`. No new color literal.
- 8 source keys available: `gobiz`, `k3mart`, `internal`, `grabfood`, `shopee`, `tiktok`, `consignment`, `bigseller`.
- 1 theme-level channel alias: `--color-channel-k3mart` (purple) defined at `src/index.css:114,229` — use for K3Mart migration-status banner border/icon only.

**Accent reserved for:**
1. Primary action buttons (`<Button>` with default variant — teal fill).
2. Active tab underline in `ChannelAuditWorkbench` issue-type tabs.
3. Focus ring on all form inputs.
4. Active row highlight in `ChannelRoutingManager` table (left border `border-l-4 border-l-primary` when row is selected for edit).

**Semantic state colors (read from `--color-status-*` tokens):**
- Success: `--color-status-success` (`#059669` light / `#34D399` dark) — "Flag ON", completed backfill, "Deducted" item status, audit issue `resolved` state.
- Warning: `--color-status-warning` (`#D97706` light / `#FBBF24` dark) — Pending audit, K3Mart shape-migration banner, "Flag OFF but ready" state, BigSeller permanently-disabled toggle tooltip.
- Error: `--color-status-error` (`#DC2626` light / `#F87171` dark) — Audit issue unresolved, backfill failure, `CHANNEL_ROUTING_NOT_CONFIGURED` display.
- Info: `--color-status-info` (`#2563EB` light / `#60A5FA` dark) — Soak-timer banner, "dry-run result" display, audit issue type legend.

**Forbidden:**
- Any new hex value in TSX files. Reuse existing `--color-*` tokens.
- Using platform colors for non-channel decoration (e.g. don't use `gobiz` teal as a general info chip — it encodes "this is GoFood data" only).
- Using `bg-primary` on non-CTA elements (e.g. don't teal-fill pagination, breadcrumbs, or info alerts).

**Anatomy (top to bottom):**
1. `<PageHeader title="Channel Routing" description="Configure which storage location deducts stock for each (source, outlet, product) combination." />`
2. Cutover progress banner (74.5.2 only — conditional render based on `channelDeductionEnabled` presence).
3. K3Mart shape-migration banner (74.5.1 dismissible — stores dismissal in localStorage).
4. `<Card>` — **Resolution Preview** (read-only lookup widget): 3 `<Select>` controls (source required, outlet optional, product optional) + "Preview resolution" button + result panel showing matched tier (1-4) + resolved `storageLocation.name` OR `CHANNEL_ROUTING_NOT_CONFIGURED` in error state.
5. `<Card>` — **Routing Rules Table** (`<Table>`): columns = Source badge, Outlet, Product, Storage location, Updated by, Updated at (WIB), Actions. Each row has [Edit] and [Delete] icon buttons. Table supports client-side sort on Source + Updated at.
6. `<Dialog>` — **Edit/Add routing rule** (opens from header button or row action): 4 fields (source `<Select>` from 8 literals, outlet `<Select>` from externalOutlets + "any outlet" option, product `<Select>` from menuProducts + "any product" option, storage location `<Select>` from storageLocations, mandatory `isDefault` `<Checkbox>` only enabled when outlet=any + product=any). Live preview of resolved tier beneath the form.

**States:**

| State | Treatment |
|-------|-----------|
| Idle | Table renders rows. Header button `Add routing rule` is enabled. |
| Loading (queries return undefined) | `<Skeleton className="h-12 w-full" />` × 5 inside Card. Header button disabled with spinner. |
| Empty | Empty state copy per table above + prominent [Add routing rule] button centered. |
| Error (routing query fails) | `<Alert variant="destructive">` with copy: `Could not load routing rules — {message}. Retrying automatically.` (Convex reactive — no manual retry button.) |

4. `<Tabs>` — **Issue type tabs**: 5 tabs (`Unmapped SKU`, `Stale mapping`, `Malformed item`, `Duplicate tx`, `Orphan item`). Active tab underline is `bg-primary`. Tab label includes count badge.
5. Per-tab content: Type legend card (from audit legend table above) + `<Table>` of issues (columns: Source, External ref, Example detail, Detected at, Actions). Each row has per-type primary action button (`Remap SKU` / `Re-link mapping` / etc.) and a `Dismiss issue` secondary button. Bulk-select via checkbox column (header checkbox for "select all in tab") + bulk action bar at top of table body when 1+ selected.

**States:**

| State | Treatment |
|-------|-----------|
| Idle | Tabs render with counts. Primary button `Run full audit` enabled. |
| Loading (audit running) | Primary button swaps to `<Loader2 className="animate-spin" />` + label `Running audit…` + disabled. Tabs still interactive for viewing previous run results. Progress shown in a small inline panel: `Scanning externalRevenueItems: {N} / {total}`. |

| Empty (clean audit) | Per-tab: empty state copy from empty-states table. Top-of-page: success banner `No audit issues open. Last run {WIB date}.` with green border-left. |
| Error (audit mutation fails) | `<Alert variant="destructive">` with copy: `Audit run failed — {message}. Previous run timestamp preserved.` |

| Destructive (delete orphan, dismiss issue) | `<AlertDialog>` per destructive table. Mandatory reason `<Textarea>`. |

**Bulk actions:** Selecting 2+ rows of the same issue type shows a compact action bar above the table: `{N} selected · [Bulk resolve] [Bulk dismiss] [Clear]`. **Keyboard:** Tab navigation through stat cards → run button → tab list → table. `ArrowDown`/`ArrowUp` in table moves row focus. `Space` toggles row checkbox. `Enter` opens primary resolution dialog for focused row.

**A11y:** Counts announced via `aria-live="polite"` on tab badge count element. Issue rows have full descriptive `aria-label` including all context (`"unmapped_sku issue from shopee, product Frollie Original 80g, detected April 19 2026. Press Enter to resolve."`).

**Responsive:** Desktop-first. At <1024px, stat panel grid becomes `grid-cols-2`; tabs switch to `<Select>` dropdown on <640px. Bulk action bar sticks to bottom of viewport on mobile.

## WIB Timezone Display

All user-facing timestamps (audit run time, flag flip time, last-run backfill, transaction dates) MUST format via helpers from `src/lib/dateUtils.ts` (6 exports — project standard). No ad-hoc `new Date(ts).toLocaleString()` calls. Mandatory format:
- Short: `Apr 19, 2026 14:32 WIB`
- Long (in detail views): `Monday, April 19 2026 at 2:32 PM WIB`
- Relative (in badges): `2h ago`, `3d ago`

Per CLAUDE.md Common Pitfall #12: `_creationTime` is insertion time, NOT business event time. The UI MUST display `createdAt` / `transactionDate` / `occurredAt` values for business dates, never `_creationTime`.
