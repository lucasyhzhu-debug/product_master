# Phase 14.1: Draft Order Update - Context

**Gathered:** 2026-02-16
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix Draft order persistence and editing behavior in the order creation flow. Currently, orders created in the new order modal are not saved as Drafts when a customer is selected, causing data loss on modal close. This phase makes Drafts persistent, editable, and consistent whether newly created or reverted from AwaitingPayment. Also fixes WhatsApp translation button bug.

</domain>

<decisions>
## Implementation Decisions

### Draft auto-creation
- The moment a customer is selected/created in the new order form, a Draft order is persisted to the database immediately
- Draft appears in the Draft Kanban column even if the user closes the modal before adding items
- Empty Drafts (no items) persist indefinitely -- user can return to them or manually delete/cancel them
- No auto-cleanup of empty Drafts

### Draft editing (clicking Draft card in Kanban)
- Clicking a Draft order card in the Kanban opens the full order creation modal (not the read-only slide-over)
- All fields are pre-filled from the existing Draft data: customer, due date, delivery method, items, quantities, voucher
- ALL fields are fully editable -- nothing is locked
- Saving updates the existing Draft order (not creating a new one)
- This is a mutation/update operation on the existing order, not a create-then-delete

### Draft column special behavior
- The Draft column behaves differently from other Kanban columns: clicking opens the edit modal, not the detail slide-over
- Draft column is sorted by draft creation date, latest at the top
- Any order_staff can delete a Draft order (no manager role required for Draft deletion)

### Reverted orders become Drafts
- When an AwaitingPayment order is reverted (moved backward) to Draft status, it becomes a regular Draft
- Clicking the reverted Draft opens the same full order creation modal, pre-filled with all existing data (items, quantities, customer, due date, delivery, voucher)
- No distinction between a "new" Draft and a "reverted" Draft -- both behave identically

### WhatsApp translation button fix
- Bug: the translate toggle in the WhatsApp receipt modal only changes the title but not the message body content
- Root cause: button is not calling the right function to switch the message content language
- Fix: ensure the translate button switches both title and full message body between Indonesian and English

### Claude's Discretion
- How to implement the Draft auto-save trigger (mutation call placement, loading states)
- Whether the order creation modal needs a "Resume Draft" visual indicator vs looking identical to new order creation
- Error handling for concurrent Draft edits
- Exact sort implementation for Draft column

</decisions>

<specifics>
## Specific Ideas

- "After the moment you create a customer or you select a customer, it becomes a draft order" -- the trigger point is customer selection, not any other field
- "When you click that order sheet inside of the draft column... you should be able to just restart the new order process with all the details of the draft order" -- the UX should feel like continuing where you left off
- Draft column is "more special than the other columns" -- it's the only column that opens the edit/creation modal instead of the detail slide-over

</specifics>
