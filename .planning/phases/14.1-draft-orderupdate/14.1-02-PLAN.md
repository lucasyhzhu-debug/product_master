    **WhatsApp language toggle fix** in `StepWhatsAppTemplate.tsx`:

    The bug: the `useQuery` call to `getMessage` does not pass the `language` state variable. Fix:

    ```tsx
    // BEFORE (broken):
    const message = useQuery(api.orders.whatsapp.getMessage, {
      orderId,
      template: templateType,
    });

    // AFTER (fixed):
    const message = useQuery(api.orders.whatsapp.getMessage, {
      orderId,
      template: templateType,
      language,  // Pass the language state so toggling actually changes the message
    });
    ```

    This is a one-line fix. The backend `getMessage` query already accepts `language: v.optional(v.union(v.literal("id"), v.literal("en")))` and passes it to `getTemplateContent`. With this fix, toggling language will cause the query to re-fetch with the new language, and the DB template for that language will be returned (or the hardcoded fallback for "id").
