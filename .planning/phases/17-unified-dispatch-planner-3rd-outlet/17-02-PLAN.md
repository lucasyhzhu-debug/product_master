  <name>Task 2: Create dispatch planner queries and remaining mutations</name>
  <files>convex/dispatchPlanner/queries.ts, convex/dispatchPlanner/mutations.ts</files>
  <action>
**Queries (convex/dispatchPlanner/queries.ts):**

1. `getChannelConfig` -- Query all `dispatchChannelConfig` records sorted by priority. No args needed.

2. `getPlannerSettings` -- Query the single `dispatchPlannerSettings` record. Return `{ dailyCapacity: 200 }` as default if none exists.

3. `getConsignmentOutlets` -- Query `dispatchConsignmentOutlets` with optional `enabledOnly: v.optional(v.boolean())` filter.

4. `getUnifiedWeeklyPlan` -- Main assembly query. Args: `{ startDate: v.string() }` (YYYY-MM-DD, should be a Monday).

   This query assembles the full grid data:

   a. Generate 7 dates from startDate using helper
   b. Fetch enabled channels from `dispatchChannelConfig` (sorted by priority)
   c. For "direct" channel: Query `orders` table for orders with `dueDate` in the 7-day window (filter statuses: not Draft, not Cancelled). For each order, fetch `orderItems` to get product quantities. Each order becomes its own "outlet" row.
   d. For "gofood" channel: Fetch `externalOutlets` where `source="gobiz"` and `isActive=true`. For past days, pull actual sales from `externalRevenue` (filter by outletId and period). For future days, pull from `dispatchPlans` where `channel="gofood"`.
   e. For "k3mart" channel: Fetch active K3Mart outlets from `externalOutlets` where `source="k3mart"`. Pull `k3martDispatchPlans` for the date range. K3Mart data is READ-ONLY in the unified planner.
   f. For "consignment" channel: Fetch enabled `dispatchConsignmentOutlets`. Pull from `dispatchPlans` where `channel="consignment"`.
   g. Compute daily totals per channel for capacity bar segments.

   Return structure:
   ```typescript
   {
     dates: string[], // 7 YYYY-MM-DD strings
     todayStr: string, // Today in YYYY-MM-DD Jakarta timezone
     dailyCapacity: number,
     channels: Array<{
       channelKey: string,
       displayName: string,
       color: string,
       priority: number,
       isEditable: boolean, // false for k3mart
       outlets: Array<{
         id: string, // outlet._id or order._id or consignment._id
         name: string,
         type: "outlet" | "order" | "consignment",
         orderId?: Id<"orders">, // For direct orders
         orderNumber?: string, // For direct orders
         dueDate?: string, // For direct orders (YYYY-MM-DD)
         productionStartDate?: string, // For direct orders (dueDate - 2)
         products: Array<{
           menuProductId: Id<"menuProducts">,
           productName: string,
           cells: Record<string, { // keyed by YYYY-MM-DD
             plannedQty: number,
             actualQty?: number,
             source: string,
             isReadOnly: boolean, // true for past days or k3mart
             isFaded?: boolean, // true for direct order production-start day (not the due date)
           }>
         }>
       }>
     }>,
     dailyTotals: Record<string, Record<string, number>>, // date -> channelKey -> total balls
   }
   ```

   **Important pitfall avoidance:**
   - Direct order quantities count in dailyTotals only at the due date, NOT at production-start day (avoid double-counting per research pitfall #2)
   - Convert order.dueDate (epoch ms) to Jakarta timezone date string before comparing
   - Past days (< todayStr) are read-only
   - K3Mart channel rows are always read-only
   - Keep query focused -- if it gets too large, split GoFood/K3Mart actual sales into a separate query

5. `simulateInventory` -- Args: `{ startDate: v.string() }`. Reads all `dispatchPlans` for the 7-day window, walks BOM for each product (menuProductComponents + componentTypes), compares cumulative required quantities against `componentStock`. Returns per-day sufficiency status:
   ```typescript
   Array<{
     date: string,
     status: "ok" | "low" | "out",
     shortages: Array<{
       componentTypeName: string,
       required: number,
       available: number,
       deficit: number,
     }>
   }>
   ```
   Check both packaging components (trackInventory=true from componentStock) and production components (balls from BOM category="production"). "low" = available < required * 1.2, "out" = available < required.

**Mutations (add to existing convex/dispatchPlanner/mutations.ts):**

6. `savePlanCell` -- Args: `{ token, date, channel, outletId?, orderId?, menuProductId, plannedQty, source? }`. Upserts a `dispatchPlans` record. Use `requireRole(ctx, token, ["manager", "admin"])`. Find existing record by date+channel+outletId+menuProductId (or orderId for direct). If exists, update plannedQty. If not, insert.

7. `updateChannelConfig` -- Args: `{ token, channelKey, updates: { priority?, commissionRate?, isEnabled?, displayName?, color? } }`. Updates a single channel config record. Auth: manager/admin.

8. `reorderChannelPriorities` -- Args: `{ token, orderedKeys: string[] }`. Receives the full ordered list of channelKeys (top = priority 1). Updates all channel config records with new priority numbers. Auth: manager/admin.

9. `updatePlannerSettings` -- Args: `{ token, dailyCapacity }`. Updates the single planner settings record (or inserts if none). Auth: manager/admin.

10. `addConsignmentOutlet` -- Args: `{ token, name, productMappings, commissionRate? }`. Inserts a new consignment outlet. Auth: admin.

11. `updateConsignmentOutlet` -- Args: `{ token, outletId: v.id("dispatchConsignmentOutlets"), name?, productMappings?, commissionRate?, isEnabled? }`. Updates an existing consignment outlet. Auth: admin.

12. `removeConsignmentOutlet` -- Args: `{ token, outletId }`. Deletes a consignment outlet and its dispatch plans. Auth: admin.
