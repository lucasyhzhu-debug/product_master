Dialog for creating/editing a settlement. This is the most important component — it shows live math preview.

- Props: `{ open: boolean, onClose: () => void, outlet: OutletData, settlement?: SettlementData }` (outlet required for rev share %, settlement optional for edit mode)
- State: `totalRevenue`, `periodStart`, `periodEnd`, `notes`
- **Live math preview** (per user decision — NON-NEGOTIABLE):
  - Compute inline: `revShareAmount = totalRevenue * outlet.revSharePercent / 100`
  - Compute inline: `frolliePayment = totalRevenue - revShareAmount`
  - Display in a `bg-muted rounded-lg p-4` card:
    - Row: "Revenue" → `formatCurrency(totalRevenue)`
    - Row: "Rev Share (X%)" → `-formatCurrency(revShareAmount)` in `text-[var(--color-status-warning)]`
    - Separator
    - Row: "Frollie Payment" → `formatCurrency(frolliePayment)` in `text-[var(--color-status-success)]`, font-semibold
  - Show math even while typing (updates on every input change)
- Date inputs: two `<input type="date">` for periodStart and periodEnd (per research recommendation — native HTML inputs, no external library)
- **Timezone-safe date conversion:** Convert date input to local midnight epoch: `new Date(dateString + "T00:00:00").getTime()` — NOT `Date.parse(dateString)` which uses UTC and causes off-by-one-day bugs in WIB (UTC+7)
- For edit mode: pre-fill from settlement, guard against editing paid settlements (should not be reachable but defend)
- On submit: call `useCreateConsignmentSettlement()` or `useUpdateConsignmentSettlement()` — use `actionToast("Settlement created", event)` for success (NOT toast.success), `toast.error()` for failures. Thread `React.MouseEvent` through handler.
