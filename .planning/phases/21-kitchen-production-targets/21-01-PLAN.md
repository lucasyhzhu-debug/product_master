**A) Add `getKitchenTargetsForDate` query to `convex/kitchenConfig/queries.ts`:**

New public query with args `{ date: v.string() }`. Return type shape:
```typescript
type KitchenTargets = {
  bigBalls: number;
  midBalls: number;
  packagingBreakdown: Array<{ menuProductId: Id<"menuProducts">; name: string; quantity: number }>;
  source: "override" | "dispatch_plan" | "defaults";
}
```

Implementation — priority chain:
1. Query `kitchenDailyOverrides` by date index. If found, build targets from override values. For packaging, use `packagingOverrides` if set; otherwise derive from ball totals using BOM lookup. Set source = "override".
2. Query `dispatchPlans` by date index, collect all entries. If any exist, compute ball totals using BOM traversal (see below). Build packaging breakdown from plan entries. Set source = "dispatch_plan".
3. Fall back to `kitchenConfig.first()`. Use `bigBallTarget`/`midBallTarget` for ball totals and `defaultPackagingMix` for packaging. Set source = "defaults".

**BOM ball-count derivation** (follow pattern from `convex/productionTargets/mutations.ts` autoCalculate):
- For each dispatch plan entry, look up `menuProductComponents` via `by_menu_product` index
- Filter components where `componentType.category === "production"`
- Check `componentType.code === "BIG_BALL"` or `"MID_BALL"`
- Multiply `comp.quantity * plannedQty`, accumulate into bigBalls / midBalls totals
- Also build packaging breakdown: group by menuProductId, sum plannedQty, look up menuProduct name

**Important:** Do NOT filter out menuProducts with `productType === "packaging"` from the packaging breakdown — they appear in dispatch plans and should show in the list. But they contribute zero balls (no production BOM components), so the BOM traversal naturally skips them.

The query return also needs to aggregate dispatch plan entries across all channels for the same date (direct + gofood + k3mart all contribute to today's total). Sum `plannedQty` per `menuProductId` across all channel entries.
