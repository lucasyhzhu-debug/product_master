### Caveat 1 verdict

**No double-count site exists in `convex/reports/`.** The if/else branching at `unitEconomics.ts:196-248` was designed with both shapes in mind from the Phase 80 UAT. The child's qty/revenue IS a one-to-one projection of parent values, but the two branches are mutually exclusive — the code only ever iterates children OR synthesizes from parent, never both for the same parent row.

`incomeStatement.ts` deserves a special note: the COGS drill-down will gain K3Mart entries post-74.5.1 because children will start existing. This is the INTENDED outcome (accurate per-product K3Mart COGS), not a regression. Revenue aggregation is untouched because it only reads parent `revenueGross`.

## Channel Routing Seed Migration

### File: `convex/migrations/channelRoutingSeed.ts`

**Public API:**
- `runRoutingSeed` (admin mutation) — Entry point. `requireRole(ctx, token, ["admin"])`. Schedules the internal action and returns `{scheduled: true}`.

**Internal API:**
- `seedChannelRoutingFromOutlets` (internal action) — The seed loop. Returns `{seeded, skipped, alreadyExists}` counters.
- `listOutletsWithLinkedLocation` (internal query) — Fetches every `externalOutlets` row with `linkedStorageLocationId`.
- `findExistingRoute` (internal query) — Idempotency check via `by_source_outlet_product` index.
- `insertSeedRoute` (internal mutation) — Inserts a single seeded row.

### Properties

| Property             | Status | Evidence |
|----------------------|--------|----------|
| Admin-gated          | ✓      | `requireRole(ctx, args.token, ["admin"])` on `runRoutingSeed` |
| Idempotent           | ✓      | `by_source_outlet_product` index lookup; skip if row exists |
| Does not modify externalOutlets | ✓ | Only inserts into `channelRouting`. Zero writes to other tables. |
| No dynamic imports   | ✓      | `grep -cE 'await\s+import\s*\(' → 0` |
| Uses static `internal.*` references | ✓ | `internal.migrations.channelRoutingSeed.*` |
| Does not create Tier-4 defaults (isDefault=true) | ✓ | All rows inserted with `isDefault: false` |

### Threat mitigation (T-74.5.1-19 Tampering)

The `findExistingRoute` idempotency check prevents the seed from overwriting manually-configured routing rules. If an admin has already added or edited a row for (source, outletId, menuProductId=null), the seed skips it and increments `alreadyExists`.

### Call-site plan (not implemented here)

Wave 3's `ChannelRoutingManager.tsx` admin page can expose a "Seed from outlets" button that calls `runRoutingSeed`. Button returns `{scheduled: true}` immediately; the UI can poll `channelRouting` to watch the rows populate. Matches the `/admin/unlinked-products-backfill` pattern.

## Deviations from Plan

### 1. [Rule 1 — Bug] Changed `action` → `internalAction` in seed migration

**Found during:** Final build after initial file creation (post-Task 8.2 commit staging).

**Issue:** I initially used `action` (public) instead of `internalAction` (internal) for `seedChannelRoutingFromOutlets`. Because `scheduler.runAfter` references the function via `internal.migrations.channelRoutingSeed.seedChannelRoutingFromOutlets`, the type-check failed — `internal.*` FunctionReferences only resolve for `internalAction`/`internalMutation`/`internalQuery`, not public `action`/`mutation`/`query`.

**Fix:** Changed `import { action, mutation }` → `import { internalAction, mutation }`. Changed `action({...})` → `internalAction({...})`. The plan's example code showed `internalAction`; the deviation was a transcription mistake.

**Commit:** Rolled into `2ac060b5` (never pushed the broken version).
