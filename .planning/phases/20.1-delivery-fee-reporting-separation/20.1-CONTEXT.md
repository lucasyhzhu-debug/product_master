# Phase 20.1: Delivery Fee Reporting Separation - Context

**Gathered:** 2026-02-22
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix the Sales Analytics page so delivery fees are separated from product revenue — showing them as a new "Delivery Fees" card rather than letting fees inflate net sales figures. All computation happens at query time using existing schema fields (`totalAmount`, `finalTotal`, `deliveryFee`). No schema changes required.

Reference: `docs/plans/2026-02-22-delivery-fee-reporting-separation-design.md` — approved design doc, covers the revenue formula, backend changes to `convex/externalData/queries.ts`, and frontend changes to `src/components/salesAnalytics/OverviewTab.tsx`.

</domain>

<decisions>
## Implementation Decisions

### Delivery Fee card UI
- **Label:** "Delivery Fees"
- **Icon:** Truck icon (Lucide)
- **Styling:** Gray/muted — deliberately understated; it's pass-through, not core revenue
- **Position:** After "Discounts Given", before Net Sales card (order: Gross → Discounts → Delivery Fees → Net → Total Collected)
- **Grid:** Change from `lg:grid-cols-4` to `lg:grid-cols-5` as per design doc

### Channel breakdown
- Aggregate card only — no per-channel delivery fee breakdown needed
- Delivery fees are only relevant for direct (internal) orders; external channel orders (GoFood, K3Mart) always have `deliveryFee = null/0`
- The internal channel's `net` should exclude delivery fees (as per design doc)
- K3Mart delivery costs (~Rp36k per delivery) are treated as a labour cost, not captured per-order — out of scope for this phase

### Zero/empty state
- Always show the card, even when total is Rp 0
- No special dimming or hiding — consistent card layout regardless of value

### Tooltip & context
- Show a short hover tooltip explaining pass-through nature
- Suggested text: "Delivery fees collected from customers and paid to drivers. Not included in Net Sales."
- Tooltip wording: Claude's discretion to keep concise and consistent with existing tooltip style

### Claude's Discretion
- Exact tooltip wording (keep it short, pass-through explanation, not included in Net Sales)
- Any spacing/typography adjustments needed to accommodate the 5-card layout on smaller screens

</decisions>

<specifics>
## Specific Ideas

- Design doc at `docs/plans/2026-02-22-delivery-fee-reporting-separation-design.md` contains the exact revenue formula, backend code diffs, and frontend change list — planner should treat this as the implementation spec
- Revenue formula: Gross Sales = `totalAmount`, Net Product Revenue = `finalTotal - deliveryFee`, Delivery Fees = `deliveryFee ?? 0`, Discounts = `totalAmount - netProduct`

</specifics>

<deferred>
## Deferred Ideas

- K3Mart per-delivery fee capture (currently treated as labour cost ~Rp36k/delivery) — possible future phase if cost tracking becomes more granular
- Per-channel delivery fee breakdown in the channel summary section — not needed now, aggregate is sufficient

</deferred>
