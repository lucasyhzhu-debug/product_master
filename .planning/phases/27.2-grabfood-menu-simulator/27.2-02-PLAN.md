**Create `src/hooks/convex/useGrabFoodMenu.ts`:**

Export a `useGrabFoodMenu` hook that bundles:
- `menuItems`: `useQuery(api.grabfoodMenu.queries.listMenuItems)` -- reactive, auto-updates
- `syncStatus`: `useQuery(api.grabfoodMenu.queries.getSyncStatus)` -- latest sync logs
- Mutations: `useMutation` for createItem, updateItem, deleteItem, reorderItems, generateUploadUrl, savePhoto, populateFromMappings
- Action: `useAction(api.integrations.grabfood.adapter.pushMenuChanges)`

Return all as a single object. Follow the established hook pattern from `useExternalData.ts`.

Also export `useMenuProducts` that returns `useQuery(api.menuProducts.queries.list)` for the add-item dialog (already exists in existing hooks -- check if `useMenuProducts` hook has a `list` query, or use `api.menuProducts.queries.listActive` if available).

**Create `src/components/grabfoodMenu/SyncStatusBadge.tsx`:**

Small component that takes `syncStatus` array (from hook). Shows the latest entry's status as a colored badge:
- success: green badge "Synced"
- error: red badge "Sync Failed"
- started: yellow badge "Syncing..."
- No entries: gray badge "Not synced"

Show relative time (e.g., "2 min ago") next to the badge using simple Date math.

**Create `src/components/grabfoodMenu/PhotoUpload.tsx`:**

Component with props: `{ menuItemId, currentPhotoUrl, onUpload }`.
- Shows current photo or placeholder
- Click to open file input (accept="image/jpeg,image/png,image/webp")
- Client-side validation: max 5MB file size, show toast error if exceeded
- On file select: call `generateUploadUrl` then `fetch(url, { method: "POST", body: file, headers: { "Content-Type": file.type } })`, then call `savePhoto` with the storageId
- Show upload progress indicator (loading state)
- After upload, the reactive query auto-updates the photo

**Create `src/components/grabfoodMenu/MenuItemCard.tsx`:**

GrabFood-app-like card component. Props: `{ item, onUpdate, onDelete, onPhotoUpload }`.

Visual layout (GrabFood style):
- **Top**: Square aspect-ratio photo area (`aspect-square bg-gray-100 dark:bg-gray-800`). If photo exists, show `<img>` with `object-cover`. If no photo, show camera icon placeholder. Availability toggle (Switch) in top-right corner overlay.
- **Bottom**: Card content area with:
  - Item name (editable on click -- use controlled Input with onBlur commit pattern from Phase 27.1-02)
  - Price displayed as "Rp XX,XXX" (editable on click -- Input type="number" with onBlur commit). Use `formatCurrency` for display, raw integer for editing.
  - Description (editable, textarea with onBlur commit, or "Add description" placeholder if empty)
  - Small delete button (trash icon) in bottom-right, with confirmation via toast or simple confirm

Colors: GrabFood green (#00B14F) for price text. White/dark backgrounds. Rounded corners. Subtle shadow.
Use shadcn Card component as base. Support dark mode with appropriate `dark:` classes.

When availability is toggled off, overlay a semi-transparent gray over the entire card to visually indicate unavailable.

**Create `src/components/grabfoodMenu/AddItemDialog.tsx`:**

Dialog component. Props: `{ open, onOpenChange, existingMenuProductIds, onAdd }`.

Content:
- Search input to filter internal menu products by name/code
- List of menu products NOT already in the GrabFood menu (filter out `existingMenuProductIds`)
- Each product shows: name, code, default price
- Click a product to select it -> shows auto-filled fields: GrabFood Name (defaults to product name), GrabFood Price (defaults to product defaultPrice), Description (empty)
- Admin can override any field before adding
- "Add to Menu" button calls `onAdd({ menuProductId, grabfoodName, grabfoodPrice, grabfoodDescription })`
- Use shadcn Dialog, Input, Button, ScrollArea components

**Create `src/components/grabfoodMenu/PushConfirmDialog.tsx`:**

Dialog component. Props: `{ open, onOpenChange, changes, onConfirm, isPushing }`.

`changes` is computed by the page from the diff between current items and their "last pushed" state (or original state from populate). Structure:
```typescript
{
  priceChanges: Array<{ name: string, oldPrice: number, newPrice: number, grabfoodItemId: string }>,
  availabilityChanges: Array<{ name: string, newStatus: "AVAILABLE" | "UNAVAILABLE", grabfoodItemId: string }>,
  newItems: Array<{ name: string, price: number }>,
  totalChanges: number,
}
```

Show a summary table:
- Section "Price Changes" -- list items with old -> new price
- Section "Availability Changes" -- list items with new status
- Section "New Items" -- list items being added
- Total changes count
- "Push to GrabFood" button (loading state when `isPushing`)
- Merchant ID display: `6-C7XYAECCTNKXJ6` (hardcoded per user decision)
- Warning text: "Changes will be pushed to GrabFood. This triggers a menu re-sync."

**Create `src/pages/GrabFoodMenuSimulator.tsx`:**

Main page layout:
- **Header area**:
  - Page title "GrabFood Menu Simulator" with GrabFood green accent
  - SyncStatusBadge (from sync status query)
  - "Populate from Product Mappings" button (shown only when menu is empty) -- calls populateFromMappings mutation
  - "Add Item" button -- opens AddItemDialog
  - "Push to GrabFood" button (green, prominent) -- opens PushConfirmDialog

- **Card grid**:
  - `grid grid-cols-2 md:grid-cols-3 lg:grid-cols-4 gap-4` responsive layout
  - Each item renders as MenuItemCard
  - Empty state: "No menu items yet. Click 'Populate from Product Mappings' to import existing items, or 'Add Item' to add products manually."

- **State management**:
  - Track "original state" (snapshot taken on page load/populate) for diff calculation
  - `pendingChanges` computed by comparing current items vs original state
  - Push flow: compute diff -> open PushConfirmDialog -> on confirm, call `pushMenuChanges` action with computed changes -> show toast on success/error -> refresh original state

- **Loading state**: Check `if (menuItems === undefined) return <Loading />` AFTER all hooks are called (per React hooks order rule).

- **Auth**: Use `useAuth()` to get token. All mutations/actions require token arg.

- All hooks MUST be called before any conditional returns.
