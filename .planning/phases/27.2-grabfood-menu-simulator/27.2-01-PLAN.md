**Schema changes in `convex/schema.ts`:**

1. Add `grabfoodMenuItems` table:
```typescript
grabfoodMenuItems: defineTable({
  menuProductId: v.id("menuProducts"),
  grabfoodItemId: v.optional(v.string()),    // GrabFood's item ID (from externalProductCode)
  grabfoodName: v.string(),                  // Override name for GrabFood display
  grabfoodDescription: v.optional(v.string()),
  grabfoodPrice: v.number(),                 // IDR integer (no decimals, exponent=0)
  isAvailable: v.boolean(),                  // Manual availability toggle
  photoStorageId: v.optional(v.id("_storage")),
  photoUrl: v.optional(v.string()),          // External URL (from GrabFood pull)
  sequence: v.number(),                      // Display order in the menu
  createdAt: v.number(),
  updatedAt: v.number(),
})
  .index("by_menu_product", ["menuProductId"])
  .index("by_sequence", ["sequence"]),
```

2. Add `photoStorageId: v.optional(v.id("_storage"))` to `menuProducts` table definition (for write-back from simulator photo uploads).

**Create `convex/grabfoodMenu/queries.ts`:**

- `listMenuItems`: Query that returns all grabfoodMenuItems joined with menuProduct name/code. For each item with a `photoStorageId`, resolve the URL via `ctx.storage.getUrl(item.photoStorageId)`. Sort by `sequence`. Return array of `{ ...item, resolvedPhotoUrl: string | null, menuProduct: { name, code, defaultPrice } }`.

- `getSyncStatus`: Query that reads recent externalSyncLogs where `source="grabfood"` and `triggeredBy` contains "menu" (e.g., "grabfood-webhook-get-menu" or "grabfood-webhook-menu-sync"). Return the latest 5 entries sorted by timestamp descending. Use `ctx.db.query("externalSyncLogs").withIndex("by_source", q => q.eq("source", "grabfood")).order("desc").take(20)` then filter client-side for menu-related entries and take 5.

- `listMenuItemsInternal`: Same as listMenuItems but as `internalQuery` (no auth check) for use by the webhook handler.

**Create `convex/grabfoodMenu/mutations.ts`:**

- `generateUploadUrl`: Protected mutation (token arg, requireRole admin). Returns `ctx.storage.generateUploadUrl()`. Follow the exact pattern from `convex/feedback/mutations.ts`.

- `savePhoto`: Protected mutation. Args: `token, menuItemId: v.id("grabfoodMenuItems"), storageId: v.id("_storage")`. Patches the grabfoodMenuItems record with `photoStorageId` and `updatedAt`. ALSO patches the linked `menuProducts` record with `photoStorageId` (write-back pattern per locked decision). If menuProduct does not exist, skip the write-back silently.

- `createItem`: Protected mutation. Args: `token, menuProductId: v.id("menuProducts"), grabfoodName: v.string(), grabfoodDescription: v.optional(v.string()), grabfoodPrice: v.number(), grabfoodItemId: v.optional(v.string())`. Sets `isAvailable: true`, `sequence` to max existing sequence + 1, `createdAt` and `updatedAt` to `Date.now()`. Validates no duplicate menuProductId in grabfoodMenuItems (one-to-one mapping).

- `updateItem`: Protected mutation. Args: `token, menuItemId: v.id("grabfoodMenuItems"), fields: v.object({ grabfoodName: v.optional(v.string()), grabfoodDescription: v.optional(v.string()), grabfoodPrice: v.optional(v.number()), isAvailable: v.optional(v.boolean()), grabfoodItemId: v.optional(v.string()) })`. Patches only provided fields + updatedAt.

- `deleteItem`: Protected mutation. Args: `token, menuItemId: v.id("grabfoodMenuItems")`. Deletes the record. Does NOT delete the linked menuProduct or externalProductMapping.

- `reorderItems`: Protected mutation. Args: `token, orderedIds: v.array(v.id("grabfoodMenuItems"))`. For each ID, patch `sequence` to its array index + 1 and `updatedAt`.

- `populateFromMappings`: Protected mutation. Args: `token`. Reads all externalProductMappings with source="grabfood". For each mapping that does NOT already have a corresponding grabfoodMenuItems record (check via by_menu_product index where menuProductId matches), create a new grabfoodMenuItems record with: `menuProductId` from mapping, `grabfoodItemId` from `externalProductCode`, `grabfoodName` from `externalProductName`, `grabfoodPrice` from `grabfoodPrice ?? menuProduct.defaultPrice ?? 0`, `isAvailable` from `isAvailable ?? true`, sequence = index + 1. Returns count of items created.

All mutations use `requireRole(ctx, args.token, ["admin"])` pattern.

**Add `pushMenuChanges` action to `convex/integrations/grabfood/adapter.ts`:**

New exported action `pushMenuChanges` with args:
- `token: v.string()`
- `merchantID: v.string()`
- `priceUpdates: v.array(v.object({ id: v.string(), price: v.number() }))` -- items whose GrabFood price changed
- `availabilityUpdates: v.array(v.object({ id: v.string(), availableStatus: v.union(v.literal("AVAILABLE"), v.literal("UNAVAILABLE")) }))` -- items whose availability toggled

Handler:
1. Auth check via `internal.platformCredentials.queries.validateAdminToken`
2. Resolve token via `resolveToken(ctx)`
3. If priceUpdates is non-empty, call `grabRequest` with PUT to `GRABFOOD_CONFIG.endpoints.menuBatch` with `{ merchantID, field: "PRICE", menuEntities: priceUpdates }` (each entity has `id` and `price`)
4. If availabilityUpdates is non-empty, call `grabRequest` with PUT to `GRABFOOD_CONFIG.endpoints.menuBatch` with `{ merchantID, field: "AVAILABILITY", menuEntities }`. For UNAVAILABLE items, include `maxStock: 0`.
5. ALWAYS call `grabRequest` POST to `GRABFOOD_CONFIG.endpoints.menuNotify` with `{ merchantID }` -- this is CRITICAL, changes are not live without it.
6. Create a sync log entry: `source: "grabfood", syncType: "manual", status: "success", triggeredBy: "push-menu"`.
7. Return `{ success: true, priceUpdatesCount, availabilityUpdatesCount }` or `{ success: false, error: "..." }` on failure.

On any API error, log to syncLog with status "error" and return the error. Do NOT throw -- return gracefully.

**Update `handleGetMenuWebhook` in `convex/integrations/grabfood/webhooks.ts`:**

Currently reads from `externalProductMappings`. Update to prefer `grabfoodMenuItems`:

1. After HMAC validation, query `grabfoodMenuItems` via `ctx.runQuery(internal.grabfoodMenu.queries.listMenuItemsInternal)`.
2. If the result has items (length > 0), build menu from those items:
   - Each item: `{ id: item.grabfoodItemId ?? item._id, name: item.grabfoodName, sequence: item.sequence, availableStatus: item.isAvailable ? "AVAILABLE" : "UNAVAILABLE", price: item.grabfoodPrice, description: item.grabfoodDescription ?? "", photos: item.resolvedPhotoUrl ? [item.resolvedPhotoUrl] : [], modifierGroups: [] }`
   - Only include items where `isAvailable === true` (soft-remove means unavailable items still exist but are not served)
3. If no grabfoodMenuItems exist, FALL BACK to existing externalProductMappings logic (keep current code as else branch).
4. Keep the rest of the response structure (merchantID, currency, sellingTimes, sections) unchanged.

Import `internal.grabfoodMenu.queries.listMenuItemsInternal` at the top of webhooks.ts. The import is already `import { internal } from "../../_generated/api"` which auto-includes new modules.
