# Phase 17.1: Product Inventory Tracker — Context

**Gathered:** 2026-02-20
**Status:** Ready for planning

<domain>
## Phase Boundary

A finished-goods inventory layer for sellable products — location-aware stock tracking where kitchen adds completed boxes and orders/GoFood sales draw stock down. This is separate from the existing packaging inventory (FIFO boxes/stickers) and ingredient inventory. Scope covers direct orders and GoFood orders only. K3Mart inventory is handled via the K3Mart cockpit and is out of scope here.

</domain>

<decisions>
## Implementation Decisions

### Stock unit & product mapping
- **1 unit = 1 box** (final packaged product, ready to sell)
- **Linked to MenuProduct** — every active MenuProduct can have stock tracked
- Current active products: Original Single, Original Triple (Jumbos and legacy products flagged as "not tracking" if they appear in GoFood/POS syncs but not added to inventory)
- **Each row = location × menu product** — one location can hold multiple products simultaneously
- Clean split: packaging inventory = raw materials; this = finished goods. No overlap.

### Inventory categorisation (InventoryManager unification)
- InventoryManager now has **3 categories**: Finished Goods (new), Ingredients (Phase 20), Packaging (existing FIFO)
- Researcher to verify current ingredient categorisation state in production DB — Phase 20 quick fix may have partially addressed miscategorised production components
- Finished goods are a new tab/section, not a replacement for the others

### Location model
- **Evaluate `storageLocations` table for reuse** — researcher to assess whether it can extend to finished goods or a separate `productInventory` table is cleaner (current use is for packaging material stock)
- **K3Mart outlets** → link to existing K3Mart outlet records (same IDs used in dispatch planner)
- **GoFood outlets** → link to existing `externalOutlets` / `gofoodDepot` records (e.g., Tamtem depot)
- **Crystal = HQ / default** — kitchen always adds stock to Crystal by default
- Locations are seeded/fixed for now (Crystal, GoFood outlets, Legatos); user-managed locations is deferred

### Kitchen add-stock flow
- **Entry point**: InventoryManager page — Finished Goods tab/section (retail-staff-friendly UI)
- **Form**: Product (MenuProduct) + Quantity only; location defaults to Crystal but can be changed
- **Audit log**: Every stock addition records user + timestamp
- **Manager adjustments**: Separate adjustment action (add or subtract) with a reason field — handles corrections, spoilage, location transfers

### Low-stock threshold & alerts
- **Threshold: 5 units** per product-location
- When stock drops below 5: alert visible to admin and manager roles (toast + visual indicator on inventory page)
- Simple, retail-staff-friendly stock input page — staff can confirm/refresh inventory per location without technical knowledge

### Order fulfilment (direct orders)
- **"Use Available Inventory" button** appears on order detail when status = **Confirmed**
- **One button for the whole order** — draws down all order items simultaneously (no per-item granularity)
- **Draw source**: Staff choose which location to draw from (dropdown showing stocked locations for the products in the order)
- **Shortfall handling**: Block — show available quantity, don't allow partial drawdown
- **Post-drawdown status**: Smart status advance — reads order's delivery method:
  - Delivery → `WaitingShipment`
  - Pickup → `WaitingPickup`
- Kitchen production is skipped entirely when fulfilled from inventory

### GoFood sales sync drawdown
- **Trigger**: Automatic on GoBiz sales sync refresh
- **Outlet matching**: Deduct from the `externalOutlet` / `gofoodDepot` record linked to the sale (e.g., Tamtem depot stock)
- **Low / no stock**: Allow negative stock — do not block sync. Low-stock alert triggers at 5 units.
- **Transaction log**: Each sync deduction logged with timestamp and GoFood order reference

### Transaction history
- **Full audit trail** per product-location: additions (kitchen), drawdowns (order fulfilment + GoFood sync), adjustments (manager)
- Log fields: type, product, location, quantity delta, user (if applicable), timestamp, reference (order ID or GoFood sale ID)

### Claude's Discretion
- Exact UI layout of the Finished Goods tab within InventoryManager
- Whether to reuse `storageLocations` or create a new table (researcher to assess + decide)
- GoFood sync deduction integration point (which function/cron to hook into)
- Toast notification implementation for low-stock alerts
- Exact SQL/Convex query structure for transaction log

</decisions>

<specifics>
## Specific Ideas

- "Retail staff friendly" — stock input should be extremely simple: pick product, enter number, tap confirm. No technical concepts visible.
- Low stock warning should be prominent enough that a manager checking the app during the day would notice it
- Kitchen always adds to Crystal first; the stock then conceptually "moves" to outlet locations via manager adjustment (transfer)

</specifics>

<deferred>
## Deferred Ideas

- **Full inventory consolidation refactor** — User wants a stocktake of all tracking logic (packaging, ingredients, finished goods, production log) and a unified refactor. This is a significant initiative deserving its own phase with careful schema migration planning.
- **User-managed locations** — Ability to add/remove locations via a settings page (vs current fixed/seeded set)
- **K3Mart finished goods via this system** — K3Mart cockpit handles K3Mart inventory; if that ever needs to unify with this system, it's a separate decision
- **Per-item order fulfilment** — Granular per-order-item drawdown (vs current whole-order approach)
- **Platform automation for other channels** — GoFood is the only automated drawdown; extending to other platforms is future work

</deferred>
