## Deviations Noted (Not Gaps)

These are design decisions that deviated from plan but were correctly resolved:

1. **FG prefix naming**: `FGAddStockDialog.tsx` and `FGAdjustStockDialog.tsx` instead of `AddStockDialog.tsx`/`AdjustStockDialog.tsx` — avoids collision with existing packaging inventory dialogs. Components are in the correct location.

2. **Component location**: `FulfillFromInventoryButton.tsx` and `InventoryAvailabilityPanel.tsx` placed in `src/components/inventory/` not `src/components/orders/` as the plan specified. More semantically correct — inventory concern accessed from an order page. OrderDetail imports from correct path.

3. **processGofoodSales args**: Plan specified `merchantId: v.string()` — actual implementation uses `outletId: v.id("externalOutlets")` (cleaner, avoids redundant lookup since outletId is already available in the revenue record). Functionally equivalent.

4. **Inner component pattern**: `FulfillFromInventoryButton` uses outer null-return + inner `FulfillFromInventoryPanel` to avoid React hooks ordering violation — a correct architectural decision not in the original plan spec.
