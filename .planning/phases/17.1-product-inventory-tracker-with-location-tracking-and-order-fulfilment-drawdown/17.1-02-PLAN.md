Implement the two integration paths for finished goods consumption: (1) manual order drawdown mutation that fulfills orders from inventory and skips kitchen production, and (2) automatic GoFood sales deduction hooked into the GoBiz sync pipeline.

Purpose: These are the two critical consumption paths that make finished goods inventory useful. Without drawdown, staff can't fulfill orders from stock. Without GoFood sync, depot stock goes stale.

Output: fulfillFromInventory mutation for direct orders, processGofoodSales internal mutation for GoFood, Phase D hook in GoBiz adapter.

<task type="auto">
  <name>Task 1: Order drawdown mutation — fulfillFromInventory</name>
  <files>convex/productInventory/mutations.ts, convex/orders/helpers/statusTransitions.ts</files>
  <action>
Add **fulfillFromInventory** mutation to `convex/productInventory/mutations.ts`:

**Args:**
- `token: v.string()`
- `orderId: v.id("orders")`
- `locationId: v.id("storageLocations")`

**Auth:** requireRole with ["order_staff", "manager", "admin"]

**Behavior (atomic, all-or-nothing):**

1. **Validate order status:** Load order by ID. Must be in `"PaymentReceived"` status. Throw descriptive error if not.

2. **Load order items:** Query orderItems by orderId, filter `isCancelled !== true`. Skip items without menuProductId.

3. **Check availability for ALL items first (no partial):**
   - For each order item with a menuProductId, query productInventory by_product_location index.
   - If any item has available stock < quantity needed, collect shortages.
   - If shortages.length > 0, throw ConvexError with `{ type: "insufficient_stock", shortages: [{ productName, needed, available }] }`. This allows the frontend to show the user exactly what's short.

4. **Deduct all items atomically:**
   - For each order item with menuProductId:
     - Load productInventory row (guaranteed to exist from step 3)
     - Calculate newQty = current - item.quantity
     - Patch productInventory row: { quantity: newQty, lastUpdated: Date.now() }
     - Insert productInventoryTransactions: { transactionType: "drawdown", quantity: -item.quantity, previousQuantity: current, newQuantity: newQty, orderId: args.orderId, performedBy: user.name, createdAt: Date.now() }

5. **Advance order status:**
   - Patch order: `{ status: "AwaitingDelivery", isKitchenVisible: false }`
   - This skips BeingPrepared entirely — kitchen production is bypassed.

6. **Log status transition:**
   - Insert into orderStatusTransitions: `{ orderId, fromStatus: "PaymentReceived", toStatus: "AwaitingDelivery", reason: "Fulfilled from inventory (skipped production)", initiator: "user", performedById: user._id, performedAt: Date.now() }`
   - Follow the pattern from existing statusUpdates.ts for the transition log format.

7. **Return** `{ success: true, itemsFulfilled: count }`

**Important:** Do NOT deduct packaging inventory (boxes, stickers). Those were consumed when the boxes were originally packed. Only deduct finished goods (productInventory).

Also check if `statusTransitions.ts` needs updating. The existing VALID_TRANSITIONS map may not include PaymentReceived -> AwaitingDelivery directly. If it doesn't, add this as a valid transition (it's the "skip production" path). Check `convex/orders/helpers/statusTransitions.ts` for the VALID_TRANSITIONS map and add the entry if missing.

  <action>
**Add `processGofoodSales` internal mutation to `convex/productInventory/mutations.ts`:**

This is an internalMutation (no auth — called from the GoBiz sync action):

**Args:**
```
items: v.array(v.object({
  menuProductId: v.id("menuProducts"),
  quantity: v.number(),
  merchantId: v.string(),
  gofoodOrderRef: v.optional(v.string()),
}))
```

**Behavior:**
1. For each item, find the externalOutlet by source="gobiz" and externalId containing the merchantId (use by_source_external_id index or scan). Then read its linkedStorageLocationId.
2. If no linkedStorageLocationId found, skip this item and log a warning (outlet not linked to a storage location yet — run the seed mutation).
3. Load or create the productInventory row for this menuProductId + locationId.
4. Deduct: newQty = currentQty - item.quantity. **Allow negative stock** (GoFood sales must never be blocked).
5. Log productInventoryTransactions with transactionType "gofood_sale", the gofoodOrderRef if available, and performedBy "system:gobiz_sync".
6. Track low-stock alerts: if newQty <= threshold, add to alerts list.
7. Return `{ processed: number, lowStockAlerts: number }`.

**Cache merchantId -> (outletId, storageLocationId) mapping** at the start of the mutation to avoid repeated queries. Load all gobiz externalOutlets once, build a Map<merchantId, { outletId, storageLocationId }>.

**Add Phase D hook to `convex/integrations/gobiz/adapter.ts`:**

In BOTH `syncGoBizRevenue` and `autoSyncGoBizRevenue` functions, AFTER the Phase C block (sticker deduction), add a Phase D block:

```typescript
// ── Phase D: Auto-deduct finished goods for GoFood sales ──
try {
  if (gofoodSaleItems.length > 0) {
    console.log(`Phase D: Deducting ${gofoodSaleItems.length} items from product inventory...`);

    // Build Phase D items from the same gofoodSaleItems used in Phase C
    // Each item needs: menuProductId, quantity, merchantId, gofoodOrderRef
    const phaseDItems = gofoodSaleItems.map(item => ({
      menuProductId: item.menuProductId as Id<"menuProducts">,
      quantity: item.quantity,
      merchantId: merchantId, // from the outer loop context
      gofoodOrderRef: undefined, // GoFood order reference if available from allNewRecords
    }));

    const phaseD = await ctx.runMutation(
      internal.productInventory.mutations.processGofoodSales,
      { items: phaseDItems }
    );

    console.log(`Phase D complete: ${phaseD.processed} deducted, ${phaseD.lowStockAlerts} low stock`);
  }
} catch (phaseDError) {
  // Phase D failure should NOT fail the overall sync
  console.log(
    "Phase D (product inventory deduction) failed:",
    phaseDError instanceof Error ? phaseDError.message : String(phaseDError)
  );
}
```
