    **Due-date grouping logic (using date-fns):**
    ```typescript
    import { isToday, isTomorrow, isBefore, startOfDay, format } from 'date-fns';
    ```

    Group orders into categories:
    1. **OVERDUE**: `dueDate` is before start of today (not today itself). `isPast(startOfDay(dueDate)) && !isToday(dueDate)`. Sort key: -1 (always first).
    2. **Due Today**: `isToday(dueDate)`. Sort key: 0.
    3. **Due Tomorrow**: `isTomorrow(dueDate)`. Sort key: 1.
    4. **Due {DayName, MonthDay}**: Future dates. Label: `Due ${format(dueDate, 'EEE, MMM d')}` (e.g., "Due Sat, Feb 22"). Sort key: dueDate timestamp.
    5. **No Due Date**: Orders without dueDate. Sort key: 999 (last).

    Within each group, EXPEDITED orders are pinned to top (unshift) per locked decision.

    **Rendering:**
    - Map over sorted groups, render `<DueDateGroupHeader />` followed by `<KitchenOrderCard />` for each order in the group
    - K3Mart synthetic card: Render at the top of the "Due Today" group (or before the first group if no orders due today) as `<K3MartSyntheticCard />`
    - If `isLoading=true`: render 3 shadcn `Skeleton` cards
    - If no orders and not loading: render empty state "No orders in kitchen" with Lucide `ChefHat` icon

    **Memoize the grouping** with `useMemo` to avoid re-computing on every render. Dependencies: `orders` array.
