**Fix getBallTotalsForDispatchPlanDate (Issue 1 — Save to Kitchen missing Direct Sales):**

The existing function (line ~1020) only queries `dispatchPlans` table. Add a second data pass that reads Direct Sales orders for the given date:

1. Query `orders` table: filter where `dueDate` matches `args.date` (YYYY-MM-DD string comparison) AND status is NOT "Draft" AND status is NOT "Cancelled". Use the same date format that `assembleDirectChannel` uses.
2. For each matching order, query its `orderItems` (filter out cancelled items if applicable).
3. Build a map of `menuProductId -> totalQty` from all order items.
4. Run the SAME BOM ball-expansion loop that already exists (lines ~1048-1065) on these order-derived quantities. The existing loop iterates over `dayPlans` — extract the BOM expansion into a shared helper function that accepts `(menuProductId, quantity, bomByProduct, componentTypeMap)` and returns `{ bigBalls, midBalls }` increments. Use this helper for both dispatchPlans entries AND order-derived entries.
5. Sum the results into the existing `bigBalls` and `midBalls` accumulators.

The existing `bomByProduct` and `componentTypeMap` loading (lines ~1033-1047) is already done before the loop and can be reused for the order pass.

**Add dailyBallTotals to getUnifiedWeeklyPlan (Issues 2 + 3):**

In `getUnifiedWeeklyPlan` (the main weekly plan query):

1. After all channel assembly functions have populated `dailyTotals`, add a new computation for `dailyBallTotals: Record<string, number>` (keyed by date string, value is total balls).
2. Load BOM data once: query all `menuProductComponents` and `componentTypes` (production category only). Build `bomByProduct` map (same pattern as getBallTotalsForDispatchPlanDate).
3. For each date in the 7-day window, iterate over ALL channel entries in `dailyTotals[date]`. For each product quantity, look up BOM and multiply by ball count. Sum all ball counts for the date.
4. BUT ALSO include Direct Sales orders in the ball count (same as Issue 1 fix above — orders are in dailyTotals already via assembleDirectChannel, so the BOM expansion on dailyTotals values should capture them).

IMPORTANT: `dailyTotals` is keyed by `[date][channelKey]` where channelKey includes channel type. The values are product counts. To get ball counts, you need per-product granularity. Since `dailyTotals` aggregates across products, you need a SEPARATE per-product-per-date accumulator during assembly. The cleanest approach:

- Add `dailyProductQty: Record<string, Record<string, number>>` (date -> menuProductId -> qty) alongside `dailyTotals` during assembly.
- Each channel assembler already has product-level data — add to `dailyProductQty[date][menuProductId] += qty` in each assembler.
- After assembly, compute `dailyBallTotals` by BOM-expanding `dailyProductQty`.

5. Add `dailyBallTotals` to the return object of `getUnifiedWeeklyPlan`.
