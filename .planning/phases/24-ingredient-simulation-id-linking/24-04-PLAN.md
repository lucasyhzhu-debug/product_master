    **Step 2: "Save targets for kitchen" button in `src/pages/DispatchPlanner.tsx`**

    The DispatchPlanner renders a `PlannerGrid` component with the weekly data. The "Save targets for kitchen" button should appear per day. The cleanest approach that avoids a major PlannerGrid refactor:

    Add a row BELOW the `PlannerGrid` (or above, depending on layout) that renders one button per date in the current 7-day window. Use the existing `weekDates` or `startDate` + `generateWeekDates` logic to get the dates array.

    Implementation in `DispatchPlanner.tsx`:
    1. Import `useSetKitchenDailyOverride` and `useGetBallTotalsForDate` from hooks
    2. Add a `SaveTargetsRow` sub-component (defined inline in the same file) that renders one button per date:
       - Button label: "Save targets" (or "Save to Kitchen")
       - On click: call `setDailyOverride({ token, date, bigBallOverride, midBallOverride, packagingOverrides, source: "restock_planner" })`
       - Ball totals come from `getBallTotalsForDispatchPlanDate` for that date

    Since `getBallTotalsForDispatchPlanDate` is a reactive query (not on-demand), use a "selected date" pattern: maintain `savingDate: string | null` state. When user clicks "Save targets" for a day:
    - Set `savingDate` to that date
    - The hook fires reactively and returns data
    - When data returns, auto-trigger the mutation and show a toast

    Alternatively, use a simpler approach: each button in the row is a small component `SaveTargetButton({ date })` that hooks into `useGetBallTotalsForDate(date)` for that specific date. When clicked, it calls `setDailyOverride` with the data already available from the reactive query.

    **Recommended pattern (simplest, follows Convex reactive model):**
    ```tsx
    function SaveTargetButton({ date, token }: { date: string; token: string }) {
      const ballTotals = useGetBallTotalsForDate(date);
      const setOverride = useSetKitchenDailyOverride();
      const [saving, setSaving] = useState(false);

      const handleSave = async () => {
        if (!ballTotals) {
          toast.error("No dispatch plan data for this date");
          return;
        }
        setSaving(true);
        try {
          await setOverride({
            token,
            date,
            bigBallOverride: ballTotals.bigBalls,
            midBallOverride: ballTotals.midBalls,
            packagingOverrides: ballTotals.packagingBreakdown.map((p) => ({
              menuProductId: p.menuProductId as Id<"menuProducts">,
              quantity: p.quantity,
            })),
            source: "restock_planner",
          });
          toast.success(`Targets saved for kitchen on ${date}`);
        } catch (e) {
          toast.error(e instanceof Error ? e.message : "Failed to save targets");
        } finally {
          setSaving(false);
        }
      };

      const hasData = ballTotals && (ballTotals.bigBalls > 0 || ballTotals.midBalls > 0);

      return (
        <Button
          variant="outline"
          size="sm"
          onClick={handleSave}
          disabled={saving || !hasData}
          title={hasData ? `${ballTotals.bigBalls} Jumbo + ${ballTotals.midBalls} Original balls` : "No dispatch plan for this date"}
        >
          {saving ? "Saving..." : "Save to Kitchen"}
        </Button>
      );
    }
    ```

    Render a row of these buttons beneath the PlannerGrid, aligned to the date columns. Use the same `weekDates` array that the planner uses. The user needs to be logged in (use `useAuth()` to get the token).

    The exact visual layout (above grid, below grid, or inline in column headers) is at Claude's discretion — choose the option with least invasive changes to `PlannerGrid.tsx` (i.e., render the row in `DispatchPlanner.tsx` itself, not inside PlannerGrid).

    Import `Id` from `convex/_generated/dataModel` at the top.

    **Step 3: Build `LinkIngredientButton` in `src/pages/IngredientsManager.tsx`**

    Add a new sub-component `LinkIngredientButton` next to `EnableTrackingButton`:

    ```tsx
    function LinkIngredientButton({ ingredient }: { ingredient: Ingredient }) {
      const { user } = useAuth();
      const linkIngredient = useLinkIngredientToComponentType();
      // Load all production+trackInventory componentTypes for the picker
      const componentTypes = useQuery(api.componentTypes.queries.listAll);
      const [open, setOpen] = useState(false);
      const [selectedId, setSelectedId] = useState<string>("");
      const [saving, setSaving] = useState(false);

      // Filter to only tracked production componentTypes
      const trackableTypes = (componentTypes ?? []).filter(
        (ct) => ct.trackInventory && ct.category === "production"
      );

      const handleLink = async () => {
        if (!user?.token || !selectedId) return;
        setSaving(true);
        try {
          await linkIngredient({
            token: user.token,
            ingredientId: ingredient._id,
            componentTypeId: selectedId as Id<"componentTypes">,
          });
          toast.success(`Linked ${ingredient.name} to inventory tracker`);
          setOpen(false);
        } catch (e) {
          toast.error(e instanceof Error ? e.message : "Failed to link");
        } finally {
          setSaving(false);
        }
      };

      return (
        <>
          {/* Amber warning badge */}
          <div className="flex items-center gap-2">
            <Badge variant="outline" className="text-amber-600 border-amber-300 bg-amber-50 dark:bg-amber-950/20">
              Unlinked
            </Badge>
            <Button variant="outline" size="sm" onClick={() => setOpen(true)}>
              Link
            </Button>
          </div>
          {open && (
            <div className="fixed inset-0 z-50 flex items-center justify-center bg-black/40">
              <div className="bg-white dark:bg-gray-900 rounded-lg p-6 w-96 shadow-xl">
                <h3 className="font-semibold mb-1">Link to Inventory Tracker</h3>
                <p className="text-sm text-muted-foreground mb-4">
                  Link <strong>{ingredient.name}</strong> to an existing tracked componentType so simulation can read its stock.
                </p>
                <select
                  className="w-full border rounded px-3 py-2 text-sm mb-4 bg-white dark:bg-gray-800"
                  value={selectedId}
                  onChange={(e) => setSelectedId(e.target.value)}
                >
                  <option value="">Select component type...</option>
                  {trackableTypes.map((ct) => (
                    <option key={ct._id} value={ct._id as string}>{ct.name}</option>
                  ))}
                </select>
                <div className="flex justify-end gap-2">
                  <Button variant="outline" size="sm" onClick={() => setOpen(false)}>Cancel</Button>
                  <Button size="sm" onClick={handleLink} disabled={!selectedId || saving}>
                    {saving ? "Linking..." : "Link"}
                  </Button>
                </div>
              </div>
            </div>
          )}
        </>
      );
    }
    ```

    Note: For the inline dialog, use a plain div overlay instead of shadcn Dialog to avoid import complexity — or use Dialog if it's already imported. Follow whichever pattern is simpler given the file's existing imports.
