**Create `src/hooks/convex/useGrabFood.ts`:**

1. `useGrabFoodOrders(outletId, fromMs?, toMs?)` — wraps `useQuery(api.grabfoodOrders.queries.listOrders, ...)` with token from auth context. Returns `{ orders, isLoading }`.

2. `useGrabFoodOrderStats(outletId?)` — wraps `useQuery(api.grabfoodOrders.queries.getOrderStats, ...)`. Returns `{ totalOrders, lastSyncedAt }`.

3. `useGrabFoodActions()` — returns action wrappers using `useAction`:
   - `syncOrders(merchantID, outletId?, fromDate?, toDate?)` — calls `api.integrations.grabfood.adapter.syncOrders`
   - `getStoreStatus(merchantID)` — calls `api.integrations.grabfood.adapter.getStoreStatus`
   - `pauseStore(merchantID, pauseDuration)` — calls `api.integrations.grabfood.adapter.pauseStore`
   - `batchUpdateAvailability(merchantID, items)` — calls `api.integrations.grabfood.adapter.batchUpdateAvailability`
   - `getMenuItems(merchantID)` — calls `api.integrations.grabfood.adapter.getMenuItems`
   Each wrapper includes the auth token from `useAuth()` context.

**Create `src/pages/GrabFoodManager.tsx`:**

Page structure per locked decisions:
- **Page header:** "GrabFood Manager" with PageHeader component
- **Outlet selector (top-level):** Dropdown at page top. Load outlets from `externalOutlets` where `source: "grabfood"`. All tabs filter by selected outlet. If only one outlet, auto-select it.
- **3 tabs:** Use shadcn Tabs component — `Orders` | `Store Status` | `Menu`

**Orders Tab (GF-06):**
- "Sync Order History" button (admin only — check `canAccessDashboard` or role check). Shows spinner during sync.
- Auto-resume display: "Last synced: {timestamp}" from `getOrderStats`. Default sync pulls from last sync timestamp.
- Expandable date picker for custom date override (collapsible section, default collapsed).
- Sync feedback: toast via sonner — "Synced N orders" on success, error message on failure.
- Orders table with columns per locked decision: Order ID (`shortOrderNumber`), Date/Time (`orderTime` formatted), Items Summary (count + first item name), Subtotal (`price.subtotal`), Promo Discount (sum of promos), Net Revenue (subtotal - promos), Payment Method (`paymentType`).
- Table uses shadcn Table component. Sort by date descending. Paginate client-side (show 25 per page).
- Loading state: skeleton rows while query loads.

**Store Status Tab (GF-07):**
- One status card per outlet (even though tab is filtered by outlet selector, show card layout for consistency with future multi-outlet view).
- Card content: Outlet name, status badge (OPEN = green, PAUSED = yellow, CLOSED = red) using shadcn Badge.
- **Pause controls:** Button group with 30 / 60 / 120 minute options. Show only when status is OPEN.
- **Unpause button:** Show only when status is PAUSED.
- **Countdown timer:** When paused, show "Resumes in Xm" with live countdown (update every 30s via useEffect interval). Use the `pauseUntil` field from store status response.
- **Manual refresh button:** "Refresh Status" button with RefreshCw icon. Shows "Last checked: X min ago" timestamp.
- Status is fetched on-demand via action (NOT reactive query — GrabFood API call). Store result in local state.

**Menu Tab (GF-08):**
- Fetch menu items via `getMenuItems` action on tab mount. Store in local state.
- Display: List of menu items — item name, current price, availability toggle (Switch component).
- **grabItemID mapping:** Each item shows its grabItemID. Next to each item, a dropdown to assign a menuProduct (from existing menuProducts query). This uses `externalProductMappings` table with `source: "grabfood"` and `externalProductCode` = grabItemID. Show "Unmapped" badge for items without mapping.
- **Toggle scope:** Individual toggles only (per locked decision — no bulk actions).
- **Publish flow:** Toggles accumulate in local state as a "pending changes" list. Show a "Publish Changes" button (only visible when there are pending changes) with a count badge ("3 changes"). Clicking calls `batchUpdateAvailability` which handles both batch update + notifyMenuUpdate.
- Success toast: "Published N menu changes".

**Styling:** Follow existing page patterns — dark mode compatible (use semantic color classes: `bg-background`, `text-foreground`, `border-border`). Use shadcn Card for sections, Badge for status indicators, Button for actions.

**Access control:** ProtectedRoute with roles `["manager", "admin"]`. Admin-only actions (sync) should have additional role check in the UI (hide sync button for non-admin).
