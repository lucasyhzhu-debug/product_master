<objective>
Eliminate N+1 query patterns in orders and dashboard queries, and add denormalized `isKitchenVisible` boolean to orders for fast kitchen lookups.

Purpose: The biggest performance bottlenecks are (1) full table scans of `orderItems` and `orderItemProduction` in kitchen/completed-today queries, (2) full table scan of all orders in dashboard, and (3) 8 separate status queries for kitchen view. This plan replaces all with targeted indexed lookups.

Output: Optimized backend queries; `isKitchenVisible` field with index on orders; all status transition points patching the new field.
</objective>

**Replace full table scans in batchFetching.ts**:

1. In `fetchOrdersWithItemsAndProduction()`: Replace the two full table scans (`ctx.db.query("orderItems").collect()` and `ctx.db.query("orderItemProduction").collect()`) with targeted per-order indexed lookups:
   ```typescript
   // For each orderId, fetch items via by_order index in parallel
   const itemsByOrder = new Map();
   await Promise.all(orderIds.map(async (orderId) => {
     const items = await ctx.db.query("orderItems")
       .withIndex("by_order", q => q.eq("orderId", orderId))
       .collect();
     itemsByOrder.set(orderId, items);
   }));

   // Collect all item IDs, then fetch production records per item in parallel
   const allItems = Array.from(itemsByOrder.values()).flat();
   const productionByItem = new Map();
   await Promise.all(allItems.map(async (item) => {
     const records = await ctx.db.query("orderItemProduction")
       .withIndex("by_order_item", q => q.eq("orderItemId", item._id))
       .collect();
     productionByItem.set(item._id, records);
   }));
   ```
   Build the same return structure (Map<orderId, { items, production }>). This scales with active orders (~30) not total history (~10000+).

2. Apply same pattern to `fetchOrderItems()`: Replace `ctx.db.query("orderItems").collect()` with parallel per-order indexed lookups.
