  <files>src/components/salesAnalytics/IntegrationHealthCard.tsx, src/components/salesAnalytics/SettingsTab.tsx</files>
  <action>
Refactor IntegrationHealthCard and SettingsTab to be registry-driven per CONTEXT.md locked decisions.

**IntegrationHealthCard.tsx changes:**

1. Import `PLATFORMS`, `PlatformMeta`, `PlatformId` from `convex/integrations/registry.ts`
2. Replace hardcoded `platformId === "k3mart" || platformId === "gobiz"` comparisons in `getOverallStatus()` with registry-driven logic:
   - Read `PLATFORMS[platformId].healthConfig` to determine behavior
   - `healthCheckType === 'token_expiry'`: use `tokenExpiresAt` and threshold days from registry
   - `healthCheckType === 'last_sync'`: use `lastSyncAt` age comparison
   - `healthCheckType === 'always_green'`: return green always (when configured)
3. Add support for `authStrategy` to determine which action button to show:
   - `'password_grant'` (GoBiz): "Refresh Token" primary button + "Configure" secondary (opens existing token dialog)
   - `'paste_token'` (BigSeller): "Paste Token" primary button (opens BigSellerTokenDialog)
   - `'client_credentials'` (GrabFood): "Test Connection" button (or just status — no action needed)
   - `'pos_login'` (K3Mart): keep existing "Configure" button behavior
   - `'session_auth'` (Internal, Consignment): no action button needed — always connected
4. Show expiry countdown badge for platforms with `hasExpiry: true`:
   - Green badge: "> X days" (X = yellowThresholdDays)
   - Yellow badge: "X days remaining"
   - Red badge: "X days remaining" or "Expired"
5. Each row: icon (use Lucide icons — Store for POS, Globe for delivery, ShoppingBag for marketplace, Database for internal) + platform name + description + status badge + last activity timestamp + primary action button

**SettingsTab.tsx changes:**

1. Replace hardcoded per-platform IntegrationHealthCard blocks with a loop over `PLATFORMS`:
   ```tsx
   {Object.values(PLATFORMS).map((platform) => (
     <IntegrationHealthCard
       key={platform.id}
       platformId={platform.id}
       platformMeta={platform}
       healthStatus={healthData?.find(h => h.platformId === platform.id)}
       onAction={...}
     />
   ))}
   ```
2. Consume `getHealthStatusAll` query from Plan 01:
   ```tsx
   const healthData = useQuery(api.platformCredentials.getHealthStatusAll);
   ```
   Handle loading state: `if (healthData === undefined) return <Loading />;`
3. Keep existing GoBiz and K3Mart dialog triggers — add BigSeller dialog trigger
4. Pass appropriate action handlers to each card (openGoBizDialog, openBigSellerDialog, openK3MartDialog, etc.)

**Per CONTEXT.md locked decision:** Row layout is consistent across all platforms despite different auth mechanics. Registry-driven rendering means adding a new platform = adding a registry entry, not new UI code.

**Anti-pattern to avoid (from RESEARCH.md):** Do NOT add platform-specific JSX branches with `if (platformId === "bigseller")` — derive all behavior from `authStrategy` and `healthConfig`.
