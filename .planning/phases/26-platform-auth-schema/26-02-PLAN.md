<task type="auto">
  <name>Task 1: GoBiz loginWithCredentials password grant action</name>
  <files>convex/integrations/gobiz/adapter.ts</files>
  <action>
Add a new exported action `loginWithCredentials` to the existing `convex/integrations/gobiz/adapter.ts` file (which already has `"use node"` at the top).

**Implementation (per RESEARCH.md verified pattern):**

1. Args: `{ token: v.string() }` (admin session token for auth check)
2. Validate admin role: call `requireRole` via `ctx.runQuery(internal.platformCredentials.queries.validateAdminToken, { token: args.token })` — or use the existing admin validation pattern already in the file
3. Read env vars: `process.env.GOBIZ_EMAIL` and `process.env.GOBIZ_PASSWORD`
4. If either env var is missing, return `{ success: false, error: "GOBIZ_EMAIL and GOBIZ_PASSWORD env vars not configured in Convex dashboard." }`
5. Call password grant endpoint:
   ```
   POST https://api.gobiz.co.id/goid/token
   Content-Type: application/json
   Body: { client_id: "go-biz-web-new", grant_type: "password", data: { email, password } }
   ```
6. If response is not OK: return `{ success: false, error: "GoBiz login failed ({status})" }`
7. Parse JSON response. Extract `access_token` and `refresh_token`.
8. Save tokens using the EXISTING `saveDirectToken` internal mutation in `platformCredentials/mutations.ts`:
   ```typescript
   await ctx.runMutation(internal.platformCredentials.mutations.saveDirectToken, {
     platformId: "gobiz",
     bearerToken: data.access_token,
     refreshToken: data.refresh_token,
   });
   ```
   Use `saveDirectToken` per RESEARCH.md recommendation — it already handles both `currentToken` and `refreshToken` fields.
9. Return `{ success: true }`

**Keep existing functionality intact** — the existing cookie-paste methods (`performGobizRefresh`, etc.) remain as fallback. The new action is additive.

**Make the action callable from frontend** — export it as a public action (not internal) since the frontend will call it via `useAction(api.integrations.gobiz.adapter.loginWithCredentials)`. The `token` arg provides auth.

<task type="auto">
  <name>Task 2: BigSeller paste-token flow with JWT decode preview</name>
  <files>convex/integrations/bigseller/adapter.ts, convex/integrations/bigseller/config.ts</files>
  <action>
Create two new files for the BigSeller integration module.

**File 1: `convex/integrations/bigseller/config.ts`**

Simple config constants:
```typescript
export const BIGSELLER_PLATFORM_ID = "bigseller" as const;
export const BIGSELLER_TOKEN_COOKIE_NAME = "muc_token";
// Max sync window per BigSeller API constraint
export const BIGSELLER_MAX_SYNC_DAYS = 31;
```

**File 2: `convex/integrations/bigseller/adapter.ts`**

Must start with `"use node";` since it may call external endpoints in the future.

Create TWO actions:

**Action 1: `previewBigSellerToken`**
- Args: `{ token: v.string(), mucToken: v.string() }`
- Validate admin role (same pattern as GoBiz)
- Import and use `decodeJwtPayload` from `convex/platformCredentials/actions.ts` (the function, not the action — if it's not exported as a standalone function, inline the decode: split JWT by '.', base64url-decode the second part, JSON.parse)
- Extract `exp` field (Unix seconds). If no `exp`: return `{ success: false, error: "JWT has no expiry field" }`
- Calculate `expiresAt` (exp * 1000 ms) and `daysRemaining` (Math.floor((expiresAt - Date.now()) / 86400000))
- If `daysRemaining < 0`: return `{ success: false, error: "Token is already expired" }`
- Optionally extract `uid` from payload for display
- Return `{ success: true, expiresAt, daysRemaining, uid }`

**Action 2: `saveBigSellerToken`**
- Args: `{ token: v.string(), mucToken: v.string() }`
- Validate admin role
- Decode JWT to extract `exp` (same as preview)
- Calculate `tokenExpiresAt` = exp * 1000
- Save to platformCredentials via `saveDirectToken` internal mutation:
  ```typescript
  await ctx.runMutation(internal.platformCredentials.mutations.saveDirectToken, {
    platformId: "bigseller",
    bearerToken: args.mucToken,
  });
  ```
- ALSO update `tokenExpiresAt` on the credential record. Check if `saveDirectToken` supports this field — if not, use `ctx.runMutation(internal.platformCredentials.mutations.updateToken, ...)` or directly patch via an internal mutation. The key is that `tokenExpiresAt` is stored so the health query (Plan 01, Task 3) can read it.
- Return `{ success: true, daysRemaining }`

**Important:** Store `muc_token` as `currentToken` (NOT `refreshToken`). BigSeller's JWT is the primary access credential — see RESEARCH.md anti-pattern warning.

**Note on `decodeJwtPayload`:** Check if the existing function in `platformCredentials/actions.ts` is exported as a reusable function or only used internally. If it's a local function, either: (a) extract it to a shared util `convex/lib/jwt.ts`, or (b) inline the base64url decode in the BigSeller adapter. Prefer (a) if the function is substantial, (b) if it's trivial.

Both actions must be public (frontend-callable), with `token: v.string()` for auth.
