  <name>Task 1: Convert saveDirectToken to internalMutation + add tokenExpiresAt param</name>
  <files>convex/platformCredentials/mutations.ts</files>
  <action>
**CRITICAL (staffreview fix): `saveDirectToken` is currently a public `mutation` but Plan 02 actions need to call it via `internal.*` path. In Convex, `internal.*` only resolves `internalMutation` exports. This MUST be fixed before the GoBiz and BigSeller actions can work.**

Two changes to `convex/platformCredentials/mutations.ts`:

1. **Convert `saveDirectToken` from `mutation` to `internalMutation`:**
   - Change `export const saveDirectToken = mutation({` to `export const saveDirectToken = internalMutation({`
   - Remove the `token: v.string()` arg (internal mutations don't need frontend auth — the calling action already validated admin role)
   - Keep all other args and handler logic unchanged

2. **Create a thin public wrapper for any frontend callers:**
   ```typescript
   export const saveDirectTokenPublic = mutation({
     args: {
       token: v.string(),
       platformId: v.string(),
       bearerToken: v.string(),
       refreshToken: v.optional(v.string()),
       tokenExpiresAt: v.optional(v.number()),
     },
     handler: async (ctx, args) => {
       await requireRole(ctx, args.token, ["admin"]);
       const { token: _, ...rest } = args;
       // Delegate to internal version
       // Note: Since this is already in the same file, call the handler directly
       // or use ctx.runMutation(internal.platformCredentials.mutations.saveDirectToken, rest)
       return await saveDirectTokenHandler(ctx, rest);
     },
   });
   ```
   Alternatively, if no frontend callers exist for `saveDirectToken` (check grep results), the public wrapper can be omitted.

3. **Add optional `tokenExpiresAt` parameter to `saveDirectToken`:**
   - Add to args: `tokenExpiresAt: v.optional(v.number())`
   - In the handler, replace the hardcoded 6h estimate logic:
     ```typescript
     // BEFORE (buggy for BigSeller):
     const estimatedExpiry = now + 6 * 60 * 60 * 1000;

     // AFTER:
     const tokenExpiry = args.tokenExpiresAt ?? (now + 6 * 60 * 60 * 1000);
     ```
   - Use `tokenExpiry` everywhere the old `estimatedExpiry` was used
   - This is non-breaking: existing callers that don't pass `tokenExpiresAt` still get the 6h estimate

**Why this matters:** Without fix #1, `ctx.runMutation(internal.platformCredentials.mutations.saveDirectToken, ...)` will fail at runtime — the `internal.*` path won't resolve a public mutation. Without fix #3, BigSeller's 30-day JWT expiry gets overwritten with a 6h estimate, making the health dashboard show wrong expiry countdowns.

<task type="auto">
  <name>Task 2: GoBiz loginWithCredentials password grant action</name>
  <files>convex/integrations/gobiz/adapter.ts</files>
  <action>
Add a new exported action `loginWithCredentials` to the existing `convex/integrations/gobiz/adapter.ts` file (which already has `"use node"` at the top).

**Implementation (per RESEARCH.md verified pattern):**

1. Args: `{ token: v.string() }` (admin session token for auth check)
2. Validate admin role: call `requireRole` via `ctx.runQuery(internal.platformCredentials.queries.validateAdminToken, { token: args.token })` — or use the existing admin validation pattern already in the file
3. Read env vars: `process.env.GOBIZ_EMAIL` and `process.env.GOBIZ_PASSWORD`
4. If either env var is missing, return `{ success: false, error: "GOBIZ_EMAIL and GOBIZ_PASSWORD env vars not configured in Convex dashboard." }`
5. Call password grant endpoint:
   ```
   POST https://api.gobiz.co.id/goid/token
   Content-Type: application/json
   Body: { client_id: "go-biz-web-new", grant_type: "password", data: { email, password } }
   ```
6. If response is not OK: return `{ success: false, error: "GoBiz login failed ({status})" }`
7. Parse JSON response. Extract `access_token` and `refresh_token`.
8. Save tokens via the `saveDirectToken` **internalMutation** (converted in Task 1):
   ```typescript
   await ctx.runMutation(internal.platformCredentials.mutations.saveDirectToken, {
     platformId: "gobiz",
     bearerToken: data.access_token,
     refreshToken: data.refresh_token,
   });
   ```
   **CRITICAL:** This call works ONLY because Task 1 converted `saveDirectToken` to `internalMutation`. The `internal.*` path resolves `internalMutation` exports, NOT public `mutation` exports.
9. Return `{ success: true }`

**Keep existing functionality intact** — the existing cookie-paste methods (`performGobizRefresh`, etc.) remain as fallback. The new action is additive.

**Make the action callable from frontend** — export it as a public action (not internal) since the frontend will call it via `useAction(api.integrations.gobiz.adapter.loginWithCredentials)`. The `token` arg provides auth.
  </action>

**File 2: `convex/integrations/bigseller/adapter.ts`**

Must start with `"use node";` since it may call external endpoints in the future.

Create TWO actions:

**Action 1: `previewBigSellerToken`**
- Args: `{ token: v.string(), mucToken: v.string() }`
- Validate admin role (same pattern as GoBiz)
- Import `decodeJwtPayload` from `../../lib/jwt` (the shared util extracted in Plan 01 Task 0)
- Extract `exp` field (Unix seconds). If no `exp`: return `{ success: false, error: "JWT has no expiry field" }`
- Calculate `expiresAt` (exp * 1000 ms) and `daysRemaining` (Math.floor((expiresAt - Date.now()) / 86400000))
- If `daysRemaining < 0`: return `{ success: false, error: "Token is already expired" }`
- Optionally extract `uid` from payload for display
- Return `{ success: true, expiresAt, daysRemaining, uid }`

**Action 2: `saveBigSellerToken`**
- Args: `{ token: v.string(), mucToken: v.string() }`
- Validate admin role
- Decode JWT to extract `exp` using `decodeJwtPayload` from `../../lib/jwt`
- Calculate `tokenExpiresAt` = exp * 1000
- Save to platformCredentials via `saveDirectToken` **internalMutation** (converted in Task 1), passing the actual expiry:
  ```typescript
  await ctx.runMutation(internal.platformCredentials.mutations.saveDirectToken, {
    platformId: "bigseller",
    bearerToken: args.mucToken,
    tokenExpiresAt,  // actual JWT exp, NOT 6h estimate
  });
  ```
  **CRITICAL:** Pass `tokenExpiresAt` explicitly. Task 1 added this optional param to `saveDirectToken` so it uses the actual JWT expiry instead of the hardcoded 6h estimate. Without this, the health dashboard would show "6 hours remaining" instead of "28 days remaining".
- Return `{ success: true, daysRemaining }`

**Important:** Store `muc_token` as `currentToken` (NOT `refreshToken`). BigSeller's JWT is the primary access credential — see RESEARCH.md anti-pattern warning.

Both actions must be public (frontend-callable), with `token: v.string()` for auth.
