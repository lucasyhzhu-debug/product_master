<task type="auto">
  <name>Task 3: Create registry-driven credential health query</name>
  <files>convex/platformCredentials/queries.ts</files>
  <action>
Add a new query `getHealthStatusAll` to `convex/platformCredentials/queries.ts` that returns health status for ALL platforms by iterating the registry.

The query should:

1. Import `PLATFORMS`, `PlatformId`, `HealthCheckType` from `convex/integrations/registry.ts`
2. For each platform in `PLATFORMS`:
   - If `healthCheckType === 'always_green'`: return `{ status: 'green', label: 'Connected' }`
   - If `healthCheckType === 'last_sync'`: look up the most recent `externalSyncLogs` entry for that platform's source; return green if synced within 48h, yellow if 2-7 days ago, red if >7 days or never synced
   - If `healthCheckType === 'token_expiry'`: look up `platformCredentials` for that `platformId`; calculate days remaining from `tokenExpiresAt`; compare against `yellowThresholdDays` and `redThresholdDays` from registry
3. Return type: `Array<{ platformId: PlatformId, status: 'green' | 'yellow' | 'red' | 'disconnected', label: string, lastActivity: number | null, daysRemaining: number | null }>`
4. Handle the "no credential exists" case: return `disconnected` status with appropriate label
5. For GrabFood specifically: check if a `platformCredentials` record exists with `platformId: "grabfood"` — if yes and it has `email` (client_id) populated, return green; otherwise return `disconnected` with label "Client credentials not configured"
6. This query requires no auth token (it's read-only status for display)

This replaces any hardcoded per-platform status logic in favor of a single registry-driven query. The frontend (Plan 03) will consume this query directly.
  </action>
