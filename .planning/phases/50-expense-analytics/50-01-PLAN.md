    - detectApproverConcentration: flags when same approver approved >80% of one employee's expenses in 30-day window

  <action>
    Create `convex/expenses/fraudHelpers.ts` with 3 pure functions (no ctx dependency). Follow the existing `helpers.ts` pattern in the same directory.

    **Constants:**
    - MS_48_HOURS = 48 * 60 * 60 * 1000
    - SPLIT_THRESHOLD = 500_000
    - CONCENTRATION_THRESHOLD = 0.80
    - MIN_EXPENSES_FOR_CONCENTRATION = 2 (don't flag trivial cases where employee has only 1-2 expenses)

    **Interface for fraud detection input:**
    ```typescript
    export interface ExpenseForFraud {
      _id: string;
      submittedBy: string;
      accountId: string;
      amount: number;
      expenseDate: number;
      approvedBy?: string;
      approvedAt?: number;
      vendorName: string;
      status: string;
    }
    ```

    **Export types for return values:**
    - SplitFlag: { employeeId, accountId, expenseIds: string[], totalAmount }
    - ConcentrationFlag: { employeeId, approverId, percent, count, totalCount }
    - Each function returns an array of flag objects

    **detectSplits(expenses: ExpenseForFraud[]): SplitFlag[]**
    - Group by (submittedBy, accountId) key
    - Within each group with 2+ expenses, sort by expenseDate ascending
    - Sliding window: for each expense, collect subsequent expenses within 48hr window
    - If cluster has 2+ expenses and sum > 500K, emit a flag
    - Deduplicate overlapping clusters by tracking seen expense IDs

    **detectApproverConcentration(expenses: ExpenseForFraud[]): ConcentrationFlag[]**
    - Filter to approved expenses only (status in ["approved", "awaiting_payment", "reimbursed"])
    - Group by submittedBy (employee)
    - For each employee with >= MIN_EXPENSES_FOR_CONCENTRATION expenses:
      - Count approvals by each approver
      - If any approver has > 80% share, emit a flag

    **detectUnfamiliarVendors(recentVendors: string[], historicalVendors: Set<string>): string[]**
    - Simple set difference: return recentVendors not in historicalVendors
    - Normalize vendor name comparison (case-insensitive via .toLowerCase())
    - Return unique vendor names

    **Tests:** Write tests FIRST (RED), then implement (GREEN). Use `describe("detectSplits", ...)` etc. Follow the pattern in `convex/expenses/__tests__/helpers.test.ts`.

  <name>Task 2: Analytics backend queries with tests</name>
  <files>convex/expenses/analyticsQueries.ts, tests/convex/expenseAnalytics.test.ts</files>
  <behavior>
    - getOpExAnalytics: returns totalOpEx, byCategory array sorted by total descending, and 6-month trend array
    - getOpExAnalytics: filters journal lines to opex accounts only (type="opex")
    - getOpExAnalytics: 6-month trend always uses trailing months from current time, not from period args
    - getOpExAnalytics: near-zero amounts (Math.abs < 0.01) excluded from byCategory display
    - getExpenseMetrics: returns byEmployee with userId, name, total for approved/awaiting_payment/reimbursed expenses
    - getExpenseMetrics: returns pendingTotal (sum of awaiting_payment expenses)
    - getExpenseMetrics: returns avgApprovalDays (mean of approvedAt - submittedAt in days)
    - getFraudFlags: returns splits, concentrations, unfamiliarVendors arrays computed via pure helpers
    - All queries require manager or admin role via protectedQuery
  </behavior>
  <action>
    Create `convex/expenses/analyticsQueries.ts` with 3 protectedQuery endpoints. Use `protectedQuery` from `convex/lib/functions.ts` with `APPROVER_ROLES` from `./constants.ts`.

    **Query 1: getOpExAnalytics**
    Args: `periodStart: v.number(), periodEnd: v.number()`
    - Fetch opex accounts via `ctx.db.query("accounts").withIndex("by_type", q => q.eq("type", "opex")).collect()`
    - Build opexIds Set and accountLookup Map
    - Fetch journal lines for the requested period via `ctx.db.query("journalEntryLines").withIndex("by_entryDate", q => q.gte("entryDate", periodStart).lt("entryDate", periodEnd)).collect()`
    - Aggregate: for each line where accountId is in opexIds, sum (debitAmount - creditAmount) per accountId
    - Compute totalOpEx as sum of all amounts (before near-zero filtering)
    - Build byCategory array with { code, name, total }, filter Math.abs(total) < 0.01, sort by total descending
    - **6-month trend (CRITICAL: independent of period selection):**
      - Use `getWibComponents(Date.now())` to get current WIB year/month
      - Use a SINGLE wide query spanning 6 months: `wibMidnightToUtc(year, month - 5, 1)` to `wibMidnightToUtc(year, month + 1, 1)`
      - Fetch all journal lines in this 6-month range via by_entryDate index
      - Bucket lines into months using `getWibComponents(line.entryDate).month`
      - For each of the 6 months, sum opex lines within that month
      - Label each month using abbreviated name (Jan, Feb, etc.)
    - Return `{ totalOpEx, byCategory, trend }`

    **Query 2: getExpenseMetrics**
    Args: `periodStart: v.number(), periodEnd: v.number()`
    - **Employee spend:** Query expenses with by_status for each of ["approved", "awaiting_payment", "reimbursed"], collect all three, filter by expenseDate within period range. Group by submittedBy, sum amounts. Join user names via batch ctx.db.get.
    - **Pending reimbursements:** Query expenses by_status("awaiting_payment"), sum amounts (no period filter -- shows all outstanding).
    - **Average approval time:** From the approved/awaiting_payment/reimbursed expenses in the period, filter those with both submittedAt and approvedAt, compute mean of (approvedAt - submittedAt) in days (divide by 86400000). Return null if no data.
    - Return `{ byEmployee: [{userId, name, total}], pendingTotal, avgApprovalDays }`
    - Sort byEmployee by total descending.

    **Query 3: getFraudFlags**
    Args: `{}` (no period -- fraud detection uses fixed time windows)
    - **Split detection (FRAUD-06):** Fetch expenses from last 48 hours window. Use `ctx.db.query("expenses").withIndex("by_status", q => q.eq("status", "submitted")).collect()` plus approved/awaiting_payment statuses. Filter by expenseDate within 48hr window from now. Pass to `detectSplits()`.
    - Actually, for splits to be meaningful, we need expenses submitted recently (not just last 48hrs). Better approach: fetch all non-voided/non-draft expenses from last 7 days (wider than 48hrs to catch clusters). The `detectSplits` function handles the 48hr windowing internally.
    - **Approver concentration (FRAUD-07):** Fetch approved expenses from last 30 days. Filter status in ["approved", "awaiting_payment", "reimbursed"]. Pass to `detectApproverConcentration()`.
    - **Unfamiliar vendor (FRAUD-08):** Fetch expenses from current period (last 30 days). Extract unique vendor names as recentVendors. Fetch expenses from 90-day lookback window, extract unique vendor names as historicalVendors Set. Pass to `detectUnfamiliarVendors()`.
    - Join user names for employeeId and approverId fields using batch ctx.db.get.
    - Return `{ splits: [...with names], concentrations: [...with names], unfamiliarVendors: string[] }`

    **Tests:** Write integration tests using `convex-test` pattern. Follow `tests/convex/incomeStatement.test.ts` structure with seed helpers. Test at minimum:
    - getOpExAnalytics returns correct totals for seeded journal lines
    - getExpenseMetrics returns correct employee breakdown and pending total
    - getFraudFlags returns expected flags for seeded fraud scenarios
    - All queries reject non-approver roles
