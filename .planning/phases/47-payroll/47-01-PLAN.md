<objective>
Backend payroll entry system: schema update, pure validation helpers (TDD), mutations (create with auto-JE, void with reversing JE, upload URL), and queries (list with filters, getById with JE details).

Purpose: Enables admin to record contractor/staff payroll entries that auto-generate double-entry journal entries for salary expense tracking. This is the simplest financial entry type -- no approval workflow, no batching, no fraud controls.

Output: Schema updated with `payrollNumber` field, tested pure helpers, working mutations and queries for payroll CRUD.
</objective>

1. **Create `convex/payroll/mutations.ts`** with three mutations:

   **`create`** (protectedMutation, roles: ["admin"]):
   - Args: employeeType (union: "contractor"/"staff"), frequency (union: "weekly"/"monthly"), amount (number), periodStart (number), periodEnd (number), description (string), attachmentFileId (optional Id<"_storage">)
   - Validate: `validatePayrollAmount(args.amount)` (from helpers)
   - Generate payroll number: `const payrollNumber = await getNextNumber(ctx, "PAY")`
   - Look up accounts by code (NEVER hardcode IDs): query `accounts` table with `by_code` index for "6100" (DR: Salaries & Wages) and "1100" (CR: Cash). Throw clear error if not found: "Required accounts (6100, 1100) not found. Run accounts:seedDefaults first."
   - Insert payroll entry FIRST (to get payrollId for sourceId): `ctx.db.insert("payrollEntries", { payrollNumber, employeeType, frequency, amount, periodStart, periodEnd, description, status: "active", createdBy: ctx.user._id, createdAt: Date.now(), ...(args.attachmentFileId && { attachmentFileId: args.attachmentFileId }) })`. NOTE: `journalEntryId` is omitted initially -- will be patched after JE creation.
   - Create JE with sourceId set to the payrollId string: `createJournalEntryWithLines(ctx, { date: args.periodEnd, description: "Payroll " + payrollNumber + ": " + args.description, sourceType: "payroll", sourceId: payrollId, createdBy: ctx.user._id, lines: [buildDebitLine(debitAccount._id, args.amount, args.description), buildCreditLine(creditAccount._id, args.amount)] })`
   - Patch payroll entry with journalEntryId: `ctx.db.patch(payrollId, { journalEntryId })`
   - Return: `{ payrollId, payrollNumber, journalEntryId }`

   **`voidEntry`** (protectedMutation, roles: ["admin"]):
   - Args: payrollId (Id<"payrollEntries">), reason (string)
   - Get entry, throw if not found
   - `validateVoidReason(args.reason)` (from helpers)
   - Guard: `if (entry.status !== "active") throw new Error("Can only void active payroll entries")`
   - Create reversing JE: `createReversalEntry(ctx, entry.journalEntryId!, "payroll_void", ctx.user._id)`. Check that journalEntryId exists before calling.
   - Patch: `ctx.db.patch(args.payrollId, { status: "voided", voidedBy: ctx.user._id, voidedAt: Date.now(), voidReason: args.reason.trim() })`
   - Return: `{ success: true }`

   **`generateUploadUrl`** (protectedMutation, roles: ["admin"]):
   - No args (empty)
   - Handler: `return await ctx.storage.generateUploadUrl()`
   - Follow exact pattern from `convex/expenses/mutations.ts`

2. **Create `convex/payroll/queries.ts`** with two queries:

   **`list`** (protectedQuery, roles: ["admin"]):
   - Args: employeeType (optional union: "contractor"/"staff"), periodStart (optional number), periodEnd (optional number)
   - If employeeType is provided, use `by_employee_type` index. Otherwise query all.
   - Collect results, then filter by period range in-memory if periodStart/periodEnd provided (filter where entry.periodStart >= args.periodStart AND entry.periodEnd <= args.periodEnd).
   - Sort by createdAt descending (newest first).
   - For each entry, resolve `createdBy` to get user name. If voided, also resolve `voidedBy` to user name.
   - Return enriched array.

   **`getById`** (protectedQuery, roles: ["admin"]):
   - Args: payrollId (Id<"payrollEntries">)
   - Get entry, throw if not found
   - Resolve createdBy -> user name
   - If voided, resolve voidedBy -> user name
   - If journalEntryId, fetch the journal entry and its lines (query journalEntryLines with by_entry index). For each line, resolve accountId to get account code and name.
   - Return enriched entry with JE details.

Import patterns: Use `import { v } from "convex/values"`, `import { protectedMutation } from "../lib/functions"`, `import { protectedQuery } from "../lib/functions"`, etc. Follow exact import patterns from `convex/reimbursements/mutations.ts` and `convex/expenses/queries.ts`.
