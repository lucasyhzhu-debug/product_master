<decisions>
## Implementation Decisions

All decisions below are LOCKED — sourced directly from the PRD. Any deviation during planning/execution must be flagged and re-approved.

### D-01: Architecture — 3 grouped snapshot queries
Create `kpiAndChannelSnapshot`, `timeSeriesSnapshot`, `skuSnapshot` in `convex/reports/unitEconomics.ts`. Each calls a single `loadFilteredData` + `precomputeBomMaps` pass, returning a composite object consumed by field selectors on the frontend.

### D-02: Zero-downtime migration via thin wrappers
The 11 existing per-widget queries (`kpiSummary`, `channelEconomics`, `channelMomentum`, `byWeekday`, `rollingTrend`, `dayHourHeatmap`, `volumeByType`, `typeMixOverTime`, `unitsPerTxnByChannel`, `aovByChannel`, `skuPareto`, `skuChannelMatrix`) are rewritten as thin wrappers that delegate to the snapshots. They remain live through Wave B so the frontend migration can land incrementally. They are DELETED in Task 23 after every caller has moved to snapshot hooks.

### D-03: Snapshot groupings (UPDATED per staffreview 2026-04-18, iteration 2 resolutions)
- `kpiAndChannelSnapshot` → `{ kpi, channelEconomics, channelMomentum }` (current + prior period for delta computation). **`channelSparklines` REMOVED** — Improvement 1 found `channelMomentum.channels[].{revenueSpark, unitsSpark, aovSpark}` already exists and `ChannelSparklineTable.tsx` already consumes it; a separate `reduceChannelSparklines` reducer would be redundant.
- `timeSeriesSnapshot` → `{ byWeekday, rollingTrend, dayHourHeatmap, volumeByType: { day, week }, typeMixOverTime: { day, week } }` (granularity precomputed server-side — client selects which to display). Note: `typeMixOverTime` is a NEW server-side reducer (Critical 2) — no existing query to extract from; `TypeMixOverTime.tsx` previously did a client-side percent transform in useState.
- `skuSnapshot` → `{ skuTop, skuChannelMatrix }` (fixed cap 20 SKUs server-side; clients slice for display topN). **`revPerUnit` and `unitsByTypeStackedBars` REMOVED** — Criticals 3 & 4 found the existing `RevPerUnitChart.tsx` and `UnitsByTypeStackedBars.tsx` widgets render channel-based and time-bucketed shapes respectively, not per-product. Adding new reducers with per-product shapes would silently reshape those charts. Widgets stay on `useChannelEconomics()` / `useVolumeByType("day")` routed through the existing snapshot fields.

### D-04: Reducer extraction pattern (Wave A)
Each of the 12 widget computations becomes a pure function `reduce<Name>(current: WindowData, prior?: WindowData, pre: Precomputed, ...extraArgs)` in `convex/reports/unitEconomics.ts` (NOT in `reducers.ts` per the PRD — the header says "Create `convex/reports/reducers.ts`" but the task body keeps them in `unitEconomics.ts`. **Ambiguity resolved: planner should keep reducers in `unitEconomics.ts` to minimize churn. If file size becomes unwieldy post-extraction, split to `reducers.ts` in a follow-up.**). Reducers accept pre-loaded data, never touch `ctx.db` directly. Unit-tested by passing fake `WindowData` shapes.

### D-05: Call-counter regression test
Monkey-patch `loadFilteredData` + `precomputeBomMaps` inside a `convex-test` run and assert:
- `kpiAndChannelSnapshot` calls `loadFilteredData` EXACTLY 2 times (current + prior)
- `timeSeriesSnapshot` calls `loadFilteredData` EXACTLY 1 time
- `skuSnapshot` calls `loadFilteredData` EXACTLY 1 time
- `precomputeBomMaps` is called EXACTLY 1 time per snapshot invocation

This guards against future unfactoring that re-introduces the fan-out.

### D-06: Readability rules enforced by primitives (not individual widgets)
- **R1** — axis labels never silently truncate. String X-axis ticks use `X_AXIS_STRING_LABEL_PROPS` (`angle: -35, textAnchor: "end", interval: 0, height: 80`). Long labels pass through `truncateWithTooltip(label, 22)` which returns `{ display, full }`; full name lands in the tooltip via `labelFormatter`.
- **R2** — tooltips use `--popover` / `--popover-foreground` tokens for WCAG AA contrast (≥4.5:1) against the dark page chrome. Category colors appear ONLY as small swatches next to value names, NEVER as the text color of the value.
- **R3** — Nivo heatmap labels use `labelTextColor: { from: "color", modifiers: [["darker", 3]] }` for auto-adapting cell text contrast.

### D-07: Nivo scope — heatmaps only
Install `@nivo/core` + `@nivo/heatmap`. Replace hand-rolled `DayHourHeatmap` + `SkuChannelHeatmap` (~280 LOC → ~110 LOC). Keep Recharts for all other charts (bars, lines, composed, stacked, dual-axis).

### D-08: Route-level lazy-load
`src/App.tsx` uses `React.lazy(() => import("./pages/AnalyticsDashboard"))` + `<React.Suspense fallback={...}>`. The Nivo chunk must NOT load when any non-`/analytics` route is visited. Verified in Task 22 by DevTools Network inspection and by the build output showing a separate `AnalyticsDashboard-<hash>.js` chunk.

### D-09: Vendor bundle cap
`npm run build` must stay within the `vite-plugin-bundlesize` cap. If Nivo pushes the vendor chunk over, bump the cap by the minimum needed in `vite.config.ts` and document the delta in the PR body. (Per user memory `feedback_vendor_bundle_cap`: Vercel enforces the cap, local may not — do not ignore a local warning.)

### D-10: M-03 cleanup — inline `jakartaHour`
The `jakartaHour(ts): number` helper in `convex/reports/unitEconomics.ts` has 1-2 call sites inside `reduceDayHourHeatmap`. Delete the helper, replace each call site with `getWibComponents(ts).hour` directly. This closes a loose thread flagged in the Phase 80 staff review.

### D-11: Install `@nivo/core` + `@nivo/heatmap` with pinned versions (no caret)

Item format mirrors Phase 73's HUMAN-UAT: `expected:` + `result: [pending]`. Item executed by the human post-deploy; automated tests cannot fully replace.

### D-16: Widget migration order (Wave B)
1. `SkuParetoChart.tsx` FIRST — it is the R1/R2 screenshot subject from the upstream defect report. Establishes the visual contract.
2. Then `UnitsByTypeStackedBars` + `TypeMixOverTime` (string X-axis, stacked bars)
3. Then `RevPerUnitChart` + `RollingTrendChart` + `WeekdayDualAxisChart` (time-series + dual-axis)
4. Then `UnitsPerTxnByChannel` + `AovByChannel` (channel-bar widgets)
5. Final sweep of non-chart widgets (`KpiRow`, `ChannelSparklineTable`, `TakeRateTable`) — only touch if audit finds hardcoded formatting or tooltip defects

### D-17: Granularity is a client-side slice, not a server arg
`volumeByType` and `typeMixOverTime` compute BOTH `day` AND `week` granularities server-side and return them as `{ day, week }`. The frontend hook accepts a granularity prop and selects one. This allows the granularity toggle to flip instantly with no new subscription.

### D-18: `skuTop` cap is server-side constant 20
`skuSnapshot` enforces `SKU_SNAPSHOT_TOP_CAP = 20` as a module-level constant. Clients slice the returned array for display (topN=10 for Pareto, topN=8 for channel matrix). Keeps payload bounded and reduces re-fetch churn when clients change their display cap.

### D-19: Preserve existing query return shapes during wrapper phase
`unitsPerTxnByChannel` and `aovByChannel` currently return subset projections of `channelEconomics`. Thin wrappers MUST preserve the exact field names the existing frontend consumes. Verify via `git log -p convex/reports/unitEconomics.ts` when adapting — any shape drift breaks pre-existing tests and we do NOT modify those tests during the wrapper phase (tests are the contract).

### Call-counter test mechanism

```ts
// In tests/convex/unitEconomicsSnapshots.test.ts
await t.run(async (ctx) => {
  const mod = await import("../../convex/reports/unitEconomics");
  const original = (mod as any).loadFilteredData;
  let loadCount = 0;
  (mod as any).loadFilteredData = async (...args: unknown[]) => {
    loadCount++;
    return original.apply(null, args);
  };
  await mod.kpiAndChannelSnapshot._handler(ctx, { fromTs: ..., toTs: ... });
  (mod as any).loadFilteredData = original;
  expect(loadCount).toBe(2);
});
```
