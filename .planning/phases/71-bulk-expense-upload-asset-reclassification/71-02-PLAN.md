      assetCategory: string;      // raw, optional
      assetName: string;          // raw, optional

      errors: CellError[];        // per-cell validation errors
      warnings: CellError[];      // per-cell warnings (e.g., high amount)
    }

    export interface BulkExpenseParseResult {
      rows: BulkExpenseRow[];
      totalParsed: number;
      validCount: number;
      warningCount: number;
      errorCount: number;
    }

    **Step 2: Add parseAndValidateBulkExpenseCsv function**

    New CSV column headers (per D-01): `date,amount,description,category,vendor,payment_method,owner,receipt_url,asset_category,asset_name`

    ```typescript
    export function parseAndValidateBulkExpenseCsv(
      csvText: string,
      accounts: AccountRef[],
      users: UserRef[],
      defaultTrusted: boolean
    ): BulkExpenseParseResult
    ```

    Implementation:
    1. Parse with Papa Parse: `Papa.parse(csvText, { header: true, skipEmptyLines: true })`
    2. Build lookup maps:
       - `accountNameMap = new Map<string, AccountRef>()` -- key is `account.name.toLowerCase()`, value is AccountRef
       - `userNameMap = new Map<string, UserRef>()` -- key is `user.name.toLowerCase()`, value is UserRef
       - Handle duplicate names: if duplicate found, overwrite (last wins) -- small user base makes this unlikely (Pitfall 3 from RESEARCH.md)
    3. For each data row, validate:
       - `date`: Parse with `strictWibDateStrToUtcMs(raw.date?.trim())`. If throws, add CellError `{ column: "date", message: "Invalid date format. Use YYYY-MM-DD" }`, set `date: null`
       - `amount`: `parseInt(raw.amount?.trim(), 10)`. Must be positive integer. Error: `"Amount must be a positive number"`
       - `description`: Required, non-empty after trim, max 500 chars. Error: `"Description is required"` or `"Description too long (max 500)"`
       - `category`: Required. Look up `accountNameMap.get(raw.category?.trim().toLowerCase())`. If not found: `{ column: "category", message: "Category '${raw.category}' not found in Chart of Accounts" }`, set `accountId: null`
       - `vendor`: Optional, max 200 chars. Warning if empty (not error).
       - `payment_method`: Required. Must be one of VALID_PAYMENT_METHODS. Error: `"Invalid payment method. Use: employee_paid, company_paid, or payment_request"`
       - `owner`: Required. Look up `userNameMap.get(raw.owner?.trim().toLowerCase())`. If not found: `{ column: "owner", message: "User '${raw.owner}' not found in system" }`, set `submitterId: null`
       - `receipt_url`: Optional. If non-empty, must start with `http://` or `https://`. Error: `"Receipt URL must be a valid URL"`
       - `asset_category`: Optional. If non-empty, must be in VALID_ASSET_CATEGORIES.
       - `asset_name`: Required when `asset_category` is present.
    4. Warning detection:
       - Amount > 10_000_000 (10M IDR): `{ column: "amount", message: "Unusually high amount" }`
    5. Count validCount (rows with 0 errors), warningCount (rows with warnings but no errors), errorCount (rows with >= 1 error)

    ```typescript
    /**
     * SearchableSelect - Popover-based filterable dropdown.
     * 
     * Used for category (account names) and owner (user names) column editing
     * in the bulk import editable preview table. Also reusable elsewhere.
     * 
     * Pattern: Popover + Input for search + scrollable filtered list.
     * No virtualization needed -- max ~54 accounts or ~10 users (RESEARCH.md A3).
     */
    ```

    Props interface:
    ```typescript
    interface SearchableSelectProps {
      items: Array<{ value: string; label: string; sublabel?: string }>;
      value: string | null;
      onSelect: (value: string, label: string) => void;
      placeholder?: string;
      searchPlaceholder?: string;
      triggerClassName?: string;
      disabled?: boolean;
    }
    ```

    Implementation:
    - Use `Popover`, `PopoverTrigger`, `PopoverContent` from `@/components/ui/popover`
    - Use `Input` from `@/components/ui/input` for the search field
    - Use `Button` with `variant="outline"` as trigger, showing selected label or placeholder
    - Internal state: `const [open, setOpen] = useState(false)` and `const [query, setQuery] = useState("")`
    - Filter: `items.filter(item => item.label.toLowerCase().includes(query.toLowerCase()))`
    - List rendering: scrollable div `max-h-48 overflow-y-auto`, each item is a `div` with `cursor-pointer hover:bg-accent p-2 text-sm rounded-sm`
    - On item click: call `onSelect(item.value, item.label)`, close popover, reset query
    - Clear query when popover opens
    - Accessibility: `role="combobox"` on trigger, `aria-expanded={open}`, `role="listbox"` on the list container, `role="option"` on each item
    - Auto-focus the search input when popover opens (use `useRef` + `useEffect`)
