# Plan 32.1: BOM COGS Resolver & Week Range Helper

## Goal
Add two pure-function helpers that the income statement query (Plan 32.2) depends on:
1. `buildProductCOGSMap` in `convex/lib/costCalculator.ts` — batches BOM preloading into per-product COGS map
2. `calculateWeekRange` in `convex/lib/periodRange.ts` — computes Monday-start week boundaries from a `weekStart` epoch ms

Both are pure functions (no Convex ctx), fully testable in isolation.

<task id="32.1.1">
<title>Add buildProductCOGSMap helper to costCalculator.ts</title>
<description>
Add a new exported function `buildProductCOGSMap` to `convex/lib/costCalculator.ts`, placed AFTER the existing `calculateMenuProductCOGS` function.

**Function signature:**

```typescript
/**
 * Build a per-product COGS map from BOM components and component types.
 * Preloads all BOM data into in-memory maps for O(1) lookups.
 *
 * Follows the getLifetimeTotalsInternal pattern: parallel table scans,
 * then single-pass aggregation into a lookup map.
 *
 * @param bomComponents - All rows from menuProductComponents table
 * @param componentTypes - All rows from componentTypes table
 * @returns Map from menuProductId string to { production, packaging, total } in IDR
 */
export function buildProductCOGSMap(
  bomComponents: Array<{
    menuProductId: string;
    componentTypeId: string;
    quantity: number;
  }>,
  componentTypes: Array<{
    _id: string;
    unitCostIdr: number;
    category: string;
  }>
): Map<string, { production: number; packaging: number; total: number }>
```

**Implementation steps:**

1. Build a `componentTypeMap: Map<string, { unitCostIdr: number; category: string }>` from the `componentTypes` array. Key = `_id` as string.

2. Iterate `bomComponents` in a single `for...of` pass:
   - Look up the component type from `componentTypeMap` using `comp.componentTypeId`
   - If not found, skip (defensive — should not happen with valid BOM data)
   - Compute `lineCost = ct.unitCostIdr * comp.quantity`
   - Get or create the product entry in the result map (key = `comp.menuProductId` as string)
   - Add `lineCost` to `production` if `ct.category === "production"`, otherwise to `packaging` (same logic as existing `calculateMenuProductCOGS`)
   - Update `total = production + packaging`

3. Return the completed map.

**Key constraints:**
- Pure function, NO Convex ctx dependency
- Single-pass aggregation (one `for...of` loop over bomComponents)
- Category logic matches existing `calculateMenuProductCOGS`: `"production"` vs everything else = packaging
- Use string keys for map (Convex IDs are typed strings but work as map keys via `as string` cast)

**Verification:**
- Function is exported from `convex/lib/costCalculator.ts`
- Given test data of 1 product with 1 BIG_BALL (unitCostIdr: 19231, category: "production") + 1 Small Box (unitCostIdr: 1500, category: "packaging") + 1 Sticker (unitCostIdr: 200, category: "packaging"), the map returns `{ production: 19231, packaging: 1700, total: 20931 }` for that product
- Function handles empty inputs (returns empty map)
- Function handles components referencing unknown componentTypeIds (skips them silently)
</description>
</task>

<task id="32.1.2">
<title>Add calculateWeekRange helper to periodRange.ts</title>
<description>
Add a new exported function `calculateWeekRange` to `convex/lib/periodRange.ts` that computes a full week range (current + previous) from a `weekStart` epoch ms value.

**Function signature:**

```typescript
/**
 * Calculate week range boundaries from a weekStart timestamp.
 * weekStart should be a Monday 00:00 WIB epoch ms.
 *
 * Returns both the current week range and the previous week range
 * for comparison calculations.
 *
 * @param weekStartMs - Epoch ms for Monday 00:00 WIB of the target week
 * @returns { currentStart, currentEnd, previousStart, previousEnd }
 *          All values are UTC epoch ms.
 */
export function calculateWeekRange(weekStartMs: number): {
  currentStart: number;
  currentEnd: number;
  previousStart: number;
  previousEnd: number;
}
```

**Implementation:**

```typescript
const WEEK_MS = 7 * 24 * 60 * 60 * 1000;

export function calculateWeekRange(weekStartMs: number) {
  return {
    currentStart: weekStartMs,
    currentEnd: weekStartMs + WEEK_MS,  // Exclusive end: next Monday 00:00 WIB
    previousStart: weekStartMs - WEEK_MS,
    previousEnd: weekStartMs,
  };
}
```

**Key constraints:**
- Pure function, no Convex ctx
- The `weekStartMs` is already a WIB Monday 00:00 timestamp in UTC epoch ms (frontend computes this, or the query validates it)
- `currentEnd` is EXCLUSIVE (Mon 00:00 of next week) — consistent with how `by_period` index range queries use `q.lt(field, end)`
- Previous week = exactly 7 days before current week start
**Verification:**
- Given `weekStartMs` = Monday 2026-02-23 00:00 WIB (= Sunday 2026-02-22 17:00 UTC):
  - `currentStart` = Sunday 2026-02-22 17:00 UTC
  - `currentEnd` = Sunday 2026-03-01 17:00 UTC (next Monday 00:00 WIB)
  - `previousStart` = Sunday 2026-02-15 17:00 UTC
  - `previousEnd` = Sunday 2026-02-22 17:00 UTC
- Function is exported from `convex/lib/periodRange.ts`

**Note:** Do NOT export `getWibComponents` or `wibMidnightToUtc` — they are private for a reason and Plan 32.2 does not need them (weekStart arrives as pre-computed epoch ms from the frontend).
</description>
</task>
