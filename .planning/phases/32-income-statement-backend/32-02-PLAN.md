# Plan 32-02: Weekly Income Statement Query

## Goal
Implement the `getWeeklyIncomeStatement` query in `convex/reports/incomeStatement.ts` that computes a complete weekly income statement: per-channel gross revenue, revenue deductions (discounts, commissions, ad/promo burn, consignment rev share), full BOM COGS (production + packaging), gross profit, confidence classification, and gap analysis — all in a single query call. Also fetches the previous week for comparison deltas.

This is the core backend deliverable for Phase 32. It consumes the `buildProductCOGSMap` and `calculateWeekRange` helpers from Plan 32.1.

### Step 2: Parallel data fetching (all I/O upfront)
**Architecture principle:** Fetch ALL data upfront in the handler, then pass to pure computation functions. No `ctx.db` calls inside helper functions.

```typescript
// Phase 1: Parallel fetch of all base data
const [
  currentRevenue,
  previousRevenue,
  currentConsignments,
  previousConsignments,
  bomComponents,
  allComponentTypes,
] = await Promise.all([
  // externalRevenue for current week (by_period index)
  ctx.db.query("externalRevenue")
    .withIndex("by_period", q => q.gte("periodStart", range.currentStart))
    .filter(q => q.lt(q.field("periodStart"), range.currentEnd))
    .collect(),
  // externalRevenue for previous week (by_period index)
  ctx.db.query("externalRevenue")
    .withIndex("by_period", q => q.gte("periodStart", range.previousStart))
    .filter(q => q.lt(q.field("periodStart"), range.previousEnd))
    .collect(),
  // consignmentSettlements for current week (by_period index — NOT full scan)
  ctx.db.query("consignmentSettlements")
    .withIndex("by_period", q => q.gte("periodStart", range.currentStart))
    .filter(q => q.lt(q.field("periodStart"), range.currentEnd))
    .collect(),
  // consignmentSettlements for previous week (by_period index)
  ctx.db.query("consignmentSettlements")
    .withIndex("by_period", q => q.gte("periodStart", range.previousStart))
    .filter(q => q.lt(q.field("periodStart"), range.previousEnd))
    .collect(),
  // BOM preload (follows getLifetimeTotalsInternal pattern)
  ctx.db.query("menuProductComponents").collect(),
  ctx.db.query("componentTypes").collect(),
]);

// Phase 2: Fetch revenue items for both periods (needs revenue IDs from Phase 1)
const allRevenueIds = [
  ...currentRevenue.map(r => r._id),
  ...previousRevenue.map(r => r._id),
];
const allRevenueItems = await Promise.all(
  allRevenueIds.map(id =>
    ctx.db.query("externalRevenueItems")
      .withIndex("by_revenue", q => q.eq("revenueId", id))
      .collect()
  )
);
// Build revenueId -> items map
const revenueItemsMap = new Map<string, Doc<"externalRevenueItems">[]>();
for (let i = 0; i < allRevenueIds.length; i++) {
  revenueItemsMap.set(allRevenueIds[i] as string, allRevenueItems[i]);
}

// Phase 3: Fetch internal order data for discount correction (both weeks)
const [currentOrderDataMap, previousOrderDataMap] = await Promise.all([
  fetchInternalOrderDataMap(ctx, currentRevenue),
  fetchInternalOrderDataMap(ctx, previousRevenue),
]);
```

**Inside `aggregateWeek`:**

#### 4a: Per-channel revenue aggregation
Group revenue records by source. For each channel:

- **Internal channel:**
  - Gross = sum of `order.totalAmount` (pre-discount) from orderDataMap. Fallback to `rec.revenueGross` if order deleted.
  - Discount = `totalAmount - (finalTotal - deliveryFee)` per order (discount is on product value only, delivery fee excluded)
  - Delivery fees tracked but NOT included in P&L (pass-through, per CONTEXT.md)
  - Net = gross - discounts (delivery fee excluded)
  - Commission = 0 (no platform fees)
  - Confidence = `"exact"`

- **Platform channels (gobiz, shopee, tiktok, k3mart, grabfood, bigseller):**
  - Gross = sum of `(rec.revenueGross ?? 0)` — **IMPORTANT: `revenueGross` is `v.optional(v.number())`, MUST use `?? 0`**
  - Commission = sum of `(rec.commission ?? 0)` — also optional
  - Ad burn = sum of `(rec.adBurn ?? 0)` — also optional (gobiz only typically)
  - Promo burn = sum of `(rec.promoBurn ?? 0)` — also optional (gobiz only typically)
  - Net = gross - commission - adBurn - promoBurn
  - Discount = 0 (platform handles discounts before revenue)
  - **All optional numeric fields from `externalRevenue` MUST use `?? 0`** to prevent NaN propagation
  - Confidence:
    - `"exact"` for gobiz, shopee, tiktok (API-synced)
    - `"inferred"` for k3mart (stock delta)
    - `"exact"` for grabfood (when data exists)

- **Consignment channel:**
  - Gross = sum of `consignments.totalRevenue`
  - Rev share deduction = sum of `consignments.revShareAmount`
  - Net = gross - revShareAmount (= frolliePayment)
  - Commission = 0
  - Discount = 0
  - Confidence = `"exact"` (manual entry)

#### 4b: Per-channel COGS resolution
For each channel, iterate over the `externalRevenueItems` linked to that channel's revenue records:

```typescript
for (const rev of channelRevenue) {
  const items = itemsMap.get(rev._id as string) ?? [];
  for (const item of items) {
    const productCogs = item.linkedMenuProductId
      ? cogsMap.get(item.linkedMenuProductId as string) ?? null
      : null;

    const itemCogs = productCogs
      ? { production: productCogs.production * item.quantity, packaging: productCogs.packaging * item.quantity, total: productCogs.total * item.quantity }
      : { production: 0, packaging: 0, total: 0 };

    const itemConfidence: "calculated" | "missing" = productCogs ? "calculated" : "missing";

    // Accumulate per-channel COGS
    channelCogs.production += itemCogs.production;
    channelCogs.packaging += itemCogs.packaging;
    channelCogs.total += itemCogs.total;
```

#### 4e: Compute totals
```typescript
const totalGross = channels.reduce((sum, ch) => sum + ch.gross, 0);
const totalDiscounts = channels.reduce((sum, ch) => sum + ch.discount, 0);
const totalCommission = channels.reduce((sum, ch) => sum + ch.commission, 0);
const totalAdBurn = channels.reduce((sum, ch) => sum + ch.adBurn, 0);
const totalPromoBurn = channels.reduce((sum, ch) => sum + ch.promoBurn, 0);
const totalRevShare = channels.reduce((sum, ch) => sum + ch.revShare, 0);
const totalDeductions = totalDiscounts + totalCommission + totalAdBurn + totalPromoBurn + totalRevShare;
const netRevenue = totalGross - totalDeductions;
const totalProductionCogs = channels.reduce((sum, ch) => sum + ch.cogs.production, 0);
const totalPackagingCogs = channels.reduce((sum, ch) => sum + ch.cogs.packaging, 0);
const totalCogs = totalProductionCogs + totalPackagingCogs;
const grossProfit = netRevenue - totalCogs;
const grossMarginPercent = netRevenue !== 0 ? (grossProfit / netRevenue) * 100 : null;
```

`grossMarginPercent = null` when `netRevenue === 0` (displays as "N/A" in UI, not NaN/Infinity).

### Step 6: Compute deltas

Helper function for delta calculation:

```typescript
function computeDelta(current: number, previous: number): { amount: number; percent: number | null } {
  const amount = current - previous;
  const percent = previous !== 0 ? ((current - previous) / previous) * 100 : null;
  return { amount, percent };
}
```

Apply to: grossRevenue, netRevenue, totalCogs, grossProfit, grossMarginPercent (as percentage point difference), and per-channel gross/net.

**Key constraints from `.planning/phases/32-income-statement-backend/32-CONTEXT.md` (locked decisions — NON-NEGOTIABLE):**
1. Delivery fees EXCLUDED from P&L — pass-through, not Frollie revenue
2. Gross revenue = product value only (totalAmount minus delivery portion for internal; revenueGross for platforms already excludes delivery)
3. Customer discount = `totalAmount - (finalTotal - deliveryFee)`
4. Consignment: show `totalRevenue` in gross, `revShareAmount` as deduction line
5. ALL consignment settlements (pending + paid) where `periodStart` falls in week
6. Seller shipping fees NOT synced yet — omit from deductions
7. Voucher discounts already reflected in `finalTotal` — no separate treatment
8. Unmapped items: revenue counted, COGS = 0, confidence = "missing"
9. Week boundaries: Monday 00:00 WIB -> Sunday 23:59 WIB (exclusive end = next Monday 00:00 WIB)
10. Returns per-product COGS breakdown within each channel for Phase 33 drill-down

**Edge cases to handle:**
- Empty week: all values = 0, no crash, empty channels array
- Zero net revenue: `grossMarginPercent = null` (not NaN/Infinity)
- Negative net revenue: valid, display as negative
- Returns: `transactionType` field on `externalRevenue` — if `"return"`, the `revenueGross` is already negative from sync. No special handling needed (returns reduce gross revenue naturally).
- Deleted orders: fallback to `rec.revenueGross` for internal records (existing pattern)

**Confidence assignment rules:**
- Revenue confidence per channel:
  - `"exact"` for internal, gobiz, shopee, tiktok, grabfood (direct data)
  - `"inferred"` for k3mart (stock delta estimation)
  - `"exact"` for consignment (manual entry)
- COGS confidence per product:
  - `"calculated"` when BOM-resolved (derived from ingredient costs)
  - `"missing"` when product has no `linkedMenuProductId`
- Overall confidence per channel = lowest confidence among its line items
