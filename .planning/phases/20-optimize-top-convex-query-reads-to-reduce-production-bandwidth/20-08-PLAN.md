Prune `getKitchenStats` intermediate data to reduce per-call payload from ~35 KB.

Purpose: `getKitchenStats` consumes 25 MB at 742 calls. The subscription MUST stay reactive (kitchen needs live updates). The optimization is purely payload reduction. The query currently fetches full `Doc<"orderItemProduction">` objects into maps but only uses numeric fields (`unitsRemaining`, `unitsCompleted`, `productionUnitCode`, `productionUnitTypeId`, `isCancelled`). **Optimization: Skip item+production lookups for Draft and AwaitingPayment orders.**

The order status flow (from CLAUDE.md) is: Draft -> AwaitingPayment -> Confirmed -> InProduction -> ... Production records (`orderItemProduction`) are created at confirmation time, NOT at draft or awaiting-payment time. Therefore Draft and AwaitingPayment orders **never** have `orderItemProduction` records. Fetching their items and production data is pure waste.

Currently the query fetches 6 separate status groups and does item+production lookups for ALL of them. Split into two groups:

1. **Count-only group** (Draft, AwaitingPayment) — fetch orders for `ordersPending` count, skip item/production lookups
2. **Production group** (PaymentReceived, BeingPrepared, Complete, AwaitingDelivery) — fetch orders AND their items+production

```typescript
// Group 1: Count-only (no production records exist for these statuses)
const [draftOrders, awaitingPaymentOrders] = await Promise.all([
  ctx.db.query("orders").withIndex("by_status", (q) => q.eq("status", "Draft")).collect(),
  ctx.db.query("orders").withIndex("by_status", (q) => q.eq("status", "AwaitingPayment")).collect(),
]);

// Group 2: Orders with production records
const [paymentReceivedOrders, beingPreparedOrders] = await Promise.all([
  ctx.db.query("orders").withIndex("by_status", (q) => q.eq("status", "PaymentReceived")).collect(),
  ctx.db.query("orders").withIndex("by_status", (q) => q.eq("status", "BeingPrepared")).collect(),
]);
const productionOrders = [...paymentReceivedOrders, ...beingPreparedOrders];

// Pending count includes all 4 statuses
const pendingOrders = [...draftOrders, ...awaitingPaymentOrders, ...productionOrders];
```

Then only fetch items/production for `productionOrders` and completed-today orders (not Draft/AwaitingPayment):

```typescript
// Only fetch items for orders that actually have production records
const relevantOrders = [...productionOrders, ...completedTodayOrders];
const relevantOrderIds = [...new Set(relevantOrders.map((o) => o._id))];
```

This eliminates all DB reads for Draft/AwaitingPayment order items and production records. Those orders still contribute to the `ordersPending` count but skip the expensive nested lookups.
