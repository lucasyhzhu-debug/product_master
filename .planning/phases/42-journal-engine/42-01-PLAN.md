<objective>
Create the double-entry journal engine: a single `createJournalEntryWithLines` helper that enforces balance validation, entryDate denormalization, and sequential JE-MMDD-NNN number generation, plus a `createReversalEntry` helper for void workflows.

Purpose: This is the accounting integrity layer. Every downstream phase (44-47) that creates journal entries MUST go through this single helper. No direct `ctx.db.insert` on journalEntries or journalEntryLines is allowed outside this file. The helper enforces double-entry integrity (debits = credits), immutability (no update mutations), and correct reversal dating (same period as original).
Output: `convex/lib/journalEngine.ts` with 2 async functions + 2 pure validation functions (lines, void pairing) + 3 convenience builders (debit, credit, reversed) + type exports, and 27 unit tests.
</objective>

  debitAmount: number;
  creditAmount: number;
  description?: string;
}

/** Valid source types for journal entries — matches schema sourceType union exactly */
export type JournalSourceType =
  | "expense_approval"
  | "expense_void"
  | "reimbursement"
  | "reimbursement_void"
  | "payroll"
  | "payroll_void"
  | "manual";  // No mutation creates manual entries in Phase 42; included to match schema

export interface CreateJournalEntryParams {
  date: number;              // Business date (accounting period), NOT Date.now()
  description: string;
  sourceType: JournalSourceType;
  sourceId?: string;         // Id of source record (expense, batch, payroll entry)
  createdBy: Id<"users">;
  lines: JournalLine[];     // Min 2 lines, debits must equal credits
}

2. **`validateJournalLines(lines: JournalLine[]): void`** (exported pure function):
   - Check `lines.length < 2` -- throw "Journal entry requires at least 2 lines"
   - Loop through lines (include line index `i` for error messages):
     - Check `debitAmount < 0 || creditAmount < 0` -- throw `Journal entry line ${i + 1}: amounts must be non-negative`
       NOTE: Negative check MUST come before integer check. A fractional negative like -50000.5 should throw "non-negative", not "whole numbers".
     - Check `!Number.isInteger(debitAmount) || !Number.isInteger(creditAmount)` -- throw `Journal entry line ${i + 1}: amounts must be whole numbers (IDR)`
     - Check `debitAmount > 0 && creditAmount > 0` -- throw `Journal entry line ${i + 1}: must have either debit or credit, not both`
     - Check `debitAmount === 0 && creditAmount === 0` -- throw `Journal entry line ${i + 1}: must have a non-zero debit or credit amount`
     - Accumulate totalDebits and totalCredits
   - Check `totalDebits !== totalCredits` -- throw `Journal entry imbalanced: debits (${totalDebits}) != credits (${totalCredits})`
   - NOTE: Integer enforcement guarantees exact equality comparison is safe (no IEEE 754 precision issues). IDR is always whole numbers.

3. **`buildDebitLine(accountId: Id<"accounts">, amount: number, description?: string): JournalLine`** (exported pure function):
   - Returns `{ accountId, debitAmount: amount, creditAmount: 0, description }`

4. **`buildCreditLine(accountId: Id<"accounts">, amount: number, description?: string): JournalLine`** (exported pure function):
   - Returns `{ accountId, debitAmount: 0, creditAmount: amount, description }`

5. **`buildReversedLines(lines: JournalLine[]): JournalLine[]`** (exported pure function -- used by createReversalEntry, testable independently):
   - Returns `lines.map(line => ({ accountId: line.accountId, debitAmount: line.creditAmount, creditAmount: line.debitAmount, description: line.description }))`

6. **`validateVoidPairing(originalSourceType: string, voidSourceType: string): void`** (exported pure function -- used by createReversalEntry, testable independently):
   - Guard non-reversible source types FIRST (explicit intent, not implicit undefined lookup):
```typescript
const NON_REVERSIBLE_TYPES = ["manual", "expense_void", "reimbursement_void", "payroll_void"];
if (NON_REVERSIBLE_TYPES.includes(originalSourceType)) {
  throw new Error(`Cannot reverse a ${originalSourceType} entry`);
}
```
   - Then validate the pairing:
```typescript
const VALID_VOID_PAIRS: Record<string, string> = {
  expense_approval: "expense_void",
  reimbursement: "reimbursement_void",
  payroll: "payroll_void",
};
const expectedVoidType = VALID_VOID_PAIRS[originalSourceType];
if (expectedVoidType !== voidSourceType) {
  throw new Error(`Cannot create ${voidSourceType} reversal for ${originalSourceType} entry`);
}
```
   - NOTE: The explicit non-reversible guard prevents accidental double-voids and documents that manual entries require manual correction (create opposite entry directly). Without this guard, the pairing map would silently reject via undefined !== voidSourceType, which works but is fragile and undocumented.

**`createJournalEntryWithLines(ctx: MutationCtx, params: CreateJournalEntryParams): Promise<Id<"journalEntries">>`:**

1. Call `validateJournalLines(params.lines)` -- throws before any DB writes if invalid
2. Generate entry number: `const entryNumber = await getNextNumber(ctx, "JE")`
3. Insert journal entry header:
```typescript
const entryId = await ctx.db.insert("journalEntries", {
  entryNumber,
  date: params.date,
  description: params.description,
  sourceType: params.sourceType,
  sourceId: params.sourceId,
  isReversed: false,
  createdBy: params.createdBy,
  createdAt: Date.now(),
});
```
4. Insert lines with denormalized entryDate:
```typescript
for (const line of params.lines) {
  await ctx.db.insert("journalEntryLines", {
    journalEntryId: entryId,
    accountId: line.accountId,
    entryDate: params.date,  // Denormalized from parent (JE-04)
    debitAmount: line.debitAmount,
    creditAmount: line.creditAmount,
    description: line.description,
  });
}
```
5. Return `entryId`

**`createReversalEntry(ctx: MutationCtx, originalEntryId: Id<"journalEntries">, sourceType: "expense_void" | "reimbursement_void" | "payroll_void", createdBy: Id<"users">): Promise<Id<"journalEntries">>`:**

1. Fetch original: `const original = await ctx.db.get(originalEntryId)`
2. Guard: if `!original` throw "Original journal entry not found"
3. Guard: if `original.isReversed` throw "Journal entry has already been reversed"
4. Guard: validate sourceType pairing — delegates to the pure function:
```typescript
validateVoidPairing(original.sourceType, sourceType);
```
   This explicitly rejects: manual entries, void-of-void (double-void), and mismatched pairings. See validateVoidPairing in Task 1 for the full logic.

5. Fetch original lines:
```typescript
const originalLines = await ctx.db
  .query("journalEntryLines")
  .withIndex("by_journal_entry", (q) => q.eq("journalEntryId", originalEntryId))
  .collect();
```
6. Guard: if `originalLines.length === 0` throw "Original journal entry has no lines (data integrity error)"
7. Build reversed lines: extract only `JournalLine` fields from the DB docs before passing to `buildReversedLines`:
```typescript
const reversedLines = buildReversedLines(
  originalLines.map((line) => ({
    accountId: line.accountId,
    debitAmount: line.debitAmount,
    creditAmount: line.creditAmount,
    description: line.description,
  }))
);
```
8. Create reversal entry using `createJournalEntryWithLines` -- CRITICAL: use `original.date` as the date, NOT `Date.now()` (JE-03). Pass `sourceId: original.sourceId` to maintain `by_source` index queryability:
```typescript
const reversalId = await createJournalEntryWithLines(ctx, {
  date: original.date,  // Same accounting period as original (JE-03), NOT Date.now()
  description: `Reversal of ${original.entryNumber}: ${original.description}`,
  sourceType,
  sourceId: original.sourceId,
  createdBy,
  lines: reversedLines,
});
```
9. Mark original as reversed:
```typescript
await ctx.db.patch(originalEntryId, {
  isReversed: true,
  reversedByEntryId: reversalId,
});
```
   NOTE: This is the ONLY `ctx.db.patch` on journalEntries allowed in the entire codebase (JE-02). It only sets isReversed/reversedByEntryId fields. No data field mutations.
10. Return `reversalId` (the new reversal entry ID, not the original)
