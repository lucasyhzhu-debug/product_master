## Phase Boundary

**Behavioral cutover phase.** Flip every channel's `channelDeductionEnabled` flag in a staged sequence, backfill historical deductions with timestamp-preserving idempotency, migrate `gofood_sale` → `channel_sale + source` on `productInventoryTransactions`, retire the 4 legacy deduct paths (`processGofoodSales` wrapper + calls, order-fulfillment direct-GoJek deduct path, K3Mart custom retroactive mapping cascade branches if redundant, per-source transaction literals), ship the consignment per-product breakdown UI, and write `docs/CHANNEL_INTEGRATION.md` onboarding runbook.

**In scope:**
1. Six historical-backfill admin buttons on `/admin/unlinked-products-backfill` (Shopee, TikTok, BigSeller, K3Mart, GrabFood, GoFood) — each idempotent via `externalRevenueItems.inventoryDeductedAt`.
2. Staged flag flips per channel (Shopee → TikTok → BigSeller → K3Mart → GoFood) with 24–48h soak + stock-outcome verification between each.
3. `gofood_sale` → `channel_sale + source: "gofood"` literal migration (strip-data-before-drop, per Convex rule).
4. Retirement of `processGofoodSales` silent-try/catch wrapper (gobiz adapter lines 747–753, 1004–1009).
5. Retirement of order-fulfillment direct-GoJek deduct path.
6. Schema cleanup — drop deprecated transaction literals after GoFood stabilizes + 72h soak.
7. Consignment per-product breakdown UI (parent D-09, promoted to mandatory scope per ROADMAP decomp note).
8. `docs/CHANNEL_INTEGRATION.md` runbook — channel onboarding recipe (folded 999.8).
9. Post-74.5.1 reconciliation items surfaced by verification: `channelAudit.test.ts` 7 failures (TDD shape drift), BigSeller normalize test platform literal drift, react-refresh lint warning on `AuditIssueTypeBadge`, `useMemo` deps warnings.

**Out of scope:**
- Pricing consolidation (999.6), SKU resolver auto-match service (999.7) — remain deferred.
- Reservation/fulfillment lifecycle changes.
- `journalEngine.ts` refactor.
- Dropping `externalOutlets.linkedStorageLocationId` (scheduled for 999.6).

**Cutover mechanics:**

- **D74.5.2-L4 — Backfill runs BEFORE flag flip for each channel.** For every channel except GoFood, the sequence per channel is: (a) backfill historical `externalRevenueItems` with `inventoryDeductedAt IS NULL`, (b) run per-channel audit, (c) resolve/dismiss audit issues, (d) flip flag, (e) soak 24–48h. This ensures all historical sales have deducted inventory before the go-forward flag flip — otherwise the first live sale would be the ONLY deducted sale for that channel, creating an inventory discontinuity.
  - **Why:** If flag flips first, live deductions start but historical gaps remain. Backfill-first establishes the baseline; flip goes forward cleanly.
  - **How to apply:** Runbook step order documented in `docs/CHANNEL_INTEGRATION.md`; admin UI progress cards reflect this sequence (backfill complete indicator gates flag-flip affordance — informational, not enforced; admin may still override).

- **D74.5.2-L5 — GoFood cutover is atomic (flip + retire in same merge).** Per parent D-14, `processGofoodSales` retirement happens atomically when the GoFood flag flips ON. There is no soak period with BOTH paths active — the code deletion + flag flip ship in the same deployment to avoid double-deduction window.
  - **Why:** Both paths running concurrently would double-deduct inventory. Atomic flip-and-retire is the only safe sequence.
  - **How to apply:** One plan covers the gofood_sale literal migration + flag flip + processGofoodSales removal + order-fulfillment direct-GoJek path removal.

- **D74.5.2-L6 — Transaction literal migration is forward-only.** The `productInventoryTransactions` type migration writes `channel_sale + source: "gofood"` for rows currently `gofood_sale`; the original `gofood_sale` literal is dropped from schema ONLY after the migration completes and GoFood soaks 72h. No rollback path from `channel_sale → gofood_sale`.
  - **Why:** Convex strip-before-drop rule (CLAUDE.md: "When removing a field, FIRST strip field data from all docs, THEN remove from schema").
  - **How to apply:** Two-step plan — (1) migration action that rewrites rows in 500-row chunks; (2) post-soak schema cleanup that drops the literal.

**Consignment per-product breakdown UI (D-09 promotion):**

- **D74.5.2-L7 — Consignment per-product breakdown UI is mandatory scope, not stretch.** ROADMAP elevates this from parent D-09's "stretch" status to required for 74.5.2. UI surfaces on the existing consignment reporting page.
  - **Why:** Item-level rows now flow through `saveRevenueItems`; not exposing this data wastes the 74.5.1 investment and leaves consignment operators blind to the breakdown they now have in the DB.
  - **How to apply:** Extend the existing consignment reporting UI with "products sold" breakdown table + "# transactions" per settlement. No new page.

**Schema cleanup ordering:**

- **D74.5.2-L8 — `channelDeductionEnabled` flag removal is a FOLLOW-UP, not part of 74.5.2.** Per parent D-14, the flag map removal happens AFTER 72h GoFood soak. Since 74.5.2 executes the flips, but the 72h soak is operational time, schema-drop the flag field in a decimal follow-up phase (74.5.3 or fold into 75). For 74.5.2: ship all code as if flags are still required; document that flag removal is tracked separately.
  - **Why:** Attempting to drop the flag field within the same phase as the flips violates strip-before-drop (cannot drop a field while code still reads it).
  - **How to apply:** 74.5.2 ships the cutover + retirement; schema drop of `channelDeductionEnabled` is filed as a 74.5.3 follow-up or folded into an appropriate post-cutover phase. Runbook documents the deferral.

**Runbook + onboarding doc:**

- **D74.5.2-L9 — `docs/CHANNEL_INTEGRATION.md` is required, not stretch.** Per ROADMAP decomp (folded 999.8). Must contain: (a) onboarding recipe for a NEW channel (step-by-step: implement `ChannelAdapter`, add to `externalSource` union, add flag key, add taxonomy entry, add routing seed, write integration test), (b) per-channel runbook for the 74.5.2 cutover sequence, (c) audit issue triage guide, (d) backfill operational guide, (e) rollback procedure (disable flag + document gap).

- **D74.5.2-L10 — Rollback procedure documented but not tooled.** The runbook includes a "how to roll back a channel" section: flip flag OFF → document the timestamp range where sales bypassed deduction → file a backfill task. No admin-UI rollback button (operational flip via `setChannelDeductionFlag` mutation is sufficient; tooling more UI here is over-engineering).

**E2E smoke from 74.5.1:**
