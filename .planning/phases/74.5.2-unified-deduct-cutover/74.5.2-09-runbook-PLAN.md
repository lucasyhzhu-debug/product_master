| Issue type | Meaning | Resolution |
|-----------|---------|------------|

| `malformed_item` | Item row has invalid data (zero quantity, negative price) | Inspect via dashboard; likely adapter bug — file a task |

**Dismissing an issue:** mark `resolvedAt = Date.now()` on the `channelAuditIssues` row via the workbench UI. Dismissed issues are excluded from blocking-count queries (used by backfill preflight per-source gate — D-17).

## Backfill operations

**Page:** `/admin/unlinked-products-backfill` → "Channel Deduction Backfill" section.

**Idempotency guarantee (D-19):** Each `externalRevenueItems.inventoryDeductedAt` is set-once. Re-clicking Backfill after completion is a no-op — the index query returns zero rows once all items are deducted.

**What backfill does:**
1. Queries `externalRevenueItems` with `source = X AND inventoryDeductedAt IS NULL` via the `by_source_deductedAt` index.
2. Skips rows with `linkedMenuProductId = undefined` (unmapped SKUs — admin must map first).
3. Invokes `processChannelSaleInternal` with `occurredAt = revenue.transactionDate` (preserves historical timestamp as ledger `createdAt`, NOT `Date.now()`).
4. Patches `inventoryDeductedAt = Date.now()` ONLY when deduction succeeds.
5. Returns `{ itemsProcessed, deducted, skipped }` per page.

**Per-source audit gate (D-17, informational):** The UI shows a yellow warning if blocking audit issues exist for the source, but the button stays clickable. Admin decides whether to backfill before resolving.

**Flag-independence (D74.5.2-L13):** Backfill does NOT read `channelDeductionEnabled`. Admin can run backfill with flag OFF, then flip ON afterward. This is intentional — backfill is a data-repair operation, separate from live-sync gating.

**Cancellation:** Navigating away during backfill aborts the loop cleanly (mountedRef unmount guard). Partially-deducted batch commits remain; re-click Backfill to resume.

## Rollback procedures

(Documents the 4 cases from RESEARCH §Rollback Procedure. Prose-only — no admin-UI rollback button per D74.5.2-L10.)

### Case A: Channel post-flip is double-deducting

**Symptom:** `productInventoryTransactions` row count for source X doubled in post-flip hours.

**Cause:** Both legacy path AND new path running (only possible for GoFood if atomicity was violated).

**Steps:**
1. Flip `channelDeductionEnabled.{source}` OFF via `/admin/product-inventory-settings`.
2. Identify duplicate window: first `createdAt` post-flip through current `Date.now()`.
3. Run `runFullAudit` via admin scheduler → surfaces `duplicate_transaction` issues.
4. Resolve each duplicate by deleting one paired row via Convex dashboard.
5. Re-flip flag ON after legacy path confirmed removed.

### Case B: Channel post-flip is under-deducting

**Symptom:** Recent `externalRevenueItems` rows have `inventoryDeductedAt = undefined`.

**Cause:** Backfill hit errors partway (rare — idempotent reruns recover).

**Steps:**
1. Flag stays ON.
2. Re-run the per-source Backfill button (idempotent — picks up where it left off).
3. Verify zero items with `linkedMenuProductId != null && inventoryDeductedAt = null AND source = X`.

### Case C: Wrong storage location resolved

**Symptom:** `productInventoryTransactions.locationId` is unexpected.

**Cause:** `channelRouting` rule misconfigured (routing precedence rule at tier 1-5 picked wrong location).

**Steps:**
1. Fix rule via `/admin/channel-routing`.
2. Identify affected rows by `productInventoryTransactions.locationId == wrong_location AND createdAt > rule_creation_time`.
3. Manually re-post corrected ledger entries (low expected volume if admin catches in soak).

### Case D: Total rollback (unrecoverable)

**Symptom:** Pre-GoFood-atomic-flip catastrophe — inconsistent ledger state, can't safely continue.

**Steps:**
1. Flip ALL flags OFF via `/admin/product-inventory-settings`.
2. Document the gap window timestamps.
3. File a plan to re-run all historical deductions against cleaned `externalRevenueItems`.
4. For GoFood: `processGofoodSales` is deleted (retired in Plan 08). Rollback requires a git revert of the retirement commit. Revert SHA pattern: `git revert -m 1 {retirement_merge_sha}`.

## Troubleshooting FAQ

**Q: Backfill button shows 0 pending items but I know there are unmapped SKUs.**
A: Backfill query filters `linkedMenuProductId != undefined`. Unmapped items appear in audit, not backfill. Map via `/admin/unlinked-products` first.

**Q: Flag flip immediately spikes `channelAuditIssues` count.**
A: Expected. Inline detection runs on every new sale via `saveRevenueItems`. Resolve via audit workbench as they surface.

**Q: I'm writing `source: "gofood"` in a new file — why fails type-check?**
A: Pitfall 1 landmine. GoFood surface uses `source: "gobiz"`. The `externalSource` union does NOT include `"gofood"`. Always use `"gobiz"` for GoFood.

**Q: Migration action errored with "Mutation time limit exceeded".**
A: Chunk size exceeded 2s limit. Per `convex/migrations/gofoodSaleToChannelSale.ts`, `PAGE_SIZE=500`. If your environment has slower mutations, lower to 250. Re-run (self-healing via `by_type` index).

**Q: Consignment settlement shows empty breakdown.**
A: Expected for pre-74.5.1 settlements. No items were emitted before the `saveRevenueItems` refactor. New settlements created via Plan 07's extended form WILL populate.
