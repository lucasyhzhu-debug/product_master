## Backfill Query Shape + Index Coverage

### Required query

For each source, backfill needs:
```typescript
ctx.db.query("externalRevenueItems")
  .withIndex(???, q => q.eq("source", source).eq("inventoryDeductedAt", undefined))
  .filter(q => q.neq(q.field("linkedMenuProductId"), undefined))
  .take(200)
```

### Existing indexes on `externalRevenueItems`

From `convex/schema.ts:1188-1194`:
```typescript
.index("by_revenue", ["revenueId"])
.index("by_source", ["source"])
.index("by_menu_product", ["linkedMenuProductId"])
.index("by_product_name", ["source", "productName"])
.index("by_source_external_item", ["source", "externalItemId"])  // Phase 79
```

**Missing:** compound index on `[source, inventoryDeductedAt]`. [VERIFIED: schema.ts:1188-1194]

### Options

**Option A — add index `by_source_deductedAt: ["source", "inventoryDeductedAt"]`** (recommended)
- Backfill query becomes: `.withIndex("by_source_deductedAt", q => q.eq("source", source).eq("inventoryDeductedAt", undefined)).filter(q => q.neq(q.field("linkedMenuProductId"), undefined)).take(200)`.
- `linkedMenuProductId` filter stays post-scan (bounded by 200 rows after index narrows).
- Pays index maintenance cost on every `externalRevenueItems` insert (5 indexes → 6).
- **One-line schema change; migration-free** (Convex builds index on deploy).

**Option B — post-scan filter via `by_source`**
- Query: `.withIndex("by_source", q => q.eq("source", source)).filter(...).take(200)`.
- Every pagination page scans ALL rows for that source even after most are deducted — O(N) forever.
- With ~10K+ Shopee rows already ingested pre-74.5.1, the filter-after approach would re-scan the same rows every backfill iteration → pathological.

**Recommendation:** Add Option A index. Cost is one line of schema + one index rebuild on deploy. Benefit compounds across the 6 backfill buttons.

### `linkedMenuProductId IS NOT NULL` filter

Rows with `linkedMenuProductId === undefined` represent unmapped SKUs. Backfill MUST skip these — `processChannelSaleInternal` returns `{deducted: false, skipReason: "unmapped_sku"}` for null menuProductId (`channelSale.ts:43`). The audit workbench surfaces these as `unmapped_sku` issues — admin should resolve (map) them BEFORE backfill, then re-run. Backfill skipping them is correct behavior, not a bug.

## Migration Action Chunking Pattern

### Mutation vs Action

Convex enforces a mutation time limit (~2 seconds for mutations, no hard limit for actions). The 500-row migration per D74.5.2-L6 must run as a **paginated internalAction** that invokes a chunked internalMutation.

```typescript
// Pattern (verified via Phase 80.2 Plan 02 — the paginated-WRITE mutation pattern)
export const migrateGofoodSaleToChannelSale = internalAction({
  args: {},
  handler: async (ctx) => {
    let cursor: string | null = null;
    let totalMigrated = 0;
    while (true) {
      const result = await ctx.runMutation(
        internal.migrations.gofoodSaleToChannelSale.migrateOnePage,
        { paginationOpts: { numItems: 500, cursor } },
      );
      totalMigrated += result.migrated;
      if (result.isDone) break;
      cursor = result.continueCursor;
    }
    return { totalMigrated };
  },
});

export const migrateOnePage = internalMutation({
  args: { paginationOpts: paginationOptsValidator },
  handler: async (ctx, args) => {
    const page = await ctx.db
      .query("productInventoryTransactions")
      .withIndex("by_type", q => q.eq("transactionType", "gofood_sale"))
      .paginate(args.paginationOpts);
    let migrated = 0;
    for (const tx of page.page) {
      await ctx.db.patch(tx._id, {
        transactionType: "channel_sale",
        source: "gobiz",  // CRITICAL: gobiz, not "gofood" — see §10.A
        externalRef: tx.gofoodOrderRef ?? `legacy-${tx._id}`,  // derive from legacy field
      });
      migrated++;
    }
    return { migrated, isDone: page.isDone, continueCursor: page.continueCursor };
  },
});
```

**500-row chunk safety:** 500 patches in one mutation is well under the 2s limit based on Phase 80.2 data (`migrateOnePageWrites` completed 500-row paginated writes in ~400ms). [VERIFIED: Phase 80.2 Plan 02 runtime metrics documented in its SUMMARY]. The pattern is proven; no time-limit exposure.

**Re-entrancy:** Must be idempotent. Re-running the migration after partial completion should skip already-migrated rows. The `by_type` index narrows to `transactionType: "gofood_sale"` only — already-migrated rows (now `channel_sale`) won't appear. Self-healing.

### Pagination threshold

**Recommendation:** Add pagination to `listAuditIssues` **as a low-priority optimization in the polish wave** (D74.5.2-L3), not as a blocker. The query returns early from index (`by_source_open` + `eq("resolvedAt", undefined)` → typically <1K open issues per source per tab), so pagination is marginal here. **If post-backfill the count exceeds 5000 open issues per source, add pagination reactively.**

## Common Pitfalls

### Pitfall 1: `source: "gofood"` vs `source: "gobiz"` migration landmine

**What goes wrong:** Migration writes `source: "gofood"` as suggested by the CONTEXT language.
**Why it happens:** CONTEXT D-03 says `gofood_sale → channel_sale + source: "gofood"`. The `externalSource` union in `convex/lib/externalSource.ts` does NOT include `"gofood"` — it uses `"gobiz"` (the integration literal). GoFood is a surface name for gobiz sync.
**How to avoid:** Migration writes `source: "gobiz"`. Verify `externalSource` union membership at migration write-time. [VERIFIED: schema.ts imports `externalSource` at line 1027]
**Warning signs:** Type-check fails on `source: "gofood"` literal; or migration produces unreadable rows that fail `externalSource` validator.

### Pitfall 2: Double-deduction during GoFood atomic flip

**What goes wrong:** Flag flips ON while `processGofoodSales` is still being invoked in the same sync cycle.
**Why it happens:** Atomicity means the code deletion + flag flip ship in the same PR merge. But deploys are not instantaneous — there's a window where the old code still runs.
**How to avoid:** Per D74.5.2-L5, the plan bundles (a) `saveRevenueItems` deduction branch gated on flag, (b) `processGofoodSales` removed, (c) gobiz adapter call sites removed, into ONE atomic deploy. During the deploy window (seconds), there is NO window where BOTH paths run — either old code (flag OFF, `processGofoodSales` runs, new path gated) OR new code (flag ON, `processGofoodSales` deleted, new path runs).
**Critical constraint:** the flag flip happens via code (default value change in the code that sets the flag OR the admin flips via UI AFTER deploy). If admin-flipped post-deploy, there IS a window where code is new but flag is still false — no deduction happens for GoFood at all during that window. Runbook should instruct the admin to flip IMMEDIATELY after deploy-complete confirmation.
**Warning signs:** `productInventoryTransactions` counts for GoFood doubled in any hour post-deploy; or zero for any hour post-deploy (under-deduction window).

### Pitfall 3: Backfill processes `linkedMenuProductId = null` rows incorrectly

**What goes wrong:** Backfill query returns items without `linkedMenuProductId`; `processChannelSaleInternal` returns `{deducted: false, skipReason: "unmapped_sku"}`; backfill loop interprets as success and patches `inventoryDeductedAt`.
**Why it happens:** `inventoryDeductedAt` should only be set when deduction ACTUALLY happened. If the row is `unmapped_sku`, we want to re-attempt after admin resolves the mapping, so `inventoryDeductedAt` must remain NULL.
**How to avoid:** Backfill query pre-filters `linkedMenuProductId IS NOT NULL` (D-16 literal quote). `processChannelSaleInternal`'s unmapped_sku branch shouldn't even be reachable from backfill. If it's reached (defensive check), DO NOT patch `inventoryDeductedAt`. Only patch on `result.deducted === true`.
**Warning signs:** Audit reports zero unmapped_sku issues but admin knows there are unmapped items; querying `externalRevenueItems WHERE inventoryDeductedAt IS NOT NULL AND linkedMenuProductId IS NULL` returns >0 rows.

### Pitfall 4: Audit gate leaks across channels

**What goes wrong:** Admin clicks "Backfill Shopee" while K3Mart has open `duplicate_transaction` audit issues; UI greys out all buttons.
**Why it happens:** Confusion about per-source vs global gate.
**How to avoid:** Per D-17 and parent D-17, gate is per-source. UI button for Shopee is enabled iff `channelAuditIssues WHERE source="shopee" AND resolvedAt IS NULL AND severity="block"` returns zero. K3Mart's state is irrelevant.
**Warning signs:** Shopee backfill button greyed out with K3Mart issues listed below. Planner MUST query `channelAuditIssues` with `.withIndex("by_source_open", ...)` for the exact source, NOT collect-all + filter.

### Pitfall 5: `collapseRevenuePeriod` drift on consignment item emit

**What goes wrong:** 74.5.1 consignment refactor preserves collapseRevenuePeriod on the parent revenue row, but child items get a different period semantic.
**Why it happens:** `saveRevenueItemsImpl` reads `revenue.transactionDate` for `buildEventFromRow.occurredAt` (channelSale.ts:155). Consignment rows have `transactionDate = periodEnd` (from `collapseRevenuePeriod`), so `occurredAt = periodEnd`. This is correct — the deduction should happen at the period-end boundary.
**How to avoid:** NO code change needed. Verified correct in 74.5.1 execution. 74.5.2 planner should not touch this.
**Warning signs:** Consignment ledger rows have `createdAt` equal to the admin's clock, not the settlement period boundary.

### Pitfall 6: Test suite module resolution bug hides regressions

**What goes wrong:** D74.5.2-L1 re-framed as shape-drift; planner writes a "change field names" plan that doesn't actually fix the failures.
**Why it happens:** 74.5.1 verification override language called it TDD drift. Actually it's a convex-test module-resolution bug on `t.action(internal.*)` calls.
**How to avoid:** Plan 01 begins with running the failing tests and reading the ACTUAL error (`Could not find module for: "productInventory/channelAudit"`), not the CONTEXT description. Fix the glob or the invocation pattern.

### Backfill mutation pattern (per-source, 200-item chunks per D-16)

```typescript
// convex/productInventory/backfill.ts (NEW)
import { internalAction, internalMutation } from "../_generated/server";
import { v } from "convex/values";
import { externalSource } from "../schema";
import { internal } from "../_generated/api";
import { buildEventFromRow, processChannelSaleInternal } from "./channelSale";

export const backfillChannelDeductions = internalAction({
  args: { source: externalSource },
  handler: async (ctx, args) => {
    let totalDeducted = 0;
    let totalSkipped = 0;
    let iterations = 0;
    const MAX_ITERATIONS = 500; // hard safety cap — 500 * 200 = 100K items max
    while (iterations++ < MAX_ITERATIONS) {
      const result = await ctx.runMutation(
        internal.productInventory.backfill.backfillOnePage,
        { source: args.source },
      );
      totalDeducted += result.deducted;
      totalSkipped += result.skipped;
      if (result.itemsProcessed === 0) break;
    }
    return { totalDeducted, totalSkipped, iterations };
  },
});

export const backfillOnePage = internalMutation({
  args: { source: externalSource },
  handler: async (ctx, args) => {
    // Requires new index `by_source_deductedAt` (see §3)
    const items = await ctx.db
      .query("externalRevenueItems")
      .withIndex("by_source_deductedAt", q =>
        q.eq("source", args.source).eq("inventoryDeductedAt", undefined))
      .take(200);

    let deducted = 0;
    let skipped = 0;
    for (const item of items) {
      if (!item.linkedMenuProductId) {
        skipped++;
        continue;
      }
      const revenue = await ctx.db.get(item.revenueId);
      if (!revenue) {
        skipped++;
        continue;
      }
      const event = buildEventFromRow(revenue, item);
      const result = await processChannelSaleInternal(ctx, event);
      if (result.deducted) {
        await ctx.db.patch(item._id, { inventoryDeductedAt: Date.now() });
        deducted++;
      } else {
        skipped++;
      }
    }
    return { itemsProcessed: items.length, deducted, skipped };
  },
});
```
