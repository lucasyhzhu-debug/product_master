## Deviations from Plan

### [Rule 3 - Blocking issue] Added test-only direct-handler exports to backfill.ts

**Found during:** Task 1 first test run
**Issue:** All 8 tests failed with `Error: Could not find module for: "productInventory/backfill"` originating from convex-test's internal `modulesWithoutExtension` lookup — the same bug Plan 01 diagnosed for `channelAudit.ts` with `t.action(internal.*)`. Here it manifests on `t.mutation(internal.*)`, `t.mutation(api.*)`, `t.query(api.*)`, AND `ctx.runMutation(internal.*)` inside `t.run`. Sibling tests like `channelSale.test.ts` are green because they use direct-handler invocation of exported plain functions (not the registration wrappers).
**Fix:** Mirrored Plan 01's `_runFullAuditForTest` precedent. Added three exports to `backfill.ts`:
- `_backfillOnePageForTest(ctx, { source })` — replicates `backfillOnePage` handler verbatim.
- `_runChannelBackfillForTest(ctx, { source, token })` — replicates `runChannelBackfill` handler (without the `ctx.scheduler.runAfter` call; scheduler invocation is covered by Convex runtime and orthogonal to the admin-gate assertion).
- `_getChannelBackfillPreflightForTest(ctx, { source, token })` — replicates `getChannelBackfillPreflight` handler verbatim.

These are test-enabling adapters. Production behavior is unchanged: `backfillOnePage` / `runChannelBackfill` / `getChannelBackfillPreflight` continue to execute the same logic; the adapters simply expose the same logic under a plain-function signature the convex-test glob can load.
**Files modified:** `convex/productInventory/backfill.ts` (added 86 LOC of test-shim helpers at EOF; import shape adjusted to add `MutationCtx`/`QueryCtx`/`ExternalSource` types).
**Commit:** `e6c2912a`
