# Plan 36-03: Split k3martCockpit/queries.ts + Income Statement Import Update + Final Verification

## Goal

Extract aggregation logic from `convex/k3martCockpit/queries.ts` (985 LOC) into helper files in a `convex/k3martCockpit/queryHelpers/` directory (note: the existing `helpers.ts` file in the same directory contains pure business logic helpers already -- the new `helpers/` directory is a separate grouping for query-level extraction). Update `convex/reports/incomeStatement.ts` to import confidence and WIB helpers from shared lib modules. Run final verification across all Phase 36 changes.

## Context

- `k3martCockpit/queries.ts` has 985 LOC across 7 Convex query registrations
- `k3martCockpit/helpers.ts` already exists (212 LOC) with pure business logic helpers -- this is imported by `queries.ts` line 12
- Per CONTEXT.md: use the same `helpers/` directory structure as externalData extraction
- Per CONTEXT.md: incomeStatement.ts gets import swap only for BFS-03 -- no additional helper extraction (656 LOC is reasonable)
- Per CONTEXT.md: pure extraction -- zero logic changes

## Analysis: k3martCockpit/queries.ts Structure

The file has 7 queries:

1. **`getOutletStockSummaryInternal`** (lines 18-156, ~138 LOC): Heavy -- fetches outlets, snapshots, revenue, builds product list with sales data. The per-outlet product building loop (lines 105-138) is ctx-independent once data is fetched. **Extract stock summary builder.**

2. **`getWeeklyDispatchPlans`** (lines 163-446, ~283 LOC): The largest query. Steps 9-11 (lines 284-432) build outlet results, plan cells, and auto-suggest. Steps 9's outlet product building (lines 301-344) and step 10's plan cell aggregation (lines 362-410) are pure once data is loaded. **Extract dispatch plan builders.**

3. **`getPreviousWeekNumber`** (lines 452-459): Private helper, stays.

4. **`getProductionReadiness`** (lines 465-608, ~143 LOC): The deficit calculation loop (lines 530-606) is ctx-dependent (needs `ctx.db.get` for menu product names). Leave in place -- extraction would require passing ctx.

5. **`getInventorySources`** (lines 614-730, ~116 LOC): Moderate but mostly ctx-dependent. Leave.

6. **`getOutletDetail`** (lines 736-817, ~81 LOC): Simple, stays.

7. **`getStockMovementHistory`** (lines 823-867, ~44 LOC): Simple, stays.

8. **`getOutletSettings`** (lines 873-985, ~112 LOC): Moderate, mostly ctx-dependent. Leave.

**Best extraction candidates:**
- From `getOutletStockSummaryInternal`: the per-outlet product list builder (~35 LOC) + outlet result mapping
- From `getWeeklyDispatchPlans`: outlet product building (~43 LOC), plan cell aggregation + subtotals (~48 LOC), auto-suggest loop (~20 LOC)

**Extraction estimate:** ~200-250 LOC of pure computation extractable from `getWeeklyDispatchPlans` (283 LOC) and `getOutletStockSummaryInternal` (138 LOC). With existing file at 985, projected result: ~735-785 LOC. Target: **under 750 LOC**.

Most remaining functions (`getProductionReadiness`, `getInventorySources`, `getOutletSettings`) are heavily ctx-dependent. Pure extraction of these would require passing ctx as parameter, which trades file size for function signature complexity. Keep them in place per the "pure extraction" design principle.
