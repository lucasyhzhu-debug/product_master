<task type="auto">
  <name>Task 1: Permission guard tests for 9 expense routes across 4 roles</name>
  <files>tests/e2e/expense-access.spec.ts</files>
  <action>
Create `tests/e2e/expense-access.spec.ts` that systematically tests all 9 expense routes for each of the 4 roles.

Structure using `test.describe` blocks per role:

**1. Admin role (full access):**
Test that admin can access ALL 9 routes. For each route:
- loginAsRole(page, 'admin')
- page.goto(route, { waitUntil: "networkidle" })
- Assert URL still contains the route path (no redirect)
- Assert page has meaningful content (not blank/error)
- screenshot(page, `expense-access-admin-{routeSlug}`)

**2. Manager role (partial access):**
Test that manager can access: /expenses, /expenses/new, /expenses/approve, /expense-analytics
Test that manager is BLOCKED from: /reimbursements, /bank-accounts, /payroll, /accounts, /import
- For blocked routes: assert URL redirects to /home (manager landing page)
- screenshot blocked redirects: `expense-access-manager-blocked-{routeSlug}`

**3. Order staff role (submit only):**
Test that order_staff can access: /expenses, /expenses/new
Test that order_staff is BLOCKED from: /expenses/approve, /expense-analytics, /reimbursements, /bank-accounts, /payroll, /accounts, /import
- For blocked routes: assert URL redirects to /orders (order_staff landing page)

**4. Kitchen role (submit only):**
Test that kitchen can access: /expenses, /expenses/new
Test that kitchen is BLOCKED from: /expenses/approve, /expense-analytics, /reimbursements, /bank-accounts, /payroll, /accounts, /import
- For blocked routes: assert URL redirects to /kitchen (kitchen landing page)

Use `test.beforeEach` within each describe to login as the appropriate role. Use `logout(page)` in `test.afterEach` to clean session for the next describe block.

For the "can access" assertions, use:
```typescript
await page.waitForURL((url) => url.pathname.includes(route), { timeout: 10_000 });
```

For the "is blocked" assertions, use:
```typescript
await page.waitForURL((url) => url.pathname === expectedRedirect, { timeout: 10_000 });
```

Add a generous 10s timeout for redirects since ProtectedRoute checks happen after Convex auth query resolves.

Keep tests concise — each test is a single route access check. Use a data-driven pattern if possible (loop over route arrays per role) or explicit individual tests for clearer Playwright reporting.

<task type="auto">

  <files>tests/e2e/expense-analytics.spec.ts</files>
  <action>
Create `tests/e2e/expense-analytics.spec.ts` that tests the analytics and admin expense pages load correctly and show expected content.

Login as admin (beforeEach) since these are all admin-only pages.

**Test 1: Expense Analytics dashboard loads with charts**
- navigateTo(page, "/expense-analytics")
- waitForDataLoad(page)
- Assert page title visible: "Expense Analytics" or similar heading
- Assert at least one chart/card element renders (look for recharts SVG elements: `svg.recharts-surface` or card elements with summary metrics)
- Assert period selector is visible (Badge toggle for Month/Custom mode)
- screenshot(page, "expense-analytics-dashboard")

**Test 2: Payroll Manager page loads and shows table**
- navigateTo(page, "/payroll")
- waitForDataLoad(page)
- Assert "Payroll" heading visible
- Assert page has a table or list of payroll entries (may be empty with "No payroll entries" message)
- Look for "New Entry" or "Add" button (confirms CRUD capability)
- screenshot(page, "expense-analytics-payroll")

**Test 3: Bank Accounts Manager page loads**
- navigateTo(page, "/bank-accounts")
- waitForDataLoad(page)
- Assert "Bank Accounts" heading visible
- Assert EntityManager table or empty state renders
- screenshot(page, "expense-analytics-bank-accounts")

**Test 4: Chart of Accounts page loads with seeded accounts**
- navigateTo(page, "/accounts")
- waitForDataLoad(page)
- Assert "Chart of Accounts" or "Accounts" heading visible
- Assert at least one account row with a 4-digit code is visible (e.g., look for text matching /\d{4}/ in the table)
- Assert OpEx accounts visible (look for "6500" or "Office & Supplies" text)
- screenshot(page, "expense-analytics-accounts")

**Test 5: Payroll entry creation (basic CRUD)**
- navigateTo(page, "/payroll")
- waitForDataLoad(page)
- Click "New Entry" or "Add" button to open form
- Fill required fields: employee type (select "contractor"), frequency ("monthly"), amount ("500000"), period description, optional description
- Submit the form
- Wait for entry to appear in the list
- Assert the new entry is visible with the amount
- screenshot(page, "expense-analytics-payroll-created")
- Note: Use "E2E-" prefix in description for identification

If any page fails to load (e.g., query error), screenshot the error state and use `test.skip()` with a descriptive message rather than failing hard. This is the bug-fix loop pattern: document the issue for 53-BUG-REPORT.md.
