  <action>
Create `tests/e2e/expense-lifecycle.spec.ts` using `test.describe.serial()` since steps must run in order.

Use a UNIQUE expense amount to make P&L verification deterministic: e.g., 123456 (Rp 123,456 -- unlikely to collide with real data). Use "E2E-" prefix in description.

**Step 1: Submit expense as OrderStaff**
- loginAsRole(page, 'order_staff')
- navigateTo(page, '/expenses/new')
- waitForDataLoad(page)
- fillExpenseForm(page, { description: "E2E-Lifecycle-Test expense", amount: "123456", vendorName: "E2E Test Vendor", glCategory: "Office & Supplies" })
  - NOTE: glCategory selector -- click #accountId, wait for options, find one containing "Office & Supplies" (account 6500)
  - paymentMethod: click #paymentMethod, select "personal" (or whatever the first/default option is -- check the actual Select options)
- If an #expenseDate input exists, fill with a date in the current month (e.g., "2026-03-15") to ensure the P&L period covers it
- Click "Submit for Approval" button
- Wait for success indication: toast message or redirect to /expenses
- screenshot(page, "lifecycle-01-submitted")
- Assert: expense appears in "My Expenses" list with "Pending" status

**Step 2: Approve expense as Admin**
- logout(page) -- clear OrderStaff session
- loginAsRole(page, 'admin')
- navigateTo(page, '/expenses/approve')
- waitForDataLoad(page)
- Find the expense card with description containing "E2E-Lifecycle-Test" or amount "123,456"
- screenshot(page, "lifecycle-02-approval-queue")
- Click "Approve" button on that card
- If amount < 500K (123,456 < 500K), no comment required -- just confirm
- Wait for approval to complete (card disappears from queue or status changes)
- screenshot(page, "lifecycle-03-approved")

**Step 3: Reimburse expense as Admin**
- navigateTo(page, '/reimbursements')
- waitForDataLoad(page)
- screenshot(page, "lifecycle-04-reimbursements")
- Find the approved expense for E2E-OrderStaff (should show in grouped view)
- Click "Create Batch" button
- Wait for ConfirmBatchDialog to open (auto-opens per Phase 46 decision)
- Fill confirm fields: BCA reference ("E2E-REF-001"), transfer date (today), select a source bank account from dropdown
- Click confirm/submit button
- Wait for success (toast or status change)
- screenshot(page, "lifecycle-05-reimbursed")

**Step 4: Verify amount on P&L**
- navigateTo(page, '/financials')
- waitForDataLoad(page)
- Switch to "Custom Range" period mode if not already
- Set date range to cover the expense date (e.g., start of current month to end of current month)
- Wait for P&L data to load
- Look for the OpEx section (text "Operating Expenses" or similar)
- Assert the amount 123,456 (formatted as IDR: "123.456" or "Rp 123.456" or "Rp123,456") appears in the "Office & Supplies" (6500) line item
  - NOTE: formatCurrency in this codebase uses Indonesian format. Check `src/lib/utils.ts` for the exact format. The number 123456 may render as "Rp 123.456" (dot thousands separator) or "123,456"
  - Use a flexible regex match: `page.locator('text=/123[.,]456/').first()` within the OpEx section
- screenshot(page, "lifecycle-06-pnl-verified")

**Error handling:** If any step fails (element not found, timeout), capture a screenshot with the step name and use `test.fail()` with a descriptive message. Do NOT use test.skip for lifecycle failures -- these are real bugs that need fixing.

**Important:** The lifecycle steps MUST be in a `test.describe.serial()` block so they run in order. Each step is a separate `test()` within the serial describe. Use a shared variable (let expenseDescription: string) at the describe scope to pass data between steps.

Actually, since Playwright serial tests share state via `test.describe.configure({ mode: 'serial' })`, and each test gets a fresh page, we need to be more careful. Two approaches:
1. One large test with all steps (simpler but long)
2. Serial tests that re-find data by unique description prefix

Recommendation: Use a single large test with labeled sections (Step 1-4). This avoids the shared-state problem and matches the order-lifecycle.spec.ts pattern.
