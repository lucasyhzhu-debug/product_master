<task type="auto">
  <name>Task 3: Backend -- invoice queries, mutations, and customer write-back</name>
  <files>convex/invoices/queries.ts, convex/invoices/mutations.ts, convex/customers/mutations.ts</files>
  <action>
Create `convex/invoices/` directory with two files, and update `convex/customers/mutations.ts`.

**convex/invoices/queries.ts:**
- `getByOrder` -- protectedQuery, `roles: ["admin", "manager"]`, args: `{ orderId: v.id("orders") }`. Query invoices with `.withIndex("by_order", q => q.eq("orderId", args.orderId))`. For each invoice with `sellerLogoStorageId`, resolve URL via `ctx.storage.getUrl()`. Return array sorted by `_creationTime` desc (latest first).

- `getById` -- protectedQuery, `roles: ["admin", "manager"]`, args: `{ invoiceId: v.id("invoices") }`. Get by ID. Resolve logo URL. Return invoice with resolved `sellerLogoUrl`.

**convex/invoices/mutations.ts:**
- `createDraft` -- protectedMutation, `roles: ["admin", "manager"]`, args: `{ orderId: v.id("orders") }`. Handler:
  1. Read the order document. Throw if not found.
  2. Check order status is PaymentReceived or later (not Draft, AwaitingPayment, Cancelled). Throw ConvexError if invalid.
  3. Check no existing draft for this order: query invoices.by_order, filter status="draft". If exists, throw "Draft already exists" error.
  4. Read customer by order.customerId.
  5. Read businessSettings singleton (`.first()`).
  6. Read bank account if settings?.defaultBankAccountId is set.
  7. Build order items from `orderItems` table (query by orderId): map to `{ productName, variant, qty, unitPrice, lineTotal }`. For each item, resolve product name from menuProducts table.
  8. Calculate subtotal from line totals. Resolve discount: if order has `orderLevelDiscount` + `orderLevelDiscountType`, compute discountAmount (IDR) and discountLabel (e.g., "10%" for percentage, omit for flat).
  9. Insert invoice record with status="draft", all seller/buyer/order snapshots, `generatedBy: ctx.user._id`, `updatedAt: Date.now()`. Return the new invoice ID.

- `updateDraft` -- protectedMutation, `roles: ["admin", "manager"]`, args: `{ invoiceId: v.id("invoices"), ...partial update fields (all optional) }`. The partial fields include: buyerName, buyerCompany, buyerNpwp, buyerAddress, buyerPhone, poNumber, dueDate, notes, items, subtotal, discountAmount, discountLabel, deliveryFee, finalTotal, sellerName, sellerAddress, sellerPhone, sellerEmail, sellerNpwp, bankName, bankAccountNumber, bankAccountName, paymentStatus, paymentMethod. Handler: get invoice, verify status="draft" (throw if final). Patch with provided fields + `updatedAt: Date.now()`.

- `discardDraft` -- protectedMutation, `roles: ["admin", "manager"]`, args: `{ invoiceId: v.id("invoices") }`. Get invoice, verify status="draft". Delete with `ctx.db.delete`.

- `finalize` -- protectedMutation, `roles: ["admin", "manager"]`, args: `{ invoiceId: v.id("invoices") }`. Handler:
  1. Get invoice, verify status="draft".
  2. Generate invoice number using helper `getNextInvoiceNumber(ctx)`:
     - Import `getWibComponents` from `convex/lib/periodRange.ts`.
     - Get current WIB time components. Build prefix: `${String(year).slice(-2)}${String(month + 1).padStart(2, "0")}` (month is 0-indexed in getWibComponents).
     - Query `invoiceCounters.by_prefix` with `.unique()` (not `.first()`).
     - If counter exists: increment `lastNumber`, patch counter.
     - If not: insert new counter with `lastNumber: 1`.
     - Format: `INV-${prefix}-${String(sequence).padStart(3, "0")}`.
  3. Patch invoice: `status: "final"`, `invoiceNumber`, `generatedAt: Date.now()`.
  4. Customer write-back: Read customer by orderId->customerId path. If invoice has buyerCompany, buyerNpwp, or buyerAddress that differ from customer record, patch customer with new values (only set fields that have values).
  5. Return `{ invoiceId, invoiceNumber }`.

**convex/customers/mutations.ts update:**
Add optional `companyName`, `npwp`, `billingAddress` fields to the `update` mutation's args validator. Include them in the patch if provided. This is a non-breaking addition. Do NOT change `create` -- these fields are only set on invoice finalize write-back or manual customer editing.
