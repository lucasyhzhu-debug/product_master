# Phase 27.1: GrabFood Menu Simulator - Context

**Gathered:** 2026-02-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Build a standalone page that simulates the GrabFood menu: pull the current live menu from GrabFood via the Partner API, display it in a GrabFood app-like preview, allow inline editing (add/remove/rename items, change prices, toggle availability), and push changes back to GrabFood with confirmation. Admin can also add new items by selecting from internal menu products (auto-filled) and upload photos that write back to internal product records.

</domain>

<decisions>
## Implementation Decisions

### Product-to-menu mapping
- Admin **manually assigns** internal menu products to GrabFood categories (no auto-mapping from tags)
- **Single section** for the entire menu — all items available during store operating hours
- Each menu product appears as a **separate GrabFood item** (no product-family + modifier grouping)
- **No modifiers** — snack products are sold as-is with no customization options
- GrabFood menu is a **curated selection** from internal menu products, not a mirror of the full catalog
- Internal menu products may include **Grab-exclusive SKUs** created specifically for GrabFood channel

### Preview visual style
- **GrabFood app-like mockup** — high visual fidelity so admin sees what customers see
- Focus on **food catalog only**: photos, names, descriptions, prices
- **No delivery fees, promo badges, or Grab branding chrome** — that's Grab's UI, not controllable
- **Standalone page** (e.g., `/grabfood-menu`) — dedicated space for the simulator
- Product photos come from GrabFood data (pulled) or uploaded in the simulator

### Edit & adjustment capability
- **Full inline editing**: admin can override name, price, and description for GrabFood specifically (GrabFood-specific values stored separately from internal product data)
- **Add items**: select from existing internal menu products only (no creating Grab-exclusive products in the simulator)
- When adding, **auto-fill** GrabFood name/price/description from internal menu product — admin can then override any field
- **Soft-remove** (toggle off): items marked unavailable on GrabFood but link preserved. Easy to re-enable
- **No stock tracking** in the simulator — availability is a manual toggle, not tied to inventory levels
- **Photo upload** in the simulator: photos saved to database and **linked back to internal menu products** (write-back pattern)

### Push-to-GrabFood workflow
- **Pull-first flow**: primary workflow is "Sync latest from GrabFood" → edit → push back
- Fresh build from scratch is a fallback (for edge case of no existing store, though store should already exist via Grab Merchant app)
- **Push with confirmation**: show summary of changes (new items, price changes, removed items) before syncing
- **Show sync status**: after push, track the GrabFood sync job (PENDING → IN_PROGRESS → SUCCESS/PARTIAL_FAILURE/FAILED)
- "Sync latest from GrabFood" button to pull current live menu state as starting point

### Claude's Discretion
- Exact GrabFood-like visual styling (colors, layout, card design)
- Data model for storing GrabFood menu overrides (likely a `grabfoodMenuItems` table or similar)
- How to handle the GrabFood Partner API menu endpoint (PUT /partner/v1/menu) vs batch update
- Sync job polling mechanism (scheduler chain vs simple polling)
- Photo storage implementation (Convex file storage)
- Error handling for API failures
- Loading and empty states

</decisions>

<specifics>
## Specific Ideas

- "Sync latest from GrabFood" button as the primary entry point — pull live menu before editing
- Photos uploaded in the simulator should flow back to internal menu products (saves duplicate work)
- GrabFood prices are in **minor units** (IDR has no decimals, so 25000 = Rp 25,000) — the UI should handle this conversion
- The sample menu structure is in `docs/grabfood-menu-simulator-sample.json` — use as reference for the GrabFood menu hierarchy
- Similar POS-style interface as existing MenuProducts page

</specifics>

<deferred>
## Deferred Ideas

- **Photo upload for internal menu products** — ability to upload photos directly in the MenuProducts manager (currently no photos on internal products). The GrabFood simulator will be the first place photos get added, flowing back to internal products.
- **Modifier group support** — if future GrabFood menu items need customization options (add-ons, flavor choices), add modifier group editing to the simulator
- **Grab-exclusive product creation** — creating new products that only exist on GrabFood (combos, bundles specific to delivery)
- **Stock/inventory integration** — link GrabFood maxStock to internal inventory levels for automatic availability management
- **Multiple sections with service hours** — if menu needs time-based sections (breakfast vs lunch), add section management

</deferred>
