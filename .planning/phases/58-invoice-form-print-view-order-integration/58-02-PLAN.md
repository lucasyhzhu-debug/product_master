**Form state management:**

Initialize local form state from the loaded `invoice` prop. Track each editable field's value AND source (FieldSource). Use a `Record<string, { value: string; source: FieldSource }>` pattern or individual state pairs.

Fields to track with their initial sources:
- **Auto-filled (source: "auto")**: sellerName, sellerAddress, sellerPhone, sellerEmail, sellerNpwp, bankName, bankAccountNumber, bankAccountName, buyerName, buyerPhone, orderNumber, orderDate, paymentStatus, paymentMethod
- **Needs-input (source: "needs-input")**: buyerCompany (unless pre-filled from customer), buyerNpwp (unless pre-filled), buyerAddress (unless pre-filled), poNumber, notes, dueDate
- If a "needs-input" field already has a value in the loaded draft (e.g., customer had a company name saved from a previous invoice), set source to "auto" instead

**Field source transition logic:**
When user types in a field with source "auto", transition to "edited" (white background). Fields with source "needs-input" stay "needs-input" until filled, then transition to "edited". The parent needs to call `handleFieldChange(fieldName, newValue)` which:
1. Updates the value in state
2. If current source is "auto", changes to "edited"
3. If current source is "needs-input" and value is non-empty, changes to "edited"
4. Schedules auto-save

**Debounced auto-save (2 seconds) -- CRITICAL TIMING:**
Use `setTimeout`/`clearTimeout` pattern (project convention, NOT lodash.debounce).
- Keep a `saveTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null)`
- Keep a `changedFieldsRef = useRef<Record<string, string>>({})` to accumulate changes between saves
- On field change: clear existing timer, add field to `changedFieldsRef.current`, set new 2-second timeout
- **CRITICAL: Set "saving" status INSIDE the setTimeout callback, NOT on every keystroke.** The user should only see "Saving..." when the mutation is actually about to fire, not on every keypress. Sequence inside the timeout callback:
  1. Set status to "saving" via `onSaveStatusChange?.("saving")`
  2. Call `useUpdateInvoiceDraft().mutate()` with accumulated changed fields from `changedFieldsRef.current`
  3. Clear `changedFieldsRef.current`
  4. On success: set status to "saved"
  5. On error: set status to "idle" (so user knows save failed)
- After successful save, set "saved" -- transition to "idle" after 5 seconds
- Cleanup: return cleanup function from useEffect that clears the save timer on unmount

**CRITICAL: Field name mapping for auto-save.** When calling `useUpdateInvoiceDraft().mutate()`, use the EXACT field names from the `updateDraft` backend mutation args (see `<interfaces>` block above). Local form state key names MUST match the backend field names: `buyerName`, `buyerCompany`, `buyerNpwp`, `buyerAddress`, `buyerPhone`, `poNumber`, `dueDate` (as epoch ms number), `notes`, `sellerName`, `sellerAddress`, `sellerPhone`, `sellerEmail`, `sellerNpwp`, `bankName`, `bankAccountNumber`, `bankAccountName`. Note: `paymentStatus` and `paymentMethod` are NOT updatable via updateDraft -- they are read-only from the order snapshot.

**CRITICAL: Prevent auto-save on initial load.** Use an `isInitializedRef = useRef(false)` flag. When the form first mounts and initializes state from the loaded invoice, set the flag to `true` AFTER initialization. Skip auto-save scheduling while `isInitializedRef.current === false`.

**Layout (WYSIWYG -- form mirrors invoice layout):**

The form layout should visually match the InvoicePrintView sections, but with editable InvoiceFieldInput components instead of plain text. Use the same 9-section structure:

1. **Header section**: Seller info fields (mostly read-only / auto-filled blue). "INVOICE" title with "DRAFT" badge.
2. **Bill To section**: buyerName (auto), buyerCompany (needs-input), buyerNpwp (needs-input), buyerAddress (needs-input), buyerPhone (auto)
3. **Order Details**: orderNumber (read-only), orderDate (read-only), dueDate (needs-input, use date input), poNumber (needs-input)
4. **Items table**: Read-only table from `invoice.items` -- NOT editable per user decision. Show #, Product, Qty, Unit Price, Line Total with formatCurrency.
5. **Totals**: Read-only computed values (subtotal, discount, delivery fee, grand total) -- NOT editable per user decision.
6. **Payment info**: Read-only from invoice snapshot (paymentStatus, paymentMethod, bank details).
7. **Signature area**: Placeholder dashed box (same as print view, informational only).
8. **Notes**: notes field (needs-input, multiline textarea).
9. **Footer preview**: Shows "Thank you" + seller name (read-only).

**Field color legend** (small inline guide at top of form, print:hidden):
Show 3 color swatches with labels: Blue = "Auto-filled", Yellow = "Needs input", White = "User edited".

Use `InvoiceFieldInput` from Plan 01 for all editable fields. Use plain text/spans for read-only values (items, totals, payment info).
