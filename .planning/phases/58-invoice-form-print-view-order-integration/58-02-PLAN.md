Create the WYSIWYG invoice form that mirrors the final printed layout but with editable fields. This is the core editing experience.

**Props:**
```typescript
interface InvoiceFormProps {
  invoice: Invoice; // Loaded draft invoice from useInvoice
  onSaveStatusChange?: (status: "idle" | "saving" | "saved") => void;
}
```

**Form state management:**

Initialize local form state from the loaded `invoice` prop. Track each editable field's value AND source (FieldSource). Use a `Record<string, { value: string; source: FieldSource }>` pattern or individual state pairs.

Fields to track with their initial sources:
- **Auto-filled (source: "auto")**: sellerName, sellerAddress, sellerPhone, sellerEmail, sellerNpwp, bankName, bankAccountNumber, bankAccountName, buyerName, buyerPhone, orderNumber, orderDate, paymentStatus, paymentMethod
- **Needs-input (source: "needs-input")**: buyerCompany (unless pre-filled from customer), buyerNpwp (unless pre-filled), buyerAddress (unless pre-filled), poNumber, notes, dueDate
- If a "needs-input" field already has a value in the loaded draft (e.g., customer had a company name saved from a previous invoice), set source to "auto" instead

**Field source transition logic:**
When user types in a field with source "auto", transition to "edited" (white background). Fields with source "needs-input" stay "needs-input" until filled, then transition to "edited". The parent needs to call `handleFieldChange(fieldName, newValue)` which:
1. Updates the value in state
2. If current source is "auto", changes to "edited"
3. If current source is "needs-input" and value is non-empty, changes to "edited"
4. Schedules auto-save

**Debounced auto-save (2 seconds):**
Use `setTimeout`/`clearTimeout` pattern (project convention, NOT lodash.debounce).
- Keep a `saveTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null)`
- On field change, clear existing timer, set new 2-second timeout
- On timeout fire: call `useUpdateInvoiceDraft().mutate()` with changed fields
- Track save status: `"idle" | "saving" | "saved"` -- surface via `onSaveStatusChange` callback
- After successful save, set "saved" -- transition to "idle" after 5 seconds
- Cleanup timer on unmount via useEffect return

**CRITICAL: Prevent auto-save on initial load.** Use an `isInitializedRef = useRef(false)` flag. When the form first mounts and initializes state from the loaded invoice, set the flag to `true` AFTER initialization. Skip auto-save scheduling while `isInitializedRef.current === false`.

**Layout (WYSIWYG -- form mirrors invoice layout):**

The form layout should visually match the InvoicePrintView sections, but with editable InvoiceFieldInput components instead of plain text. Use the same 9-section structure:

1. **Header section**: Seller info fields (mostly read-only / auto-filled blue). "INVOICE" title with "DRAFT" badge.
2. **Bill To section**: buyerName (auto), buyerCompany (needs-input), buyerNpwp (needs-input), buyerAddress (needs-input), buyerPhone (auto)
3. **Order Details**: orderNumber (read-only), orderDate (read-only), dueDate (needs-input, use date input), poNumber (needs-input)
4. **Items table**: Read-only table from `invoice.items` -- NOT editable per user decision. Show #, Product, Qty, Unit Price, Line Total with formatCurrency.
5. **Totals**: Read-only computed values (subtotal, discount, delivery fee, grand total) -- NOT editable per user decision.
6. **Payment info**: Read-only from invoice snapshot (paymentStatus, paymentMethod, bank details).
7. **Signature area**: Placeholder dashed box (same as print view, informational only).
8. **Notes**: notes field (needs-input, multiline textarea).
9. **Footer preview**: Shows "Thank you" + seller name (read-only).

**Field color legend** (small inline guide at top of form, print:hidden):
Show 3 color swatches with labels: Blue = "Auto-filled", Yellow = "Needs input", White = "User edited".

Use `InvoiceFieldInput` from Plan 01 for all editable fields. Use plain text/spans for read-only values (items, totals, payment info).

**1. src/pages/InvoicePage.tsx:**

This page component handles 3 modes based on URL:
- **Form mode**: `/orders/:orderId/invoice` (no invoiceNumber param, no ?preview)
- **Preview mode**: `/orders/:orderId/invoice?preview` (query param)
- **Print view mode**: `/orders/:orderId/invoice/:invoiceNumber` (has invoiceNumber param)

Use `useParams` to get `orderId` and `invoiceNumber`, `useSearchParams` to check `?preview`.

```typescript
export function InvoicePage() {
  const { orderId: orderIdParam, invoiceNumber } = useParams<{ orderId: string; invoiceNumber: string }>();
  const [searchParams] = useSearchParams();
  const isPreview = searchParams.has("preview");
  const navigate = useNavigate();
  const orderId = orderIdParam as Id<"orders"> | undefined;
  // ... mode logic
}
```

**Mode determination:**
- If `invoiceNumber` is present -> print view mode (show finalized invoice)
- If `isPreview` is true -> preview mode (show draft as InvoicePrintView in bordered card)
- Else -> form mode (show InvoiceForm)

**Data loading:**

All hooks MUST be called before any conditional returns (React hooks rule).

```typescript
const invoices = useInvoicesByOrder(orderId);
// For print view: find the finalized invoice by invoiceNumber
// For form/preview: find the draft
```

**Form mode flow:**
1. Check `invoices` for existing draft. If draft exists, render InvoiceForm with draft data.
2. If no draft exists, show a "Creating draft..." state and call `useCreateInvoiceDraft().mutate({ orderId })` once (use a `useEffect` with a `creatingRef` guard to prevent double-calls in StrictMode). After creation, the reactive `useInvoicesByOrder` will pick up the new draft.
3. Show save status indicator in the page header area (right-aligned, small muted text): "Saving..." / "Saved just now". Use a `setInterval` to transition from "Saved just now" to "Saved N min ago" after 1 minute.

**Action buttons (print:hidden, above the form):**
- "Back to Order" (left) -- navigates to `/orders/${orderId}`
- "Discard Draft" (outline, destructive) -- shows ConfirmDialog, on confirm calls `useDiscardInvoiceDraft` then navigates back to order detail
- "Preview" -- navigates to `?preview` (appends query param)
- "Generate Invoice" (brand button, primary) -- shows ConfirmDialog ("This will finalize the invoice and assign a number. This cannot be undone."), on confirm calls `useFinalizeInvoice`, then navigates to `/orders/${orderId}/invoice/${result.invoiceNumber}`

**Preview mode flow:**
1. Load draft from `invoices` (find status="draft").
2. Render InvoicePrintView inside a bordered card container: `<div className="border rounded-lg shadow-sm mx-auto max-w-[210mm] bg-white"><InvoicePrintView data={draftData} /></div>`
3. Action buttons: "Back to Edit" (removes ?preview), "Generate Invoice" (same as form mode)

**Print view mode flow:**
1. Find finalized invoice by matching `invoiceNumber` in `invoices` array.
2. Render InvoicePrintView in a bare wrapper: `<div className="invoice-print-area"><InvoicePrintView data={invoiceData} /></div>`
3. Action buttons (print:hidden): "Back to Order", "Print" (calls `window.print()`), "New Invoice" (calls createDraft for same order, navigates to form)
4. For logo: ensure `<img>` has `loading="eager"` to prevent missing image in print. Optionally track logo load state and only enable Print button after logo loads.

**Loading states:** Use `PageHeader` with title "Invoice" and show `LoadingCards` while data is loading (invoices === undefined).

**Error states:** If orderId is missing or invoice not found, show error card with "Invoice not found" message and back button.

Export as named export: `export function InvoicePage() { ... }`
