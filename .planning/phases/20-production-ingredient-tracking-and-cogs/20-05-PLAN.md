Extend the existing `simulateInventory` query in `convex/dispatchPlanner/queries.ts`:

**Current behavior:** Walks BOM for each dispatch plan product, sums required packaging components per day, compares against componentStock to find shortages.

**Extension:** Also walk the production component hierarchy to calculate ingredient requirements.

1. After the existing packaging BOM walk (which uses menuProductComponents), add a second pass for ingredients:
   - For each dispatch plan entry, get its production BOM (menuProductComponents where the componentType has category="production" and trackInventory=false)
   - For each production component, call `collectLeafIngredients` to get all leaf ingredients with quantities
   - Multiply by the planned quantity for that day
   - Aggregate ingredient requirements by ingredientId per day

2. Track ingredient stock separately: Fetch componentStock for ingredient-type componentTypes (category="production" AND trackInventory=true). Build a map of ingredientComponentTypeId -> available stock.

3. Walk through days cumulatively (same pattern as existing packaging simulation):
   - For each day, subtract that day's ingredient requirements from running stock
   - If any ingredient goes below zero, add it to the shortages for that day

4. **Projected resupply dates**: For each ingredient, calculate when stock will run out based on the daily consumption rate. Format as "Runs out by {dayName}" (e.g., "Runs out by Wednesday"). Include this in the response.

5. **Response format extension**: Add an `ingredientShortages` array to each day's result, alongside the existing `shortages` (for packaging). Each ingredient shortage has: `ingredientName`, `required` (cumulative), `available` (starting stock), `deficit`, `runsOutDate` (the first date stock goes negative).

6. Add a top-level `ingredientStatus` to the response: array of `{ ingredientName, currentStock, totalRequired7Days, runsOutDate: string | null }`.

7. The simulation is still triggered by manual "Simulate" button (no change to trigger mechanism). Just extend the data returned.

Import `collectLeafIngredients` from `../lib/hierarchyTraversal`.
  </action>
