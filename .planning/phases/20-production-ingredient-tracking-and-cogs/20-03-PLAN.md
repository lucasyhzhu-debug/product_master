Add a new optional field to the create args: `isIngredientTracker: v.optional(v.boolean())`. When `isIngredientTracker=true`, allow trackInventory=true even for category="production".

**inventoryIntegration.ts** -- Add new function `consumeIngredientMaterialsInternal`:

```typescript
export async function consumeIngredientMaterialsInternal(
  ctx: MutationCtx,
  args: { orderId: Id<"orders"> }
): Promise<{ consumed: number; warnings: string[] }>
```

Logic:
1. Get the order and its items (orderItems by orderId)
2. For each order item with a menuProductId:
   a. Get the menu product's production BOM: query menuProductComponents.by_menu_product, filter to componentTypes where category="production" and trackInventory=false (these are the ball types, not ingredient trackers)
   b. For each production component in BOM: call `collectLeafIngredients(ctx, componentTypeId)` to get all leaf ingredients with quantities
   c. Multiply each ingredient's totalQuantity by the order item quantity (comp.quantity * orderItem.quantity)
3. Aggregate all ingredient requirements by ingredientId (sum quantities across order items and production components)
4. For each aggregated ingredient:
   a. Find the linked componentType (via ingredients table -> ingredientComponentTypeId)
   b. If no linked componentType or trackInventory=false, skip (ingredient doesn't track inventory)
   c. Get the kitchen location (storageLocations.by_type("kitchen"))
   d. Try to consume using `consumeFromFIFO` from inventory/fifo.ts
   e. If insufficient stock: DO NOT throw. Instead, allow negative stock -- consume what's available, then create a negative adjustment to bring stock to the needed level. Add warning message: "Insufficient stock for {ingredientName}: needed {qty}, available {available}"
   f. Create componentTransaction records for the consumption
   g. Update componentStock via updateComponentStock helper

Return { consumed: totalIngredientsConsumed, warnings: [...] }
