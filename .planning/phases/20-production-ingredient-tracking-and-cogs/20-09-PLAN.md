  <name>Task 1: Filter Planned Manual to posSlot-assigned food products</name>
  <files>convex/dispatchPlanner/queries.ts</files>
  <action>
In `getUnifiedWeeklyPlan`, the `menuProductMap` is built by filtering `allMenuProducts` for `isActive=true` and `productType !== "packaging"`. This includes all legacy active products without POS slots.

**Fix**: Add a posSlot filter so only products with a defined `posSlot` (food slot) appear in Planned (Manual). Products without posSlot are legacy and should be hidden.

Find the menuProductMap build loop (around lines 147-156):
```typescript
const allMenuProducts = await ctx.db
  .query("menuProducts")
  .withIndex("by_active", (q) => q.eq("isActive", true))
  .collect();
const menuProductMap = new Map<string, Doc<"menuProducts">>();
for (const mp of allMenuProducts) {
  if (mp.productType === "packaging") continue;
  menuProductMap.set(mp._id, mp);
}
```

Change to:
```typescript
const allMenuProducts = await ctx.db
  .query("menuProducts")
  .withIndex("by_active", (q) => q.eq("isActive", true))
  .collect();
const menuProductMap = new Map<string, Doc<"menuProducts">>();
for (const mp of allMenuProducts) {
  // Skip packaging-only products
  if (mp.productType === "packaging") continue;
  // Skip products not assigned to a food POS slot (legacy / inactive in POS)
  if (!mp.posSlot) continue;
  menuProductMap.set(mp._id, mp);
}
```

This filter applies to ALL uses of `menuProductMap` in the query — which includes Planned (Manual) for direct sales, GoFood product rows (from existing plans), and consignment product rows. This is intentional: only POS-slotted products should appear in dispatch planning.

NOTE: GoFood and consignment outlets also add products from EXISTING `dispatchPlans` records (`productIds` from `outletPlans`). Those products may reference legacy menuProductIds. The lookup `menuProductMap.get(mpId)` will return `undefined` for unslotted products — handle gracefully with `const productName = mp?.name ?? "Unknown"` (already done in GoFood section). The product will still render with "Unknown" name. This is acceptable — existing saved plans preserve their data, only new product rows are restricted.

After making the change, also check `assembleDirectChannel` where Planned (Manual) row is built (around lines 344-386). The loop `for (const [mpId, mp] of menuProductMap)` already uses the filtered map, so no additional change needed there.

If no records exist, GoFood renders 0 outlets. Do NOT add seeding code to this plan — if outlets are missing, the executor should note this in the SUMMARY and the user can seed via the Convex dashboard. The backend code is correct.
