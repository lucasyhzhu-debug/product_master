<task type="auto">
  <name>Task 1: Production recipe CRUD mutations + queries</name>
  <files>convex/productionRecipes/mutations.ts, convex/productionRecipes/queries.ts</files>
  <action>
Create `convex/productionRecipes/` directory with two files:

**mutations.ts** -- All mutations require `token: v.string()` and use `requireRole(ctx, args.token, ["admin", "manager"])`:

1. **addSubComponent** -- Args: token, parentComponentId (Id<"componentTypes">), childComponentId (Id<"componentTypes">), quantityPerUnit (number), unit (string). Validate: parent exists + category="production", child exists + category="production", parent !== child, call `wouldCreateCycle(ctx, parentComponentId, childComponentId)` and throw if true. Check max depth: traverse from root to ensure adding this link won't exceed 3 tiers. Get current max sortOrder from productionComponentLinks.by_parent, insert with sortOrder = max+1. Return new link ID.

2. **removeSubComponent** -- Args: token, linkId (Id<"productionComponentLinks">). Delete the link.

3. **updateSubComponentQuantity** -- Args: token, linkId (Id<"productionComponentLinks">), quantityPerUnit (number), unit (string). Patch the link.

4. **addIngredient** -- Args: token, componentTypeId (Id<"componentTypes">), ingredientId (Id<"ingredients">), quantityPerUnit (number), unit (string). Validate: componentType exists + category="production", ingredient exists. Check for duplicate (same componentTypeId + ingredientId). Snapshot ingredientName from ingredient.name. Calculate cachedLineCost using calculateLineCost(ingredient.costPerBaseUnit, quantityPerUnit, unit). Insert into productionComponentIngredients with next sortOrder.

5. **removeIngredient** -- Args: token, linkId (Id<"productionComponentIngredients">). Delete the link.

6. **updateIngredientQuantity** -- Args: token, linkId (Id<"productionComponentIngredients">), quantityPerUnit (number), unit (string). Get ingredient to recalculate cachedLineCost. Patch the link.

After any mutation that changes recipe composition (add/remove/update), schedule COGS cache invalidation for the affected componentType using `ctx.scheduler.runAfter(0, internal.productionRecipes.mutations.recalculateComponentCogs, { componentTypeId })`.

7. **recalculateComponentCogs** (internalMutation) -- Args: componentTypeId. If component.cogsMode !== "calculated", skip. Call `traverseHierarchy(ctx, componentTypeId, 1, new Set(), 3)` to get all leaf ingredients. Sum lineCosts for total COGS. Count ingredients with unitCost=0 or null for cogsMissingCount. Patch componentType with `cachedCalculatedCogs`, `cogsCacheUpdatedAt: Date.now()`, `cogsMissingCount`. If cogsMissingCount === 0 AND cachedCalculatedCogs changed, also update `unitCostIdr` to match (so menu product cost cascade works). Then schedule `invalidateMenuProductCosts` for any menu products using this component.

**queries.ts** -- No auth required for queries:

1. **getRecipeForComponent** -- Args: componentTypeId (Id<"componentTypes">). Returns { subComponents: [...], ingredients: [...] } by querying productionComponentLinks.by_parent and productionComponentIngredients.by_component. For each sub-component link, join with the child componentType to get name, code, batchSize, unitCostIdr. For each ingredient link, join with the ingredient to get name, costPerBaseUnit, baseUnit. Sort both by sortOrder.

2. **calculateCogs** -- Args: componentTypeId (Id<"componentTypes">). Calls collectLeafIngredients, returns { totalCogs, missingCount, breakdown[] } where breakdown contains each ingredient path with its line cost.

3. **getComponentsWithTiers** -- Args: none. Fetches all production componentTypes. For each, count nesting depth by walking productionComponentLinks.by_parent recursively (max 3). Return components sorted by tier descending (highest tier first), then by name alphabetically within each tier. Each result includes { ...componentType, tier: number }.

Import `wouldCreateCycle` and `traverseHierarchy` / `collectLeafIngredients` from `../lib/hierarchyTraversal`. Import `requireRole` from `../lib/auth`. Import `calculateLineCost` from `../lib/costCalculator`.
  </action>
  <verify>Run `npm run type-check`. Verify all mutations and queries compile without errors. Verify recalculateComponentCogs only patches componentTypes fields (cachedCalculatedCogs, cogsCacheUpdatedAt, cogsMissingCount, unitCostIdr) -- confirm no orderItems or orders table is written (forward-only COGS: historical orders keep their original costs).</verify>
  <done>productionRecipes/mutations.ts has 7 functions (6 user-facing + 1 internal). productionRecipes/queries.ts has 3 query functions. Circular reference prevention works via wouldCreateCycle. COGS recalculation is lazy and cached.</done>

<task type="auto">
  <name>Task 2: Extend componentTypes mutations + cost invalidation cascade</name>
  <files>convex/componentTypes/mutations.ts, convex/lib/costInvalidation.ts</files>
  <action>
**componentTypes/mutations.ts** -- Extend the existing `create` and `update` mutations:

1. In `create` mutation: Accept optional new fields `batchSize` (number), `batchSizeUnit` (string). Default `cogsMode` to "manual" for production components. Store `manualUnitCostIdr` = unitCostIdr at creation time.

2. In `update` mutation: Accept optional new fields `batchSize`, `batchSizeUnit`. Add a new action: **toggleCogsMode** -- when `cogsMode` is provided and differs from current:
   - Switching to "calculated": Save current `unitCostIdr` to `manualUnitCostIdr` (preserve fallback). Schedule recalculateComponentCogs to compute and cache.
   - Switching to "manual": Restore `unitCostIdr` from `manualUnitCostIdr` if it exists. Clear `cachedCalculatedCogs`.

3. **Relax the production+trackInventory validation**: The existing validation (around line 70-71) prevents production components from having trackInventory=true. Do NOT change this yet -- ingredients will be handled differently in Plan 03 by adding ingredient-type entries. Leave this validation as-is.

**costInvalidation.ts** -- Add a new internalMutation:

**invalidateProductionComponentCosts** -- Args: ingredientId (Id<"ingredients">). When an ingredient's cost changes (triggered from ingredients/mutations.ts):
1. Find all productionComponentIngredients.by_ingredient for this ingredientId
2. For each affected componentType: update the cachedLineCost on the ingredient link, then mark the component's `cogsCacheUpdatedAt` as undefined (stale marker)
3. Walk productionComponentLinks.by_child to find parent components that use the affected component as a sub-component -- mark those stale too (cascade up)
4. For components with cogsMode="calculated" that were marked stale, schedule recalculateComponentCogs (from productionRecipes/mutations.ts) via ctx.scheduler.runAfter(0, ...)

Also extend the existing `invalidateIngredientCosts` trigger in `convex/ingredients/mutations.ts`: After the existing cost invalidation call, also schedule `invalidateProductionComponentCosts` with the same ingredientId.
  </action>
