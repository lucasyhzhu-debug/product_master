This file does NOT need heavy helper migration. The patterns are too custom for generic helpers to add value.

**Shipping mutations (`convex/shipping/mutations.ts`):**

**DO NOT wrap with protectedMutation.** Per research Pitfall 6, shipping mutations are internal system calls:
- `incrementAgencyUsage` -- called by order mutations when shipping agency is set
- `decrementAgencyUsage` -- called by order mutations when shipping agency changes
- `seedFromExistingOrders` -- dashboard utility, run once

These are NOT user-facing CRUD operations. They must remain as bare `mutation()` so order mutations can call them internally without session context.

**Only change:** Add a JSDoc comment to the file header explaining why these remain unwrapped:
```typescript
/**
 * Shipping Agency Usage Mutations
 *
 * NOTE: These mutations are INTERNAL system calls invoked by order mutations,
 * not user-facing CRUD operations. They intentionally remain as bare mutation()
 * without protectedMutation wrapper. Auth is enforced by the calling order
 * mutations which use their own auth wrappers. See Phase 5 research Pitfall 6.
 */
```

**Shipping queries (`convex/shipping/queries.ts`):**

Shipping queries have unique patterns (usage tracking, top-N by index) that do not map to generic helpers. Keep as-is with public `query`. No changes needed -- these are read by order creation UI which is already behind ProtectedRoute.
