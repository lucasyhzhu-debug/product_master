Populate all 8 expense guide section mappings. Use realistic source globs:

For `lastReviewedCommit`, use the current HEAD commit hash (run `git rev-parse HEAD` to get it).

2. Create `scripts/validate-docs-manifest.cjs` as a Node.js CommonJS script (matches existing scripts/ convention). The script should:
- Read `.planning/docs-manifest.json`
- Read `src/lib/helpGuides.ts` or parse a simplified section list from the manifest itself
- For each guide with status "live" in the registry, check that every section ID has at least one mapping entry in the manifest
- Warn about unmapped sections (sections in guide registry but no manifest entry)
- Warn about orphaned mappings (manifest entries whose docFile does not exist on disk)
- Validate that every `docFile` path actually exists using `fs.existsSync`
- Exit 0 if all checks pass, exit 1 if any errors (unmapped sections = error, orphaned = warning)
- Use `console.log` for output with clear PASS/FAIL/WARN prefixes per check

3. Add to `package.json` scripts: `"validate:docs-manifest": "node scripts/validate-docs-manifest.cjs"`

The validation script does NOT need to parse TypeScript imports. It reads the manifest JSON and checks:
(a) Every `{guide, section}` pair in manifest has a corresponding file at `docFile`
(b) Cross-references against a hardcoded list of live guides + their section IDs (read from the manifest's own entries grouped by guide, since the manifest IS the source of truth for what's mapped)

For detecting unmapped sections, the script should accept an optional `--guide-sections` JSON file or simply warn that "no coverage check possible without guide registry data" and skip that check. The primary validation is: every docFile exists, no duplicate mapping IDs, valid JSON structure.
