# Phase 27.1: GrabFood Webhooks & Partner Configuration - Context

**Gathered:** 2026-02-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Implement all 6 GrabFood inbound webhook endpoints (GET menu, submit order, order state, menu sync, integration status, menu push) with DB-stored HMAC secret, so the GrabFood App Simulator test cases work end-to-end. Frontend gets a new Webhooks tab with HMAC secret field + copyable webhook URLs. This is a **passive integration** — webhooks observe and log, they do NOT control the order lifecycle (orders are accepted from the GrabFood Merchant App on phone).

**Critical distinction:** GrabFood (Grab) and GoFood/GoBiz (Gojek) are completely separate platforms and companies. This phase is for the official GrabFood Partner API only.

</domain>

<decisions>
## Implementation Decisions

### Webhook response behavior
- All 6 handlers follow the same pattern: validate HMAC, console.log key fields, write to syncLogs table, return HTTP 200
- **No grabfoodOrders DB writes** — orders are not stored, only logged. The existing `upsertOrder` mutation should be **removed**
- HMAC failures also written to syncLogs as `status: "error"` (not just console.log)
- Always return HTTP 200, even on HMAC failure or processing error (per GrabFood spec)
- **No outbound actions** in response to webhooks — never call order/prepare, never auto-accept orders. This system is for transaction tracking and sales reporting only

### GET /menu endpoint
- Dynamically built from `externalProductMappings` where `source="grabfood"` joined with `menuProducts`
- **Price source:** GrabFood-specific price from mapping if set, otherwise fall back to internal menuProduct basePrice
- **Availability:** Per-mapping toggle — inactive items excluded or marked UNAVAILABLE in menu JSON
- Single section "Frollie Menu" with single category "Snacks"
- Item IDs from `externalProductMappings.externalProductCode`

### Order-to-internal mapping
- Follows standard platform integration pattern: product codes from menu endpoint auto-create `externalProductMappings` entries with `source="grabfood"`
- Admin manually maps GrabFood product codes to internal menu products via inline dropdown in Settings
- **Auto-create on sync** — when menu is pulled from GrabFood, unmapped product codes appear automatically for mapping
- No auto-creation of internal orders — GrabFood integration is passive/observational

### Menu sync failure notification
- When GrabFood reports PARTIAL_FAILURE or FAILED on a menu sync job, show a warning banner in the Webhooks tab
- Banner reads from latest syncLog entry for source="grabfood" + syncType="webhook"

### Settings UI — Webhooks tab
- **New tab** "Webhooks" in GrabFoodManager (separate from existing Settings tab)
- **HMAC Secret field** — password input with show/hide toggle, saves to `platformCredentials.hmacSecret`
- **Webhook URLs** — 6 read-only URLs with copy-to-clipboard buttons, auto-detected from current environment (dev vs production)
- **GrabFood price** — editable per product mapping in the Settings tab (alongside SKU mapping dropdown)
- **Availability toggle** — per product mapping, controls whether item is served in GET /menu response
- **Sync error banner** — shows at top of Webhooks tab when last menu sync had errors
- Clean and simple — no status indicators, no last-received timestamps

### Claude's Discretion
- Exact HMAC validation implementation details
- SyncLog entry structure for webhook events
- How to derive the Convex site URL from the current environment
- Console.log format for webhook payloads
- Error banner styling and dismissal behavior

</decisions>

<specifics>
## Specific Ideas

- "I'm only using this to track transactions and do sales reporting right now" — orders are accepted from the GrabFood Merchant App, not from our system
- Platform-specific pricing follows the same pattern as other platforms (GoFood, BigSeller)
- The existing `upsertOrder` mutation in `grabfoodOrders/mutations.ts` should be removed as part of cleanup
- App Simulator test cases #1-7 need HTTP 200 responses + valid menu JSON, but we don't need to interact with the order lifecycle
- Production merchant ID: `6-C7XYAECCTNKXJ6`

</specifics>

<deferred>
## Deferred Ideas

- **Manual order accept/reject from our UI** — if they ever want to accept GrabFood orders from the web app instead of the phone app, that's a separate phase
- **Order persistence** — storing GrabFood orders in DB for display/analytics is a future capability if the passive logging proves insufficient
- **Multiple menu sections/categories** — currently single section is fine, but may need expansion as product line grows
- **Inventory-linked availability** — automatically marking items unavailable based on stock levels

</deferred>
