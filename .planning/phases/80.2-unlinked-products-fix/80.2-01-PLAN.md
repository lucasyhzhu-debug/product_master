## Risk Register

| Risk | Mitigation |
|------|-----------|
| Backfill hits a deleted order and crashes | Explicit `skippedMissingOrder` branch; log + continue. |
| Backfill hits an order with empty orderItems | Explicit `skippedEmptyOrderItems` branch; log + continue (no insert attempt). |
| Backfill exceeds Convex write limit on large datasets | Paginated-primary design with default limit 200, caller loops cursor. |
| New index on `externalRevenue` triggers rebuild lag in prod | Convex index build is background and non-blocking for queries; run during low-traffic window. Commit schema change alone for easy rollback. |
| Continue-guard change causes duplicate child inserts | `saveRevenueItems` already dedups by `(revenueId, externalItemId)` (mutations.ts:752-759); additionally, the new existence pre-check gates entry. |
| Return type change in `applyRetroactiveProductMappingImpl` breaks callers | Additive-only change: new `externalRevenueUpdated` field alongside existing `updatedItems` and `bigsellerUpdated`. All 3 call sites (mutations.ts:625, 651, 711) just return the object; no field destructuring. Grep confirms zero frontend reads of these fields. |
| Prod K3Mart parents with null `externalProductCode` slip past cascade | Wave 4.2 pre-flight query catches this; escalate if count > 0 (out of scope). |
| Bad mapping propagates via cascade, linking wrong menu product | Rollback path: re-run `applyRetroactiveProductMapping` with `menuProductId: undefined` to un-link; Wave 4.5 Convex export provides point-in-time restore. |
| Paginated backfill leaves work half-done if mutation fails mid-page | Convex mutations are transactional per invocation; failure rolls back writes but `continueCursor` is returned on success only. Next invocation re-processes the same page (idempotent). |

## Rollback Procedure

1. **Code rollback:** revert the feature branch merge commit on main; CI redeploys previous Convex code.
2. **Data rollback (K3Mart cascade):** re-run `applyRetroactiveProductMapping` for each mapped SKU with `menuProductId: undefined` to un-link parents.
3. **Data rollback (Direct backfill):** delete `externalRevenueItems` rows inserted by backfill, identifiable by `externalItemId` prefix `{orderNumber}-` AND `createdAt >= <backfill-timestamp>`. Alternatively, restore from `npx convex import` of the Wave 4.5 export.
4. **Schema rollback:** the added index is additive; removing it is safe (drop from schema.ts and push). Queries would silently fall back to full-table scan (slow but correct).
