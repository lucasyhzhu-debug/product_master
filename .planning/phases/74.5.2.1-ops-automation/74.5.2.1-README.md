# Phase 74.5.2.1 — Ops Automation (close 74.5.2 operational gaps)

## Why this phase exists

Phase 74.5.2 (unified-deduct-cutover) shipped with 3 operational follow-ups that would otherwise become manual-forever rituals:

1. Admin must flip `channelDeductionEnabled.gobiz` ON immediately post-deploy
2. Admin must flip BOTH `k3mart` + `consignment` flags together (D74.5.2-L14 composite toggle was deferred)
3. Admin must manually deduct stickers daily until 74.5.3 ships packaging BOM resolution

Items 1 and 2 are small (<1-2h each) and permanent fixes — 74.5.2.1 closes them.

Item 3 (sticker BOM auto-deduction) belongs to a proper **74.5.3** phase (see §Scope below — 74.5.3 does NOT exist yet as of 2026-04-21; references in 74.5.2 deferred-items.md are conceptual placeholders).

## Scope

### In scope
1. **Plan 01 — Auto-enable gobiz channel deduction on deploy.**
   - New `internal` mutation `ensureGobizChannelDeductionOn` that idempotently flips the flag to `true` if currently `false`/undefined.
   - GitHub Actions post-deploy step in `.github/workflows/deploy.yml` invoking it via `npx convex run --prod`.
   - Tests: idempotency (no-op when already true), missing-settings-row handling.
2. **Plan 02 — K3Mart composite flag toggle UI (D74.5.2-L14).**
   - New `mutation` `flipK3MartBundle({ enable, token })` that atomically patches both `k3mart` and `consignment` keys.
   - New composite button in `src/pages/ProductInventorySettings.tsx` — single affordance above the per-source switches labeled "Flip K3Mart bundle (both paths)".
   - Tests: auth gate, atomic-both-keys behavior.
3. **Plan 03 — Deferred-items cleanup + docs.**
   - Update `.planning/phases/74.5.2-unified-deduct-cutover/deferred-items.md`: mark items #4 (gobiz auto-flip) and #5 (K3Mart composite) as RESOLVED; keep #2 (sticker gap), #3 (shim governance), #6 (token pattern) open — repoint #2 to a new `74.5.3-packaging-bom-deduction` phase candidate.
   - Update `docs/CHANNEL_INTEGRATION.md`: update flag-flip procedure (now automatic), update K3Mart bundle section (now one-click).
   - Update `docs/CHANGELOG.md`.

### Out of scope (deferred)
- **Sticker auto-deduction (item #2 in deferred-items.md)** — requires BOM-resolution logic in `processChannelSaleInternal` + per-source packaging mapping. This is a proper feature extension, NOT an ops cleanup. Candidate for a new phase `74.5.3-packaging-bom-deduction`.
- **Shim pattern governance (item #3)** — TESTING_GUIDE.md entry + CI grep check. Belongs with testing infrastructure work.
- **Token-in-query-args pattern (item #6)** — project-wide security review, needs its own phase.

## Success criteria
- [ ] `ensureGobizChannelDeductionOn` is idempotent and tested (truthy-already + falsy-toggle + no-settings-row branches).
- [ ] `.github/workflows/deploy.yml` invokes the flag-flip step after Convex deploy (or documented in deploy runbook if CI structure differs).
- [ ] `flipK3MartBundle` mutation is admin-gated via `requireRole`, atomically patches both flag keys, returns final state.
- [ ] `ProductInventorySettings.tsx` shows a prominent composite toggle (disabled while loading current settings).
- [ ] `npm run type-check` PASS; `npm run build` PASS; full test suite green.
- [ ] `deferred-items.md` items #4 and #5 marked RESOLVED with commit references.
- [ ] CHANNEL_INTEGRATION.md no longer instructs manual flag-flip (items covered by automation).

## Effort estimate
- Plan 01: ~1.5h (mutation + 3 tests + CI workflow edit)
- Plan 02: ~1.5h (mutation + 2 tests + UI button + hook)
- Plan 03: ~30min (doc updates + commit)

Total: ~3.5h across 2 waves (backend+CI and UI in parallel, then docs).

## Risks
- **Convex CI secret for prod invocation** — the deploy workflow already has prod auth; the post-deploy step just chains a second `npx convex run --prod` call. Low risk.
- **Rollback** — if `flipK3MartBundle` is mis-clicked in prod, the existing per-source toggles can still flip flags independently. Revert is a single admin click per flag.
