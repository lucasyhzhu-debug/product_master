# Plan 01 — Auto-enable gobiz channel deduction post-deploy

## Objective

Automate the 74.5.2 operational reminder "Flip `channelDeductionEnabled.gobiz` ON immediately post-deploy" by adding an idempotent internal mutation + GitHub Actions post-deploy step. Eliminates the manual ritual and the recoverable under-deduction window.

## Context

Phase 74.5.2 cut over GoFood to the unified `channel_sale` dispatch but left the feature flag OFF by default. The runbook instructs admins to flip it ON via `/admin/product-inventory-settings` immediately after deploy. The window between deploy-complete and flag-flip is a recoverable under-deduction window — manual enough to be error-prone.

## Tasks

### Task 1: Create `ensureGobizChannelDeductionOn` internal mutation

**File:** `convex/productInventory/startupMigrations.ts` (NEW)

Create a new Convex module with an internal mutation that:
1. Reads the (singleton) `productInventorySettings` row.
2. If no row exists: return `{ skipped: "no-settings-row" }`.
3. If `channelDeductionEnabled.gobiz === true`: return `{ already_on: true }`.
4. Otherwise: patch `channelDeductionEnabled: { ...existing, gobiz: true }` and return `{ flipped: true }`.

Guarantees:
- **Idempotency:** Multiple invocations are safe — the `already_on` guard prevents redundant writes.
- **No clobber:** Spreads existing `channelDeductionEnabled` object so sibling flags (shopee, tiktok, etc.) are preserved.
- **Admin-only export pattern:** Internal mutation, invoked via `npx convex run --prod` with admin credentials (not exposed as public API).

### Task 2: Test suite

**File:** `convex/productInventory/__tests__/startupMigrations.test.ts` (NEW)

Three tests using `convexTest` + the D74.5.2-L1 direct-handler shim pattern if module resolution needs it:
1. **T1 `no settings row → skipped`:** empty DB, call mutation, assert `{ skipped: "no-settings-row" }`.
2. **T2 `gobiz already true → no-op`:** seed settings with `channelDeductionEnabled: { gobiz: true }`, call, assert `{ already_on: true }` AND no patch occurred (verify `channelDeductionEnabled` unchanged by comparing before/after).
3. **T3 `gobiz false/undefined → flipped, siblings preserved`:** seed `{ shopee: true, gobiz: false }`, call, assert `{ flipped: true }` AND post-state is `{ shopee: true, gobiz: true }`.

### Task 3: GitHub Actions post-deploy step

**File:** `.github/workflows/deploy.yml` (MODIFY)

Add a new step AFTER the existing Convex deploy step, BEFORE the Vercel deploy step (so the flag is flipped before the frontend can route traffic to the new code):

```yaml
- name: Ensure gobiz channel deduction flag is ON
  run: npx convex run --prod productInventory/startupMigrations:ensureGobizChannelDeductionOn
  env:
    CONVEX_DEPLOY_KEY: ${{ secrets.CONVEX_DEPLOY_KEY }}
```

Verification note: if the existing workflow doesn't have a clean Vercel-after-Convex ordering, add the step right after Convex deploy and note the timing in the PR description.

## Rollback
If the CI step causes a deploy failure, remove the step from `deploy.yml` and keep the mutation in the codebase (no prod impact). The mutation is dormant without CI invocation.

## Pitfalls
1. **Convex CLI version** — `npx convex run --prod` requires Convex CLI >= 1.x (current project uses compatible version). No extra install needed.
2. **Deploy key scope** — `CONVEX_DEPLOY_KEY` must have permission to invoke mutations, not just deploy functions. Check `.github/workflows/deploy.yml` existing permissions; if scoped narrowly, may need a separate invocation secret.
3. **Singleton settings row** — `productInventorySettings` is treated as a singleton elsewhere in the codebase (e.g., `initializeSettings`). Use `.first()`, not `.collect()`.
