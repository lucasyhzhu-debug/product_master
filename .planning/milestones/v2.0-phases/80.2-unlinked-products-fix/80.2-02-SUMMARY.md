## Decisions Made

- **`by_order_number`, not `by_orderNumber`** — plan text referenced `by_orderNumber` but the actual schema index name on `orders` (line 319) is `by_order_number` (snake_case). This is a Rule 3 blocking fix (plan's index name wouldn't resolve at type-check time). Documented inline and used in the backfill helper.
- **Bundled Tasks 2.2 + 2.3 into one commit** — both tasks touch only `mutations.ts` and Task 2.3 depends directly on Task 2.2's `backfillInternalRevenueItemsPageImpl`. Splitting would produce an intermediate commit with an exported private helper and no public caller — awkward for review. The plan's checkpoint section endorses a single "fix(revenue): …" commit covering the wave, so this is in-spec.
- **api.d.ts grep assertion in plan is a false positive** — Convex codegen uses module-typeof reflection (`typeof externalData_mutations`) rather than inlining function names. `grep -q 'backfillInternalRevenueItems' convex/_generated/api.d.ts` returns 0, but the function IS reachable via `api.externalData.mutations.backfillInternalRevenueItems` and the type-check confirms it (the adapter's `internal.externalData.queries.hasExternalRevenueItemsQuery` resolves cleanly). The plan's assertion was over-strict — no file change required.
- **Halt-loud failure mode for the guard** — the plan explicitly decided "do not silently swallow query errors" and the adapter comment documents this. A try/catch around `hasExternalRevenueItemsQuery` would silently re-create the orphan-creation bug on every transient failure with no error in logs. Halt-loud is recoverable (operator re-runs once Convex stabilizes); silent skip is corruption that compounds.
