## Structure

The runbook is organized as a numbered TOC + 7 operational sections + FAQ:

1. **Architecture overview** — 1-paragraph recap of 74.5.1 spine + 74.5.2 cutover, pointing at parent RESEARCH for the 1098-LOC architectural doc. Documents the 5 key tables (`productInventorySettings.channelDeductionEnabled`, `channelRouting`, `channelAuditIssues`, `externalRevenueItems.inventoryDeductedAt`, `productInventoryTransactions.transactionType + source`), key constants (the `"gobiz"` landmine), and key interfaces (`ChannelAdapter` + 5-tier `resolveChannelRoute`).

2. **Onboarding a new channel** — 9-step recipe: add to `externalSource` union, implement `ChannelAdapter`, add `channelDeductionEnabled` key, wire `saveRevenueItems` dispatch (no-op since it's source-agnostic), seed routing rules (minimum: Tier 4 default), add platform colors, add backfill card, write integration tests, flip flag + soak. Code snippet shows the `ChannelAdapter` literal shape directly.

3. **74.5.2 cutover runbook** — D-12 cutover order + GrabFood skip rationale (D74.5.2-L15). Per-channel procedure (non-GoFood): backfill → audit → flip → soak → verify parity + sampling spot-check. Includes copy-pasteable Convex dashboard queries for daily row count, SC4 parity assertion, and 10-row sampling spot-check. K3Mart bundle flip section clarifies D74.5.2-L14 (both `k3mart` + `consignment` toggles together). GoFood atomic cutover walks through the 6-step sequence with an explicit IMMEDIATELY callout at step 4 + window-analysis explainer for why the ordering minimizes risk.

4. **Audit issue triage** — 5 exact `AuditIssueType` literals with severity + meaning + resolution. Grep-verified against `convex/productInventory/channelAudit.ts` AuditIssueType union (NOT the planner template's incorrect `wrong_location` / `zero_quantity_non_return` placeholders). Documents the two-tier detection split (cheap inline vs expensive `runFullAudit`) and dismiss-vs-fix semantics.

5. **Backfill operations** — D-19 idempotency guarantee (set-once `inventoryDeductedAt`), D-17 informational audit gate, D74.5.2-L13 flag-independence, D-18 progress card contents, D74.5.2-L15 GrabFood permanent-OFF. Explains the 5-step server-side flow (index query → skip-unmapped → call `processChannelSaleInternal` with historical `occurredAt` → patch `inventoryDeductedAt` on success → return stats).

6. **Rollback procedures** — 4 cases (A: double-deduct, B: under-deduct, C: wrong location, D: total rollback). Case D includes the concrete revert-SHA pattern for GoFood rollback (`git revert -m 1 <merge-sha>`). Cases A-C point at existing mutations + admin UI; no new tooling per D74.5.2-L10.

7. **Known gaps and follow-ups** — 5 explicitly-scoped gaps: sticker auto-deduction (post-retirement gap, follow-up candidate), `channelDeductionEnabled` field drop (deferred, D74.5.2-L8), `gofood_sale` literal drop (deferred, D74.5.2-L6), `tsc -b` build errors in gofoodSaleToChannelSale.ts (Plan 10 owns per deferred-items.md), 74.5.1 HUMAN-UAT items (auto-resolve during cutover per D74.5.2-L11).

8. **Troubleshooting FAQ** — 9 common Q&A pairs covering the most likely admin confusions (unmapped SKU invisibility, flag spike post-flip, `gobiz` vs `gofood` literal, migration time-limit, empty consignment breakdown, routing throw, flag-OFF backfill, re-run double-deduction risk, deploy-flag window slippage, rollback SHA lookup).
