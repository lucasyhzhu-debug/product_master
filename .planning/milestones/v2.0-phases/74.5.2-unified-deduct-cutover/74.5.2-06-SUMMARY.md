# Phase 74.5.2 Plan 06: Admin Backfill UI Summary

One-liner: Extended /admin/unlinked-products-backfill with a "Channel Deduction Backfill" section containing 6 per-source cards (Shopee, TikTok, BigSeller, K3Mart, GoFood, GrabFood) driven by a new admin public mutation `runOneChannelBackfillPage` + React hooks — shared helper refactor avoids `ctx.runMutation` indirection and D-17 audit gate is informational-only.

## Outcome

- Shared helper `backfillOnePageImpl` extracted (mirror of `saveRevenueItemsImpl` pattern); `backfillOnePage` internalMutation and new `runOneChannelBackfillPage` admin mutation both delegate via plain function call — no indirection.
- 2 React hooks shipped: `useChannelBackfillPreflight(source)` reactive + `useRunChannelBackfill()` client-loop runner.
- Admin page gains a 4th Card section "Channel Deduction Backfill" with 6 per-source sub-cards (responsive `sm:grid-cols-2 lg:grid-cols-3`).
- Per-source audit gate is informational: blocking issues render a yellow `⚠` banner with a link to `/admin/channel-audit`, but the backfill button remains clickable.
- GrabFood (D74.5.2-L15) renders a dedicated "Awaiting OAuth scope — no items to backfill yet" state and disables its button via `isGrabFoodAwaitingScope`.
- `npm run type-check` passes
- `npm run build` passes (22.86s, no bundle-size violations)
- `npm run lint` introduces zero new errors on the files touched by this plan; pre-existing lint errors elsewhere unchanged.
