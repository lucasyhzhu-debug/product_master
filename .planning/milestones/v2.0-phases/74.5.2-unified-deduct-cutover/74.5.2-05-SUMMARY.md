## Deviations from Plan

### [Rule 3 - Cross-plan bridge] Direct-handler test shims forward-declared for Plan 04

**Found during:** Task 1 implementation (pre-authoring analysis of Plan 03 SUMMARY).
**Issue:** Plan 05's SPEC code uses `ctx.runMutation(internal.migrations.gofoodSaleToChannelSale.migrateOnePage, ...)` inside `t.run`. Plan 03's SUMMARY (commit `e6c2912a`, decisions block, and Verification Gate §Deviations) proves this pattern FAILS with convex-test 4.0.18 for files under `convex/productInventory/` — specifically the `modulesWithoutExtension[prefix + path]` lookup at `node_modules/convex-test/dist/index.js:1062` returns `undefined` for sibling-test glob results. The migrations directory inherits the same resolver issue (same prefix depth, same lookup path shape: `"../../migrations/gofoodSaleToChannelSale"`).

**Fix:** Adopted the Plan 01 + Plan 03 established pattern — direct-handler invocation via `_fooForTest` exports. Plan 04's action file must include three such exports:
- `_migrateOnePageForTest(ctx: MutationCtx, { paginationOpts })` — replicates `migrateOnePage` handler verbatim against `MutationCtx`.
- `_migrateGofoodSaleToChannelSaleForTest(ctx: ActionCtx, { triggeredBy })` — replicates the internalAction handler.
- `_runGofoodSaleToChannelSaleMigrationForTest(ctx: MutationCtx, { token })` — replicates the public runner's `requireRole` + scheduler hop.

This mirrors:
- `convex/productInventory/channelAudit.ts` `_runFullAuditForTest` (Plan 01, commit `8d81e4d3`).
- `convex/productInventory/backfill.ts` `_backfillOnePageForTest` / `_runChannelBackfillForTest` / `_getChannelBackfillPreflightForTest` (Plan 03, commit `e6c2912a`).

**Why Rule 3 (blocking) vs Rule 1 (bug):** The plan's spec code uses the failing pattern, but Plan 01 and Plan 03 already established that this workaround is unavoidable for `convex/migrations/` and `convex/productInventory/` module paths under the current convex-test version. Proceeding with the plan's literal spec would produce RED tests indefinitely; the established workaround is the only viable pattern.

**Files modified (Plan 04 follow-up needed):**
- `convex/migrations/gofoodSaleToChannelSale.ts` — Plan 04 executor (parallel worktree) must add the three `_fooForTest` exports. If Plan 04 ships without them, the post-merge test gate will fail with `Cannot find module ../gofoodSaleToChannelSale` or `_migrateOnePageForTest is not a function`. The orchestrator should either (a) inject the shims during the wave merge or (b) open a follow-up ticket in 74.5.2 against Plan 04 to add them (non-behavioral, additive).
