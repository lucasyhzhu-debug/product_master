## Which Fix (of 1/2/3/4) Resolved the Bug

**Hypothesis 1 (preferred per RESEARCH.md and Task 0 diagnostic):**
Direct-handler invocation via a new `_runFullAuditForTest` export in `convex/productInventory/channelAudit.ts`. Tests invoke the helper inside `t.run(async (ctx) => ...)` — the same pattern used by the known-green `channelSale.test.ts` in the same directory.

Hypotheses 2, 3, 4 (glob suffix / eager flag / convex-test version parity) were NOT attempted — Hypothesis 1 succeeded on the first run, all 7 tests green and type-check clean.

## Root Cause

`t.action(internal.productInventory.channelAudit.runFullAudit, ...)` throws `Could not find module for: "productInventory/channelAudit"` at `node_modules/convex-test/dist/index.js:1062` (`Object.actionFromPath` → `getFunctionFromPath` → `modulesWithoutExtension[prefix + path]`).

The glob pattern `import.meta.glob("../../**/*.ts")` is identical to the glob in `channelSale.test.ts` (same directory, green). The differentiator is the `t.action(internal.*)` invocation itself — `channelSale.test.ts` uses `t.run(async (ctx) => processChannelSaleInternal(ctx, ...))` and passes 8/8, never invoking `t.action`. This rules out the glob pattern as the cause and points to convex-test's `actionFromPath` resolver as the failing code path.

The `productSubstitution.test.ts` reference in RESEARCH.md uses a different glob shape `"../../convex/**/*.*s"` from a different directory depth (`tests/convex/`), making direct comparison non-trivial. Hypothesis 1 sidesteps the `t.action` code path entirely, matching the proven in-directory pattern from `channelSale.test.ts`.

## Final Glob Pattern Used

Unchanged — `import.meta.glob("../../**/*.ts")`. The fix does NOT alter the glob; it alters the invocation style.

## Convex-test Version Observations

- `convex-test` 4.0.18 (Vitest + convex-test both locked at 4.0.18 per package-lock).
- `actionFromPath` resolver at `node_modules/convex-test/dist/index.js:1062` is the failure site.
- `findModulesRoot` (line 1067) extracts a prefix from the first key containing `_generated`. For globs rooted at `convex/productInventory/__tests__/`, prefix resolves to `"../../"`, so lookup becomes `"../../productInventory/channelAudit"`. Why this specific lookup fails while the file IS in the glob result set remains unexplained — but since `t.run` + direct handler invocation works identically in `channelSale.test.ts`, the fix was to use that pattern rather than debug convex-test internals.

## Implementation Notes

**New export in `channelAudit.ts`:** `_runFullAuditForTest(ctx: MutationCtx, args: {triggeredBy: string})` — replicates the `runFullAudit` handler body verbatim, calling `ctx.db.*` directly instead of `ctx.runQuery`/`ctx.runMutation` on internal refs. Production `runFullAudit` `internalAction` export is unchanged — continues to call its paginated `internalQuery`/`internalMutation` helpers in live flow.

**Single-page scan in the helper:** Tests seed <20 items; `ctx.db.query("externalRevenueItems").collect()` is O(seed-size). Production path keeps `paginate()` for 10K+ row safety.

**Import style in the test:** `import { detectAuditIssuesForItem, _runFullAuditForTest } from "../channelAudit"`. The `api`/`internal` imports are retained for potential future tests but are currently only touched via the `void api` line at EOF (unchanged). `internal` remains imported but unused — tolerated, matches pre-fix state.
