## Decisions Made

- **Expand placement: SettlementTimeline.tsx, not OutletCard.tsx** — PLAN explicitly allows either file; SettlementTimeline renders each settlement row and was the natural site for per-row expand. OutletCard already delegates settlement display to it.
- **Create-only items inputs** — Editing items on existing settlements is out of Plan 07 scope (read-only breakdown display is sufficient for viewing). Keeps write-side contract simple; `updateSettlement` mutation unchanged.
- **Raw Convex `useQuery` for menuProducts picker, not `useMenuProducts`** — The `useMenuProducts` hook transforms to legacy snake_case shape that hides `_id` and `defaultPrice`. Matches AnalyticsFilterBar, AddStockDialog, BigSellerOrdersTable pattern.
- **Auto-fill from product picker: productName + unitPrice** — When a menuProduct is selected, unit price auto-fills from `defaultPrice` for fast row creation; admin can still override.
- **Direct-handler test shims for consignment subtree** — convex-test's module resolver fails with `"Could not find module for: consignment/queries"` (same class as D74.5.2-L1 productInventory/* bug). Exported `_getSettlementItemsForTest` + `_getSettlementItemsWithAuthForTest` for test invocation via `t.run(ctx => ...)` bypasses the broken resolver.

**4. [Rule 3 - Blocking] convex-test module-resolution bug on consignment/* subtree**
- **Found during:** Task 1 (running `npm run test -- --run convex/consignment/__tests__/getSettlementItems.test.ts`)
- **Issue:** `t.query(api.consignment.queries.getSettlementItems, ...)` threw `Error: Could not find module for: "consignment/queries"` on 4 of 6 tests. Same class as D74.5.2-L1 (`productInventory/*` subtree) discovered in Plan 01. The convex-test glob/resolver pairing fails for certain subtrees in this project.
- **Fix:** Refactored `getSettlementItems` handler to delegate to a shared `_getSettlementItemsForTest(ctx, id)` pure helper; added `_getSettlementItemsWithAuthForTest(ctx, id, token)` for the role-gated path. Tests invoke the helpers via `t.run(async (ctx) => _getSettlementItemsForTest(ctx, id))` — bypasses the broken resolver. Same pattern as `_runFullAuditForTest` in `convex/productInventory/channelAudit.ts` from Plan 01.
- **Files modified:** `convex/consignment/queries.ts`, `convex/consignment/__tests__/getSettlementItems.test.ts`
- **Verification:** All 7 tests pass; full vitest suite stays green (1709 passed, 2 skipped, zero regressions)
- **Committed in:** `9ee24163`

**5. [Rule 3 - Blocking] Pre-existing `tsc -b` errors in `convex/migrations/gofoodSaleToChannelSale.ts` block build**
- **Found during:** Task 2 (running `npm run build` after SettlementFormDialog changes)
- **Issue:** Prior-wave commit `01328888` shipped `migrateGofoodSaleToChannelSale` with (a) unused `args` parameter (TS6133) and (b) recursively-typed `result` variable in a while loop reading from `ctx.runMutation(internal.*)` — TypeScript cannot infer the result type before the action's own return type is known, triggering TS7022. Verified present at Task 1 baseline (`9ee24163`) — NOT introduced by my work.
- **Fix:** Prefixed unused parameter with `_` (`_args`) + added explicit return-type annotation on the `ctx.runMutation` result (`{ migrated, isDone, continueCursor }`) to break the inferential cycle.
- **Files modified:** `convex/migrations/gofoodSaleToChannelSale.ts`
- **Verification:** `npm run build` passes; zero semantic change (action behavior unchanged; `triggeredBy` arg still accepted and passed through by the scheduler; migration loop logic unchanged)
- **Committed in:** `47eb8920` (Task 2 commit, bundled per deviation protocol)
