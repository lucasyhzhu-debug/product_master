# Plan 02 — K3Mart composite flag toggle (D74.5.2-L14)

## Objective

Ship the D74.5.2-L14 composite affordance that was deferred from 74.5.2: a single button in `ProductInventorySettings.tsx` that atomically flips BOTH `k3mart` and `consignment` flags. Eliminates the risk of an operator flipping only one flag and violating the K3Mart bundle invariant.

## Context

CONTEXT decision D74.5.2-L14 specified: "Flip K3Mart (both paths)" composite toggle that atomically sets both `channelDeductionEnabled.k3mart` and `channelDeductionEnabled.consignment` in one mutation. Phase 74.5.2 shipped only the 6 individual per-source backfill cards + per-flag switches; the composite UI was never added. The interim runbook guidance tells admins to flip both flags manually — error-prone and D74.5.2-L14 non-compliant.

## Tasks

### Task 1: Admin-gated composite mutation

**File:** `convex/productInventory/mutations.ts` (MODIFY — append new `flipK3MartBundle` export)

New `mutation` (public, admin-gated):
```typescript
export const flipK3MartBundle = mutation({
  args: { enable: v.boolean(), token: v.string() },
  handler: async (ctx, args) => {
    await requireRole(ctx, args.token, ["admin"]);
    const settings = await ctx.db.query("productInventorySettings").first();
    if (!settings) throw new Error("productInventorySettings row not found — call initializeSettings first");
    const nextFlags = {
      ...(settings.channelDeductionEnabled ?? {}),
      k3mart: args.enable,
      consignment: args.enable,
    };
    await ctx.db.patch(settings._id, { channelDeductionEnabled: nextFlags });
    return {
      k3mart: args.enable,
      consignment: args.enable,
    };
  },
});
```

Guarantees:
- Admin-only via `requireRole`.
- Atomic (single `patch` call — Convex mutation is transactional).
- Preserves all other sibling flags (spread over `channelDeductionEnabled`).
- Returns the final state of the two flipped flags for UI confirmation.

Implementation sketch:
```tsx
const settings = useQuery(api.productInventory.queries.getSettings);
const k3mart = settings?.channelDeductionEnabled?.k3mart ?? false;
const consignment = settings?.channelDeductionEnabled?.consignment ?? false;
const bothOn = k3mart && consignment;
const bothOff = !k3mart && !consignment;
const outOfSync = !bothOn && !bothOff;
const flip = useFlipK3MartBundle();

const handleClick = async () => {
  const result = await flip({ enable: !bothOn, token: user!.token });
  toast.success(`K3Mart bundle: k3mart=${result.k3mart}, consignment=${result.consignment}`);
};
```

## Pitfalls
1. **Singleton settings row** — use `.first()`, not `.collect()`. Consistent with other settings mutations.
2. **Spread order** — spread `channelDeductionEnabled` FIRST, then override `k3mart`/`consignment`. Inverted order would clobber user's other flags.
3. **Out-of-sync detection** — the "OUT OF SYNC" pill is defensive UX; it can trigger if an admin used the per-source switches to flip only one flag. The composite button's next-click always restores consistency.
4. **No direct schema change** — `channelDeductionEnabled` is already `v.optional(v.record(v.string(), v.boolean()))` or equivalent loose-map type; no schema edit needed.
