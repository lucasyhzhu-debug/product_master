## Files Created/Modified

## Decisions Made

- **Resolution = record decision, not mutate data (74.5.1 scope):** Remap SKU / Re-link mapping / Merge duplicate / Delete orphan all call `resolveAuditIssue` with a resolution string. Data mutations (linkedMenuProductId patch, row deletion) happen in `/admin/product-mappings` or a separate DB repair — the audit page opens that surface in a new tab via `window.open`. Avoids reimplementing mapping UI in this plan.
- **Dismiss is reversible, Delete Orphan is destructive:** Dismiss uses AlertDialog default confirm variant (UI-SPEC §Destructive Confirmations: "not destructive — reversible by re-audit"). Delete Orphan resolve button uses destructive variant because the orphan cannot be recovered.
- **Bulk via loop, not new backend endpoint:** Keeps 74.5.1 backend surface minimal; per-item failures aggregated into one toast. Future optimization if >100 bulk items become common.
- **Orphan row deletion deferred:** 74.5.1 records the decision. Actual `ctx.db.delete` on orphan rows is deferred to 74.5.2 or manual Convex dashboard — avoids adding a destructive backend mutation in a plan that's primarily UI scope.
