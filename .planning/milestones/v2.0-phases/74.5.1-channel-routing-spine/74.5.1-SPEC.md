## Goal

All six channels (GoFood, Shopee, TikTok, BigSeller, K3Mart, internal) flow through one
atomic `saveRevenueItems` entry that writes revenue AND deducts inventory, driven by an
admin-configurable `channelRouting` table, with full historical deduction backfill
preserving original sale timestamps.

---

## Background

**Current state (from codebase scout 2026-04-19):**

- Five adapter directories exist: `convex/integrations/{gobiz,bigseller,internal,k3mart,grabfood}/`
- `saveRevenueItems` (`convex/externalData/mutations.ts:787`) is called by 3/5 adapters
  (gobiz, bigseller, internal) but performs **no inventory deduction**.
- `processGofoodSales` (`convex/productInventory/mutations.ts:716`) is the **only**
  current deduction path — GoFood-exclusive, uses `transactionType: "gofood_sale"`.
- Shopee, TikTok, BigSeller, K3Mart, and internal sales have **zero inventory deduction**.
- No `channelRouting` table. GoFood routing comes from `externalOutlets.linkedStorageLocationId`.
- No `channelAuditReports`, `channelAuditIssues`, or `inventoryDeductedAt` fields.
- Phase 78 deliverables `stockTracker.ts` + `substitution.ts` exist and are ready to reuse.
- Phase 79 populated `linkedMenuProductId` on Shopee/TikTok items — SKU resolution groundwork done.
- Phase 80 delivered `externalSourceToDisplayChannel` + `channelTaxonomy.ts` — reuse, do not reinvent.

**Gap:** Every channel except GoFood produces stock drift daily. Adding a new channel today
requires replicating three different patterns.

## Requirements

1. **ChannelAdapter contract + ChannelSaleEvent type**: A shared `ChannelAdapter` interface
   and `ChannelSaleEvent` canonical type exist; all five adapters implement the interface.
   - Current: No unified adapter interface. Each adapter normalizes raw payloads with its
     own pattern. No shared event type.
   - Target: `convex/integrations/_shared/channelAdapter.ts` exports `ChannelAdapter`
     interface (`{ source, fetch(), normalize() }`) and `ChannelSaleEvent` type. All five
     adapters (gobiz, bigseller, internal, k3mart, grabfood) implement `ChannelAdapter`
     and emit `ChannelSaleEvent[]` from `normalize()`.
   - Acceptance: `npm run type-check` passes; `grep -r "ChannelSaleEvent"` returns hits in
     all five adapter files; no adapter imports its own normalization shape — only
     `ChannelSaleEvent`.

2. **channelRouting table + resolveChannelRoute**: A `channelRouting` Convex table stores
   admin-configured routing rules; `resolveChannelRoute()` resolves `(source, outlet?,
   product?)` to a `storageLocationId` using 5-tier precedence.
   - Current: `channelRouting` does not exist. GoFood routing is implicit via
     `externalOutlets.linkedStorageLocationId`. No routing for any other channel.
   - Target: `channelRouting` table in schema with indexes `by_source`,
     `by_source_outlet`, `by_source_product`, `by_source_outlet_product`.
     `resolveChannelRoute()` checks Tier 1 (source+outlet+product) → Tier 2
     (source+outlet) → Tier 3 (source+product) → Tier 4 (source default) → Tier 5 throw
     `CHANNEL_ROUTING_NOT_CONFIGURED`. Seeded from existing GoFood outlet mappings via
     migration.
   - Acceptance: Unit tests cover all 5 tiers including Tier 5 throw. Type-check passes.
     A source with no routing row causes `CHANNEL_ROUTING_NOT_CONFIGURED` throw — not a
     silent fallback to any default location.

3. **saveRevenueItems becomes atomic revenue + deduction entry**: `saveRevenueItems`
   dispatches `processChannelSaleInternal` for each eligible item inside the same mutation.
   - Current: `saveRevenueItems` writes `externalRevenueItems` only. No deduction dispatch.
     GoFood deduction happens separately via `processGofoodSales`.
   - Target: After writing revenue items, `saveRevenueItems` iterates eligible items
     (linkedMenuProductId != null, quantity > 0, inventoryDeductedAt == null) and calls
     `processChannelSaleInternal(ctx, event)`. Sets `inventoryDeductedAt = Date.now()` on
     success. Entire mutation rolls back if deduction throws.
   - Acceptance: Integration test confirms revenue row + inventory transaction created in
     one mutation call. Running the same items twice produces zero additional transactions.
     `inventoryDeductedAt` is set on deducted items and null on skipped items.

4. **processChannelSaleInternal — Layer 4 deduction core**: New internal helper resolves
   routing, applies substitution plan, deducts stock, and writes a `channel_sale`
   transaction row with the historical `occurredAt` timestamp.
   - Current: Does not exist. Closest analogue is `processGofoodSales` (GoFood-only,
     hard-coded outlet lookup, no substitution plan reuse).
   - Target: `convex/productInventory/channelSale.ts` exports
     `processChannelSaleInternal(ctx, event: ChannelSaleEvent)`. Calls Phase 78's
     `resolveSubstitutionPlan` + `stockTracker` pattern. Inserts
     `productInventoryTransactions` row: `transactionType: "channel_sale"`,
     `source: event.source`, `createdAt: event.occurredAt`, `quantity: -event.quantity`,
     `externalRef: externalTransactionId + externalItemId`. Negative stock always allowed.
   - Acceptance: Integration test with Phase 78 stock tracker bridge passes. GoFood stock
     outcomes after cutover are byte-for-byte identical to `processGofoodSales` outcomes
     in regression snapshot test.

5. **processGofoodSales retired + gofood_sale literal migrated**: The legacy GoFood
   deduction path is removed; all existing `gofood_sale` transaction rows are migrated to
   `channel_sale` + `source: "gofood"`.
   - Current: `processGofoodSales` is live at `productInventory/mutations.ts:716`. Schema
     has `v.literal("gofood_sale")` in `productInventoryTransactions.transactionType`.
   - Target: GoFood adapter reroutes through `saveRevenueItems` → `processChannelSaleInternal`.
     `processGofoodSales` function deleted. Migration updates all `transactionType:
     "gofood_sale"` rows to `{ transactionType: "channel_sale", source: "gofood" }` in
     500-row chunks. `gofood_sale` literal removed from schema after migration completes.
   - Acceptance: `grep -r "processGofoodSales"` returns zero results. `grep -r
     "gofood_sale"` returns zero results (schema + all code). `npm run type-check` passes.
     Regression test confirms GoFood stock counts unchanged post-migration.

6. **Audit detection + channelAuditWorkbench**: `runFullAudit()` detects five issue types
   across all `externalRevenueItems`; `ChannelAuditWorkbench.tsx` admin page exposes tabbed
   resolution UI; historical backfill is gated on a clean audit report.
   - Current: No audit infrastructure. Data quality issues (unmapped SKUs, duplicate
     transactions, etc.) are invisible and unresolvable.
   - Target: `runFullAudit()` emits `channelAuditReports` + `channelAuditIssues` rows for
     five types: `unmapped_sku`, `stale_mapping`, `malformed_item`,
     `duplicate_transaction`, `orphan_item`. Each issue type has at least one resolution
     action (remap, exclude, merge, delete, ignore). Backfill trigger disabled while any
     `channelAuditReports.status === "pending"` has unresolved issues.
   - Acceptance: Each of the five issue types is detectable by seeding a test record that
     triggers it. "Start backfill" button is disabled with open issues; enabled when all
     resolved. Resolution logs `resolvedBy`, `resolvedAt`, `resolution` on
     `channelAuditIssues`.

7. **ChannelRoutingManager admin UI**: Admin page for managing the routing matrix (default
   location per source + outlet/product overrides).
   - Current: No UI for channel routing configuration. GoFood routing is implicit in outlet
     records; other channels have no routing at all.
   - Target: `/admin/channel-routing` page (`ChannelRoutingManager.tsx`) renders routing
     matrix table. Edit modal per row: pick default location, add/remove outlet overrides,
     add/remove product overrides. Save validates no duplicate `(source, outlet?,
     product?)` combination.
   - Acceptance: CRUD round-trip E2E test passes (create routing row → verify in DB →
     edit → verify → delete → verify). Duplicate combination shows validation error.
     Admin role required (`requireRole(ctx, token, ["admin"])`).

8. **Historical deduction backfill (all-time)**: One-shot admin action processes all
   undeducted `externalRevenueItems` back to the earliest records, preserving original
   sale timestamps for analytics fidelity.
   - Current: All non-GoFood sales (and GoFood sales before the deduction path existed)
     have `inventoryDeductedAt == null`. Stock counts are completely decoupled from
     historical sales.
   - Target: Backfill action queries `externalRevenueItems` WHERE `inventoryDeductedAt IS
     NULL AND linkedMenuProductId IS NOT NULL`, ordered by `transactionDate` ASC, 200 items
     per mutation chunk (looped by an internal action). Calls `processChannelSaleInternal`
     with `occurredAt = revenue.transactionDate`. Writes summary to `channelAuditReports`.
     Negative stock accepted without error.
   - Acceptance: Running backfill twice produces zero additional transactions (idempotency).
     Transaction rows created by backfill have `createdAt` matching `transactionDate` of
     the source revenue row, not `Date.now()`. Backfill progress visible in admin settings
     page with items-processed count.

9. **Sync logs gain deduction counters**: `externalSyncLogs` records per-sync deduction
   results so operational monitoring can track the new deduction path.
   - Current: Sync logs record sync status + item counts but not inventory deduction results.
   - Target: `externalSyncLogs` table gets optional `itemsDeducted: v.optional(v.number())`
     and `itemsSkipped: v.optional(v.number())`. Adapters populate these fields at end of
     each sync action.
   - Acceptance: After a sync run, log entry shows `itemsDeducted` + `itemsSkipped` counts.
     `npm run type-check` passes. Fields are optional so existing log reads don't break.

## Boundaries

**In scope:**
- Layer 1: `ChannelAdapter` interface + `ChannelSaleEvent` type; normalize gobiz, bigseller,
  internal (shape only); reroute k3mart + grabfood through `saveRevenueItems`
- Layer 3: `saveRevenueItems` deduction dispatch + `inventoryDeductedAt` flag + audit-issue
  detection hooks
- Layer 4: `processChannelSaleInternal` + `channelRouting` table + `resolveChannelRoute()` +
  `ChannelRoutingManager` admin UI
- Audit: `runFullAudit()` + `channelAuditReports` + `channelAuditIssues` tables +
  `ChannelAuditWorkbench` admin UI
- Migration: seed `channelRouting` from `externalOutlets.linkedStorageLocationId`; migrate
  `gofood_sale` → `channel_sale + source`; historical deduction backfill (all-time)
- `externalSyncLogs` deduction counter fields
- Tests: unit (routing, audit, normalize), integration (atomicity, idempotency, backfill),
  E2E (routing UI, audit workbench)
- K3Mart consignment semantics: all existing consignment-specific logic in
  `convex/integrations/k3mart/` and `convex/consignment/mutations.ts` must be preserved
  when rerouting k3mart through `saveRevenueItems`

**Out of scope:**
- **Pricing consolidation** (999.6) — `menuProductChannelPricing` table; deprecate
  `restockTargets.customPrice`, `externalProductMappings.grabfoodPrice`. Deferred: requires
  separate design and does not block inventory accuracy.
- **SKU resolver auto-match service** (999.7) — confidence-threshold config, manager review
  queue. Deferred: `resolveSkuToMenuProduct` contract is defined this phase; full service
  deferred.
- **Channel onboarding recipe** (999.8) — `docs/CHANNEL_INTEGRATION.md` proving
  architecture scalability. Deferred: written after architecture is proven stable.
- **Direct-order reservation/fulfillment lifecycle** — `reserveStockForOrderInternal` path
  left untouched. Different semantic ("not yet fulfilled") from channel sales ("already
  happened").
- **Layer 5 journal posting** — `journalEngine.ts` unchanged; only validate new transactions
  flow through it correctly.
- **`externalOutlets.linkedStorageLocationId` drop** — deprecated this phase (stop writing);
  dropped in 999.6 cleanup. Not removed in 74.5.
- **GrabFood OAuth2 scope + outlet IDs** — infrastructure works, 401 handled gracefully
  (existing blocker). Not resolved in this phase.

## Constraints

1. **Phase 78 reuse (mandatory):** `resolveSubstitutionPlan()` and `stockTracker.getStock()`
   from Phase 78 (`convex/productInventory/substitution.ts`, `stockTracker.ts`) MUST be
   reused. Do not reimplement stock deduction logic.
2. **Phase 80 reuse (mandatory):** `externalSourceToDisplayChannel` and `channelTaxonomy.ts`
   from Phase 80 MUST be reused. Do not add new source-to-display mapping.
3. **Convex mutation time limit:** Backfill MUST chunk 200 items per mutation call, looped
   by an internal action. Single-mutation backfill of the full dataset will time out.
4. **Transaction-type migration before literal removal:** Schema `gofood_sale` literal can
   only be removed AFTER all existing rows have been migrated. Strip data before dropping
   schema field (existing Convex rule).
5. **K3Mart consignment semantics must be preserved:** K3Mart's consignment-specific logic
   (collapsed-period revenue, outlet-level delivery receipts) must survive the adapter
   refactor. Reference `convex/consignment/mutations.ts` and `convex/integrations/k3mart/`
   carefully before restructuring.
6. **Negative stock:** `processChannelSaleInternal` must allow negative stock for all channels
   without error. Post-sale semantics — the stock was already sold.
7. **`npm run build` must pass** before any sub-phase merges to main.
8. **Admin role enforcement:** All admin pages use `<ProtectedRoute>` with explicit admin
   role filter. All mutations use `requireRole(ctx, args.token, ["admin"])`.
