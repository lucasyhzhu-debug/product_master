## What was built

### 1. Shared channel-integration components (`src/components/channelIntegration/`)

**`SourceBadge.tsx`** — colored source badge driven entirely by `getPlatformPalette(source)` from `src/lib/platformColors.ts`. `size` prop (`sm` / `md`). Reads `sourceToPlatform(source)` for the display label unless overridden. Zero hex literals. Zero new palette entries.

**`ResolutionPreviewPanel.tsx`** — standalone read-only preview widget:
- 3 `<Select>` controls (source required, outlet + product optional with "Any" sentinel)
- "Preview resolution" button triggers `useQuery(api.productInventory.channelRoutingQueries.previewRouteResolution, ...)`
- 4 states per UI-SPEC:
  - idle (no trigger yet) → no result shown
  - loading → `<Skeleton className="h-16 w-full" />`
  - success → `<Alert role="status">` with `Tier N match` + resolved storage location name
  - error → `<Alert variant="destructive" role="status">` with routing-not-configured message
- Auto-invalidates trigger when input tuple changes (admin must re-click "Preview")

**`ChannelFlagRow.tsx`** — one row of the 8-key flag map:
- Discriminated `FlagState` union: `{enabled: boolean}` | `{disabled: true; reason; tooltip}`
- Left: `<SourceBadge>` + display channel label + optional "Last flipped {date} by {user}" sub-row (formatted via `formatShortWIB`)
- Right: state chip (`Deduction: on` / `Deduction: off` / `N/A · aggregate-only source` / `Blocked · OAuth pending` / `Permanent off`) + `<Switch>`
- Disabled sources use `<Tooltip>` wrap with explicit tooltip copy; Switch gets `aria-describedby` pointing at an `sr-only` span for AT

### 2. Admin pages

**`src/pages/ChannelRoutingManager.tsx`** — route `/admin/channel-routing`:
- Primary anchor: `<ResolutionPreviewPanel>` (per UI-SPEC "Primary visual anchor" rule)
- Routing Rules Table card with columns: Source badge, Outlet, Product, Storage location, Default, Updated by, Updated at (WIB), Actions
- Empty state: "No routing rules yet" with [Add routing rule] CTA
- Loading state: 5 skeleton rows
- Edit / Add dialog: 4 fields (source/outlet/product/storage) + `isDefault` Checkbox (auto-disabled unless outlet+product both "Any") + notes Textarea. Source/outlet/product locked in edit mode (immutable post-creation per Plan 03 contract).
- Duplicate-combo error: inline `<Alert variant="destructive">` at top of dialog + visual highlight (`border-l-4 border-l-destructive bg-destructive/5`) on the offending table row
- Delete: `<AlertDialog>` with destructive-variant confirm button. Copy matches UI-SPEC §Destructive Confirmations verbatim.
- "Seed from outlets" button (outline variant) calls Plan 08's `runRoutingSeed` mutation — toast success on schedule
- Sonner toasts for every save/update/delete outcome

**`src/pages/ProductInventorySettings.tsx`** — route `/admin/product-inventory-settings`:
- PageHeader + single "Channel deduction" card
- 8 `<ChannelFlagRow>` rows rendered in the canonical order: shopee, tiktok, gobiz, k3mart, consignment (enabled) → bigseller, grabfood, internal (disabled)
- Disabled-reason tooltips copied verbatim from UI-SPEC / D74.5.1-L1/L2
- Progress indicator: `{onCount}/5 eligible channels flipped ON` (5 = 8 minus 3 disabled)
- Flip-ON: `<AlertDialog>` with required `FLIP` text input (UI-SPEC §Error States row 3 — no backfill has run in 74.5.1)
- Flip-OFF: `<AlertDialog>` with destructive-variant confirm button (rollback signal per UI-SPEC §Destructive Confirmations)
- Second warning toast appears after successful flip-ON: "Flag on without backfill. Schedule backfill..."

### 3. Convex hook wrapper (`src/hooks/convex/useChannelRouting.ts`)

Two exports:
- `useChannelRouting(token)` → `{rules, createRule, updateRule, deleteRule, seedFromOutlets}`
- `useChannelFlags(token)` → `{flags, setFlag}`

Each accepts `token: string | undefined` and `"skip"`s the query when token is absent — matches CLAUDE.md Common Pitfall #2 guidance.

### 4. Backend module (`convex/productInventory/channelFlags.ts`)

- `getChannelDeductionFlags({token})` — query, admin-gated. Returns `{...DEFAULT_FLAGS, ...stored}` so callers always get all 8 keys even if the settings row is absent / the field is not yet persisted.
- `setChannelDeductionFlag({token, source, enabled})` — mutation, admin-gated. Patches the 8-key object; creates the single-row `productInventorySettings` record on first flip with sensible defaults (threshold=5, alertMode=toast, autoAdvanceOnDrawdown=true). Returns `{source, enabled, flippedBy, flippedAt}` for optimistic UX.
- Both gate on `requireRole(ctx, args.token, ["admin"])` per CONTEXT D-03, threat T-74.5.1-21. Token stripped from args before any DB op (Pitfall #10).

### 5. App.tsx integration

Two lazy imports + two routes added inside `BEGIN 74.5.1 ROUTES` / `END 74.5.1 ROUTES` comment markers so Plan 10 (ChannelAuditWorkbench) can append `/admin/channel-audit` inside the same block without merge conflict with this plan's commit. Both routes use `<ProtectedRoute allowedRoles={["admin"]}>` — matching the existing `/admin/unlinked-products-backfill` pattern.

### 6. Date helpers (`src/lib/dateUtils.ts`)

Two new exports per UI-SPEC §WIB Timezone Display:
- `formatShortWIB(utcMs: number) → "Apr 19, 2026 14:32 WIB"` — short admin-UI format used on tables, flag-flip sub-rows, etc.
- `formatLongWIB(utcMs: number) → "Monday, April 19 2026 at 2:32 PM WIB"` — long format reserved for detail views.

Both read from `WIB_OFFSET_MS` (already in the file). Plain-JS implementation (no `date-fns` locale dependency needed — Indonesian copy is already handled by `formatIndonesianDate`).

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 2 — missing critical functionality] `formatShortWIB` / `formatLongWIB` helpers did not exist**

- **Found during:** Task 9.1 while implementing `ChannelFlagRow.tsx`
- **Issue:** Plan action body imported `formatShortWIB` from `src/lib/dateUtils.ts`, and UI-SPEC §WIB Timezone Display lists `formatShortWIB` / `formatLongWIB` as the mandatory format entry points for every user-facing timestamp across new 74.5.1 surfaces. The existing `src/lib/dateUtils.ts` exports `utcToWibDateStr`, `utcToWibTimeStr`, `formatDateTimeId`, etc., but none matched the UI-SPEC format strings (`Apr 19, 2026 14:32 WIB`, `Monday, April 19 2026 at 2:32 PM WIB`).
- **Fix:** Added both helpers to `src/lib/dateUtils.ts`. Both are pure functions over `WIB_OFFSET_MS` + standard Date arithmetic; no new deps.
- **Files modified:** `src/lib/dateUtils.ts`
- **Commit:** `4c8b1497`
- **Rationale for auto-fix (not checkpoint):** UI-SPEC contract is approved; single-source-of-truth principle ("No ad-hoc `new Date(ts).toLocaleString()` calls") is a hard rule; alternatives (use existing helpers with wrong format) would have violated the contract on the first render.

**2. [Rule 3 — blocking build issue] `convex/_generated/api.d.ts` missing channelFlags module**

- **Found during:** Task 9.3 first `npm run type-check` after creating `channelFlags.ts`
- **Issue:** Convex's generated API file `api.d.ts` did not include `productInventory/channelFlags` because `npx convex codegen` requires `CONVEX_DEPLOYMENT` (not set in worktree). `api.productInventory.channelFlags` resolved to `undefined` at type-check.
- **Fix:** Manually patched `convex/_generated/api.d.ts` — added the `import type * as productInventory_channelFlags from ...` declaration and the registry map entry. Matches the pattern used by prior worktree executors (Phase 80.2).
- **Files modified:** `convex/_generated/api.d.ts`
- **Commit:** `f3ef5d4b`
- **Follow-up required:** When this branch is merged and `npx convex dev` runs on a non-worktree tree, `api.d.ts` will regenerate automatically — the manual patch is a bridging fix, not a permanent edit.

- UI-SPEC rules (zero `font-bold` in new components, zero hex literals)
