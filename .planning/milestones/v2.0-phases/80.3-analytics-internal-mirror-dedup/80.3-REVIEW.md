## Warnings

### WR-01: Pre-existing `Date.now()` in modified test file violates Phase 73 deterministic-timestamp rule

**File:** `convex/reports/__tests__/unitEconomics-unlinked.test.ts:122,156`
**Issue:** The modified test file retains two `const now = Date.now();` calls that pre-date Phase 80.3 (originally introduced in Phase 80.2). The 80.3 PLAN's "Non-Negotiables" section explicitly lists:

> **Deterministic timestamps in tests, no `Date.now()`** (Phase 73 lesson).

The new file `unitEconomics.test.ts` correctly uses `const NOW = 1713400000000` per the rule, but when 80.3 modified the second test in the unlinked file (adding the native `orders+orderItems` twin to make the assertion R5-aware), the surrounding `Date.now()` calls were not refactored.

Tests currently pass because the ±1000ms window slack (`fromTs: now - 1000, toTs: now + 1000`) tolerates clock drift, AND because both seeds and queries use the same `now` within a single test. But this is fragile — any future test that asserts on the bucket label (e.g. day-of-week-specific behavior) would silently misbehave on weekday boundaries.

**Fix:** Replace both `Date.now()` calls with the same deterministic constant pattern used in `unitEconomics.test.ts:48`:

```ts
// At top of file
const NOW = 1713400000000;

// Inside each test, replace:
const now = Date.now();
// With:
const now = NOW;
```

(Or rename the local to `NOW` and inline directly.) Single-commit cleanup, ~4 lines changed, no behavior change.

### IN-02: Repetitive seed setup across 11 symmetry tests — DRY opportunity

**File:** `convex/reports/__tests__/unitEconomics.test.ts:290-460`
**Issue:** All 11 Test 17 symmetry tests share identical setup:

```ts
const t = convexTest(schema);
const mp = await seedMenuProduct(t, "Original 80g", "ORIGINAL_XXX", 23000);
await seedBigBallBom(t, mp, 1);
await seedDirectOrderWithMirror(t, mp);
const r = await t.query(api.reports.unitEconomics.<snapshot>, { fromTs: FROM_TS, toTs: TO_TS });
```

The only deltas per test are: (a) the menu product code suffix (`_KPI`, `_CHE`, `_CMO`, etc.), (b) the snapshot query name, and (c) the assertion. The PLAN actually mentions extracting `seedDirectOrderWithMirror` (which was done) but the per-test boilerplate could be reduced further with a shared `setupSymmetryFixture(t)` helper returning `{ mp, query: <fn> }`.

This is an Info rather than Warning because tests are readable as-is, the duplication is regular (low cognitive cost), and DRYing it could obscure the per-test intent.

**Fix:** Optional — extract a small fixture helper. Example:

```ts
async function setupSymmetryFixture(t: TestT, codeSuffix: string) {
  const mp = await seedMenuProduct(t, "Original 80g", `ORIGINAL_${codeSuffix}`, 23000);
  await seedBigBallBom(t, mp, 1);
  await seedDirectOrderWithMirror(t, mp);
  return mp;
}
```

Each test then reduces from 5 lines to 2 — `const mp = await setupSymmetryFixture(t, "KPI"); const r = await t.query(...);`.

### IN-03: Test 17 doesn't cover the `prior` window for reducers that consume both periods

**File:** `convex/reports/__tests__/unitEconomics.test.ts:290-460`
**Issue:** `reduceKpi` and `reduceChannelMomentum` accept both `current` AND `prior` `WindowData`. The seeds in Test 17 only insert data in the current window (NOW); the prior-period window is empty. This means R5's effect on `loadPriorPeriodFilteredData` (which calls `loadFilteredData` for the prior span) is exercised but always with zero rows.

A more thorough test would also seed an internal mirror in the prior window and assert that `kpi.prior.orderCount === 1` (not 2) and `kpi.delta` is computed correctly. Pre-R5 the prior period would also double-count, inflating both buckets by 2× and producing a misleading delta.

This is an Info rather than Warning because R5 is positioned in `loadExternalStream`, which is called identically by both `loadFilteredData` and `loadPriorPeriodFilteredData` (via the shared loader function — verified at `unitEconomics.ts:432-438`). So the prior-period skip is structurally guaranteed; an explicit test would be belt-and-suspenders, not a coverage gap.

**Fix:** Optional — add one test that seeds an internal mirror in the prior window. Example:

```ts
it("kpi prior window: internal mirror in prior period is also skipped", async () => {
  const t = convexTest(schema);
  const mp = await seedMenuProduct(t, "Original 80g", "ORIGINAL_PRIOR", 23000);
  await seedBigBallBom(t, mp, 1);
  // Seed in PRIOR window (NOW - 2 days)
  const PRIOR = NOW - 2 * 86400000;
  await seedDirectOrderWithMirror(t, mp, "0418-001"); // helper would need PRIOR override
  const r = await t.query(api.reports.unitEconomics.kpiAndChannelSnapshot, {
    fromTs: NOW - 86400000,
    toTs: NOW + 86400000,
  });
  expect(r.kpi.prior.orderCount).toBe(1); // not 2
});
```
