## 3. Exact R5 Placement Inside `loadExternalStream`

Relevant code (`convex/reports/unitEconomics.ts` lines 118–132):

```ts
const byPeriod = await ctx.db
  .query("externalRevenue")
  .withIndex("by_period", (q) => q.gte("periodStart", scanFrom))
  .collect();

const revenueRows: Doc<"externalRevenue">[] = [];
for (const r of byPeriod) {
  // Skip returns & delta_inferred; we only want realized sales.
  if (r.transactionType && r.transactionType !== "sales") continue;
  const ts = r.transactionDate ?? r.periodStart;
  if (ts < args.fromTs || ts >= args.toTs) continue;
  const ch = sourceToDisplayChannel(r.source);
  if (channelSet && !channelSet.has(ch)) continue;
  revenueRows.push(r);
}
```

**Three placement candidates:**

| Option | Placement | Cost | Safety |
|---|---|---|---|
| A | Before any filter (line 124, first statement in loop) | Cheapest — skips all downstream work | Safe; `source === "internal"` is a schema-required literal |
| B | After `transactionType` check, before ts filter (line 127) | Same as A but one extra branch per row | Safe |
| C | At start of build-loop (line 148) after `revenueRows` is built | Most expensive — runs ts/channel work for rows we'll discard | Still correct but wasteful |

**Chosen: Option A** — place as the first line of the per-row loop at line ~125 (before the existing `transactionType` check). Rationale:
- Cheapest: avoids running `sourceToDisplayChannel(r.source)` and the ts filter for rows we'll discard.
- Also skips the `externalRevenueItems` child fetch for internal rows (line 135-142) because `revenueRows` never contains them — a win on Convex document-read quota.
- Matches the staff-review addendum's exact rule `if (parentRev.source === "internal") continue;`.

**Also evaluated:** adding the skip at the `externalRevenueItems` fetch stage (line 135-142) as a secondary defence. Rejected — redundant and harder to maintain. The single skip at line ~125 is the complete fix.

**Proposed diff** (canonical placement, ready for the executor):

```ts
// Before line 126 (the existing transactionType check)
for (const r of byPeriod) {
  // R5 — skip the internal mirror. `source === "internal"` rows are a
  // projection of the `orders` table (see convex/integrations/internal/
  // adapter.ts); every such row has a native `orders`+`orderItems` twin
  // that's loaded separately in loadFilteredData. Including internal rows
  // here would double-count every Direct/WhatsApp/Instagram order.
  if (r.source === "internal") continue;
  // Skip returns & delta_inferred; we only want realized sales.
  if (r.transactionType && r.transactionType !== "sales") continue;
  ...
}
```

Comment phrasing matches precedent in the codebase:
- `convex/externalData/helpers/dashboardHelpers.ts:83` — `if (source === "internal") continue; // handled separately above`
- `convex/reports/incomeStatement.ts:247` — `if (source === "internal") { ... }` block

Schema literal `v.literal("internal")` is confirmed at `convex/schema.ts:21`.

## 6. Edge Cases

### 6.1 Cancelled orders
`convex/integrations/internal/queries.ts:16-40` (`getRevenueOrders`) filters native orders by `REVENUE_COUNTABLE_STATUSES` before mirroring. Cancelled orders never have an internal mirror. R5 skip is safe. No regression risk.

### 6.2 100% discount orders (`finalTotal === 0`)
Per MEMORY.md Phase 70 lesson: `validateFinalPrice` blocks `finalTotal < 0` but allows zero. A 100%-voucher direct order reaches `REVENUE_COUNTABLE_STATUSES`, gets mirrored, and currently double-counts in Analytics. R5 skip drops the mirror → native path still counts the zero-revenue but 1-order entry. Correct.

### 6.3 Historical orphan mirrors (Phase 80.2 bug)
`syncInternalOrders` pre-2026-04-10 created parent mirrors without children (219 rows). These currently hit the "no item-level detail" branch in `loadExternalStream` (line 178-209) and synthesize a fake item. With R5, orphan mirrors are skipped entirely — native path remains the sole counter. 80.2's fix restores children but that's orthogonal; R5 renders the orphan issue moot for Analytics regardless of 80.2 status.

### 6.4 Consignment rows
Consignment uses `source === "consignment"`, NOT `"internal"`. R5 does not affect consignment. Confirmed via MEMORY.md `lessons_consignment_recognition.md` and `convex/schema.ts:21` (consignment is a separate literal).

### 6.5 Reversed bank statements
`convex/lib/journalEngine.ts` has a `bank_statement_reversal` sourceType (from MEMORY.md file table), but this does not write to `externalRevenue`. Not affected by R5.

### 6.6 Zero-revenue-countable orders with status changes
If an order is mirrored (status countable), then changed to Cancelled — the mirror row persists. `syncInternalOrders` would need to delete it on re-sync (Phase 80.2's scope?). R5 skip means Analytics simply ignores the stale mirror; native path also skips the Cancelled order (line 282: `if (o.status === "Draft" || o.status === "Cancelled") continue;`). Net effect: stale mirror is invisible to Analytics. Safe.

## 7. Rollback Plan

**Primary:** straight `git revert` of the R5 commit. The change is one line; reverting is trivial and does not require a feature flag.

**If production impact warrants faster rollback:** hotfix PR with `// TEMP-REVERT-R5` comment, one-line revert, no test changes. Merge via admin-bypass if needed. Re-apply with fix in a follow-up PR.

**Convex reactivity note:** because queries are reactive, a deploy-then-revert cycle causes all analytics subscribers to recompute twice. No client-side cache to invalidate. Users may see a brief flicker in KPI cards.

**Feature-flag option (REJECTED):** adding `if (r.source === "internal" && !enableDoubleCount) continue;` behind a feature flag is overkill for a 1-line bug fix specified by staff-review 4 days ago. Skip.
