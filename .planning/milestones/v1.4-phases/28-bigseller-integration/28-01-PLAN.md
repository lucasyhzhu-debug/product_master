**Create `convex/integrations/bigseller/sync.ts`** ("use node"):

This is the core scheduler-chain. Import from `../../_generated/server` (internalAction, internalMutation, action), `../../_generated/api` (internal), and local helpers/config.

1. **`updateSyncStage`** (internalMutation): Upserts the singleton `bigsellerSyncState` document. Args: stage, pollAttempt, maxPolls, attempt, startDate, endDate, optional errorMessage, optional summary, optional completedAt. Query for existing doc — if exists, patch it; if not, insert new. 2. **`startSync`** (action — public, admin-only): Entry point called by frontend. Args: `token: v.string(), startDate: v.optional(v.string()), endDate: v.optional(v.string())`. Validates admin role via `requireRole`. If no dates provided, use incremental sync: query last successful sync log for "bigseller" source to get last sync date, default startDate = lastSync or 30 days ago, endDate = today. Validate date range <= 31 days (BIGSELLER_MAX_SYNC_DAYS). Check current sync state — if already `"triggering"` or `"polling"`, return `{ success: false, error: "Sync already in progress" }`. Set sync stage to `"triggering"`. Use existing `createSyncLog` from `convex/externalData/mutations.ts` to create sync log. Use existing `getCredentialsInternal` from `convex/platformCredentials/queries.ts` for token resolution — do NOT write custom token lookup. Schedule `triggerSync` via `ctx.scheduler.runAfter(0, ...)`. Return `{ success: true }`.

3. **`triggerSync`** (internalAction): Args: startDate, endDate, attempt, syncLogId. Resolve token using `getCredentialsInternal`. Call `POST ${BIGSELLER_API_BASE}/sync/task/create.json`. Log raw response via `updateSyncLog` from `convex/externalData/mutations.ts` — use existing sync log infrastructure, NOT custom logging. If `code === -1` and msg contains "sync task is in progress" — this is "join existing sync" per locked decision. Update stage to "polling". If `code === 0` — success, update stage to "polling". If HTML response detected — auth failure, update stage to "failed" with "Token expired — paste new token" error, update platformCredentials lastRefreshStatus to "error". Schedule `pollSyncTask` with 60s delay.

4. **`pollSyncTask`** (internalAction): Args: startDate, endDate, pollAttempt, maxPolls, attempt, syncLogId. Resolve token using `getCredentialsInternal`. Call `GET ${BIGSELLER_API_BASE}/sync/task/detail/new/get.json`. Parse `data.progressInfo.taskStatus`.
   - If `"complete"`: update stage to "fetching", schedule `fetchOrders` immediately (runAfter 0).
   - If pollAttempt >= maxPolls: if attempt === 1, update stage to "retrying", schedule `triggerSync` with attempt=2 after 5s (auto-retry once per locked decision). If attempt >= 2, update stage to "failed" with error "Sync timed out after 2 attempts".
   - Otherwise: update stage with incremented pollAttempt, schedule next `pollSyncTask` after 60s.
   - HTML response detection at EVERY API call point: same auth failure handling as triggerSync. Token may expire mid-sync.

5. **`fetchOrders`** (internalAction): Args: startDate, endDate, attempt, syncLogId. Resolve token using `getCredentialsInternal`. Call `POST ${BIGSELLER_API_BASE}/pageList.json` using `buildPageListBody`. Paginate: start at pageNo=1, fetch pages while `pageNo <= totalPage` (from response `data.totalPage`). Handle edge case: totalPage = 0 (empty sync) — show "No orders found" summary, not error. For each page:
   - Parse `data.rows` array (each row = one order).
   - Call `mapOrderToStorage` for each row, batch-insert via `ctx.runMutation(internal.bigsellerOrders.mutations.upsertOrders)`.
   - Call `mapOrderToRevenue` for each row, batch-insert via `ctx.runMutation(internal.externalData.mutations.saveRevenue)`.
   - Collect SKU codes from all orders for product mapping registration.
   - After all pages fetched: call `saveProductMappings` with all unique SKU codes (source = "shopee" or "tiktok" based on order platform).
   - Calculate summary: totalOrders, newOrders (inserted), updatedOrders (patched), totalRevenue (sum of platformIncome), unmappedSkus (count of SKU codes without linkedMenuProductId in externalProductMappings).
   - Update sync stage to "complete" with summary. Empty sync (0 orders): summary has totalOrders=0, show "No orders found" — do not error.
   - Update sync log to "success" with duration via existing `updateSyncLog`.
   - Handle partial failures: if a page fetch fails, log the error, continue with next page if possible, mark sync as "complete" with partial data rather than failing entirely.
   - HTML response detection at EVERY fetch call: auth failure handling, abort if detected.

**Important implementation notes:**
- All actions use `"use node"` directive at top of sync.ts
- Token resolution: ALWAYS use existing `getCredentialsInternal(ctx, "bigseller")` from `convex/platformCredentials/queries.ts` — never write custom credential lookup
