In `loginWithCredentials` (around line 1055), the `body` passed to `fetch` currently nests credentials under a `data` key:

```
body: JSON.stringify({
  client_id: "go-biz-web-new",
  grant_type: "password",
  data: { email, password },   // WRONG — causes 400
}),
```

Change it to flat top-level fields:

```
body: JSON.stringify({
  client_id: "go-biz-web-new",
  grant_type: "password",
  email,
  password,
}),
```

Also fix the error handler at `if (!response.ok)` (around lines 1068-1072). Currently it discards the response body and returns only the HTTP status code. Read the response body and include it in the error message so the admin sees GoBiz's actual error text:

```typescript
if (!response.ok) {
  let errorBody = "";
  try {
    const errData = await response.json() as Record<string, unknown>;
    errorBody = errData.error_description
      ? String(errData.error_description)
      : JSON.stringify(errData);
  } catch {
    errorBody = await response.text().catch(() => "");
  }
  return {
    success: false,
    error: `GoBiz login failed (${response.status})${errorBody ? `: ${errorBody}` : ""}`,
  };
}
```

No other changes to this file.

In `previewBigSellerToken` (around line 58), the uid extraction currently only checks `payload.uid`:

```typescript
const uid = typeof payload.uid === "string" ? payload.uid : undefined;
```

BigSeller muc_token may store the user identifier under a different claim name. Replace this single check with a find across the four most common claim keys:

```typescript
const uid = [payload.uid, payload.user_id, payload.sub, payload.id]
  .find((v): v is string => typeof v === "string");
```

This is a one-line change. No other changes to this file. Keep the return shape identical: `{ success: true, expiresAt, daysRemaining, uid }` — `uid` remains `string | undefined`.
