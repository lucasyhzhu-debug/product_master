Create `src/components/shared/EntityManager.tsx` implementing a generic CRUD UI component.

**Type definitions (exported):**

```typescript
export interface EntityColumn<T> {
  key: keyof T | string;
  header: string;
  width?: string;
  sortable?: boolean;
  render?: (item: T) => ReactNode;
}

export interface EntityManagerConfig<T extends { _id: string }> {
  // Identity
  entityName: string;          // Singular: "Ingredient"
  entityNamePlural: string;    // Plural: "Ingredients"

  // Data
  items: T[] | undefined;      // undefined = loading

  // Display
  columns: EntityColumn<T>[];
  icon?: LucideIcon;           // Optional icon for empty state + header

  // Form (for create/edit dialog)
  formSections: FormSection<any>[];
  getFormDefaults: () => Record<string, any>;
  getFormInitialData: (item: T) => Record<string, any>;
  transformFormData?: (data: Record<string, any>) => Record<string, any>;

  // Mutations
  onCreate: (data: any) => Promise<any>;
  onUpdate: (id: string, data: any) => Promise<any>;
  onDelete: (id: string) => Promise<any>;
  onBulkDelete?: (ids: string[]) => Promise<void>;

  // Page layout
  pageTitle: string;
  pageDescription?: string;
  backTo?: string;
  backLabel?: string;

  // Card view
  cardRender?: (item: T, actions: { onEdit: () => void; onDelete: () => void }) => ReactNode;

  // Behavior
  searchable?: boolean;
  searchKeys?: (keyof T)[];
  searchPlaceholder?: string;
  defaultView?: "table" | "cards";
  supportsUndo?: boolean;       // If true, undo toast after delete (for entities without referential deps)
}
```

**Internal hooks:**

`useViewPreference(key: string, defaultView)`:
- Reads/writes `entityManager:{key}:view` in localStorage.
- Returns `[view, setView]` tuple.

**Component structure:**

```
EntityManager<T>
  PageHeader (title, description, backTo, action={Add button + ViewToggle})
  Search bar (optional, controlled input with client-side filtering)
  BulkActionBar (appears when items selected, shows count + Delete Selected button)
  TableView OR CardGridView (based on current view preference)
  Create/Edit Dialog (uses FormBuilder inside Dialog)
  ConfirmDialog (for delete confirmation)
```

**Key implementation details:**

1. **View Toggle**: Two icon buttons (List for table, LayoutGrid for cards) in the header next to the "Add" button. Uses `useViewPreference` hook for localStorage persistence.

2. **Table View**: Uses shadcn Table components. Renders columns from config. Sortable columns have clickable headers with sort direction indicator (ChevronUp/ChevronDown). Client-side sorting via `Array.sort()`. Checkbox column as first column for bulk selection.

3. **Card Grid View**: Responsive grid (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`). If `cardRender` is provided, uses it. Otherwise, auto-generates cards from column config (card title = first column, details = remaining columns). Each card has edit/delete action buttons. Checkbox in card corner for bulk selection.

4. **Search**: Optional. Controlled input with magnifying glass icon. Filters items client-side by checking if any `searchKeys` field contains the search string (case-insensitive). If `searchKeys` not provided but `searchable: true`, searches all string fields.

5. **Create/Edit Dialog**: Uses `Dialog` from shadcn, contains `FormBuilder` with the provided `formSections`. Dialog title: "Add {entityName}" or "Edit {entityName}". On create: calls `onCreate(transformedData)`, closes dialog on success. On edit: calls `onUpdate(item._id, transformedData)`, closes dialog on success.

6. **Delete Flow (per user decision -- belt and suspenders)**:
   - Step 1: ConfirmDialog with "Delete {entityName}" title and "Are you sure?" description, variant="destructive".
   - Step 2: On confirm, call `onDelete(id)`.
   - Step 3: If `supportsUndo: true`, show undo toast (for tags, storage locations). If false (ingredients, materials, customers -- referential deps), show plain success toast.
   - The undo toast for simple entities: `toast.success("{name} deleted", { action: { label: "Undo", onClick: () => onCreate(cachedItemData) } })`. Cache the item data before delete for re-creation.

7. **Bulk Selection**: Checkbox in first column of table / corner of cards. "Select All" checkbox in table header. When items selected, a floating bar appears above the list showing "{N} selected" with "Delete Selected" button. Bulk delete loops over individual `onDelete` calls (no backend bulk mutation exists). Only show bulk actions when `onBulkDelete` is provided OR more than 0 items are selected (use `onDelete` in a loop).

8. **Loading State**: When `items === undefined`, render `TablePageSkeleton` from existing LoadingState component.

9. **Empty State**: When `items` is empty array, render `EmptyState` with icon, "No {entityNamePlural}" title, descriptive message, and "Add {entityName}" CTA button.

10. **Brand compliance**: Follow Phase 9 patterns:
    - Use `PageHeader` component for title/description/back.
    - Use semantic color tokens (text-muted-foreground, bg-card, border-border).
    - Rounded corners per brand reference (rounded-xl for cards, rounded-lg for smaller elements).
    - Hover states: `hover:bg-accent/50` for rows, `hover:shadow-md` for cards.
    - Dark mode compatible (use CSS variables, no hardcoded colors).

**FormBuilder integration detail:**
The `FormBuilder` component currently renders its own submit button with Save icon. Inside the EntityManager dialog, we need the form submit to work within the dialog footer pattern. Approach: Pass `FormBuilder` the form sections and handle submission. Use `FormBuilder`'s `onSubmit` callback and its own submit button. The dialog wraps the FormBuilder with its own padding. Don't add separate DialogFooter -- let FormBuilder handle its own buttons with `submitLabel` set to "Create" or "Update" and `onCancel` set to close the dialog.
