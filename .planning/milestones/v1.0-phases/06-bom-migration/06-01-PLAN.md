  <files>convex/migrations/bomBackfill.ts</files>
  <action>
Create `convex/migrations/bomBackfill.ts` with a mutation `backfillMenuProductBOM`.

**Mapping table (CRITICAL — counterintuitive naming, verified against CLAUDE.md Pitfall #11):**
```typescript
const PRODUCTION_TYPE_TO_BOM_CODE: Record<string, string> = {
  "original": "BIG_BALL",    // 80g/Jumbo — NOT what "original" name suggests
  "bite_sized": "MID_BALL",  // 45g/Original — counterintuitive
};
```

**Algorithm:**
1. Fetch all `menuProducts` from the DB
2. For each menuProduct:
   a. If `productionType` is null/undefined/empty → skip (per user decision: "skip products with no productionType")
   b. Look up the BOM code from `PRODUCTION_TYPE_TO_BOM_CODE[productionType]`
   c. If no mapping found → log as error, skip
   d. Find the `componentType` record where `code` matches the BOM code (query `componentTypes` table)
   e. If no componentType found → log as error, skip
   f. Delete ALL existing `menuProductComponents` entries for this menuProduct where the linked componentType has `category === "production"` (per user decision: "overwrite existing BOM entries")
   g. Insert a new `menuProductComponent` with:
      - `menuProductId`: the menuProduct's `_id`
      - `componentTypeId`: the matched componentType's `_id`
      - `quantity`: `menuProduct.productionUnits` (direct mapping per user decision)
      - `consumptionStage`: `"production"`
3. Return a structured report: `{ total, backfilled, skipped, errors, details[] }`

**Important details:**
- Use `mutation` (not `internalMutation`) so it can be called from the dashboard Functions tab
- Accept `token: v.string()` arg and use `requireRole(ctx, args.token, ["admin"])` for auth
- With only 8 products, no batching needed — process all in a single mutation call
- The deletion step must query `menuProductComponents` by `menuProductId`, then check each component's `componentTypeId` against componentTypes with `category === "production"` before deleting
- Log each action (skip, delete, insert) to the details array for debugging

**Per user decision:** "Overwrite existing BOM entries" means even correctly-configured products (like "Original - Triple" which already has correct BOM) will be overwritten. The verification query in Task 2 will catch these mismatches for manual correction.

  <name>Task 2: Create BOM verification comparison query</name>
  <files>convex/migrations/bomVerification.ts</files>
  <action>
Create `convex/migrations/bomVerification.ts` with a query `verifyBOMConsistency`.

**Return shape:**
```typescript
interface VerificationResult {
  total: number;
  matched: number;
  mismatched: number;
  skipped: number;
  details: Array<{
    productId: string;
    productName: string;
    deprecatedType: string | undefined;
    deprecatedUnits: number | undefined;
    bomCode: string | null;
    bomQuantity: number | null;
    status: "match" | "mismatch" | "no_bom" | "no_deprecated";
  }>;
}
```

**Algorithm:**
1. Fetch all `menuProducts`
2. For each menuProduct:
   a. Read `productionType` and `productionUnits` (deprecated fields)
   b. Query `menuProductComponents` for this product, join with `componentTypes` to find entries with `category === "production"`
   c. If no deprecated fields → status: `"no_deprecated"`, increment skipped
   d. If no BOM entries → status: `"no_bom"`, increment mismatched
   e. Compare: Map deprecated `productionType` through `PRODUCTION_TYPE_TO_BOM_CODE` to get expected BOM code. Compare expected code + units against actual BOM code + quantity. If they match → status: `"match"`. If they differ → status: `"mismatch"`.
3. Return the VerificationResult

**Important:** Use the same `PRODUCTION_TYPE_TO_BOM_CODE` mapping table as the backfill. Extract to a shared constant or duplicate with a comment referencing the other file.

Use `query` (not `internalQuery`) so it can be called from the dashboard. Accept `token: v.string()` and use `requireRole(ctx, args.token, ["admin"])`.

Per user decision: "Log mismatches, don't halt" — the query returns all results including mismatches. It does not throw on mismatch.
  </action>
