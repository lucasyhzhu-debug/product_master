**Ingredients mutations (`convex/ingredients/mutations.ts`):**

1. Replace `import { mutation } from "../_generated/server"` with `import { protectedMutation } from "../lib/functions"`
2. `create` mutation: Change to `protectedMutation({ roles: ["manager", "admin"], args: { ... }, handler: ... })`.
   - Remove `createdBy: v.optional(v.string())` from args
   - In handler, use `ctx.user.name` instead of `args.createdBy ?? "admin"` for the `createdBy` field
   - Remove `token` if present (it should not be -- these have no auth currently)
3. `update` mutation: Change to `protectedMutation({ roles: ["manager", "admin"], ... })`. No createdBy changes needed (update does not write createdBy).
4. `remove` mutation: Change to `protectedMutation({ roles: ["manager", "admin"], ... })`.

**Ingredients queries (`convex/ingredients/queries.ts`):**

1. Replace manual implementations with query helpers from `../lib/queryHelpers`:
   - `list`: Use `listAll(ctx, "ingredients", { limit: args.limit })` -- keep as public `query` (all authenticated users can see ingredients)
   - `get`: Use `getById` or keep inline `ctx.db.get(args.id)` (trivial)
   - `search`: Use `textSearch(ctx, "ingredients", args.query, ["name", "brand"], args.limit)`
2. Keep using `query` from `../_generated/server` (queries are public reads -- any authenticated user accessing the ingredients page has already passed ProtectedRoute)

**Materials mutations (`convex/materials/mutations.ts`):**

Same pattern as ingredients. Replace `mutation` with `protectedMutation`, roles: `["manager", "admin"]`.
- `create`: Remove `createdBy` from args, derive from `ctx.user.name`
- `update`: Wrap with protectedMutation
- `remove`: Wrap with protectedMutation

**Materials queries (`convex/materials/queries.ts`):**

Same pattern as ingredients queries. Use `listAll` for `list`, `textSearch` for `search`. Keep as public `query`.

**Tags mutations (`convex/tags/mutations.ts`):**

1. Import both `protectedMutation` AND `publicMutation` from `../lib/functions`
2. `create`: Change to `protectedMutation({ roles: ["manager", "admin"], ... })` -- tags are managed by managers/admins only
3. `update`: Change to `protectedMutation({ roles: ["manager", "admin"], ... })`
4. `remove`: Change to `protectedMutation({ roles: ["manager", "admin"], ... })`
5. `seedDefaults`: Change import to use `publicMutation` from `../lib/functions` (NOT bare `mutation` from `../_generated/server`). `publicMutation` is a re-export of `mutation` but importing from `lib/functions` keeps all mutation imports centralized in one source. This is a dashboard utility run without user context. Per Pitfall 5 in research, seed functions must remain unauthenticated.

**Tags queries (`convex/tags/queries.ts`):**

1. `list`: Keep as public `query` (tags are read by recipe editor, used by all roles). Can use `listAll` but tags currently use `.order("asc").collect()` which is slightly different. Use `listAll(ctx, "tags", { order: "asc", limit: 1000 })` to preserve ascending order and get all tags (small table).
2. `get`: Keep inline `ctx.db.get(args.id)` or use `getById`
3. `getMany`: Keep as-is (Promise.all pattern, not a standard helper case)

**CRITICAL: Do NOT import `mutation` from `_generated/server` in migrated files.** Use `protectedMutation` from `../lib/functions` for user-facing mutations and `publicMutation` (or raw `mutation` import from `_generated/server`) only for seed/migration functions.

**Frontend hook updates (all 3 files):**

For each hook file, apply these changes:

1. Replace `import { useQuery, useMutation } from "convex/react"` with:
   ```typescript
   import { useQuery } from "convex/react";
   import { useSessionMutation } from "convex-helpers/react/sessions";
   ```

2. In all mutation hooks (useConvexCreate*, useConvexUpdate*, useConvexDelete*):
   - Replace `useMutation(api.*.mutations.*)` with `useSessionMutation(api.*.mutations.*)`
   - The `useSessionMutation` hook automatically injects `sessionId` from the SessionProvider context
   - The mutation call signature stays the same (pass data, no token needed)

3. For query hooks: Keep using `useQuery` from `convex/react` (queries remain public -- no auth needed on reads for these entities since ProtectedRoute handles page access)

4. **useIngredients.ts specific:**
   - Remove `createdBy` from the `IngredientCreateInput` interface (no longer passed from frontend)
   - Remove any `createdBy` passing in the create mutation call

5. **useMaterials.ts specific:**
   - Remove `createdBy` from the `MaterialCreateInput` interface
   - Remove any `createdBy` passing in the create mutation call

6. **useTags.ts specific:**
   - Update mutation hooks (create, update, remove) to use `useSessionMutation`
   - `useConvexSeedTags` should keep using `useMutation` (NOT useSessionMutation) because seedDefaults is a public mutation that does not accept sessionId
   - This means both `useMutation` and `useSessionMutation` are imported in this file

**Tags test updates (`tests/convex/tags.test.ts`):**

1. Import `createTestSession` from `../../tests/helpers/authTestHelper`

2. For every test that calls `api.tags.mutations.create`, `api.tags.mutations.update`, or `api.tags.mutations.remove`:

   - Add `sessionId` to the mutation args: `t.mutation(api.tags.mutations.create, { name: "...", sessionId })`

3. Tests calling `api.tags.mutations.seedDefaults` do NOT need sessionId (it remains a public mutation)

4. The "Default Tag Seeding" and "Idempotency" tests should remain unchanged (seedDefaults is public)

5. The "Tag CRUD Operations" tests must be updated:
   - `can create a custom tag`: Add `sessionId` to create args
   - `prevents duplicate tag names`: Add `sessionId` to both create calls
   - `can update tag name`: Add `sessionId` to create and update calls
   - `can delete tag`: Add `sessionId` to create and remove calls
