  <name>Task 1: Build productionLog aggregation queries + rewrite resetCounts</name>
  <files>

  <action>
**Add aggregation queries to `convex/productionLog/queries.ts`:**

Add `getAggregatedCounts` query (replaces `productionCounts.queries.getAll`):
1. Fetch all active menuProducts via `by_active` index
2. Fetch all `productionResets` records, build a Map of menuProductId -> lastResetAt
3. For each menuProduct, query `productionLog` with `by_menu_product` index, filter entries where `timestamp > lastResetAt` (default lastResetAt to 0 if no reset exists)
4. Aggregate: boxed = SUM(box) - SUM(unbox), stickered = SUM(sticker) - SUM(unsticker) + SUM(return_goldfinch), packed = SUM(pack) - SUM(unpack), shippedToGoldfinch = SUM(ship_goldfinch)
5. Derive ball info from BOM (same pattern as existing `productionCounts/queries.ts::getAll` — fetch menuProductComponents + componentTypes, build ballType/ballCount per product)
6. Return array matching EXACT same shape as current `productionCounts.queries.getAll`:
   ```typescript
   {
     menuProductId, menuProductName, menuProductCode, posSlot, productType,
     ballType, ballCount, boxed, stickered, packed, shippedToGoldfinch,
     availableForStickering: boxed - stickered,
     availableForPacking: stickered - packed,
     lastResetAt, lastResetBy
   }
   ```

Add `getCountsByMenuProduct` query (replaces `productionCounts.queries.getByMenuProduct`):
- Args: `{ menuProductId: v.id("menuProducts") }`
- Same aggregation logic but for a single product
- Return same shape as current `productionCounts.queries.getByMenuProduct`

**IMPORTANT:** The `return_goldfinch` action type represents products returned from Goldfinch depot that need re-stickering. In the old system, `returnFromGoldfinch` incremented `productionCounts.stickered`. In the new aggregation, `return_goldfinch` log entries should be added to the `stickered` total (they represent items that became available for stickering again).

**Rewrite `convex/productionCounts/mutations.ts` — `resetCounts`:**

Replace the current implementation that zeros out `productionCounts` records with one that:
1. Still requires manager/admin role via `requireRole`
2. If `menuProductId` provided: upsert into `productionResets` table — find existing record by `by_menu_product` index, if exists patch `lastResetAt: Date.now(), lastResetBy: user.name`, if not insert new record
3. If no `menuProductId` (reset all): fetch all active menuProducts, upsert a `productionResets` record for each
4. Return `{ reset: count }` same as before
5. Do NOT touch `productionCounts` table at all (it's now read-only archive)
  </action>

  </verify>
