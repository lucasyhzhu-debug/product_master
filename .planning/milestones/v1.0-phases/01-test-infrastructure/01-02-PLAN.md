**Test structure (20 tests in 4 describe blocks):**

**1. Basic FIFO ordering (5 tests):**
- Oldest batch consumed first when 2 batches available
- Oldest batch consumed first when 3+ batches available
- Middle batch consumed after oldest depleted
- Newest batch consumed last (after all older batches depleted)
- Single batch consumption works correctly

**2. Partial depletion (5 tests):**
- Consuming 75 from 100-unit batch leaves 25 remaining
- Consuming across 2 batches: depletes first batch, partially depletes second
- Consuming exact batch quantity (100 from 100) marks batch as depleted
- Multiple partial consumptions from same batch accumulate correctly (consume 30, then 40, then 30 from 100-unit batch)
- Cost calculation uses weighted average when consuming across batches

**3. Expired batch handling (5 tests):**
- FIFO skips expired batch and consumes next oldest active batch (from RESEARCH.md Pitfall 3)
- Multiple expired batches skipped correctly
- All batches expired returns error (no stock available)
- Partially expired queue (expired, active, active) consumes from first active
- Expiry check uses current timestamp correctly

**4. Edge cases and constraints (5 tests):**
- Consuming more than available stock returns error (prevents negative stock per CONTEXT.md)
- Empty inventory returns error
- Concurrent consumption (simulate 2 mutations) maintains consistency
- Zero quantity consumption returns error
- Batch exactly depleting triggers status change to 'depleted'

**Implementation notes:**
- Use `convexTest(schema)` for isolated DB per test
- Use helpers from Task 1 for fixtures
- Use `t.mutation(api.inventory.consumeStock, {...})` or equivalent FIFO mutation
- Verify batch state with `verifyBatchState(t, batchId, expectedRemaining)`
- Direct DB queries to verify batch status changes: `t.run(async (ctx) => ctx.db.get(batchId))`
- Each test: Arrange (create batches with different purchaseDates), Act (consume stock), Assert (verify FIFO order + remaining quantities)
- Use realistic data: batches of 50-200 units, consumption of 30-150 units, costs 500-1000 IDR/unit

**Known failure scenarios to cover (from CONTEXT.md):**
- Stock going negative: Assert error thrown when consuming more than available
- Wrong batch order (FIFO violation): Verify purchaseDate ordering in consumption
- Inventory leaks: Not directly FIFO concern, but verify batches marked depleted when empty

**FIFO algorithm verification pattern (from RESEARCH.md):**
```typescript
// Create batches: old (2 days ago), middle (1 day ago), new (today)
```
