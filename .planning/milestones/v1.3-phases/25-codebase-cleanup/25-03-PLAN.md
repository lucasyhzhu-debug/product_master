## protectedMutation Pattern Reference

```typescript
// convex/lib/functions.ts — existing wrapper (DO NOT MODIFY)
export const protectedMutation = customMutation(mutation, {
  args: SessionIdArg,  // adds sessionId arg automatically
  input: async (ctx, { sessionId }, { roles }: { roles: UserRole[] }) => {
    const user = await getSessionUser(ctx, sessionId);
    if (!user || !user.isActive) throw new ConvexError("Unauthorized");
    if (!roles.includes(user.role as UserRole)) throw new ConvexError("Unauthorized");
    return { ctx: { ...ctx, user: user as Doc<"users"> }, args: {} };
  },
});

// Reference pattern (from convex/ingredients/mutations.ts):
export const create = protectedMutation({
  roles: ["manager", "admin"],
  args: { name: v.string(), ... },
  handler: async (ctx, args) => {
    // ctx.user is Doc<"users"> — auto-populated
    // NO token arg, NO manual requireRole needed (but keep existing requireRole calls)
    return await ctx.db.insert("ingredients", { ...args });
  },
});
```

## Migration rules for each mutation:
1. Replace: import { mutation } from "../../_generated/server"
   With: import { protectedMutation } from "../../lib/functions"
   (Keep other imports from _generated/server like query, internalMutation if used)

2. For each mutation that has requireRole() calls and token: v.string() arg:
   - Change mutation({ args: { token: v.string(), ...rest }, handler })
   - To: protectedMutation({ roles: [SAME_ROLES_AS_requireRole_call], args: { ...rest (no token) }, handler })
   - Keep requireRole() call inside handler as belt-and-suspenders

3. For mutations WITHOUT requireRole (createDraft, updateDraft style "public" mutations):
   - Leave as bare mutation() — these are intentionally public
   - Or convert to publicMutation re-export if it exists in lib/functions.ts
   - Do NOT use protectedMutation with roles: [] — would always reject

4. IMPORTANT: After removing token from args, also remove destructuring of token from args in handler body (e.g., const { token, ...data } = args — remove token from destructure)

5. ctx.user is now available in handler — can use ctx.user.name for createdBy fields if needed
