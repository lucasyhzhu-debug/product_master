**File 1: `convex/integrations/internal/queries.ts`**

Replace the current `getRevenueOrders` implementation. The current version does `ctx.db.query("orders").collect()` (full table scan) then filters in JS. Replace with:

```typescript
import { v } from "convex/values";
import { internalQuery } from "../../_generated/server";
import { REVENUE_COUNTABLE_STATUSES } from "./config";

export const getRevenueOrders = internalQuery({
  args: { sinceTimestamp: v.optional(v.number()) },
  handler: async (ctx, args) => {
    // If sinceTimestamp provided, only fetch orders created after that time
    // This avoids re-processing the entire orders table on every sync
    let allOrders;
    if (args.sinceTimestamp) {
      // Use _creationTime filter since orders table doesn't have a by_confirmedAt index
      // We fetch orders created since (sinceTimestamp - 24h buffer) to catch
      // orders that were created before last sync but confirmed after
      const bufferMs = 24 * 60 * 60 * 1000;
      const cutoff = args.sinceTimestamp - bufferMs;
      allOrders = await ctx.db
        .query("orders")
        .filter((q) => q.gte(q.field("_creationTime"), cutoff))
        .collect();
    } else {
      // First sync: full scan
      allOrders = await ctx.db.query("orders").collect();
    }

    return allOrders.filter((order) =>
      (REVENUE_COUNTABLE_STATUSES as readonly string[]).includes(order.status)
    );
  },
});
```

Key design: Use a 24-hour buffer before `sinceTimestamp` to catch orders created before last sync but confirmed after. The downstream `saveRevenue` dedup by `externalTransactionId` (orderNumber) handles any overlap safely.

**IMPORTANT — `.filter()` on `_creationTime` limitation:** The `.filter()` approach does NOT reduce DB read bandwidth at the Convex layer — Convex still scans the full `orders` table and filters in JS. The optimization here reduces the number of downstream `saveRevenue` mutation calls (from ~5.2K to near-zero), which is the primary bandwidth savings. To also reduce DB-layer read bandwidth, add a `by_creationTime` index to `convex/schema.ts`:

In `convex/schema.ts`, find the `orders` table definition and add:
```typescript
.index("by_creationTime", ["_creationTime"])
```

Then replace the `.filter()` call above with:
```typescript
allOrders = await ctx.db
  .query("orders")
  .withIndex("by_creationTime", (q) => q.gte("_creationTime", cutoff))
  .collect();
```

This makes the incremental query index-backed, reducing both mutation calls AND DB read bandwidth.
