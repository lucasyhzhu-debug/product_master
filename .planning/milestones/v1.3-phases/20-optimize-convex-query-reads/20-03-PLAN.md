<objective>
Bound the `getRevenue` query to the selected period instead of fetching all records unbounded.

Purpose: `getRevenue` consumes 80 MB at ~94 KB/call. The OverviewTab calls `useConvexExternalRevenue()` without `periodStart`/`periodEnd`, causing a full table scan of all `externalRevenue` records. Bounding to the selected period (or a sensible default) dramatically reduces payload.

Output: Modified OverviewTab to pass period bounds to the existing `getRevenue` query.
</objective>

**File 2: `src/hooks/convex/useExternalData.ts`**

The hook at lines 36-47 already accepts `periodStart` and `periodEnd` as optional parameters. No changes needed to the hook itself — the fix is entirely in how OverviewTab calls it.

However, if the "allTime" period must still work, add a default bound in the hook:
```typescript
export function useConvexExternalRevenue(
  source?: "k3mart" | "gobiz" | "internal",
  periodStart?: number,
  periodEnd?: number
) {
  // Default to last 90 days if no period specified (prevents full table scan)
  const effectivePeriodStart = periodStart ?? (Date.now() - 90 * 24 * 60 * 60 * 1000);
  const data = useQuery(api.externalData.queries.getRevenue, {
    source,
    periodStart: effectivePeriodStart,
    periodEnd,
  });
  return { data, isLoading: data === undefined };
}
```

This ensures that even if callers forget to pass period bounds, the query is always bounded.
