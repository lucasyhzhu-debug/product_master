  <name>Task 1: Create submitShiftRecord and updateShiftRecord mutations</name>
  <files>convex/kitchenShiftRecords/mutations.ts</files>
  <action>
Create new file `convex/kitchenShiftRecords/mutations.ts` with two mutations:

**A) `submitShiftRecord` mutation:**

Args:
```typescript
{
  token: v.string(),
  date: v.string(),  // YYYY-MM-DD
  produced: v.array(v.object({
    menuProductId: v.id("menuProducts"),
    quantity: v.number(),
  })),
  waste: v.array(v.object({
    menuProductId: v.id("menuProducts"),
    reason: v.union(v.literal("qa_testing"), v.literal("spoilage"), v.literal("waste")),
    quantity: v.number(),
  })),
}
```

Handler logic (in order):
1. `requireRole(ctx, args.token, ["kitchen", "order_staff", "manager", "admin"])` — all roles can submit
2. Find Kitchen storage location: `ctx.db.query("storageLocations").withIndex("by_type", q => q.eq("locationType", "kitchen")).first()`. Throw `ConvexError("Kitchen storage location not found. Please run the seed function first.")` if null.
3. Validate: for each waste entry, find matching produced entry. If `waste.quantity > produced.quantity` for same menuProductId, throw `ConvexError("Waste cannot exceed produced quantity for [productName]")`. Look up menuProduct name for the error message.
4. **Add produced quantities to productInventory** — for EACH produced item with quantity > 0:
   - Query `productInventory` via `by_product_location` index with `(menuProductId, kitchenLocation._id)`
   - Compute `previousQuantity = existing?.quantity ?? 0`, `newQuantity = previousQuantity + item.quantity`
   - If existing: `ctx.db.patch(existing._id, { quantity: newQuantity, lastUpdated: now })`
   - If not: `ctx.db.insert("productInventory", { menuProductId, locationId: kitchenLocation._id, quantity: newQuantity, lastUpdated: now })`
   - Insert `productInventoryTransactions` with `transactionType: "add"`, quantity, previousQuantity, newQuantity, `performedBy: user.name`, `reason: "End-of-shift production"`, `createdAt: now`
   - Track in `inventoryUpdates` array for the shift record

5. **Deduct waste quantities** — for EACH waste item with quantity > 0:
   - Same productInventory lookup
   - `newQuantity = previousQuantity - waste.quantity`
   - Patch or insert productInventory
   - Insert `productInventoryTransactions` with `transactionType: "adjust"`, `quantity: -waste.quantity`, reason: `"End-of-shift waste (${waste.reason})"`, `createdAt: now`
   - Track in inventoryUpdates (delta is negative)

6. Insert `kitchenShiftRecords` with all fields: date, submittedAt (Date.now()), submittedBy (user.name), submittedByUserId (user._id), produced (filtered > 0), waste (filtered > 0), inventoryUpdates.

CRITICAL: The inventory upsert pattern MUST be inlined (Convex mutations cannot call other mutations). Copy the exact pattern from `convex/productInventory/mutations.ts` lines 51-86.

**B) `updateShiftRecord` mutation:**

Args:
```typescript
{
  token: v.string(),
  recordId: v.id("kitchenShiftRecords"),
  produced: v.array(v.object({ menuProductId: v.id("menuProducts"), quantity: v.number() })),
  waste: v.array(v.object({
    menuProductId: v.id("menuProducts"),
    reason: v.union(v.literal("qa_testing"), v.literal("spoilage"), v.literal("waste")),
    quantity: v.number(),
  })),
  editNote: v.optional(v.string()),
}
```

Handler logic:
1. `requireRole(ctx, args.token, ["manager", "admin"])` — only managers can edit
2. Get existing record: `ctx.db.get(args.recordId)`. Throw if not found.
3. Find Kitchen location (same as above).
4. **Compute inventory delta per product:**
   - For each menuProductId that appears in old or new produced/waste:
   - `oldNet = oldProduced - oldWaste` (sum waste across all reasons for that product)
   - `newNet = newProduced - newWaste`
   - `delta = newNet - oldNet`
   - If delta !== 0, apply adjustment:
     - Query productInventory by_product_location
     - `newQuantity = previousQuantity + delta`
     - Patch productInventory
     - Insert productInventoryTransactions with `transactionType: "adjust"`, `quantity: delta`, reason: `"Shift record edit by ${user.name}"`, createdAt: now
5. Build new inventoryUpdates array from the adjustments.
6. Patch the record: update produced, waste, inventoryUpdates, editedAt (Date.now()), editedBy (user.name), editNote.
  </action>
  <verify>Run `npm run type-check` — mutations compile. Verify both mutations are exported in `convex/_generated/api.d.ts`.</verify>
  <done>submitShiftRecord handles full inventory integration (add produced, deduct waste, log transactions). updateShiftRecord computes delta adjustments with audit trail. Both enforce role-based access.</done>
</task>

Create new file `convex/kitchenShiftRecords/queries.ts` with two queries:

**A) `getShiftRecordsByDate` query:**
- Args: `{ date: v.string() }` — public query (all kitchen roles can view today's records)
- Query `kitchenShiftRecords` via `by_date` index where date equals arg
- Collect and return ordered by submittedAt ascending
- For each record, look up menuProduct names for the produced/waste entries using `ctx.db.get()` with Promise.all for parallel fetches
- Return enriched records with product names attached

Return shape per record:
```typescript
{
  _id, date, submittedAt, submittedBy,
  produced: Array<{ menuProductId, menuProductName, quantity }>,
  waste: Array<{ menuProductId, menuProductName, reason, quantity }>,
  editedAt?, editedBy?, editNote?,
}
```

**B) `getShiftHistory` query:**
- Args: `{ token: v.string(), startDate: v.optional(v.string()), endDate: v.optional(v.string()) }`
- Auth: `requireRole(ctx, args.token, ["manager", "admin"])` — only managers see full history
- Default range: last 7 days if no dates provided. Compute using `Date` math and WIB offset (+7 hours).
- Query `kitchenShiftRecords` via `by_date` index with range filter:
  - If startDate and endDate provided: `.withIndex("by_date", q => q.gte("date", startDate).lte("date", endDate))`
  - Collect and order by date descending, then submittedAt descending
- Enrich with menuProduct names (same pattern as above)
- Return array of enriched records grouped conceptually by date (flat array, UI handles grouping)
