  <action>
    **Add `createDraft` mutation** to `orderCrud.ts`:

    A minimal mutation that creates a Draft order with just a customer. No items required.

    Args:
    - `customerId: v.optional(v.id("customers"))` -- existing customer
    - `newCustomer: v.optional(v.object({ name: v.string(), phone: v.optional(v.string()) }))` -- inline new customer
    - `createdByUserId: v.optional(v.id("users"))` -- creator
    - `createdBy: v.optional(v.string())` -- creator name fallback

    Handler logic:
    1. Resolve customer (same pattern as existing `create` mutation -- either lookup by customerId or insert new customer)
    2. Generate order number via `generateOrderNumber(ctx)`
    3. Insert order with:
       - `status: "Draft"`
       - `isKitchenVisible: false`
       - `paymentStatus: "Unpaid"`
       - `orderDate: Date.now()`
       - `totalAmount: 0`, `totalCost: 0`, `totalMargin: 0`, `finalTotal: 0`
       - `itemCount: 0`
       - `deliveryType: "Pickup"` (default)
       - Customer fields (customerId, customerName, customerPhone)
       - Creator fields (createdBy, createdByUserId)
    4. Log audit event: `logOrderEvent(ctx, orderId, "created", { toStatus: "Draft", triggeredBy: "user", userId: args.createdByUserId })`
    5. Return `orderId`

    **Add `updateDraft` mutation** to `orderCrud.ts`:

    Updates all editable fields on a Draft order. Does NOT handle items (frontend uses existing `replaceItems` from `itemCrud.ts` for that).

    Args:
    - `orderId: v.id("orders")`
    - `customerId: v.optional(v.id("customers"))` -- change customer
    - `newCustomer: v.optional(v.object({ name: v.string(), phone: v.optional(v.string()) }))` -- change to new customer
    - `dueDate: v.optional(v.number())`
    - `deliveryAddress: v.optional(v.string())`
    - `deliveryType: v.optional(v.string())`
    - `notes: v.optional(v.string())`
    - `voucherCode: v.optional(v.string())`
    - `lowPriceConfirmed: v.optional(v.boolean())`

    Handler logic:
    1. Fetch order, validate `status === "Draft"` (throw if not)
    2. If customerId or newCustomer provided, resolve customer (same pattern as create):
       - If customerId: lookup customer, get name/phone
       - If newCustomer: insert new customer, get id/name/phone
       - Patch order with new customerId, customerName, customerPhone
    3. Build patch object from provided optional fields (only patch fields that are explicitly provided, skip undefined)
    4. Handle voucher change:
       - If voucherCode is provided and different from current: clear old voucher usage (releaseVoucherUsage if voucherId exists), validate and apply new voucher (validateAndApplyVoucher), record new usage
       - If voucherCode is empty string: clear voucher fields (voucherId, voucherCode, voucherDiscountValue) and release usage
    5. Recalculate finalTotal if voucher changed
    6. Apply patch to order
    7. Return orderId
  </action>
  <verify>
    `npm run build` passes. `grep "createDraft\|updateDraft" convex/orders/mutations/orderCrud.ts` returns matches for both exports.
  </verify>
  <done>
    createDraft creates minimal Draft order with customer only (no items required). updateDraft updates all editable fields including customer change and voucher handling. Both mutations are exported and type-safe.
  </done>

    **Fix Draft column sort in `listForKanban`** (queries.ts):

    Currently all non-complete columns sort by `dueDate ascending`. The Draft column should sort by `_creationTime descending` (newest first) per user decision.

    In the `listForKanban` query handler, after fetching orders for each column, change the sorting logic:

    ```typescript
    // Replace the current else branch:
    if (col.key === "complete") {
      // ... existing complete sort (keep as-is)
    } else if (col.key === "draft") {
      // Draft column: newest first (creation date descending)
      sortedOrders = orders.sort(
        (a, b) => b._creationTime - a._creationTime
      );
    } else {
      // Other columns: dueDate ascending (nearest due first), nulls last
      sortedOrders = orders.sort(
        (a, b) => (a.dueDate ?? Infinity) - (b.dueDate ?? Infinity)
      );
    }
    ```

    **Fix WhatsApp language toggle** in `StepWhatsAppTemplate` via backend (`whatsapp.ts`):

      orderId,

    // language is never passed, so getMessage always uses default "id"

Check that `getMessage` already passes `args.language` to `getTemplateContent` -- it does (line ~498: `args.language ?? "id"`).
