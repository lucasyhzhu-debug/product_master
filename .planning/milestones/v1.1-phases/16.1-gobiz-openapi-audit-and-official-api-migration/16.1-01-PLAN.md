    **For each doc file, structure as:**
    ```markdown
    # [Section Title]

    > Source: [URL crawled]
    > Last crawled: 2026-02-16

    ## Integration Status
    <!-- To be filled in Plan 02 -->

    ## Overview
    [Section description]

    ## Endpoints
    [For each endpoint:]
    ### [METHOD] [path]
    **Purpose:** [what it does]
    **Authentication:** Bearer token (OAuth2)
    **Request:**
    - Headers: [required headers]
    - Body: [request schema with types]
    **Response:** [response schema with types]
    **Example:**
    ```typescript
    // Request
    [sanitized example]

    // Response
    [sanitized example]
    ```
    **Error Codes:** [relevant errors]

    ## Notes
    [Rate limits, caveats, important details]
    ```

    - Structure for machine consumption: consistent headers, code blocks, typed schemas
    - Include sanitized request/response examples (replace real IDs/tokens with placeholders like `<OUTLET_ID>`, `<ACCESS_TOKEN>`)
    - Note environment URLs: sandbox vs production
    - Include deprecated endpoint warnings if found in official docs
    - Each doc is self-contained (can be read without other docs)

    **00-overview.md must include:**
    - Table of all 12 doc files with brief descriptions
    - Environment URLs (sandbox OAuth, production OAuth, sandbox API, production API)
    - Prerequisites for using the API (partner registration, scopes)
    - Base URL patterns
    - Authentication model summary
    - Link structure of the portal

    **If Firecrawl is unavailable:** Use WebFetch on each URL individually. Extract content, convert to structured markdown manually. This is acceptable per locked decisions (Firecrawl preferred but WebFetch is fallback).
