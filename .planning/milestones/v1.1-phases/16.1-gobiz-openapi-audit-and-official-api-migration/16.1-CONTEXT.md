<decisions>
## Implementation Decisions

### Crawl scope & depth
- Full site crawl of developer.gobiz.com — all API sections, not just what we currently use
- The developer portal is a structured multi-page site (e.g., developer.gobiz.com/docs/api/auth/direct-integration), not a single document
- Store crawled docs as one markdown file per API section in docs/apiS/gobiz-official/ (mirrors portal structure)
- Download all diagrams/images locally to docs/apiS/gobiz-official/images/ for offline access
- Firecrawl MCP is set up and available for systematic portal crawl

### Migration strategy
- Endpoint-by-endpoint migration — verify each API call individually before swapping
- Auth migration first — since everything depends on auth working, migrate authentication before data endpoints
- Keep old unofficial endpoint code as fallback during migration (comment out or feature-flag, don't delete)
- Test against live production GoBiz account — we only have production credentials, read-only calls are safe

### Gap handling
- Keep unofficial endpoints for gaps — use official API where possible, fall back to unofficial only for data the official API can't provide
- Document all official API capabilities, even ones we don't use yet — full reference for future phases
- Respect all official rate limits strictly — we're moving to a legitimate integration
- Produce a formal gap analysis document (gap-analysis.md) with endpoint mapping table, status per endpoint, and action items

### Documentation output
- Claude-first documentation — structured markdown optimized for Claude consuming as context
- Include sanitized real request/response examples from actual GoBiz production calls
- Replace existing docs/apiS/ GoBiz files with new official docs — old unofficial docs superseded
- Each API section doc includes an "Integration Status" header mapping: endpoint → our Convex function → status (official/unofficial/not-used)

### Claude's Discretion
- Exact file naming within docs/apiS/gobiz-official/ (based on portal section names)
- How to organize the gap analysis table columns
- Level of detail in request/response examples
- Whether to include deprecated endpoint warnings from official docs

</decisions>
