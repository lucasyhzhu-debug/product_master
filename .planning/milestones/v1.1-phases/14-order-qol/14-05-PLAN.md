    **Create OrderCreate.tsx:**
    New page component at `/orders/new`. Layout (top to bottom):

    1. **Header bar:** "New Order" title + "Back to Orders" link (navigates to /orders)
    2. **Customer section (TOP of form per user decision ORD-05):**
       - `<CustomerSearch />` component -- search input with autocomplete dropdown
       - When customer selected: show name + phone inline, edit button
       - When no match: "Create new customer" inline form (name required, phone optional)
       - Auto-save trigger: when customer is set (selected or created), auto-create Draft order via `create` mutation. Store orderId in state for subsequent item adds.
    3. **Due date section:**
       - `<DueDatePills />` component -- row of tappable pills
       - Below pills: "Pick a date" link/button that opens a native date input as fallback
    4. **Delivery section:**
       - Delivery/Pickup toggle (reuse existing `<DeliveryToggle />` component)
       - `<QuickAddressButtons />` for Crystal and Goldfinch locations
       - Address text input for custom delivery address
    5. **Items section:**
       - Reuse existing `<OrderFormPOS />` component (slot-based menu product grid) -- do NOT reinvent per user decision
       - Items are added via the POS grid, calling addItem mutation on the Draft order
       - Show running total at bottom
    6. **Voucher section:**
       - Reuse existing `<VoucherInput />` component
    7. **Notes section:**
       - Textarea for order notes
    8. **Submit button:**
       - "Submit Order" button at bottom -- calls `submitOrder` mutation (Draft -> AwaitingPayment)
       - On success: navigate back to /orders (Kanban) and show toast "Order submitted"
       - The WhatsApp payment modal will be triggered from the Kanban slide-over (per user decision: WhatsApp modal pops up after submit -- this is handled in OrderSlideOver when the order transitions to AwaitingPayment)

    **REMOVED fields (per user decisions):**
    - Sales channel (GoFood/Direct/K3Mart/etc.) -- REMOVED
    - Payment method (BCA/QRIS/Cash) -- REMOVED

    **Create CustomerSearch.tsx:**
    Customer search + autocomplete component:
    - Text input with debounced search (300ms)
    - Calls `useQuery(api.customers.queries.search, { query: searchText })` -- returns matching customers
    - Dropdown with matching results (name + phone preview)
    - Click result to select customer
    - "Add new customer" option at bottom of dropdown (expands inline mini-form: name input + phone input + "Add" button)
    - Selected state: show customer name + phone with "Change" button to re-open search
    - Props: `onCustomerSelect(customerId: Id<"customers">, name: string, phone?: string)` and `onNewCustomer(name: string, phone?: string)`

    **Create DueDatePills.tsx:**
    Quick-tap due date selector:
    - Generate pills for next 7 days using `date-fns`:
      - Today: "Today" (special label)
      - Tomorrow: "Tomorrow" (special label)
      - Days 2-6: Day name (e.g., "Sat", "Sun", "Mon", "Tue", "Wed")
    - Each pill shows: day name (bold) + date below (e.g., "Feb 17")
    - Selected pill has `bg-brand text-white` styling, unselected has `bg-muted hover:bg-muted/80`
    - Pills arranged in horizontal scrollable row
    - Below pills: "Pick a date" link opens native `<input type="date" />` for manual selection
    - Props: `value: number | undefined`, `onChange: (timestamp: number) => void`
    - Use `startOfDay()` from date-fns to normalize timestamps

    **Create QuickAddressButtons.tsx:**
    Two quick-add address buttons per ORD-04:
    - "Crystal" button: sets deliveryAddress to Crystal location address, deliveryType to "Pickup" (self-pickup)
    - "Goldfinch" button: sets deliveryAddress to Goldfinch location address, deliveryType to "Pickup"
    - Small pill buttons in a row
    - These are self-pickup by order creator per user decision
    - Props: `onSelect(address: string, deliveryType: string)`

    **Update App.tsx:**
    Add route for `/orders/new`:
    ```tsx
    <Route
      path="orders/new"
      element={

        </ProtectedRoute>
      }
    />
    ```

    The `/orders/new` route should use the standard Layout (not fullWidth) since it's a form page.
