  <name>Task 1: Schema migration + status engine rewrite</name>
  <files>

    convex/orders/validators.ts

    convex/orders/helpers/index.ts
  </files>
  <action>
    **Schema changes (convex/schema.ts):**
    1. Replace the `status` union on `orders` table with exactly 7 values:
       - `Draft`, `AwaitingPayment`, `PaymentReceived`, `BeingPrepared`, `AwaitingDelivery`, `Complete`, `Cancelled`
    2. Remove deprecated statuses: `InProduction`, `Boxed`, `Labeled`, `ProductionComplete`, `Packaging`, `WaitingShipment`, `CompleteShipped`, `WaitingPickup`, `PickedUp`
    3. Add new fields to `orders` table:
       - `createdByUserId: v.optional(v.id("users"))` -- links to users table for creator attribution
       - `expedited: v.optional(v.boolean())` -- marks rush orders
       - `kitchenEnteredAt: v.optional(v.number())` -- timestamp when order entered kitchen (auto-entry tracking, one-time threshold consumed)
    4. Update `orderEvents` table:
       - Add `userId: v.optional(v.id("users"))` field -- who performed the action (links to users table)
       - Keep existing `triggeredBy` field for system/kitchen/user categorization
    5. Keep all existing indexes intact. The `by_status` and `by_status_due_date` indexes still work with new status values.

    **Validators (convex/orders/validators.ts):**
    1. Update `statusValidator` to match new 7-value enum exactly
    2. Keep `channelValidator` and `orderItemInput` unchanged

    **Status transitions (convex/orders/helpers/statusTransitions.ts):**
    1. Rewrite `ALL_ORDER_STATUSES` to new 7 values
    2. Update `TERMINAL_STATUSES` to `["Complete", "Cancelled"]`
    3. Rewrite `computeIsKitchenVisible()`: kitchen sees `BeingPrepared` only (not Draft, AwaitingPayment, PaymentReceived, AwaitingDelivery, Complete, Cancelled). The kitchen query separately fetches completed-today orders.
    4. Remove `transitionToInProduction`, `transitionToPackaging`, `transitionToBoxed`, `transitionToLabeled` -- these intermediate statuses no longer exist
    5. Keep `logOrderEvent` and `logStatusTransition` but update the `LogOrderEventOptions` interface to include `userId: v.optional(v.id("users"))` and pass it through to ctx.db.insert
    6. Add a `FORWARD_TRANSITIONS` map defining valid forward transitions:
       ```
       Draft -> AwaitingPayment
       AwaitingPayment -> PaymentReceived
       PaymentReceived -> BeingPrepared
       BeingPrepared -> AwaitingDelivery
       AwaitingDelivery -> Complete
       ```
    7. Add a `BACKWARD_TRANSITIONS` map:
       ```
       AwaitingPayment -> Draft
       PaymentReceived -> AwaitingPayment (or Draft)
       BeingPrepared -> PaymentReceived
       AwaitingDelivery -> BeingPrepared
       Complete -> AwaitingDelivery
       ```
    8. Add `isValidForwardTransition(from, to)` and `isValidBackwardTransition(from, to)` helper functions
    9. Any status (non-terminal) can transition to Cancelled

    **Status update mutation (convex/orders/mutations/statusUpdates.ts):**
    1. Update `OrderStatusUpdate` interface to use new status type
    2. Remove inventory integration for Boxed/Labeled transitions (these statuses no longer exist)
    3. Inventory integration now:
       - `PaymentReceived` (was `Confirmed`): Reserve stock
       - `BeingPrepared` (was `InProduction`): Consume production materials AND boxing materials AND sticker materials (all happen at once since Boxed/Labeled merged into BeingPrepared)
       - `Cancelled`: Release reservations (unchanged)
    4. Update `confirmedAt` logic: set when transitioning TO `PaymentReceived` (was `Confirmed`)
    5. Add `reason` and `userId` optional args to `updateStatus` mutation for audit trail backward transitions
    6. Add backward transition handling: when going from PaymentReceived backward, clear `confirmedAt` (sales reversal per user decision)

    **Order CRUD (convex/orders/mutations/orderCrud.ts):**
    1. Update `create` mutation: initial status is `Draft` (not `AwaitingPayment`)
    2. Add `createdByUserId` field to order creation -- accept as optional arg, store on order
    3. Remove `channel` from create args (per user decision: remove sales channel field)
    4. Remove `paymentMethod` handling from create (per user decision: remove payment method field)
    5. Keep `soldBy` field -- this is the creator display name, but also add `createdByUserId` for the machine-readable link

    **Kitchen mutations (convex/orders/mutations/kitchen.ts):**
    1. Replace all `InProduction`/`Boxed`/`Labeled` references with `BeingPrepared`
    2. The kitchen "Complete Order" action transitions `BeingPrepared -> AwaitingDelivery`
    3. Remove per-step transitions (filling -> boxing -> labeling are now all within BeingPrepared)

    **Packaging mutations (convex/orders/mutations/packaging.ts):**
    1. Update all status references from old to new
    2. Package status tracking (empty/filling/filled/packed on orderItems) STAYS -- this is visual progress within BeingPrepared, not a separate order status

    **Inventory integration (convex/orders/mutations/inventoryIntegration.ts):**
    1. Update status references in comments and logic
    2. All material consumption (production + boxing + sticker) triggers on `BeingPrepared` entry

    **Kitchen queries (convex/orders/kitchenQueries.ts):**
    1. Update status filters to use `BeingPrepared` instead of `InProduction`/`Boxed`/`Labeled`

    **Order queries (convex/orders/queries.ts):**
    1. Update all status literals in query args and filters
    2. Update the `list` query status filter union
    3. Update `listPaginated` if it exists

    **WhatsApp (convex/orders/whatsapp.ts, whatsappHelpers.ts):**
    1. Update status references in template selection logic
    2. `Confirmed` -> `PaymentReceived`, `WaitingShipment`/`WaitingPickup` -> `AwaitingDelivery`, `CompleteShipped`/`PickedUp` -> `Complete`

    **Types (convex/orders/types.ts):**
    1. Update any `OrderStatus` or `OrderWithItems` type to use new statuses

    **Helpers index (convex/orders/helpers/index.ts):**
    1. Update re-exports if any names changed

    **Migration (convex/orders/mutations/migrations.ts):**
    1. Create `migrateToNewStatuses` mutation that:
       - Queries ALL orders
       - Maps: `Confirmed` -> `PaymentReceived`, `InProduction`/`Boxed`/`Labeled`/`Packaging`/`ProductionComplete` -> `BeingPrepared`, `WaitingShipment`/`WaitingPickup` -> `AwaitingDelivery`, `CompleteShipped`/`PickedUp` -> `Complete`
       - `Draft` and `AwaitingPayment` stay as-is, `Cancelled` stays
       - Updates `isKitchenVisible` using new `computeIsKitchenVisible`
       - Logs migration in console with count of orders migrated per status
  </action>
  <verify>

  </verify>
