In `traverseHierarchy`, after computing `childUnits` and before recursing into `traverseHierarchy` for the child, add a cost-leaf check:

```typescript
// Cost-leaf: child has no direct ingredients AND no sub-component links
// (or cogsMode === "manual") → synthesize cost entry from child's stored unit cost
const childIngredients = await ctx.db
  .query("productionComponentIngredients")
  .withIndex("by_component", (q) => q.eq("componentTypeId", link.childComponentId))
  .collect();

const childLinks = await ctx.db
  .query("productionComponentLinks")
  .withIndex("by_parent", (q) => q.eq("parentComponentId", link.childComponentId))
  .collect();

const isCostLeaf =
  childIngredients.length === 0 &&
  childLinks.length === 0;

if (isCostLeaf || childComponent.cogsMode === "manual") {
  // Use stored unit cost (either manualUnitCostIdr or unitCostIdr)
  const storedCost = childComponent.manualUnitCostIdr ?? childComponent.unitCostIdr ?? 0;
  if (storedCost > 0) {
    results.push({
      ingredientId: link.childComponentId as unknown as Id<"ingredients">,
      ingredientName: childComponent.name,
      totalQuantity: childUnits,
      unit: childComponent.unit ?? "unit",
      unitCost: storedCost,
      lineCost: storedCost * childUnits,
    });
  }
  continue; // Do not recurse into cost-leaf
}
```

Place this block BEFORE the recursive `traverseHierarchy` call. When `isCostLeaf` is false and `cogsMode` is not `"manual"`, fall through to the existing recursive call (no change to happy path).

Note: The `IngredientUsage` interface uses `ingredientId: Id<"ingredients">` — for the synthetic entry, cast `childComponentId` as needed. The COGS calculator sums `lineCost` across all entries, so the type cast works here (no DB lookup on the ID in the cost summation path).

Also check what fields exist on `componentTypes` for `cogsMode` and `manualUnitCostIdr` by reading `convex/schema.ts` before editing. If `cogsMode` is not on the schema, use only the `isCostLeaf` check (no ingredients + no sub-links).
