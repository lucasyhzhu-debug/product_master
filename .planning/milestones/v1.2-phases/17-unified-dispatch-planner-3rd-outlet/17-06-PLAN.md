**Gap 1 — Timezone fix in getWeekDates (convex/k3martCockpit/helpers.ts):**

The `getWeekDates()` function (lines 77-93) uses `d.getDay()` on a Date created with `+07:00` offset. When the JS runtime is in UTC (Convex server), `getDay()` returns the UTC day which can differ from Jakarta day. Fix by computing day-of-week from the Jakarta date string:

```typescript
export function getWeekDates(startDate: string): string[] {
  // Parse in Jakarta timezone to get correct day-of-week
  const d = new Date(startDate + "T12:00:00+07:00"); // Use noon to avoid DST edge cases
  const jakartaDateStr = d.toLocaleDateString("en-CA", { timeZone: "Asia/Jakarta" });
  const jakartaDate = new Date(jakartaDateStr + "T12:00:00+07:00");

  // Get day of week from Jakarta perspective
  const dayParts = new Intl.DateTimeFormat("en-US", {
    weekday: "short",
    timeZone: "Asia/Jakarta",
  }).format(d);

  const dayMap: Record<string, number> = {
    Sun: 0, Mon: 1, Tue: 2, Wed: 3, Thu: 4, Fri: 5, Sat: 6,
  };
  const dayOfWeek = dayMap[dayParts] ?? 0;
  const adjustedDow = dayOfWeek === 0 ? 7 : dayOfWeek; // Sunday = 7

  // Calculate Monday
  const monday = new Date(jakartaDate);
  monday.setDate(jakartaDate.getDate() - adjustedDow + 1);

  const dates: string[] = [];
  for (let i = 0; i < 7; i++) {
    const current = new Date(monday);
    current.setDate(monday.getDate() + i);
    dates.push(current.toLocaleDateString("en-CA", { timeZone: "Asia/Jakarta" }));
  }
  return dates;
}
```

**Gap 1 — Timezone fix in WeekNav.tsx (src/components/dispatchPlanner/WeekNav.tsx):**

The `getCurrentMonday()` function (lines 56-66) and `formatDateRange()` (lines 22-46) both already use `toLocaleDateString("en-CA", { timeZone: "Asia/Jakarta" })` correctly for formatting. The issue is `today.getDay()` on line 62 — the Date object is created with `+07:00` offset but `getDay()` returns UTC-based day if the browser is not in Asia/Jakarta timezone.

Fix `getCurrentMonday()` to use the same pattern as the backend fix:

```typescript
function getCurrentMonday(): string {
  const now = new Date();
  const todayStr = now.toLocaleDateString("en-CA", { timeZone: "Asia/Jakarta" });

  // Get Jakarta day-of-week using Intl
  const dayName = new Intl.DateTimeFormat("en-US", {
    weekday: "short",
    timeZone: "Asia/Jakarta",
  }).format(now);

  const dayMap: Record<string, number> = {
    Sun: 0, Mon: 1, Tue: 2, Wed: 3, Thu: 4, Fri: 5, Sat: 6,
  };
  const dayOfWeek = dayMap[dayName] ?? 0;
  const mondayOffset = dayOfWeek === 0 ? -6 : 1 - dayOfWeek;

  const today = new Date(todayStr + "T12:00:00+07:00");
  today.setDate(today.getDate() + mondayOffset);
  return today.toLocaleDateString("en-CA", { timeZone: "Asia/Jakarta" });
}
```

Also update the same `getCurrentMonday()` in `src/pages/DispatchPlanner.tsx` (lines 47-56) with the identical fix.
