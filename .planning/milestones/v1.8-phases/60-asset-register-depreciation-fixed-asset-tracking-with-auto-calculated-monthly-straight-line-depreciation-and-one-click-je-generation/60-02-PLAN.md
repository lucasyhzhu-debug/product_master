       - No args (auto-detects missing months via WIB current month)
       - Fetch all active depreciable assets (by_status index, filter depreciable categories)
       - For each asset, call computeMissingMonths to get missing YYYY-MM strings
       - For each asset+month combo:
         a. Resolve debit account (6150 Depreciation Expense) and credit account (per-category glAccumCode) via by_code index
         b. Calculate amount: use calculateFinalMonthAmount to handle last-month remainder
         c. Create JE via createJournalEntryWithLines with sourceType="depreciation", sourceId=asset._id (as string), date=first day of that month (WIB midnight to UTC), description="Depreciation: {assetName} ({YYYY-MM})"
         d. Update asset: patch accumulatedDepreciation += amount, lastDepreciationMonth = YYYY-MM
         e. Check if fully depreciated: if accumulatedDepreciation >= (cost - salvageValue), patch status to "fully_depreciated"
       - Return summary: { assetsProcessed, totalJEs, totalAmount, monthsCovered }
       - IMPORTANT: Resolve GL accounts ONCE at start (not per-iteration). Cache account IDs by code in a Map.

    5. **disposeAsset** (roles: ["admin"]):
       - Args: assetId, disposalType (sold/scrapped/written_off), disposalDate, saleProceeds (default 0)
       - Validate: asset must be active or fully_depreciated (not already disposed)
       - Calculate gain/loss via calculateDisposalGainLoss
       - Resolve GL accounts: 1500 (Fixed Assets), per-category accum depr, 1100 (Cash if sold), 7300 (gain) or 7400 (loss)
       - Create compound disposal JE:
         * DR Accumulated Depreciation (full accumulated amount)
         * DR Cash (saleProceeds, only if > 0)
         * DR Loss on Disposal (7400, only if loss)
         * CR Fixed Assets (1500, original cost)
         * CR Gain on Disposal (7300, only if gain)
       - IMPORTANT: Use sourceType="manual" (NOT "depreciation") for disposal JEs. Rationale: disposal is semantically different from depreciation -- using "depreciation" would cause voidDepreciationMonth to accidentally reverse disposal JEs, conflating two different accounting events. Using "manual" keeps disposal JEs safe from batch void operations.
       - Use createJournalEntryWithLines with sourceType="manual", sourceId=asset._id, description="Disposal: {assetName} ({disposalType})"
       - Patch asset: status="disposed", disposalDate, disposalType, saleProceeds, disposalGainLoss, disposalJournalEntryId

    6. **voidDepreciationMonth** (roles: ["admin"]):
       - Args: month (YYYY-MM string)
       - Parse month into year/month, compute month date range using `calculateMonthRange` from periodRange.ts
       - Query journalEntries using the NEW `by_sourceType_date` compound index:
         ```
         ctx.db.query("journalEntries")
           .withIndex("by_sourceType_date", q =>
             q.eq("sourceType", "depreciation")
              .gte("date", monthStart)
              .lte("date", monthEnd)
           )
           .filter(q => q.eq(q.field("isReversed"), false))
           .collect()
         ```
       - For each JE: call createReversalEntry with sourceType="depreciation_void"
       - For each affected asset (sourceId on JE = asset._id string):
         a. Recalculate accumulatedDepreciation: query ALL non-reversed depreciation JEs for this asset using by_source index (sourceType="depreciation", sourceId=assetId), sum the debit amounts from their JE lines on the depreciation expense account. Or simpler: subtract the voided monthly amount from the current accumulatedDepreciation.
         b. Find the "last posted month": query the asset's remaining non-reversed depreciation JEs (by_source index), find the max date, convert to YYYY-MM. If no remaining JEs, set lastDepreciationMonth to undefined.
         c. Revert status: if asset was "fully_depreciated" and accumulatedDepreciation is now less than depreciable amount, patch status back to "active".
       - Return summary: { jesReversed, assetsAffected }

       **Clarification on "last posted month" recalculation after void:**
       After voiding, the mutation MUST accurately determine the last remaining depreciation month per asset. Algorithm:
       1. Query `journalEntries` with `by_source` index: `sourceType="depreciation"`, `sourceId=assetIdString`
       2. Filter: `isReversed === false`
       3. If results empty: `lastDepreciationMonth = undefined`
       4. Otherwise: find max `date` value, convert to YYYY-MM using getWibComponents
       This ensures correct state even when voiding non-consecutive months.
