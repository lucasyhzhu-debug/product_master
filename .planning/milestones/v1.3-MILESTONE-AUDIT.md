## Integration Findings

### Finding 1 — GF-02: Frontend Role Guard Missing on Save Mappings (Warning)

**File:** `src/components/gofoodDepot/DepotMappingSection.tsx` lines 263-268

**Issue:** GoFood Depot route uses `canAccessDashboard` permission (manager + admin). `saveOutletProductMappings` backend mutation requires admin only. `DepotMappingSection.tsx` renders "Save Mappings" button with no role check — managers can click it and receive a generic "Failed to save mappings" toast with no explanation.

**Backend:** Correctly enforces admin role (`requireRole(ctx, args.token, ["admin"])`)

**Fix:** Add `const { user } = useAuth(); const isAdmin = user?.role === "admin";` and disable/hide the button when `!isAdmin`.

**Severity:** Warning (not a data integrity issue — backend enforces correctly; UX issue only)

---

### Finding 2 — GoFood → Kitchen Flow: Intentional Manual Step (Info)

**Finding:** GoBiz sync does not auto-create kitchen overrides. Manager must manually open Dispatch Planner and click "Save to Kitchen" per date.

**Context:** Architecturally correct — managers decide production targets. The Save to Kitchen button (Phase 24) is the explicit bridge. Not a defect.
