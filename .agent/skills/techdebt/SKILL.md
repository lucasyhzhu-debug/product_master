# Skill: /techdebt

## Purpose

Scan the codebase at the end of a session (or on demand) to identify code duplication, consolidation opportunities, and patterns that should be refactored. Generates a prioritized tech debt report.

## When to Use

- End of coding session (routine cleanup check)
- Before creating a PR (quality gate)
- When planning refactoring work
- User explicitly requests a tech debt scan

## Workflow

### Step 1: Scan for Known Patterns

Run these searches to identify duplication:

1. **Card Components:**
   ```bash
   # Find all card components
   find src/components -name "*Card.tsx" -type f
   ```

2. **Button Set Components:**
   ```bash
   find src/components -name "*Buttons.tsx" -type f
   ```

3. **Dialog Components:**
   ```bash
   find src/components -name "*Dialog.tsx" -type f
   ```

4. **Mutation Files:**
   ```bash
   find convex -name "mutations.ts" -type f
   ```

5. **Hook Files:**
   ```bash
   find src/hooks -name "*.ts" -type f
   ```

### Step 2: Analyze Specific Patterns

For each category, grep for these indicators:

| Category | Grep Pattern | What It Indicates |
|----------|--------------|-------------------|
| Field normalization | `\?\? .*_` | Legacy camelCase/snake_case handling |
| Card wrappers | `<Card>` followed by `<CardHeader>` | Identical component structure |
| CRUD boilerplate | `export const (create\|update\|remove) = mutation` | Mutation factory opportunity |
| Hook wrappers | `mutate:.*async.*mutateAsync:` | Hook factory opportunity |
| Toast patterns | `toast\.(success\|error)` in hooks | Consolidate with mutation wrapper |
| Barrel exports | `export \{` vs `export \{ default as` | Inconsistent export style |

### Step 3: Check for Unused Exports

```bash
# Find exported functions/components and check if imported elsewhere
grep -r "export const\|export function\|export default" src/
```

## Known Patterns in This Codebase

### Critical: Card Component Duplication
- **Files:** RecipeCard, IngredientCard, MaterialCard, PackagingCard, ProductCard
- **Pattern:** Identical Card/CardHeader/CardContent wrapper + field normalization
- **Fix:** Extract `<EntityCard>` generic component

### High: Mutation Hook Boilerplate
- **Files:** useOrders.ts (lines 416-800)
- **Pattern:** 10+ hooks with identical mutate/mutateAsync + toast
- **Fix:** Create `useMutationHook()` factory

### High: Button Set Components
- **Files:** ChannelButtons, PaymentMethodButtons, ShippingAgencyButtons
- **Pattern:** Primary buttons + dropdown + custom input
- **Fix:** Create `<SelectableButtonSet>` component

### High: CRUD Mutation Boilerplate
- **Files:** All `convex/*/mutations.ts` files
- **Pattern:** Identical create/update/updateTags/remove structure
- **Fix:** Create mutation factory in `convex/lib/`

### Medium: Dialog Components
- **Files:** ConfirmDialog, CancellationDialog, EnhancedCancellationDialog
- **Pattern:** Similar dialog structure with step management
- **Fix:** Create dialog factory with step support

### Medium: Naming Convention Handling
- **Files:** All card components
- **Pattern:** `field ?? field_legacy` normalization scattered
- **Fix:** Create `normalizeEntity()` utility
